# 04 · 五大规划内容实战（教材9.3）

> 教材9.3是本章的「正文」，从利益相关方诉求、组织体系、管理体系、技术体系到运营体系，五方面逐一展开。本节用华航项目逐一落地。

## 9.3.1 关注利益相关方的安全诉求

### 📖 教材知识点

**利益相关方**：能对组织活动产生影响、受到影响或感觉受到影响的任何个人、群体或组织。

不同角色的诉求差异显著：
- **信息安全主管**：更多安全投资
- **股东**：投入是否产生效益
- **员工**：安全对自己有什么影响（会不会太麻烦）

### 🏗 华航项目实践

我们梳理了华航项目六大利益相关方的安全诉求：

| 利益相关方 | 角色 | 核心诉求 | 我们的应对 |
|------|------|------|------|
| **集团CIO** | 决策者 | 安全不要影响业务、预算可控 | 安全不影响正常业务流程，85万/年ROI分析 |
| **信息中心安全主管** | 推动者 | 安全体系够全面、能通过合规检查 | 等保三级+ISO 27001+四部法律全覆盖 |
| **业务部门负责人** | 使用者 | 别太麻烦、别让系统变慢 | 分区分级管控：核心系统严格、一般查询简化 |
| **数据工程师** | 内部用户 | 开发环境数据可用、不要每次都要审批 | 测试数据脱敏后开放使用，减少审批环节 |
| **旅客（终端用户）** | 外部客户 | 个人信息安全、隐私不被滥用 | 隐私政策明示+知情同意+数据最小化采集 |
| **民航局（监管方）** | 外部监管 | 合规达标、数据可控 | 定期合规报告+迎检准备+专项审计 |

> **关键洞察**：不同利益相关方对"安全"的定义完全不同。对CIO是"别出事"，对业务部门是"别碍事"，对安全主管是"全覆盖"，对监管是"合规"。好的安全规划必须在这些诉求中取得平衡。

## 9.3.2 信息安全组织体系规划

### 📖 教材知识点

**信息安全组织框架四要素**：

| 要素 | 组成 | 职责 | 口诀 |
|------|------|------|:---:|
| **最高管理层** | 治理者 + 执行管理者 | 决策和资源保障 | **最** |
| **协调机构** | 最高管理层 + 各部门负责人 | 跨部门协调推进 | **协** |
| **内部组织** | 主管部门（可新增安全部门/指定IT主管）+ 配合部门 | 日常执行和落实 | **内** |
| **外部联系** | 消防、信息安全专业组织、政府监管部门等 | 外部资源获取和合规 | **外** |

> **速记口诀**：**最协内外**

### 🏗 华航项目实践

```
华航信息安全组织架构

┌─────────────────────────────────────────┐
│ 最高管理层                                │
│ ├ 治理者：集团CIO（安全战略审批+年度预算）  │
│ └ 执行者：信息中心总经理（安全建设总负责）  │
├─────────────────────────────────────────┤
│ 协调机构：信息安全委员会                   │
│ ├ 组长：集团CIO                           │
│ ├ 成员：各业务部门负责人+法务+内审         │
│ └ 例会：每季度一次，审议安全重大事项        │
├─────────────────────────────────────────┤
│ 内部组织                                  │
│ ├ 主管部门：信息安全组（3人：架构师+运维+审计）│
│ └ 配合部门：开发组/运维组/数据组 指定安全接口人│
├─────────────────────────────────────────┤
│ 外部联系                                  │
│ ├ 公安部等保测评机构（年度定级测评）        │
│ ├ 外部安全服务商（季度渗透测试）           │
│ ├ 国家信息安全漏洞库（CNNVD）              │
│ └ 行业安全联盟（民航信息安全工作组）        │
└─────────────────────────────────────────┘
```

> **考点提示**：组织四要素选择题考过。重点记"协调机构"包含各部门负责人，"外部联系"是个常设关系而非临时合作。

## 9.3.3 信息安全管理体系规划

### 📖 教材知识点

**ISMS四大特点**：
1. 基于风险评估，以预防控制为主
2. 强调遵守法律法规及合同方要求
3. 全过程动态控制，控制费用与风险平衡
4. 强调保护关键性信息资产（不是全部），确保CIA

**两大常见体系**：

| 体系 | 定位 | 适用范围 |
|------|------|------|
| **ISO 27001** | 国际标准，基于风险评估的ISMS | 自愿认证，第三方审核 |
| **等级保护（等保）** | 国家强制标准，分五级保护 | 国内强制，公安监管 |

### 🏗 华航：等保三级落地

**等保五个等级**：

| 等级 | 名称 | 破坏后影响 | 华航匹配 |
|:---:|------|------|:---:|
| 1 | 自主保护级 | 损害公民法人权益 | ❌太低 |
| 2 | 指导保护级 | 严重损害公民权益 | ❌不够 |
| 3 | **监督保护级** | **损害社会秩序或国家安全** | ✅华航等级 |
| 4 | 强制保护级 | 严重损害社会秩序 | ❌过高 |
| 5 | 专控保护级 | 特别严重损害国家安全 | ❌过高 |

> **速记口诀**：**自指监强专**

**等保基本框架——「一个中心、三重防御」**：

```
         ┌──────────────┐
         │ 安全管理中心  │ ← 一个中心
         └──────┬───────┘
    ┌───────────┼───────────┐
    ▼           ▼           ▼
┌───────┐ ┌───────┐ ┌───────┐
│安全计算│ │安全区域│ │安全网络│ ← 三重防御
│ 环境  │ │ 边界  │ │ 通信  │
└───────┘ └───────┘ └───────┘
```

> **速记口诀**：**一中三防**

**等保实施方法（6步）**：
安全定级→基本安全要求分析→系统特定安全要求分析→风险评估→改进和选择安全措施→实施安全保护

### 🏗 华航双体系建设

华航同时推行ISO 27001和等保三级「双体系融合」：

| 维度 | ISO 27001 | 等保三级 | 融合策略 |
|------|------|------|------|
| 范围 | 覆盖所有信息资产 | 聚焦关键信息系统 | 等保为底线，ISO 27001为高线 |
| 控制项 | 114项控制措施（附录A） | "一中三防"+管理要求 | 等保要求全部纳入ISO 27001 SOA |
| 审计 | 第三方年审 | 公安年检 | 合并审计，减少重复 |

> **考点提示**：等保五个等级的名称和影响递进是选择题必考点。另外注意「一中三防」和「等保2.0强化可信计算」。

## 9.3.4 信息安全技术体系规划

### 📖 教材知识点

**七大核心安全技术**：

| 编号 | 技术 | 核心内容 | 华航应用 |
|:---:|------|------|------|
| 1 | **身份认证** | 10种认证方式 | 双因素认证（动态口令+静态密码）+生物识别（门禁） |
| 2 | **访问控制** | DAC/RBAC/Rule-BAC/MAC四种 | RBAC+ABAC混合，四级数据分级定权 |
| 3 | **入侵检测** | 实时/事后两种 | Suricata IDS实时检测+日志事后分析 |
| 4 | **防火墙** | 四部分构成（规则/验证/包过滤/网关） | PaloAlto NGFW，3-7层防护 |
| 5 | **网闸** | 物理隔离+数据摆渡 | 内外网隔离，数据交换经网闸摆渡 |
| 6 | **防病毒** | 六条准则（拒检控清恢替） | ClamAV+商业病毒库，容器镜像扫描 |
| 7 | **数据加密** | 5种类型（对称/非对称/链路/节点/端到端） | AES-256存储加密+TLS 1.3传输加密+国密算法 |

#### 🔑 1. 身份认证（10种方式）

| 认证方式 | 核心原理 | 华航使用场景 |
|------|------|------|
| VIEID | 唯一网络身份证 | —（尚未使用） |
| 静态密码 | 用户自设 | 内部员工Portal登录 |
| 智能卡 | 不可复制硬件 | — |
| 短信密码 | 随机动态码（what you have） | 旅客身份二次验证 |
| 动态口令 | 60秒变换，一次有效（what you have） | 管理员操作审批 |
| USB Key | 冲击/响应或PKI模式 | 核心系统运维登录 |
| 生物识别 | who you are（人脸/行为特征） | 机房门禁（虹膜+人脸） |
| 双因素认证 | 两种方式组合 | 全员双因素（密码+OTP） |
| Infogo认证 | 网络安全准入 | — |
| 虹膜认证 | 近红外扫描，高可靠性 | 机房核心区域门禁 |

#### 🔐 2. 访问控制（4种机制）

| 机制 | 缩写 | 核心 | 华航应用 | 口诀 |
|------|:---:|------|------|:---:|
| 自主访问控制 | DAC | 客体所有者定义规则 | 个人工作文件共享 | **自** |
| 基于角色的访问控制 | RBAC | 按角色定义权限 | 全员按岗位角色分配 | **角** |
| 基于规则的访问控制 | Rule-BAC | 综合主体+请求+客体判定 | ABAC动态脱敏（乘务vs地服） | **规** |
| 强制访问控制 | MAC | 基于安全级别标签 | 机密级数据强制标签管控 | **强** |

> **速记口诀**：**自角规强**

> **考点提示**：四种访问控制中，DAC和MAC是一对对比概念（前者自主←→后者强制），RBAC和Rule-BAC是一对易混概念（前者基于角色身份←→后者基于规则条件）。

#### 🛡 3-7. 其余五大技术速览

| 技术 | 关键考点 | 华航故事 |
|------|------|------|
| **入侵检测** | 实时vs事后，IDS已纳入等保范畴 | 2025年3月Suricata实时检测到一次SQL注入尝试，3分钟内阻断 |
| **防火墙** | 四部分构成（服务访问规则/验证工具/包过滤/应用网关） | PaloAlto NGFW日均阻断12万次攻击尝试 |
| **网闸** | 物理隔离+无协议摆渡，两套独立系统分时连接 | 数据资产管理平台与外网之间经网闸进行数据交换 |
| **防病毒** | 六条准则「拒检控清恢替」 | ClamAV引擎+商业病毒库，容器镜像进入前强制扫描 |
| **数据加密** | 对称vs非对称+链路vs节点vs端到端 | AES-256存储加密+TLS 1.3传输+国密SM2/SM4 |

> **加密类型速记口诀**：**对非链节端**（对称/非对称/链路/节点/端到端）
> **防病毒六条口诀**：**拒检控清恢替**

## 9.3.5 信息安全运营体系规划

### 📖 教材知识点

**五大核心控制方法 + 两项运营活动**：

| 类别 | 方法/活动 | 核心要点 | 口诀 |
|------|------|------|:---:|
| 控制方法 | **因需可知** | 仅授予执行工作所需的数据访问权限 | **知** |
| 控制方法 | **最小特权** | 仅授予执行工作所需的特权（含数据+系统权限） | **权** |
| 控制方法 | **职责分离** | 制衡系统，无人可单独危及系统安全 | **分** |
| 控制方法 | **双人控制** | 关键任务需两人批准 | **双** |
| 控制方法 | **岗位轮换** | 防欺诈+交叉培训 | **转** |
| 控制方法 | **强制休假** | 突然实施，他人接管，可发现欺诈 | **假** |
| 运营活动 | **安全培训与意识提升** | 基础知识→操作规范→模拟演练→持续宣传 | **训** |
| 运营活动 | **应急响应** | 策略→联系→流程→演练→记录 五步 | **急** |

> **速记口诀**：**知权分双转假，训急处后改**

### 🏗 华航运营体系实践

| 方法 | 华航落地实践 |
|------|------|
| **因需可知** | 数据工程师仅能访问自己负责的业务域数据，不能跨域查询全部120+套系统数据 |
| **最小特权** | 运维人员日常仅有只读权限，需要修改时走审批流程临时提权，操作完成后自动回收 |
| **职责分离** | 安全策略制定（安全架构师）与安全策略执行（安全运维工程师）由不同人担任 |
| **双人控制** | 数据库生产环境的DDL操作需两人同时确认，一方发起+一方审批 |
| **岗位轮换** | 安全组3人每半年轮换一次负责的系统模块，减少单点依赖 |
| **强制休假** | 关键岗位每年至少一次连续5个工作日的强制休假，期间由B角接管 |
| **安全培训** | 全员入职安全培训+季度钓鱼邮件模拟演练+管理层年度安全意识考核 |
| **应急响应** | 定义P1-P4四级事件，P1级30分钟响应，每半年一次全链路应急演练 |

#### 🚨 应急响应五步（华航落地）

| 步骤 | 内容 | 华航实践 |
|:---:|------|------|
| 1 | 制定应急响应策略 | P1-P4四级分类，明确各级响应时间和责任人 |
| 2 | 建立紧急联系渠道 | 建立安全事件通报群（含CIO/安全组/业务负责人/法务/PR） |
| 3 | 制定应急响应流程 | 检测→确认→遏制→根除→恢复→复盘 六阶段SOP |
| 4 | 进行应急演练 | 2025年3月全链路容灾演练（模拟主中心网络中断，12分钟切换） |
| 5 | 建立报告记录 | 每次事件详细记录+月度汇总+季度复盘报告 |

> **考点提示**：运营控制方法中，「因需可知」和「最小特权」是一组对比概念（前者管数据访问范围，后者管操作权限级别）。「岗位轮换」和「强制休假」是选择题经典易混点——区别在于前者是计划性轮岗，后者是突然强制。
