## 一、四大项目管理工具全面对比

|------|-------------|---------|---------|---------------|
| 类型 | SaaS/私有部署 | 国产开源 | 商业软件 | 商业软件(桌面+在线) |
| 敏捷Scrum | ✅ 原生支持 | ✅ | ✅ | ❌ |
| 看板Kanban | ✅ | ✅ | ✅ | ❌ |

### 1.2 各工具核心机制

#### PingCode — 研发全生命周期覆盖

```
需求收集 → 需求管理 → 项目管理(Scrum/Kanban/瀑布) → 测试管理 → 效能度量
                ↕
           知识管理(Wiki)
```

**特色**：
- 自动采集研发过程数据 → 效能仪表盘
- 三种开发模型（Scrum / Kanban / 瀑布）原生支持
- 子产品组合灵活搭配

#### 禅道 — 四层管理框架

::: tip 禅道四层框架
**项目集 → 产品 → 项目 → 执行**
:::

| 层级 | 角色 | 核心概念 |
|:---:|------|---------|
| 项目集 | 管理者 | 宏观视角、预算、周期、资源配置 |
| 产品 | 产品经理 | 需求梳理、规划管理（**整个活动核心**） |
| 项目 | 项目经理 | Scrum/瀑布/看板模型选择 |
| 执行 | 团队 | 需求、任务、缺陷、用例（迭代管理） |

#### Jira — 事务驱动+工作流

Jira的核心概念：
- **项目** = 一组事务的集合
- **事务(Issue)** = 最小跟踪单元（缺陷/功能/任务）
- **工作流** = 事务从创建→完成的状态流转路径

#### Microsoft Project — 专业项目管理

项目管理5阶段支持：建议 → 启动和计划 → 实施 → 控制 → 收尾

核心功能：项目计划、任务管理、资源管理、甘特图、多种视图、报告、路线图

## 二、🔥 华航实战：禅道 + Jira 双轨制

### 为什么双轨？

> 华航项目涉及7大功能模块并行开发，团队分布在3个城市。单一工具无法同时满足**项目管理层的宏观把控**和**开发团队层的敏捷迭代**需求。

| 层级 | 工具 | 为什么 |
|------|------|--------|
| 项目组合层 | **禅道** | 项目集→产品→项目三层框架天然适合多模块管理 |
| 开发执行层 | **Jira** | Scrum看板+灵活的Issue工作流，程序员熟悉 |
| 文档中枢 | **Confluence** | 双工具通过Confluence桥接文档和需求 |
| 效能度量 | **禅道+PingCode** | 禅道管项目级度量，PingCode管研发效能 |

### 具体运作

1. **禅道**中创建项目集"华航数据平台"，下设7个子项目（对应7大模块）
2. 产品经理在禅道管理需求池和路线图，设定P0/P1/P2优先级
3. 每个Sprint开始，需求从禅道同步到**Jira**，拆分为Story和Task
4. 开发人员每天在Jira看板上更新任务状态
5. Sprint结束时，完成的Story在Jira中标记Done，同步回禅道更新进度
6. **Confluence**承载所有设计文档、Sprint回顾、技术决策记录

## 三、项目管理工具选型7要素

::: tip 核心口诀
**「规需易安本方扩」**
:::

| 要素 | 说明 | 华航思考 |
|:---:|------|---------|
| **规**模 | 小团队简单工具即可，大团队需复杂工具 | 29节点+30人团队，需企业级工具 |
| **需**求 | 匹配业务功能和特性 | 同时需要敏捷和瀑布管理能力 |
| **易**用性 | 界面直观、易于导航 | 双轨制增加学习成本，但分工明确 |
| **安**全性 | 保护敏感信息 | GitLab+禅道私有部署 |
| 成**本** | 开源需二次开发，商业需付费 | 禅道开源免费降低总成本 |
| **方**式 | 工作方式：远程协作？实时？移动端？ | 三城远程，Jira/Confluence的云端协作 |
| **扩**展 | 未来增长和扩展性，自定义能力 | Jira的插件生态确保可扩展 |
