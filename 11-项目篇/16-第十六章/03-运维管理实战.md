## 一、监控工具

### 1.1 三大开源监控对比

监控工具对运行维护服务对象进行数据采集和监控，评估可能导致运行故障的因素。

| 特性 | **Zabbix** | **Nagios** | **Prometheus** |
|------|-----------|-----------|---------------|
| 模型 | 推/拉混合 | **推(Push)** | **拉(Pull)** ← 关键！ |
| 架构 | Server-Proxy-Agent | Server-Agent | Server主动抓取HTTP |
| 存储 | 关系型数据库 | 文件/RDB | **时序数据库** |
| Web管理 | ✅ 内置 | Nagios XI付费 | ❌ 需Grafana |
| 扩展性 | 百万级指标 | 大规模需付费版 | 天生水平扩展 |
| 告警 | 灵活通知机制 | 短信/邮件/脚本 | AlertManager |
| 适合场景 | 传统IT基础设施 | 中小规模 | **微服务/云原生** ← 关键！ |

::: warning 易错点
Nagios是**推模型**（Agent主动推送数据给Server），Prometheus是**拉模型**（Server主动从HTTP接口抓取）。选择题常考这个区别！
:::

### 1.2 统一运维监控平台 6大模块

::: tip 核心口诀
**「采检警障视监」**
:::

| 模块 | 功能 | 统一化目标 |
|:---:|------|-----------|
| **采**集 | 集中下发采集任务 | 统一采集 |
| **检**测 | 多种异常检测算法、异常防抖 | 统一检测 |
| **警**告 | 多种告警通知途径 | 统一告警 |
| **障**管理 | 故障全生命周期管理 | — |
| **视**图 | 全局总览/应用视角/拓扑视图 | 统一展示 |
| **监**控 | 集中管理监控对象和配置 | — |

**两种建设方式**：
1. **基于开源软件自主开发**：Zabbix/Nagios/Prometheus基础上集成封装
2. **定制商业化运维监控平台**：嘉为蓝鲸、锐捷网络、华胜天成等

### 🔥 华航实战：Prometheus + Grafana 监控体系

> 2024年10月部署初期，我们使用Zabbix做基础监控，但随着K8s容器化部署上线，Zabbix对动态容器环境支持不足。我推动升级为**Prometheus + Grafana**方案：Prometheus通过Service Discovery自动发现K8s Pod和Service，采集业务指标、JVM指标、数据库指标等100万+监控项；Grafana构建三层仪表盘（全局总览→应用视角→拓扑视图）。关键创新是设置了**动态基线告警**——根据历史7天数据自动计算阈值，避免固定阈值误报。

## 二、过程管理工具 (ITSM)

### 2.1 ITSM核心概念

ITSM是一套**面向过程、以客户为中心**的管理方法和规范，通过集成IT服务和业务，帮助组织对IT系统的规划、研发、实施和运营进行有效管理。

核心ITSM流程：

::: tip 核心口诀
**「请件题变」**
:::

| 流程 | 英文 | 内容 |
|:---:|------|------|
| 服务**请**求管理 | Service Request | 标准化服务申请（如账号开通、资源申请） |
| 事**件**管理 | Incident | 非计划中断或服务质量下降 |
| 问**题**管理 | Problem | 事件的根本原因分析 |
| **变**更管理 | Change | 有计划地修改IT基础设施 |

### 2.2 两大ITSM工具

| 工具 | 特点 | 适用场景 |
|------|------|---------|
| **Jira Service Management** | 渠道整合、AI辅助、资产/配置管理 | 与Jira/Confluence深度集成的团队 |
| **ServiceHot ITSM** | 国产化适配、可视化流程、开箱即用 | 国产化要求高的政企客户 |

### 🔥 华航实战：Jira SM 四流程闭环

> 我们使用Jira Service Management构建ITSM体系：
> - **服务请求**：统一服务门户，用户提交资源申请、账号开通等 → 自动路由至审批人
> - **事件管理**：监控告警自动创建事件工单 → P1/P2/P3/P4分级 → 15分钟响应SLA
> - **问题管理**：重复事件自动关联 → 根因分析 → 知识库沉淀
> - **变更管理**：所有生产变更必须提交RFC → CAB审批 → 变更窗口执行
>
> 上线后，事件平均处理时间从4.5小时降至1.8小时，变更失败率从12%降至3%。

## 三、自动化专用工具

### 3.1 作业调度/批处理工具

| 工具 | 架构 | 特点 | 核心区别 |
|------|------|------|---------|
| **Puppet** | C/S，需安装客户端 | 周期拉取配置，Web管理界面 | 老牌，功能全面 |
| **SaltStack** | C/S + MQ | 秒级执行，RSA加密 | 速度快，安全性高 |
| **Ansible** | **无需客户端** | SSH协议，模块化 | **最轻量** ← 关键！ |

::: warning 易错点
Ansible **不需要**在管控对象上安装客户端，基于SSH协议！这是它与Puppet/SaltStack的最大区别。
:::

### 3.2 操作自动化工具

| 工具 | 核心定位 | 关键特性 |
|------|---------|---------|
| **Jenkins** | 持续集成自动化 | Java开源、插件丰富、跨平台、流水线Pipeline |
| **Chef** | 自动化部署配置 | Ruby DSL、云原生友好、大规模部署 |

### 🔥 华航实战：Ansible + Jenkins 自动化体系

> 运维自动化分为两个层面：
> - **环境层面**：用**Ansible**管理29节点的一致配置，从OS基础配置→中间件安装→应用部署全流程Playbook化。新节点上线从手工4小时缩短至**18分钟**。
> - **交付层面**：用**Jenkins Pipeline**实现CI/CD，代码提交→构建→测试→镜像打包→K8s部署全自动。日构建次数从2次提升至**20+次**。

## 四、服务台

服务台是IT运维服务中**供方与需方沟通交互的重要界面**，是供方与需方之间的**单一连接点**。

### 三大服务台工具

| 工具 | 特点 |
|------|------|
| **ServiceDesk Plus** | 图形化工作流、集成资产管理+CMDB、全方位IT管理 |
| **ServiceHot** | AI智能机器学习、多渠道路由（邮件/电话/Web/微信） |
| **云智慧服务台** | 即时通信+呼叫中心+自助提单、AI全文检索 |

### ChatOps

ChatOps以**沟通为中心**，通过ChatBot将成员和工具连接，以**对话方式完成工作**，消除信息孤岛。

> 华航项目中，我们在Jira SM中集成了智能客服机器人（类似ChatOps），用户在服务门户可直接通过对话查询知识库、提交工单、查询进度。一线服务台人工负荷降低**40%**。

## 五、知识管理

### 三大知识库工具

| 工具 | 定位 | 核心优势 |
|------|------|---------|
| **ITSM内置知识库** | 紧耦合 | 与事件/问题/变更流程深度集成，智能推送 |
| **Confluence** | 企业Wiki | 富文本、模板、插件生态、与Jira深度集成 |
| **PingCode Wiki** | 国产知识库 | 自动化权限、企微/飞书集成、Markdown支持 |

### 🔥 华航实战：Confluence知识管理

> 知识库建设是14主题论文框架中明确标注的子题目方向（见06-论文实战范文）。我们以Confluence为核心构建三层知识体系：
>
> | 层级 | 内容 | 数量 |
> |------|------|:---:|
> | L1 基础知识 | 架构文档、部署手册、接口规范 | 150+ |
> | L2 运维知识 | 故障处置SOP、巡检清单、变更方案 | 250+ |
> | L3 经验沉淀 | 故障复盘报告、最佳实践、FAQ | 120+ |
>
> 通过KPI考核（每人每月5条）+ 质量评审机制，试运行结束积累**520条知识**，工单平均解决时间从8h降至5.2h。

## 六、备件管理

备件管理针对硬件和软件虚拟资产，常见功能：

::: tip 核心口诀
**「存保批查」**
:::

| 功能 | 内容 |
|:---:|------|
| **存** | 库存信息管理（数量/资产/采购/供应商/文档/干系人） |
| **保** | 备件维保服务生命周期管理（交付/维保/维修/退换货/报废） |
| **批** | 出入库审批流程（与ITSM流程关联） |
| **查** | 备件查询与追踪（便捷查询+可视化报表） |

## 七、新型运维工具

### 7.1 AIOps（智能运维）

AIOps利用大数据、人工智能或机器学习技术，解决自动化运维未能解决的问题，最终实现**运维无人化、智能化**。

| 代表产品 | 核心能力 |
|---------|---------|
| **嘉为蓝鲸** | 腾讯蓝鲸PaaS体系，异常检测/指标预测/关联分析/健康画像/根因分析 |
| **云智慧** | 数据驱动平台、数百场景模板、国产化适配 |

### 7.2 DevOps工具链

DevOps = Development + Operations，通过自动化CI/CD实现软件快速交付和持续改进。

| 工具类别 | 代表工具 |
|---------|---------|
| 版本控制 | Git, SVN |
| 自动化构建 | Maven, Gradle |
| 自动化测试 | Selenium, JUnit |
| CI/CD | Jenkins, GitLab CI/CD |
| 配置管理 | Ansible, Chef, Puppet |
| 日志管理 | ELK Stack (ES + Logstash + Kibana) |
| 容器化 | Docker, Kubernetes |
| 云平台 | AWS, Azure, GCP |

### 7.3 云管理工具

| 工具类型 | 功能 |
|---------|------|
| **CloudOS** | 虚拟化云，物理→逻辑转变，灵活管理资源 |
| **CMP** | 多云统一管理，含云资源适配/服务管理/运营管理/云门户 |
| **CSM** | 云安全，安全监测/审计/威胁分析/防护/处置 |
| **CPS** | 云专业服务，云迁移/测试/备份 |
