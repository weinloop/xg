
### 2.2 部署拓扑

- **总部主中心（北京）**：Active，承载全部核心业务，20个Worker节点 + 2个GPU节点
- **华东容灾中心（南京）**：Standby，实时数据同步，RTO ≤ 15min，RPO ≤ 5min
- **5大区域边缘节点**：就近服务区域用户，每节点1台边缘服务器，承载数据采集+本地缓存

## 三、服务模式分层详解（对应教材6.2.4）

### 3.1 IaaS层：基础设施即服务

| 要素 | 华航项目实现 |
|------|------------|
| **虚拟化技术** | VMware vSphere 实现计算虚拟化，每物理机划分4-6个VM |
| **计算资源池** | 20个Worker VM（16vCPU/64GB）+ 2个GPU直通VM（8×NVIDIA A100） |
| **存储资源池** | Ceph分布式存储：对象存储(RGW) / 块存储(RBD) / 文件存储(CephFS) |
| **网络资源池** | SDN软件定义网络，VLAN隔离业务/管理/存储三个平面 |
| **主要用户** | 系统管理员（运维团队） |

### 3.2 PaaS层：平台即服务

| 要素 | 华航项目实现 |
|------|------------|
| **容器编排** | Kubernetes 1.28，管理200+个Pod |
| **CI/CD流水线** | GitLab CI + Harbor镜像仓库 + ArgoCD部署 |
| **数据开发平台** | JupyterHub + Spark on K8s，供数据工程师开发ETL/分析任务 |
| **模型训练平台** | MLflow + GPU资源池，供AI团队训练数据分类/血缘模型 |
| **主要用户** | 开发人员（数据工程师、AI工程师） |

### 3.3 SaaS层：软件即服务

| 模块 | 功能 | 服务对象 |
|------|------|---------|
| 数据资产管理 | 10万+资产目录管理 | 数据管理员、业务部门 |
| 数据质量治理 | 5000+质量规则自动检测 | 数据治理团队 |
| 数据安全管控 | 分类分级 + 脱敏 + 审计 | 安全管理员 |
| 数据血缘图谱 | 120+套系统字段级血缘追踪 | 数据架构师 |
| 智能标签 | AI自动打标 + 标签推荐 | 全体用户 |
| AI辅助决策 | 自然语言查询数据资产 | 管理层、业务分析员 |

## 四、云服务类型选择分析（对应教材6.2.1）

华航项目选择**混合云**架构，核心决策逻辑：

| 业务类型 | 部署位置 | 理由 |
|---------|---------|------|
| **稳态业务**（核心数据处理、元数据管理、安全审计） | 总部私有云 | 高可靠、低时延、数据安全性要求高 |
| **敏态业务**（AI模型训练、临时数据分析） | 可弹性扩展到公有云 | 需要GPU弹性算力、按需付费 |
| **边缘业务**（数据采集、本地缓存、实时监控） | 5大区域边缘节点 | 超低时延（< 5ms）、海量异构数据接入 |

### 混合云统一能力实现

- **服务门户统一**：用户通过统一Portal访问，后端自动路由到对应云环境
- **资源监控统一**：Prometheus + Grafana 统一监控所有节点
- **账户权限统一**：LDAP + OAuth2.0 统一身份认证

## 五、计算资源规划详解（对应教材6.3）

### 5.1 计算资源形态分布

| 形态 | 数量 | 配置 | 用途 |
|------|:---:|------|------|
| 虚拟机（VM） | 20+5 | 16vCPU/64GB/500GB SSD | 微服务容器宿主机 |
| 容器（Container） | 200+ | K8s Pod | 7大功能模块微服务 |
| 裸金属（Bare Metal） | 2 | 128vCPU/512GB | Oracle RAC数据库集群 |
| GPU | 2 | 8×NVIDIA A100/节点 | AI模型训练+血缘计算 |
| 弹性计算（ECR） | 按需 | Auto Scaling | 峰值流量弹性扩容 |

### 5.2 vCPU容量规划计算（★★★ 首考计算题核心）

**场景**：数据资产查询API，高峰期5000并发，平均响应时间200ms

$$总vCPU = 5000(峰值QPS) \times 0.2(单请求CPU耗时·秒) \times 1.5(冗余系数) = 1500 vCPU$$

需约 94 个实例（1500 ÷ 16vCPU/实例），实际部署 20 Worker（320 vCPU）配合弹性扩展应对。

> **考点提示**：这个公式必须能默写，首考25分案例计算题就考了这个。题目可能给你不同参数（比如冗余系数1.3 v.s. 1.5），要学会代入计算。

## 六、存储资源规划详解（对应教材6.4）

### 6.1 存储类型与数据映射

| 数据类型 | 容量 | 存储类型 | 选择理由 |
|---------|:---:|------|------|
| 结构化业务数据（元数据、规则、配置） | 15PB | **块存储（SAN/iSCSI）** | 高性能IOPS、低延迟、数据库需求 |
| 非结构化文件（PDF/Word/图片） | 30PB | **对象存储（S3兼容）** | 海量扩展、元数据管理、成本低 |
| 共享文件（临时/日志/备份） | 5PB | **文件存储（NAS/NFS）** | 多节点共享访问、便于管理 |

### 6.2 存储9步过程在华航的落地

| 步骤 | 华航项目实践 |
|------|------------|
| ①收集需求 | 调研120+套源系统数据类型、增长速率、访问模式 |
| ②分析评估 | 预测3年数据增长：结构化年增30%、非结构化年增50% |
| ③技术选择 | Ceph分布式存储：RBD(块)+RGW(对象)+CephFS(文件) |
| ④架构设计 | 3副本策略 + 纠删码(k=8,m=3)冷数据降存储成本40% |
| ⑤安全规划 | AES-256静态加密 + TLS传输加密 + 分级访问控制 |
| ⑥容量规划 | 当前50PB → 3年后预扩至120PB（预留扩容空间） |
| ⑦性能优化 | SSD缓存池加速热数据，IOPS提升3倍 |
| ⑧管理监控 | Prometheus监控IOPS/吞吐/延迟，异常自动告警 |
| ⑨定期评估 | 每季度review存储使用率，动态调整副本策略 |

## 七、云数据中心规划（对应教材6.5）

### 7.1 数据中心分级与选址

| 数据中心 | 级别（GB 50174） | 定位 |
|---------|:---:|------|
| 北京总部主中心 | **A级** | IT生产中心，承载核心业务 |
| 南京容灾中心 | **B级** | 灾难备份中心，异地灾备 |
| 5大区域边缘节点 | **C级** | 边缘计算节点，数据采集+本地服务 |

### 7.2 PUE目标

**目标 PUE ≤ 1.4**，通过以下措施实现：
- 自然冷却（北京冬季利用室外低温）、冷热通道隔离
- 虚拟化提高服务器利用率（从传统30%提升至70%）
- 模块化UPS（效率96%+）
