# 01 · 项目全景 — 华航数据资产平台（HR视角）

> 从「人员管理」的角度重新审视华航项目：12个人的团队怎么搭？8类角色怎么定？谁管谁？谁培训谁？谁考核谁？

---

## 一、团队基本盘

| 维度 | 数据 |
|------|------|
| **总人数** | 12人核心团队（不含外包标注和临时人员） |
| **甲方人员** | 华航信息中心指派2人（项目经理1人+数据治理对接人1人） |
| **乙方人员** | 我方10人（涵盖全部技术和管理角色） |
| **管理架构** | 三层治理：决策层（指导委员会/季度会）→ 管理层（PMO/月度会）→ 执行层（各角色/周例会） |
| **服务范围** | 总部北京 + 5大区域中心（各配1名数据管家） + 23个分公司（远程支持） |
| **人员预算** | 含在580万/年合同额中，约占35%（≈200万） |

## 二、8类角色定义

```
                    ┌──────────────┐
                    │  指导委员会   │  ← 华航VP+我方总监（季度）
                    └──────┬───────┘
                           │
                    ┌──────┴───────┐
                    │   PMO/PM     │  ← 李姐（周度统筹）
                    └──────┬───────┘
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
   ┌────┴────┐      ┌──────┴──────┐    ┌──────┴──────┐
   │ 技术组   │      │  数据组     │    │  运营组      │
   │ 3人      │      │  3人        │    │  4人         │
   └─────────┘      └─────────────┘    └─────────────┘
   平台运维×2        数据工程师×1       5区域数据管家×5
   安全专员×1        数据分析师×1       质量专员×1
                     数据架构师×1
```

| 角色 | 人数 | 汇报关系 | 核心职责 |
|------|:---:|------|------|
| **项目经理** | 1 | →指导委员会 | 整体协调、进度管理、客户沟通 |
| **数据架构师** | 1 | →项目经理 | 数据架构设计、技术选型、架构评审 |
| **数据工程师** | 1 | →数据架构师 | ETL开发、数据建模、质量规则实施 |
| **数据分析师** | 1 | →数据架构师 | 需求分析、指标体系、数据探查 |
| **平台运维** | 2 | →项目经理 | K8s集群运维、Ceph存储管理、监控告警 |
| **安全专员** | 1 | →项目经理 | 安全策略、等保合规、审计日志 |
| **质量专员** | 1 | →项目经理 | 数据质量监控、5000规则维护、质量报告 |
| **数据管家** | 5 | →质量专员 | 区域数据标准落地、质量巡检、用户培训 |

## 三、关键HR事件时间线

```
2024年7月 ─── 项目启动，初始8人团队到位
    │         核心问题：数据管家职责边界不清
    │         动作：启动工作分析
    │
2024年8月 ─── 完成全部8类岗位工作说明书
    │         发现：数据管家岗位定义过宽（标准+运维+培训混在一起）
    │         动作：岗位重新设计，剥离运维操作给运维团队
    │
2024年9月 ─── 5大区域数据管家全部招聘到位
    │         招聘策略：内部推荐+校园招聘为主，猎头补充高端岗
    │         团队扩展至12人
    │
2024年10月 ─── 首批数据管家完成40小时认证培训
    │         1人未通过认证考试 → 跟岗学习2周 → 补考通过
    │         建立「持证上岗」制度
    │
2024年11月 ─── 首次季度绩效考核
    │         引入行为锚定评价法（BARS），为每类角色设不同锚点
    │         数据工程师考核维度：ETL准时率/数据质量/业务满意度
    │
2025年3月 ─── 容灾演练暴露人员应急能力不足
    │         启动「A/B角轮岗」制度，确保任一岗位缺人时服务不中断
    │
2025年6月 ─── 试运行结束，全员绩效回顾
    │         12人全部通过考核，2人晋升
```

## 四、人员管理的三大挑战与应对

| 挑战 | 表现 | 13章对应知识点 | 解决措施 |
|------|------|:---:|------|
| **角色边界模糊** | 数据管家同时承担标准制定、运维操作、用户培训 | 13.2 工作分析+岗位设计 | 工作说明书明确职责 → 剥离运维操作 → 按工作特征模型重新设计 |
| **人才流失风险** | 数据工程师/分析师市场上紧缺，薪资竞争激烈 | 13.3 人力资源战略 | 投资战略（培养稀缺人才）+ 混合战略（核心岗内部培养） |
| **培训效果不佳** | 初次培训后，数据管家在5区域的实际操作差异大 | 13.5 培训效果评估 | 柯氏4层次评估 → 增加「行为变化」层次的考核 → 跟岗+案例分析 |

## 五、教材知识点映射总表

| 教材节 | 知识点 | 华航项目对应 |
|:---:|------|------|
| 13.1 | 人力资源五大环节 | 规划（7月）→招聘（8-9月）→维护（薪酬+环境）→提升（培训认证）→评价（BARS季度考核） |
| 13.2 | 工作分析10步骤 | 8类岗位逐一走完4阶段10步骤（2024.7-8月） |
| 13.2 | 定性+定量分析方法 | 面谈法（访小赵）+问卷法（团队问卷）+典型事例法，定量用简化PAQ |
| 13.2 | 岗位设计4方法 | 工作特征模型（拆分数据管家职责），高绩效工作体系（区域团队自治） |
| 13.3 | 人力资源战略 | 投资战略为主（培养稀缺数据人才），混合战略（巴伦分类） |
| 13.3 | 需求预测 | 转换比率分析：按平台二期主题域翻倍估算需增4工程师+2分析师 |
| 13.3 | 供给预测 | 技能清单+马尔可夫转移矩阵（预测分析师年流失40%） |
| 13.4 | 招聘渠道 | 内推+网络（基础岗）/猎头（架构师）/校园（应届）/临时雇员（标注） |
| 13.4 | 录用测试 | 能力测试（笔试）+工作样本法（现场建模）+半结构化面试 |
| 13.5 | 培训4层次 | 反应（满意度问卷）→学习（认证考试）→行为（跟岗观察）→效果（业务指标变化） |
| 13.6 | BARS行为锚定 | 为8类角色分别制定行为锚定等级表 |
| 13.6 | 薪酬设计 | 基于能力的薪酬体系（数据工程师按SQL/Spark/建模能力分级） |
