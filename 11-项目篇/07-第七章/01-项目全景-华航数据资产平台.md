# 01 · 项目全景：网络环境视角看华航数据资产平台

> 如果说第4章是从战略维度看项目、第5章是从应用维度看项目、第6章是从云资源维度看项目，那么这一章——我们从网络环境的维度，一次性看清华航项目的数据是如何「流动」的。

## 一、网络视角的项目全貌

华航集团数据资产智能管理平台，覆盖集团总部、5大区域中心（华北北京、华东南京、华南广州、西南成都、西北西安）、23家分公司，涉及120+套业务系统接入、50PB数据存储、日均10亿次API调用。要把这么多节点连在一起、把这么多数据安全高效地搬来搬去——靠的就是一套精心规划的三级网络体系。

| 维度 | 华航项目网络数据 | 对应教材考点 |
|------|---------------|------|
| **网络层级** | 总部→5区域→23分公司三级架构 | 广域网分层拓扑 |
| **广域网** | 总部-区域MPLS专线≥1Gbps；区域-分公司IPSec VPN | MPLS / VPN技术选型 |
| **局域网** | 每区域核心+汇聚+接入三层架构 / 6业务域VLAN隔离 | VLAN划分 / STP / DHCP |
| **无线网** | 总部办公Wi-Fi 6全覆盖 + 机场货站NB-IoT传感网 | 5G / Wi-Fi 6 / NB-IoT |
| **网络安全** | 等保三级（防DDoS / WAF / IPS / VPC隔离） | 安全域划分 / 防火墙 |
| **IP地址** | 10.0.0.0/8私网 → 按区域+业务域子网划分 | IPv4地址规划 |
| **网管** | Prometheus + Grafana + 自研FCAPS五功能平台 | 故障/配置/性能/计费/安全 |
| **机房** | 总部2个标准机房 + 5区域机房 | PUE / 动环监控 / 布线 |

## 二、三级网络拓扑全景图

从网络视角看，华航项目是一个典型的「总部集中管控+区域边缘部署+分支轻量接入」的三级网络架构。

```
                         ┌──────────────────────┐
                         │     总部（北京）        │
                         │  核心路由器集群(双活)    │
                         │  MPLS PE 主节点        │
                         │  防火墙集群 + WAF       │
                         │  10.0.0.0/16          │
                         └──────┬───────┬───────┘
                                │       │
                    MPLS 专线 ≥1Gbps   MPLS 专线 ≥1Gbps
                                │       │
            ┌───────────────────┼───────┼───────────────────┐
            │                   │       │                   │
    ┌───────┴───────┐   ┌───────┴──┐ ┌─┴──────────┐   ┌────┴──────────┐
    │ 华北(北京)     │   │华东(南京) │ │华南(广州)   │   │西南(成都)/    │
    │ 容灾主备双活   │   │容灾中心   │ │区域中心     │   │西北(西安)     │
    │ 10.1.0.0/16   │   │10.2/16   │ │10.3-5/16   │   │10.6-7/16     │
    └───────┬───────┘   └──────┬───┘ └──────┬──────┘   └──────┬────────┘
            │                  │             │                  │
     IPSec VPN (控制成本)  IPSec VPN     IPSec VPN          IPSec VPN
            │                  │             │                  │
    ┌───────┴───────┐   ┌──────┴───┐  ┌─────┴──────┐    ┌─────┴──────┐
    │ 4家分公司      │   │ 5家分公司 │  │ 6家分公司   │    │ 8家分公司   │
    │ 10.x.0.0/24   │   │10.x/24   │  │10.x/24     │    │10.x/24     │
    └───────────────┘   └──────────┘  └────────────┘    └────────────┘
```

**设计逻辑**：
- **总部-区域**：MPLS专线保证高带宽（≥1Gbps）、低延迟（<20ms）、服务等级（CoS/QoS），承载核心业务数据同步、实时质量检测等关键流量
- **区域-分公司**：IPSec VPN降低23条线路的租用成本，分公司以网关设备拨入区域中心VPN网关
- **华东南京**：作为容灾中心，与北京总部之间10Gbps专线实时数据同步（RPO≤5分钟）

## 三、网络视角的三大设计约束

### 约束一：SLA倒逼网络可靠性设计

项目SLA要求99.99%可用性（年停机≤52.56分钟），这对网络层意味着：

| 网络层 | 可靠性手段 | 目标 |
|--------|----------|------|
| 广域网 | 总部-区域MPLS主链路 + 4G/5G无线备链路 | 主备切换<30秒 |
| 局域网 | 核心交换机堆叠 + STP环路保护 + VRRP网关冗余 | 单点故障不中断 |
| 无线网 | AC双机热备 + AP冗余覆盖20%重叠 | 任一AP故障无缝切换 |
| 安全设备 | 防火墙主备HA + IPS联动 | 安全设备不成为单点瓶颈 |

### 约束二：50PB数据驱动的带宽规划

日均10亿次API调用 + 120套系统数据同步，对网络带宽提出严峻挑战：

| 流量类型 | 日均量 | 带宽需求 | 承载网络 |
|---------|------|------|------|
| 数据同步流量 | 18TB/天（120系统→总部） | ≥2Gbps持续 | MPLS专线 |
| API查询流量 | 10亿次/天（P99<200ms） | 峰值3Gbps | MPLS + CDN |
| 容灾同步流量 | 增量10GB/天 | 突发10Gbps | 总部-南京专线 |
| 视频监控回传 | 5TB/天（5区域机房） | ≥500Mbps | 管理网专线 |

### 约束三：等保三级带来的安全分区要求

等保三级要求网络严格分区隔离，华航项目的网络分区如下：

```
┌─────────────────────────────────────────────────────┐
│                      互联网区                        │
│  (DDoS清洗 → WAF → 反向代理 → 互联网边界防火墙)       │
├─────────────────────────────────────────────────────┤
│                    DMZ 服务区                        │
│  (Portal Web / API Gateway / CDN边缘节点)            │
├─────────────────────────────────────────────────────┤
│                    核心业务区                        │
│  (数据资产管理 / 质量治理 / 安全管控 / 血缘图谱)       │
│  → 仅允许DMZ区白名单IP + 运维管理区访问               │
├─────────────────────────────────────────────────────┤
│                    数据存储区                        │
│  (Ceph集群 / 数据库集群 / 备份存储)                   │
│  → 仅允许核心业务区指定端口访问(1521/3306/6379等)     │
├─────────────────────────────────────────────────────┤
│                    运维管理区                        │
│  (堡垒机 / 网管平台 / 日志审计 / 漏洞扫描)            │
│  → 仅允许运维人员VPN拨入后访问                       │
└─────────────────────────────────────────────────────┘
```
