# 02 · 网络架构与主要技术实践（教材7.1）

> 教材7.1是整个网络环境规划的地基——五模块体系、OSI七层、TCP/IP、拓扑结构……每个概念在华航项目中都有具体的设备、数据和故事。

## 7.1.1 信息网络系统一般体系框架模型

教材将信息网络系统分为五大模块：**网络传输平台、网络和应用服务平台、安全服务平台、网络管理和维护平台、环境系统**。

**口诀：传应安管网**

### 华航项目五层落地对照表

| 教材模块 | 华航项目落地 | 关键设备/数据 |
|---------|------------|-------------|
| **网络传输平台** | MPLS骨干网 + 交换机集群 + 光纤布线 | 核心路由器2台、汇聚交换机6台、接入交换机47台 |
| **网络和应用服务平台** | DNS + 负载均衡 + API Gateway + K8s Ingress | Nginx集群、Istio服务网格、7大模块总计200+Pod |
| **安全服务平台** | 防火墙 + WAF + IPS + DDoS清洗 + 堡垒机 + 漏洞扫描 | 等保三级认证，安全事件月均告警＜50条 |
| **网络管理和维护平台** | Prometheus + Grafana + 自研FCAPS平台 + 日志审计 | 监控指标＞2000项，告警响应时间＜5分钟 |
| **环境系统** | 总部2个标准机房 + 5区域机房 + 精密空调 + 消防 | 机房PUE≤1.5，动环监控全覆盖 |

**项目故事**：2024年10月网络部署阶段，我在调研时发现一个隐患——5大区域中心的安全服务平台能力参差不齐，华东南京只有基础防火墙而没有IPS。这违反了等保三级对「入侵防范」的要求。我紧急协调预算，为华东和西南各增配一台IPS设备，并在全网统一安全策略模板，确保五大模块在每一级节点都完整覆盖。事后证明这个决策很及时——2025年3月的等保正式测评中，网络层面的安全项一次通过。

> **考点提示**：五模块是选择题常考点，记住「传应安管网」五字口诀，考试中能秒选。

## 7.1.2 开放系统互连（OSI）七层模型

ISO于1984年提出OSI七层参考模型，自下而上为：物理层→数据链路层→网络层→传输层→会话层→表示层→应用层。

**口诀：物数网传会表应**

### 华航项目七层实例对照

| 层号 | 层名 | 在华航项目中的具体存在 | 关键设备/协议 |
|:---:|------|------|------|
| 1 | **物理层** | 光纤（单模/多模）、6类双绞线、Wi-Fi 6射频 | 光模块SFP+、RJ45模块 |
| 2 | **数据链路层** | VLAN隔离（6业务域）、STP防环、MAC地址表 | Cisco Catalyst 9300交换机 |
| 3 | **网络层** | OSPF路由、IPSec VPN隧道、MPLS标签转发 | 核心路由器、IP 10.0.0.0/8 |
| 4 | **传输层** | TCP承载数据库同步、HTTPS API调用、UDP视频监控 | TCP端口1521(DB)/443(API) |
| 5 | **会话层** | 运维堡垒机SSH会话、API Gateway Token管理 | SSH/SSL/TLS |
| 6 | **表示层** | JSON→XML格式转换、Gzip压缩、AES-256加密 | Nginx解压缩模块 |
| 7 | **应用层** | 7大功能模块Portal、DNS服务、邮件告警 | HTTP/HTTPS、SMTP |

**项目故事**：2024年12月压力测试期间，华南区域API调用P99延迟一度飙升至420ms（目标200ms）。追踪后发现不是网络层问题，而是在**表示层**——Nginx未启用Gzip压缩，API返回的JSON载荷平均1.2MB，加上跨区域传输时延被放大。我们在Nginx配置中启用Gzip压缩`gzip_types application/json`后，载荷压缩至平均180KB，P99延迟降回175ms。这个案例让我深刻理解：**性能问题往往出在你最想不到的那一层**。

> **考点提示**：七层名称及顺序是必修。记「物数网传会表应」，考试选择题可能让你判断某协议属于哪一层（如HTTP=应用层、ARP=数据链路层）。

## 7.1.3 TCP/IP协议族、IPv4、IPv6

### TCP/IP四层 vs 华航项目协议栈

| TCP/IP层 | 华航项目使用的主要协议 | 典型场景 |
|----------|------|------|
| **应用层** | HTTP/HTTPS、DNS、NTP、SMTP | Portal访问、域名解析、时间同步、告警邮件 |
| **传输层** | TCP（数据库同步/API调用）、UDP（视频监控/日志采集） | TCP可靠传输、UDP低延迟 |
| **网络层** | IP、ICMP、OSPF、BGP、MPLS | 路由选择、故障探测 |
| **物理和数据链路层** | ARP、VLAN、STP、Ethernet | MAC寻址、VLAN隔离、防环 |

### IPv4地址规划实战（10.0.0.0/8私网）

华航项目全部采用RFC 1918私网地址（A类 10.0.0.0/8），通过NAT转换访问公网。具体子网划分：

| 区域 | 子网段 | 范围 | 用途 |
|------|------|------|------|
| 总部核心网 | 10.0.0.0/16 | 10.0.0.1~10.0.255.254 | 核心服务器、数据库、存储 |
| 总部DMZ区 | 10.1.0.0/16 | 10.1.0.1~10.1.255.254 | Portal Web、API Gateway |
| 华北区域 | 10.2.0.0/16 | 10.2.0.1~10.2.255.254 | 北京容灾节点 |
| 华东/华南/西南/西北 | 10.3~6.0.0/16 | — | 区域业务+边缘计算 |
| 分公司 | 10.100~122.0.0/24 | — | 23家分公司各/24网段 |
| 管理网 | 10.200.0.0/16 | — | 运维堡垒机、监控、日志 |
| 无线网 | 10.250.0.0/16 | — | Wi-Fi终端、NB-IoT网关 |

**关键设计**：每个区域的6个业务域（核心业务/数据存储/安全管理/运维管理/无线接入/视频监控）使用不同VLAN ID + 不同IP子网实现逻辑隔离。例如总部核心业务VLAN 10→10.0.10.0/24、数据存储VLAN 20→10.0.20.0/24。

### IPv6规划（面向未来）

虽当前全部使用IPv4，但考虑到运营商5G SA架构以IPv6为底座、以及华航未来物联网扩展需求，我们在网络规划中预留了IPv6地址空间：

- 每个/16 IPv4块对应一个/48 IPv6块
- 核心路由器同时启用IPv4/IPv6双栈
- 互联网出口NAT64网关支持IPv6→IPv4转换

> **考点提示**：IPv4五类地址范围是高频考点（A：1-126、B：128-191、C：192-223），私网地址三段范围要熟记。IPv6=128位=IPv4的4倍。

## 7.1.4 传输平台一般架构和主要技术

### 华航项目的传输技术选型

| 传输类型 | 选型技术 | 理由 |
|---------|------|------|
| **有线骨干** | 光纤（单模）+ DWDM波分复用 | 单纤40Gbps，满足总部-南京10Gbps同步需求 |
| **有线接入** | 6类双绞线 + 光纤到桌面 | 千兆到桌面，服务器万兆上联 |
| **无线骨干** | 4G/5G备链路 | MPLS主链路故障时自动切换 |
| **无线接入** | Wi-Fi 6 (802.11ax) | 办公区高密接入，单AP支持100+终端 |
| **物联网无线** | NB-IoT | 机场货站温湿度传感器、振动传感器 |

### 路由协议选型

| 路由域 | 协议 | 原因 |
|------|------|------|
| AS内部（总部+5区域） | **OSPF** | 链路状态协议，收敛快，适合中型网络 |
| AS间（与外部网络） | **BGP** | 策略丰富，适合多出口互联 |
| 静态路由 | 分公司VPN隧道 | 结构简单，不频繁变化 |

> **考点提示**：内部路由协议（RIP/OSPF/IS-IS）vs 外部路由协议（BGP）的区别是选择题常考点。

## 7.1.5 网络拓扑结构

教材列举了总线型、星形、环形、树形、网状、复合型六种拓扑结构。

华航项目的网络拓扑采用了**复合型**：核心层网状（总部双路由器全互联，提供最高可靠性）、汇聚层双星形（每区域两台汇聚交换机，上联总部、下联接入）、接入层星形（各分公司单线上联区域汇聚）。

### 拓扑选择逻辑

| 层级 | 拓扑类型 | 为什么这样选 |
|------|---------|------------|
| **核心层** | 网状（双路由全互联） | 99.99%可用性要求，容不下单点故障 |
| **汇聚层** | 双星形 | 兼顾可靠性与成本，主备链路自动切换 |
| **接入层** | 星形 | 分公司节点简单，IPSec VPN星形接入 |
