## 7.2 广域网规划

### 7.2.1 广域网一般架构

教材将企业广域网分为核心层→汇聚层→接入层三层架构，与华航项目的三级网络完美对应：

| 教材层级 | 华航对应 | 拓扑 | 节点数 |
|:---:|------|------|:---:|
| **核心层** | 总部北京（双路由器全互联） | 网状 | 2台核心路由器 |
| **汇聚层** | 5大区域中心 | 双星形 | 6台汇聚交换机 |
| **接入层** | 23家分公司 | 星形 | 23台VPN网关 |

### 7.2.2 广域网主要技术

#### MPLS —— 核心链路的技术底座

MPLS在IP数据包基础上增加一个标签（Label），基于标签而非IP地址进行路由转发。华航项目在总部到5大区域之间部署MPLS专线：

| 参数 | 取值 | 说明 |
|------|------|------|
| 带宽 | ≥1Gbps（总部-区域） | 承载数据同步+API调用双流 |
| 延迟 | <20ms | 经测试验证，北京-广州19ms |
| 丢包率 | <0.01% | 运营商SLA承诺 |
| CoS服务等级 | Gold/Silver/Bronze三级 | 数据同步Gold、API Silver、日志Bronze |
| LDP标签分发 | LDP协议 | 每台核心路由器启用LDP |

**项目故事**：2024年11月广域网联通测试时，北京到西南成都的MPLS延迟稳定在35ms——比预期高了15ms。排查发现运营商的路由路径经过了武汉中转，增加了跳数。我们协调运营商调整为北京→成都直连路径，延迟降至19ms。这个案例说明：**即使租用的是运营商专线，作为系统规划与管理师仍需主动优化路由路径**。

#### IPSec VPN —— 23家分公司的低成本接入

| 参数 | 取值 | 说明 |
|------|------|------|
| 加密算法 | AES-256 | 国密SM4备选 |
| 认证方式 | 预共享密钥 + IKEv2 | 分公司网关证书认证 |
| 隧道数量 | 23条（每分公司一条到所属区域） | 星形拓扑 |
| 带宽 | 100Mbps/分公司 | 满足分公司日常业务 |
| 备份链路 | 4G/5G无线备链路 | 主VPN故障时自动切换 |

**成本对比**：

| 方案 | 23条线路年费 | 适用场景 |
|------|:---:|------|
| 全部MPLS专线 | 约180万/年 | 不现实，预算超标 |
| 全部IPSec VPN | 约15万/年 | 带宽和SLA不满足 |
| 混合方案（实际） | 约75万/年 | ✅ MPLS保核心 + VPN降边缘 |

### 7.2.3 广域网规划六大内容

**口诀：景需预技拓址**

| 内容 | 华航项目的做法 |
|------|-------------|
| **建设背景** | 华航数据资产平台是全新建设，需要在现有集团办公网之外搭建独立的业务承载网 |
| **需求分析** | 功能需求（120+系统接入、10亿API调用/天）、业务需求（99.99%可用性）、运维需求（统一网管） |
| **项目预算** | 网络总预算约120万/年（含MPLS专线租费75万、设备折旧25万、人员运维20万） |
| **技术方向** | MPLS（核心） + IPSec VPN（分支） + 4G/5G无线备链路 + IPv4私网 + IPv6预留 |
| **网络拓扑结构** | 核心网状 → 汇聚双星形 → 接入星形，每个区域独立子网 |
| **IP地址逻辑资源** | 10.0.0.0/8私网，按区域+业务域划分，VLAN ID 10-60对应6业务域 |

## 7.3 局域网规划

### 7.3.1 局域网一般架构

局域网由计算机设备、网络连接设备、网络传输介质三大部分构成。根据规模分为多层级结构（大型/大中型）、二层结构（中型）、星形结构（小型）。

华航项目总部和5大区域中心均采用**三层结构**（核心层+汇聚层+接入层）：

```
总部局域网（三层架构）：

核心层 ── 2台三层交换机（堆叠/VRRP）
  │
  ├── 汇聚层 ── 每楼层1台三层交换机（共4台）
  │     │
  │     └── 接入层 ── 每楼层4台二层交换机（47端口/台）
  │
  └── 服务器接入 ── 2台TOR交换机（万兆上联核心）
```

### 7.3.2 局域网主要技术 —— VLAN

VLAN的核心价值是将局域网从逻辑上划分为独立的广播域，实现隔离。教材列出6种VLAN划分方法：

| 划分方法 | 优点 | 缺点 | 华航使用场景 |
|---------|------|------|------------|
| **按端口划分** | 简单、适用任何规模 | 用户换端口需重配 | ✅ **主要方式**——6业务域对应6组端口 |
| 按MAC地址划分 | 用户移动自动保留VLAN | 初始化配置量大 | 少量使用——运维人员笔记本 |
| 按网络层协议划分 | 可按应用组织用户 | 效率低、检查IP帧头费时 | 未使用 |
| 按IP组播划分 | 灵活性高、可跨广域网 | 局域网效率不高 | 未使用 |
| 按策略划分 | 组合多种分配方法 | 复杂度高 | 未使用 |
| 按用户定义/非用户授权 | 灵活定制 | 需要认证体系 | 未使用 |

### 7.3.3 局域网规划五大重点

**口诀：划号由STP、DHCP**

#### （1）VLAN划分 —— 6业务域VLAN设计

| VLAN ID | 业务域 | IP子网（总部） | 说明 |
|:---:|------|------|------|
| 10 | 核心业务区 | 10.0.10.0/24 | Portal、API、数据处理 |
| 20 | 数据存储区 | 10.0.20.0/24 | Ceph、数据库集群 |
| 30 | 安全管理区 | 10.0.30.0/24 | 防火墙管理、IPS、堡垒机 |
| 40 | 运维管理区 | 10.0.40.0/24 | Prometheus、Grafana、日志 |
| 50 | 无线接入区 | 10.250.0.0/16 | Wi-Fi终端、NB-IoT网关 |
| 60 | 视频监控区 | 10.0.60.0/24 | 机房摄像头、NVR |

#### （2）VLAN编号

国际标准 VLAN ID 范围 1~4094（实际可用 1~4096）。华航项目规划原则：
- 每个区域统一使用 VLAN ID 10-60（6业务域×5区域=30个VLAN足够）
- 总部 VLAN ID 10-60
- 华北 VLAN ID 110-160（百位=区域编号）
- 华东 VLAN 210-260，以此类推
- 交换机间的Trunk链路允许所有VLAN通过

#### （3）VLAN间路由设计

华航采用**三层交换机 VLAN间路由**（方式三）：
- 核心交换机启用`ip routing`
- 为每个VLAN配置SVI（Switch Virtual Interface）作为该VLAN的默认网关
- 通过ACL控制VLAN间访问（如核心业务区VLAN 10可访问数据存储区VLAN 20的1521端口，但禁止其他VLAN访问）

#### （4）STP设计

STP（生成树协议）的目的：逻辑上发现并阻断二层环路，防止广播风暴。

华航STP配置：
- 根桥：核心交换机1（优先级4096）
- 备用根桥：核心交换机2（优先级8192）
- 接入层交换机启用`spanning-tree portfast`（终端端口跳过STP计算，加快上线）
- 全局启用`bpduguard`（防止非法交换机接入）

#### （5）DHCP设计

| 范围 | DHCP方案 | 说明 |
|------|---------|------|
| 总部 | 核心交换机SVI作为DHCP中继，专用DHCP服务器（Windows Server） | 大型局域网，需专门DHCP代理 |
| 区域中心 | 汇聚三层交换机本地DHCP池 | 中型局域网，交换机直接分配 |
| 分公司 | VPN网关设备内置DHCP | 小型网络，设备自带 |

**项目故事**：2024年11月总部局域网部署时，一次诡异的故障让我们排查了整整2小时——某台新接入的交换机未配置STP，导致一条不经意的网线将两台交换机形成环路，瞬间广播风暴吞没了整个核心业务VLAN的带宽。外部的API调用全部超时。我们用`show spanning-tree`定位到环路端口后立即shutdown，随后部署了全局bpduguard策略。**这个教训让我铭记：STP不是可选项，是必选项**。

> **考点提示**：
> - 广域网六大内容：**景需预技拓址**
> - 局域网五大重点：**划号由STP、DHCP**
> - VLAN划分6种方法（按端口最常用）
> - STP = 防环路、防广播风暴；DHCP = 自动分配IP
