# 五种规划方法应用

> 对应教材4.4信息系统规划常用方法。五种方法是综合选择题的绝对高频考点，也是论文可能直接出题的方向。

---

## 五法对比总表（★必背）

> 口诀：**S转B查C抓V链Z架**

| 方法 | 全称 | 提出者 | 年份 | 核心思想 | 一句话记忆 |
|------|------|--------|:----:|---------|-----------|
| **SST** | 战略目标集转移法 | William King | 1978 | 组织战略集→信息系统战略集的转换 | 「翻译」组织战略为系统战略 |
| **BSP** | 企业信息系统规划法 | IBM公司 | 1970s | 自顶向下分析需求，自底向上设计结构 | 「调查分析」企业信息需求定方案 |
| **CSF** | 关键成功因素法 | Zani/Rockart | 1970/1980 | 少数关键成功因素决定信息需求 | 「抓住」主要矛盾定信息需求 |
| **VCA** | 价值链分析法 | Michael Porter | 1985 | 价值链上识别战略环节优先部署IT | 「找到」增值环节优先上IT |
| **Zachman** | Zachman框架 | John Zachman | 1987 | 6W×6层=36格的企业架构分类 | 「网格化」描述企业信息 |

## 方法一：SST 战略目标集转移法（4.4.1）

### 教材知识点

**核心**：把组织战略集（使命/目标/战略/属性）→ 转换成 → 信息系统战略集（系统目标/约束/建设战略）

**三步法**：
1. 画出利益相关方结构
2. 确定利益相关方要求
3. 定义组织对每个利益相关方的任务和战略

最终送交最高管理者审查获取反馈。

### 项目应用

我在华航项目中运用SST方法，将集团数字化转型战略逐层分解为信息系统建设目标：

```
组织战略集                          信息系统战略集
┌──────────────────┐    SST转换    ┌──────────────────┐
│ 使命：数据驱动决策  │ ──────────→ │ 系统目标：数据资产  │
│ 目标：数字化转型    │              │   可见/可管/可用    │
│ 战略：三年行动规划  │              │   /可控/智能       │
│ 属性：集团一体化    │              │ 系统约束：29节点    │
└──────────────────┘              │   覆盖/等保三级     │
                                  │ 建设战略：迭代增量  │
                                  │   +阶段门控        │
                                  └──────────────────┘
```

**利益相关方分析**：

| 利益相关方 | 要求 | 信息系统任务和战略 |
|-----------|------|------------------|
| 集团CIO | 统一管控+数字化转型 | 29节点统一平台 |
| 客运事业部VP | 旅客数据统一 | 旅客ID编码标准化 |
| 机务维修VP | 维修数据准确 | 飞行小时数质量规则 |
| 财务总监 | 报表数据一致 | 财务一致性检测 |
| 安全部总监 | 数据安全合规 | 分级分类+脱敏+等保 |

> **论文金句**：「在信息系统规划实践中，我们采用战略目标集转移法（SST），将集团数字化转型战略目标逐层分解为信息系统建设目标，以'五层架构'对应五大体系，确保平台建设方向与业务战略高度一致。」

## 方法二：BSP 企业信息系统规划法（4.4.2）

### 教材知识点

**核心理念**：管理功能应独立于组织机构（组织变动不影响系统设计）

**四个基本步骤**（口诀：**目功数构**）：

| 步骤 | 内容 | 关键要点 |
|------|------|---------|
| 1.定义管理目标 | 采访各级管理层，绘制目标树 | 各子目标服从总体目标，不能矛盾 |
| 2.定义管理功能 | 基于资源生命周期识别（产生/获得/服务/归宿） | **BSP方法的核心** |
| 3.定义数据类 | 实体法+功能法，归纳10~20个数据类 | 建立功能/数据类矩阵 |
| 4.定义信息结构 | C-U矩阵→聚类分组→子系统划分 | 将密切联系的数据和功能划入同一子系统 |

**现状**：BSP产生于信息系统发展初级阶段，ERP等成熟软件已形成标准结构，新问题需新方法。

### 项目应用

华航集团已建成约120套业务系统，数据分布广泛且关系复杂，非常适合BSP方法。我组织团队对各业务系统进行全面调查分析：

**定义管理功能**（基于资源生命周期）：

| 业务域 | 产生 | 获得 | 服务 | 归宿 |
|--------|------|------|------|------|
| 旅客服务 | 旅客注册 | 旅客信息采集 | 旅客服务 | 旅客信息归档 |
| 航班运行 | 航班计划 | 航班动态采集 | 航班运行监控 | 航班数据归档 |
| 机务维修 | 维修计划 | 维修执行 | 维修监控 | 维修记录归档 |

**定义数据类**（归纳结果）：

| 数据类 | 来源系统 | 数据量级 | 关键问题 |
|--------|---------|---------|---------|
| 旅客数据 | PSS/常旅客/客服/航食 | 8PB | 12种ID编码规则 |
| 航班数据 | FOC/ACARS/气象 | 12PB | 入库延迟最高15分钟 |
| 维修数据 | MRO/航材管理 | 6PB | 飞行小时偏差超1% |
| 财务数据 | FMS/票证结算 | 2PB | 差异率20% |
| 安全数据 | 安检/机组资质 | 1.5PB | 完整率仅82% |

> **实践发现**：通过BSP分析，我们发现「旅客」数据在6个系统中存在12种不同的ID编码规则，这一发现直接推动了数据标准统一专项任务的优先排期。

### 考点提示

> **选择题高频**：BSP四步骤的顺序——目标→功能→数据类→信息结构。
> **选择题高频**：BSP的核心是「定义管理功能并进行分组」。
> **选择题高频**：BSP强调「管理功能应独立于组织机构」。

## 方法三：CSF 关键成功因素法（4.4.3）

### 教材知识点

**核心**：组织的信息需求由少数几个关键成功因素决定

**四个来源**（口诀：**产竞环暂**）：
1. 个别产业的结构
2. 竞争策略、产业地位及地理位置
3. 环境因素
4. 暂时因素

**四类CSF**：内部型 / 外部型 / 监控型 / 建立型

**四步实施**：
1. 确定战略目标
2. 识别所有成功因素（逐层分解）
3. 确定关键成功因素（德尔菲法/模糊综合评价法）
4. 识别绩效指标和衡量标准

**特点**：抓住主要矛盾、突出重点；适用于高层管理者；但很少涉及如何用IT支持目标。

### 项目应用

我先后与集团CIO、客运VP、机务维修VP等6位高层进行一对一深度访谈，识别出4个关键成功因素：

| 关键成功因素 | 来源 | 高层关注焦点 | 映射平台模块 | 量化目标 |
|-------------|------|-------------|-------------|---------|
| 数据标准统一 | 产业结构 | 12种旅客ID编码 | 数据资产目录 | ≥800数据元标准 |
| 跨部门数据共享 | 竞争策略 | 审批周期15天 | 数据共享交换 | ≥10亿调用/审批≤3天 |
| 数据安全合规 | 环境因素 | 旅客信息泄露风险 | 数据安全管控 | 0安全事件/等保三级 |
| 数据价值释放 | 暂时因素 | 分析师70%时间找数据 | 智能问答+血缘 | 问答准确率≥85% |

> **实践要点**：CSF方法帮助我确保规划聚焦于对集团战略最具价值的方向，而非面面俱到。4个CSF直接映射到4个核心功能模块，形成了「战略→CSF→功能模块→量化目标」的清晰链路。

### 考点提示

> **选择题高频**：CSF四来源——产业结构/竞争策略/环境因素/暂时因素。注意「技术因素」**不属于**四来源。
> **选择题高频**：CSF特点——「很少涉及如何利用信息技术支持目标的实现」是CSF的局限性。
> **选择题高频**：CSF适用于高层管理者。

## 方法四：VCA 价值链分析法（4.4.4）

### 教材知识点

**四个基本观点**：
1. 价值是组织一切活动的核心
2. 基本活动+支持性活动
3. 相互依存形成系统
4. 竞争优势来自价值链优化

**四步应用**：
1. 识别组织价值链（基本价值过程=线性 + 支持价值过程=幕后）
2. 确定关键价值**增加**环节（客户调查、贡献率排序）
3. 确定关键价值**减少**环节（客户满意度降低的影响）
4. 明确IT对关键价值环节的支持

### 项目应用

我梳理了华航集团航空运输的核心价值链：

```
基本价值过程（线性）：
航班计划 → 售票 → 值机 → 安检 → 登机 → 飞行 → 到达 → 行李提取 → 售后服务

支持价值过程（幕后）：
人力资源 │ 财务管理 │ 计划研发 │ 采购管理 │ 信息技术
```

**关键价值增加环节**：航班延误应急处置——跨部门数据互通时效性直接影响旅客满意度和运营效率。

**关键价值减少环节**：数据申请审批周期15个工作日——严重影响航班延误应急处置等时效性业务。

**IT支持决策**：在一期规划中优先安排数据共享交换模块和安全管控模块建设，将审批周期从15天压缩到3天。

> **实践价值**：VCA帮助我找到了「好钢用在刀刃上」的切入点——不是所有环节都需要同时上IT，而是优先在价值贡献最大的环节突破。

### 考点提示

> **选择题高频**：VCA的基本活动包括「生产、销售、进料后勤、发货后勤、售后服务」；支持性活动包括「人事、财务、计划、研究与开发、采购」。
> **选择题高频**：价值增加环节=对客户的贡献率排序；价值减少环节=降低满意度的影响。

## 方法五：Zachman 框架（4.4.5）

### 教材知识点

**结构**：6行（纵向）× 6列（横向）= 36格

**横向6W**（口诀：**数功网人时因**）：

| 6W | 对应 | 含义 |
|----|------|------|
| What | 数据 | 什么 |
| How | 功能 | 如何做 |
| Where | 网络 | 什么地点 |
| Who | 人员 | 谁 |
| When | 时间 | 什么时间 |
| Why | 动机 | 为什么 |

**纵向6层**：

| 层次 | 关注者 | 关注内容 |
|------|--------|---------|
| 范围模型 | 规划人员 | 发展方向、业务宗旨、系统边界 |
| 企业模型 | 系统所有者 | 企业结构、处理、组织 |
| 系统模型 | 体系架构师 | 业务处理功能 |
| 技术模型 | 构造人员 | 技术模型解决信息处理 |
| 详细模型 | 集成工作者 | 语言、数据库、网络细节 |
| 功能模型 | 使用人员 | 系统能否支持职能工作 |

**六步实施**：确定愿景原则 → 现状描述分析 → 目标架构定义 → 差距改进点分析 → 制订实施计划 → 持续改进优化

### 项目应用

我运用Zachman框架对华航平台进行架构定义，以What（数据）列为例：

| 层次 | What（数据） | 华航对应 |
|------|-------------|---------|
| 范围模型 | 业务事项 | 8大业务域数据资产 |
| 企业模型 | 语义模型 | 数据元标准≥800项 |
| 系统模型 | 逻辑数据模型 | ODS/DWD/DWS/ADS/DIM五层 |
| 技术模型 | 物理数据模型 | PostgreSQL/Neo4j/ES/ClickHouse |
| 详细模型 | 数据定义 | 表结构/字段/索引设计 |
| 功能模型 | 数据 | 数据资产目录10万项 |

> **实践要点**：Zachman框架帮助我从6个视角6个层次全面描述平台架构，确保不遗漏关键维度。特别是在架构评审时，用36格矩阵逐一检查，有效避免了架构盲区。

### 考点提示

> **选择题高频**：Zachman横向6W对应关系——What=数据/How=功能/Where=网络/Who=人员/When=时间/Why=动机。注意**不要搞反**What和How。
> **选择题高频**：纵向6层关注者——规划人员/系统所有者/架构师/构造人员/集成工作者/使用人员。
> **选择题高频**：Zachman六步实施顺序。

## 五法组合应用

教材指出：「在日趋复杂的组织环境及外部竞争压力下，信息系统规划面临非单一管理或非单一技术的问题，因此在组织实际规划过程中，常常将多个方法进行有机结合。」

### 华航项目的五法组合

| 方法 | 在项目中的角色 | 解决什么问题 |
|------|--------------|-------------|
| SST | 战略对齐的顶层方法 | 确保平台方向与集团战略一致 |
| BSP | 现状梳理的全面方法 | 梳理120套系统的功能和数据类 |
| CSF | 聚焦重点的优先方法 | 识别4个CSF确定核心模块优先级 |
| VCA | 价值优先的突破方法 | 找到航班延误场景优先突破 |
| Zachman | 架构定义的框架方法 | 6W×6层全面描述平台架构 |

> **论文写作要点**：如果论文考「规划方法」，正文应说明你为什么选择这些方法、每种方法解决了什么问题、方法之间如何配合。不是罗列五种方法，而是展示组合应用的逻辑。

## 五法考试速查

| 考点 | 出题方式 | 易错点 |
|------|---------|--------|
| 方法-提出者-年份匹配 | 连线/选择 | CSF是Zani 1970提出，Rockart 1980发展为战略 |
| BSP四步骤 | 顺序题 | 目功数构，不是数功目构 |
| BSP核心理念 | 选择题 | 管理功能独立于组织机构 |
| CSF四来源 | 挑出不属于的 | 产竞环暂，不含「技术因素」 |
| CSF特点 | 选择题 | 适用于高层，很少涉及IT支持 |
| VCA基本vs支持活动 | 分类题 | 基本活动是线性的，支持是幕后的 |
| VCA价值增加vs减少 | 区分题 | 增加=贡献率，减少=满意度降低 |
| Zachman 6W对应 | 对应关系 | What=数据（不是功能），How=功能 |
| Zachman纵向6层 | 关注者匹配 | 规划→范围，所有者→企业，架构师→系统 |
| 五法组合 | 论文/案例 | 说明选择理由和配合逻辑 |
