# 项目全景 — 华航集团数据资产智能管理平台

> 这是我在2024年至2025年深度参与的真实项目。本章从信息系统规划的视角，对项目全貌进行系统梳理，为后续所有知识点的落地提供锚点。

---

## 一、项目基本盘

### 1.1 一句话概括

华航集团投资580万元/年（三年总预算1,740万元），建设覆盖总部及29个节点的统一数据资产智能管理平台，用14个月时间解决120套系统50PB数据的「孤岛、质量、共享、安全、价值」五大痛点，实现数据资产「可见、可管、可用、可控、智能」。

### 1.2 关键参数

| 维度 | 参数 | 我在规划中的角色 |
|------|------|----------------|
| 招标人 | 华航集团有限公司 | 乙方核心规划参与者 |
| 投资规模 | 580万/年，三年总预算1,740万 | 参与成本估算与资源规划 |
| 建设周期 | 2024.8—2025.9（14个月） | 负责里程碑规划与任务拆解 |
| 组织覆盖 | 总部+5区域中心+23分公司=29节点 | 参与部署架构与组织体系设计 |
| 数据规模 | 120+套系统，50PB数据资产 | 主导数据架构与标准体系规划 |
| 量化目标 | 10万目录/5000规则/10亿调用/99.99%可用 | 参与目标定义与SLA设计 |
| 我的角色 | 信息系统规划核心参与者 | 战略对齐、框架设计、方法选择、实施推进 |

### 1.3 项目背景：为什么要做这个规划

华航集团是国内大型航空运输企业集团，业务覆盖客运、货运、机务维修、航食配餐、地面服务、航空培训全产业链，员工超8万人。经过多年信息化建设，已建成航班运行控制系统（FOC）、旅客服务系统（PSS）、收益管理系统（RMS）、机务维修管理系统（MRO）等核心业务系统约120套，沉淀数据资产总量超过50PB。

但数据管理面临五大突出问题：

| 痛点 | 具体表现 | 量化数据 |
|------|---------|---------|
| 数据孤岛 | 各系统独立建设，标准不统一 | 旅客ID编码规则12种（6个系统） |
| 数据质量 | 缺乏统一监控治理 | 业务报表差异率15%-20% |
| 数据共享 | 跨部门审批周期长 | 平均15个工作日 |
| 数据安全 | 敏感数据缺乏精细管控 | 合规风险 |
| 数据价值 | 分析师大量时间用于找数据 | 70%时间找数据，30%做分析 |

2024年3月，集团数据治理委员会审议通过《华航集团数据资产管理三年行动规划（2024-2026）》，明确将「数据资产智能管理平台」作为年度一号工程。

> **规划视角**：这正是教材4.1所说的——「信息系统规划是组织战略规划的有机组成部分，是组织关于数字能力的目标及其实现的总体谋划」。集团三年行动规划是组织战略，数据资产智能管理平台是信息系统战略，两者通过规划实现对齐。

## 二、建设目标体系

### 2.1 总体目标

构建覆盖集团总部、5大区域中心和23家分公司的统一数据资产智能管理平台，实现数据资产的「可见、可管、可用、可控、智能」，打造航空行业数据治理标杆，支撑集团数字化转型战略落地。

### 2.2 量化目标

| 指标类别 | 具体指标 | 目标值 | 实际达成 | 达成率 |
|---------|---------|--------|---------|--------|
| 资产规模 | 入湖数据资产目录 | ≥10万项 | 12.3万项 | 123% |
| 质量管理 | 配置数据质量规则 | ≥5,000条 | 5,200条 | 104% |
| 数据服务 | 年数据服务调用次数 | ≥10亿次 | 12.6亿次 | 126% |
| 并发性能 | 并发用户数 | ≥5,000 | 5,800 | 116% |
| 响应性能 | 页面查询响应时间 | ≤2秒 | 1.4秒 | 优于30% |
| 可用性 | 系统整体可用性 | ≥99.99% | 99.995% | 年不可用26分钟 |
| 安全合规 | 重大数据安全事件 | 0起 | 0起 | 达标 |

> **规划视角**：量化目标体现了教材4.2.1中「战略目标需要以时间为轴线、以阶段为区隔，对发展目标进行定性和定量的表达」。每个目标都有明确的度量方式和考核周期，为后续SLA设计和BSC度量奠定基础。

### 2.3 阶段目标

| 阶段 | 时间 | 里程碑 | 交付物 | 成熟度定位 |
|------|------|--------|--------|-----------|
| 一期 | 2024.8-2024.12 | 平台框架+核心功能 | 资产目录+质量管理+运维监控 | 打基础→提效率 |
| 二期 | 2025.1-2025.6 | 全功能+分公司推广 | 共享+安全+血缘+智能问答 | 做协同 |
| 三期 | 2025.7-2025.9 | 验收+持续运营 | 性能优化+知识转移+运维体系 | 强决策 |

> **规划视角**：三阶段目标对应教材4.2.1的成熟度五级——一期「打基础」「提效率」，二期「做协同」，三期向「强决策」迈进。遵循「基础优先」「稳态先行」的发展路径原则。

## 三、技术架构全貌

### 3.1 五层逻辑架构

```
┌─────────────────────────────────────────────────┐
│  用户层                                          │
│  数据治理委员会│数据管家│业务分析师│运维│管理层    │
├─────────────────────────────────────────────────┤
│  应用层（7大功能模块）                            │
│  数据资产目录│数据质量管理│数据共享交换│数据安全管控│
│  数据血缘图谱│智能问答│运维监控中心              │
├─────────────────────────────────────────────────┤
│  服务层                                          │
│  元数据服务│标准服务│规则引擎│API网关│认证授权    │
│  血缘引擎│NLP引擎│LLM引擎│消息总线│调度编排      │
├─────────────────────────────────────────────────┤
│  数据层                                          │
│  元数据库(PG)│图谱库(Neo4j)│搜索(ES)│规则库(Mongo)│
│  缓存(Redis)│对象存储(MinIO)│日志(Kafka+CH)      │
├─────────────────────────────────────────────────┤
│  基础设施层                                       │
│  私有云IaaS│容器云PaaS(K8s)│CDN│VPC/WAF│备份容灾  │
└─────────────────────────────────────────────────┘
```

> **规划视角**：五层架构对应教材4.2.2「感、传、智、用、安」的框架模式。华航集团已有120套独立建设的系统（典型的「以应用功能为主线的框架」），我们规划转向「以平台能力为主线的框架」，将「竖井式」系统转化为「平层化」平台能力。

### 3.2 部署架构

```
              集团总部DC（主中心·北京）
              3 Master + 20 Worker + 数据库主库
                    │ MPLS专线 ≥1Gbps
    ┌───────────────┼───────────────┐
    │               │               │
华北区域(北京)   华东区域(上海)   华南区域(广州)
边缘K8s节点      边缘K8s节点      边缘K8s节点(容灾中心Standby)
    │               │               │
西南区域(成都)   西北区域(西安)
边缘K8s节点      边缘K8s节点
    │               │
 23家分公司（轻量代理） IPSec VPN
```
