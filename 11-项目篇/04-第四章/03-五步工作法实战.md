# 五步工作法实战

> 对应教材4.3信息系统规划工作要点。五步法构成一个完整闭环，是案例分析题的高频考点。

---

## 五步法总览

> 口诀：**需场诊规改**

```
内外部需求挖掘 → 场景化模型分析 → 深度诊断与评估 → 整体与专项规划 → 持续改进
     4.3.1            4.3.2            4.3.3           4.3.4           4.3.5
```

教材原文：「信息系统规划是一项复杂的需要持续迭代的过程，其工作要点主要包括：内外部需求挖掘、场景化模型分析、深度诊断与评估、整体与专项规划、持续改进。」

---

## 第一步：内外部需求挖掘（4.3.1）

### 教材知识点

#### 内部需求挖掘——五项任务

1. 理解组织战略
2. 熟悉业务流程
3. 收集用户需求
4. 评估现有系统
5. 感知数字环境

#### 内部需求挖掘——五项注意事项

- 以原始信息获取为主
- 避免直接给出解决方案
- 及时开展引导性培训
- 谨慎信息交叉传递
- 关注隐性需求的推演

#### 外部需求挖掘——六项任务

1. 国家战略导入
2. 行业趋势分析
3. 技术趋势研究
4. 竞争环境分析
5. 客户期望调研
6. 标准与规范引用

#### 整合分析——九项内容

主要矛盾、需求优先级、关键干系人需求、外部要求、创新环境、数字化水平、治理与文化模式、重大风险、推进策略。

### 项目实践

我在华航项目中的需求挖掘工作历时3个月（2024年6-8月），覆盖5大区域中心和23家分公司。

**内部需求挖掘**：

| 任务 | 我的具体做法 | 获取的关键信息 |
|------|------------|--------------|
| 理解组织战略 | 研读《三年行动规划》，访谈CIO | 「数据驱动决策」是能力主线 |
| 熟悉业务流程 | 跟班客运/货运/机务各1周 | 旅客ID 12种编码规则导致数据孤岛 |
| 收集用户需求 | 发放问卷300份+访谈50人 | 数据分析师70%时间用于找数据 |
| 评估现有系统 | 查勘120套系统架构文档 | 系统间集成困难，数据差异率15%-20% |
| 感知数字环境 | 盘点数据资产50PB | 各区域数字素养参差不齐 |

> **实践要点**：在需求挖掘中，我始终坚持「以原始信息获取为主，不追求需求的有效性和精细化」。有一次货运部门提出「我们需要实时货运追踪」，我没有立即给出技术方案，而是继续追问「追踪什么数据？谁需要看？多久算实时？」——避免过早引入技术判断导致需求失真。

**外部需求挖掘**：

| 任务 | 我的具体做法 | 获取的关键信息 |
|------|------------|--------------|
| 国家战略导入 | 研读「十四五」数字经济发展规划 | 数据要素成为新生产要素 |
| 行业趋势分析 | 调研国航/东航/南航数据治理实践 | 三大航均在建设数据中台 |
| 技术趋势研究 | 关注LLM/湖仓一体/云原生 | LLM可用于数据知识问答 |
| 竞争环境分析 | 对标行业数据治理成熟度 | 华航处于2-3级，落后领先者 |
| 客户期望调研 | 访谈机场/航油/配餐合作伙伴 | 期望实时数据共享 |
| 标准规范引用 | 梳理等保/数据安全法/民航局要求 | 四部法律法规需逐项对标 |

### 考点提示

> **选择题高频**：内部需求挖掘方法包括「资料收集、交流访谈、现有系统查勘、业务现场查勘、案头研究」——「竞品对标分析」属于**外部**需求挖掘，不是内部。
>
> **选择题高频**：内部需求挖掘的注意事项中「以原始信息获取为主，不追求需求的有效性和精细化」是常见考点。

## 第二步：场景化模型分析（4.3.2）

### 教材知识点

#### 八维度分析模型

| 维度 | 分析内容 |
|------|---------|
| 场景定义 | 目标、范围、业务背景、利益相关者 |
| 角色分析 | 职责、需求、行为、作用与影响 |
| 业务分析 | 业务模式、流程、需求、发展 |
| 数据分析 | 数据流、来源/类型/结构、开发利用价值 |
| 技术分析 | 管理/工艺/决策/信息技术现状与发展 |
| 组织分析 | 组织文化、人员技能、组织流程 |
| 风险分析 | 技术/安全/管理风险与应对策略 |
| 政策与法律分析 | 合规性分析 |

#### 三阶段应用

- 规划前：识别需求、明确目标
- 规划中：评估方案可行性与风险
- 规划后：监控评估效果

#### 优缺点

- **优点**：贴近实际需求、提供指导参考、提高系统适应性
- **缺点**：数据采集分析困难、可行性受限

### 项目实践

我以「航班延误应急处置」这一高价值场景为例进行场景化分析：

**场景拆解与选择**（教材六步法）：
1. 从信息系统目标价值链拆解：实时数据获取→多部门协同→旅客信息推送
2. 从业务发展能力链拆解：实时数据融合→智能决策支持→自动通知推送
3. 交叉融合：定义「智能延误预警与处置」场景
4. 评价条件：场景可清晰表达，相关技术准备就绪

**八维度分析**：

| 维度 | 分析内容 | 规划决策影响 |
|------|---------|-------------|
| 场景定义 | 航班延误≥30分钟触发应急处置 | 需要实时数据采集≤5分钟 |
| 角色分析 | 运控中心/地服/客运/机务/航食 | 5类角色需要差异化数据视图 |
| 业务分析 | 延误预警→资源调配→旅客安置→信息发布 | 需要跨6部门数据共享 |
| 数据分析 | 航班动态/旅客信息/机务状态/天气/运力 | 数据API网关P99≤500ms |
| 技术分析 | 实时流式数据+智能决策+自动通知 | Kafka流式+LLM辅助决策 |
| 组织分析 | 运控中心牵头，多部门协同 | 需要联合办公机制 |
| 风险分析 | 数据延迟风险/误判风险/信息泄露风险 | 实时监测+人工复核+脱敏 |
| 政策法律 | 旅客信息保护/航班安全数据管理 | 遵循个保法+民航局要求 |

> **实践价值**：这个场景分析直接驱动了数据共享交换模块中「实时流式数据交换」和「数据API网关低延迟（P99≤500ms）」设计指标的确定。审批周期从15个工作日压缩到3个工作日，为航班延误应急处置提供了实时数据支撑。

### 考点提示

> **选择题高频**：场景化模型分析八维度——「财务分析和投资回报分析」**不属于**八维度之一。
>
> **案例题**：可能要求按八维度对给定场景进行分析。

## 第三步：深度诊断与评估（4.3.3）

### 教材知识点

#### 成熟度五级（与4.2.1的成熟度对应）

| 等级 | 教材核心内涵 |
|------|------------|
| 一级 | 确立主要工作+基本策划+规范化建设 |
| 二级 | 管理精细化流程化+解决运行效率 |
| 三级 | 协同一体化+数据流替代业务流程+知识沉淀 |
| 四级 | 敏捷能力建设+数据模型预测决策+治理改革 |
| 五级 | 生态一体化+自组织模式+应对未知风险 |

#### 诊断评估实施三步

1. **计划与打分**：0分/0.5分/0.8分/1分四级打分，由低到高逐级
2. **权重与计算**：参考标准或自动设定权重，分析整体
3. **记录与确认**：形成底稿，标注不满足项，获得干系人确认

#### 木桶原理

组织整体能力水平 = 最短板的能力水平状态

#### 相关国标

GB/T 43439（数字化转型成熟度）、GB/T 39116（智能制造成熟度）

### 项目实践

我建立了包含业务能力维度和成熟度等级维度的二维评估模型：

**业务能力维度**：数据标准化、数据质量管理、数据共享能力、数据安全能力、数据价值应用5个能力域。

**成熟度等级维度**：5级。

**对5大区域中心的评估结果**：

| 区域中心 | 数据标准化 | 数据质量 | 数据共享 | 数据安全 | 数据价值 | 综合 | 推广策略 |
|---------|:---------:|:-------:|:-------:|:-------:|:-------:|:----:|---------|
| 华东（上海） | 3.0 | 2.5 | 3.0 | 2.5 | 3.0 | **3.0** | 首批试点 |
| 华南（广州） | 2.5 | 3.0 | 2.5 | 3.0 | 2.5 | **3.0** | 首批试点 |
| 华北（北京） | 2.5 | 2.0 | 2.0 | 2.5 | 1.5 | **2.0** | 第二批 |
| 西南（成都） | 2.0 | 2.0 | 1.5 | 2.0 | 2.0 | **2.0** | 第二批 |
| 西北（西安） | 1.5 | 2.0 | 1.5 | 2.0 | 2.0 | **2.5** | 第二批 |

> **实践要点**：评估结果直接影响了推广策略——先在成熟度3级的华东和华南试点，验证后再向2级的其他区域推广。这体现了「木桶原理」——西北区域的数据共享能力仅1.5级，是最短板，需要重点补强。

> **首考真题印证**：2025年11月选择题第12题——「GBT43439中，建立了服务度量框架，是属于第（）」→ 答案是**三级**。成熟度三级侧重「协同一体化」和「集成平台化」，建立度量框架正是三级的要求。

### 考点提示

> **选择题高频**：成熟度打分四级——0分（全部不能满足）/0.5分（部分满足，系统性缺陷）/0.8分（大部分满足，局部缺陷）/1分（全部满足）。
>
> **选择题高频**：木桶原理——组织整体能力取决于**最短板**。
>
> **首考已考**：GBT43439成熟度三级建立了服务度量框架。

## 第四步：整体与专项规划（4.3.4）

### 教材知识点

#### 需求整合三维度

- 业务领域维（部门团队主线）
- 能力建设维（人员/技术/流程/资源/数据/知识）
- 技术发展维（可获取条件驱动）

#### 两种推演模式

- **自底向上**：适合以解决业务效率为主的组织
- **自顶向下**：适合解决协同与敏捷的组织

#### 整体规划三要点

与战略一致性、协同一体化、资源优化

#### 专项规划四要点

明确主体、领域系统性、技术路线强化、细致时间轴

#### 一致性检查四方面

规划-需求对应、内容协调、科学可行性、干系人理解一致

### 项目实践

**整体规划**：采用「自顶向下」模式——从集团数据治理战略出发，逐层分解到区域中心和分公司，形成覆盖29个节点的统一规划蓝图。华航集团需要跨5大区域23家分公司协同，属于「解决协同与敏捷的组织」，因此自顶向下更合适。

**专项规划**：针对8大业务域分别制定专项规划。

| 业务域 | 专项规划重点 | 技术路线 |
|--------|------------|---------|
| 旅客服务 | 旅客ID统一编码+常旅客数据整合 | 数据元标准≥800项 |
| 航班运行 | 实时数据采集≤5分钟+FOC集成 | Kafka流式+API网关 |
| 机务维修 | 飞行小时数与ACARS对齐 | 质量规则+血缘追溯 |
| 财务结算 | 客运收入与票证一致 | 一致性质量规则 |
| 安全安保 | 机组资质完整率100% | 完整性检测+告警 |
| 货运物流 | 实时货运追踪 | 增量纳入P1优先级 |
| 人力资源 | 人事数据标准化 | 数据元标准映射 |
| 市场营销 | 客户画像整合 | 标签管理+推荐 |

**一致性检查**：在整体规划与专项规划形成过程中，我持续检查四个方面——规划成果与集团战略对应、各专项之间协调一致、技术路线科学可行、各区域干系人理解一致。

### 考点提示

> **案例题高频**：自顶向下 vs 自底向上的适用场景判断。解决协同→自顶向下，解决效率→自底向上。
>
> **案例题**：一致性检查四方面可能要求列举。

## 第五步：持续改进（4.3.5）

### 教材知识点

#### 五个关注点

1. 持续跟踪组织战略
2. 感知技术创新
3. 关注数据管理和信息安全
4. 注重用户体验和用户参与
5. 建立监测和评估机制

### 项目实践

我建立了月度规划评审机制，每月组织数据治理委员会评审规划执行情况。

**典型案例**：2024年10月二期规划评审中，数据治理委员会提出将「AI驱动的数据质量智能修复」纳入建设范围。我通过评估技术可行性和资源影响后，将其作为二期增量任务纳入规划调整方案——这体现了持续改进中「持续跟踪组织战略」和「感知技术创新」两个关注点。

**监测评估机制**：

| 机制 | 频率 | 产出 |
|------|------|------|
| 月度规划评审 | 月度 | 规划执行偏差分析 |
| SLA达成分析 | 月度 | SLA报告+改进项 |
| 用户满意度调查 | 季度 | 满意度报告+改进计划 |
| 重大故障复盘 | 事件触发 | 根因分析+预防措施 |
| 年度服务评审 | 年度 | 下年度改进计划 |

> **实践要点**：规划不是一次性的活动。教材4.3.5明确指出「信息系统规划是一个持续改进的过程」。在华航项目中，规划文档经历了3次重大修订，每次都基于内外部环境变化和实施反馈。

## 五步法考试应用

### 案例题答题模板

当案例题问「该组织在规划过程中存在什么问题，应如何改进」时，用五步法框架定位问题：

```
问题定位 → 对应步骤 → 教材要求 → 项目做法 → 改进建议

例：某组织规划时直接给出技术方案，未充分挖掘需求
→ 定位到4.3.1内外部需求挖掘
→ 教材要求「避免直接给出解决方案，以原始信息获取为主」
→ 华航项目中我坚持3个月调研，不急于给方案
→ 建议：补充需求挖掘工作，采用资料收集/访谈/查勘等方法
```

### 论文写作映射

论文若考「信息系统规划的工作要点」，正文按五步法分节，每节遵循「概念定义→项目故事→量化效果」结构。
