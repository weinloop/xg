## 一、九大基本概念

### 概念全景速查

教材5.1.1提出了应用系统规划设计的9个基本概念，它们是高质量应用系统设计的理论基础。

| # | 概念 | 一句话理解 | 华航项目实践 |
|:--:|------|-----------|------------|
| 1 | 抽象 | 抓住本质，忽略细节 | 把120+系统抽象为8大业务域 |
| 2 | 体系架构 | 系统组成结构+交互方式 | 5层逻辑架构+微服务部署架构 |
| 3 | 模式 | 最佳实践的复用 | 工厂模式创建数据源连接，代理模式实现服务网关 |
| 4 | 关注点分离 | 分而治之 | 7大模块各管各的，通过接口通信 |
| 5 | 模块化 | 独立命名的可处理单元 | 每个模块有独立的代码仓库+CI/CD |
| 6 | 信息隐蔽 | 模块内部细节对外不可见 | 数据安全模块的脱敏算法其他模块不可见 |
| 7 | 功能独立 | 高内聚+低耦合 | 质量检测引擎只做规则执行，不关心数据来源 |
| 8 | 求精 | 自顶向下逐步细化 | 从「数据质量管理」→「规则配置」→「字段级校验」 |
| 9 | 重构 | 不改功能，优化内部结构 | 二期将单体规则引擎重构为微服务 |

### 1.1 抽象 — 从120+系统到8大业务域

> **教材**：抽象分四个层次——业务抽象、过程抽象、数据抽象、技术抽象。

**项目故事**：2024年4月，面对华航集团120+套异构系统，我主导了四层抽象工作。

**业务抽象**：将120+套系统归纳为8大业务域（旅客服务、航班运行、机务维修、货运物流、财务结算、安全安保、人力资源、市场营销），每个域提取核心价值活动。例如，「旅客服务」域抽象出旅客信息管理、订单处理、行程服务3个核心组件。

**过程抽象**：以「数据质量检测」为例，高层抽象为「系统自动发现并报告数据质量问题」，隐藏了规则引擎选择（Drools vs 自研）、执行频率（定时+实时）、结果通知（工单+Kafka消息）等实现细节。

**数据抽象**：定义了「数据资产」对象，属性包括资产ID、名称、类型、所属域、创建时间、数据量、质量评分等，隐藏了元数据采集的具体实现（JDBC/Crawler/API三种方式）。

**技术抽象**：选择PostgreSQL+Neo4j+ES的混合存储架构，统一通过数据访问层（DAL）屏蔽底层技术差异，确保各模块以一致方式访问数据。

> **考点提示**：四类抽象的辨析是选择题高频考点。记住——业务抽象（做什么业务）→过程抽象（怎么做步骤）→数据抽象（用什么数据）→技术抽象（用啥技术）。

### 1.2 体系架构 — 五层逻辑架构

> **教材**：体系架构是系统组成结构+交互方式+所用数据结构。架构模型包括框架模型、动态模型、过程模型、功能模型。

**项目故事**：2024年5月，我主导绘制了华航平台的五层逻辑架构图。

**框架模型**（静态结构）：定义了界面交互层→业务处理层→服务层→数据处理层→数据存储层的五层结构，每层有明确的构造元素。

**动态模型**（行为变化）：定义了数据资产目录模块应对元数据变更的流程——当源系统表结构变化时，Crawler自动发现→进入待确认队列→数据管家审核→自动更新资产目录，整个过程在15分钟内完成。

**过程模型**（业务流程）：定义了数据共享交换的业务流程——需求方提交申请→数据Owner审批→网关配置路由→生成API Key→调用方接入。

**功能模型**（功能层次）：将7大模块进一步划分为28个一级子功能、96个二级子功能，形成完整的功能树。

> **考点提示**：四种架构模型的辨析——框架模型（静态结构）、动态模型（行为变化）、过程模型（业务流程）、功能模型（功能层次）。

---

### 1.3 模式 — 工厂+代理+责任链

> **教材**：创建型模式（工厂/原型/建造者）、结构型模式（组合/桥接/代理）、行为型模式（责任链/状态/指令）。

**项目故事**：在华航平台开发中，我们运用了多种设计模式：

- **工厂模式**（创建型）：数据源连接场景。面对Oracle/MySQL/SQL Server/Hive/HBase等10+种数据源类型，通过DataConnectionFactory工厂类统一创建连接，调用方只需传入数据源类型和配置参数。

- **代理模式**（结构型）：API网关场景。Kong API Gateway作为所有微服务的代理，统一处理认证、限流、日志，后方服务无需重复实现。

- **责任链模式**（行为型）：数据质量检测场景。一条数据依次经过「非空检查→格式校验→范围校验→业务逻辑校验→跨表一致性校验」5个处理器，任一环节失败即报告问题。

> **考点提示**：记住三类模式的典型代表——创建型（工厂模式造对象）、结构型（代理模式加中间层）、行为型（责任链模式流水线）。

---

### 1.4 关注点分离 + 模块化

> **教材**：关注点分离是把复杂问题分解为独立可解的块；模块化是关注点分离最常见的表现。

**项目故事**：华航平台7大模块就是关注点分离的直接体现。每个模块负责一个独立关注点：

| 模块 | 关注点 | 独立程度 |
|------|--------|:---:|
| 数据资产目录 | 数据资产的编目与检索 | 有独立代码仓库 |
| 数据质量管理 | 数据质量的检测与评分 | 独立CI/CD流水线 |
| 数据共享交换 | 数据服务的发布与调用 | 独立部署 |
| 数据安全管控 | 数据安全的分类/脱敏/审计 | 独立安全策略 |

模块之间通过RESTful API通信，一个模块的变更不会影响其他模块。

---

### 1.5 信息隐蔽 + 功能独立

> **教材**：信息隐蔽——每个模块对其他模块隐蔽自己的设计决策；功能独立——高内聚、低耦合。

**项目故事**：以数据安全模块为例——

**信息隐蔽**：脱敏算法（如手机号中间4位替换为****）的实现细节完全封装在安全模块内部。其他模块只需调用脱敏接口，传入「字段名+原值」，获取脱敏后结果，无需关心算法细节。

**高内聚**：质量检测引擎只做一件事——执行质量规则并返回结果。数据来源、结果展示、工单流转分别由数据集成模块、前端界面、工作流引擎负责。

**低耦合**：模块间通过定义良好的接口通信，而非直接访问对方数据库。例如，资产目录模块需要质量评分时，调用质量模块的REST API获取，而非直接读质量模块的MongoDB。

> **考点提示**：内聚性（模块内部功能强度）vs 耦合性（模块间相互依赖）的辨析，高内聚+低耦合=好的设计。

---

### 1.6 求精 + 重构

> **教材**：求精是自顶向下逐步细化；重构是不改功能，优化内部结构。

**项目故事——求精**：数据质量管理模块的开发遵循求精过程。第一步高层陈述：「系统自动检测数据质量问题」。第二步细化：「支持配置规则→定时执行→生成工单→统计评分」。第三步进一步细化：「规则类型包括完整性/一致性/准确性/及时性/唯一性5大类，每类有预置模板」。一直到每个功能的详细设计文档。

**项目故事——重构**：二期建设中，我们将一期的单体规则执行引擎重构为微服务架构。功能保持不变（依然是执行规则返回结果），但内部结构从「一个Jar包包含所有逻辑」变为「规则管理、执行调度、结果存储三个独立微服务」，部署更灵活、扩展更方便。

> **考点提示**：求精和重构的区别——求精是正着走（模糊→清晰），重构是横着走（功能不变，结构优化）。

## 二、四种基础架构

> 教材5.1.2提出4种应用系统基础架构。

### 2.1 分层体系

> **教材**：界面交互层→业务处理层→数据处理层→数据存储层

华航平台严格遵循四层分层体系（实际扩展为五层，加了一层服务层）。每层有明确的职责边界：

| 层 | 职责 | 华航平台实现 |
|----|------|------------|
| 界面交互层 | 系统与用户交互 | React 18 + Ant Design Pro |
| 业务处理层 | 业务流程+数据计算 | 7大模块的Spring Boot微服务 |
| 数据处理层 | 数据读写处理 | MyBatis Plus / Neo4j OGM / ES Client |
| 数据存储层 | 数据持久存储 | PG + Neo4j + ES + MongoDB + Redis |

---

### 2.2 以数据为中心的架构

> **教材**：先规划设计数据环境，然后按系统对数据的业务应用划分子系统。

华航平台本质上是数据处理系统，天然适合以数据为中心的架构。我们的做法是：

1. **先规划数据环境**：确定元数据库（PG）、图谱库（Neo4j）、搜索引擎（ES）、规则库（MongoDB）、缓存（Redis）五种数据存储
2. **再划分应用模块**：围绕这些数据存储设计7大功能模块
3. **数据驱动设计**：每个模块的数据模型先于业务逻辑确定

---

### 2.3 客户机/服务器架构（B/S）

> **教材**：两层C/S→三层C/S→B/S，B/S架构优点是不需客户端维护，支持远程服务。

华航平台选择B/S架构的理由：

- **29个节点跨地域**：总部+5区域中心+23分公司，要求零客户端部署
- **浏览器即可访问**：无论Windows/Mac/Linux，有浏览器就能用
- **中央集中维护**：升级只需更新服务器，不需更新每个客户端

但B/S架构也有局限（Web服务器间接获取数据，性能不如C/S），为此我们在总部数据中心部署了应用服务器集群（6节点），确保响应时间≤2秒。

---

### 2.4 组件分布架构

> **教材**：组件部署在多台计算机节点上，通过中间层构件通信。CORBA/DCOM/EJB。

华航平台的微服务架构本质上是组件分布架构的现代实现：

- **每个微服务 = 一个分布组件**：部署在K8s集群的不同节点
- **中间层构件**：Kong API Gateway + Kafka消息总线
- **服务发现**：Consul实现服务注册与发现
- **组件间通信**：同步用REST/gRPC，异步用Kafka

> **考点提示**：三种分布式组件中间件——CORBA（通用）、DCOM（微软）、EJB（Java/Sun），记住对应关系。
