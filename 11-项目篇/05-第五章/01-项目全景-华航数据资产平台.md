## 一、应用系统视角下的项目基本盘

### 1.1 一句话概括

华航集团建设覆盖总部及29个节点的统一数据资产智能管理平台，包含**7大核心应用模块**，涉及**120+系统间的300+接口**集成，要求在14个月内完成从初步调研到系统验收的全过程。项目总投资580万元/年，要求系统可用性≥99.99%。

### 1.2 关键参数（应用系统维度）

| 维度 | 参数 | 应用系统规划关联 |
|------|------|-----------------|
| 软件模块数 | 7大核心模块 + 3个公共组件 | 体系结构定义→模块划分 |
| 接口规模 | 120+系统间300+接口 | 接口定义→外部/内部接口 |
| 数据表数量 | 元数据库200+表，图数据库15类节点 | 数据定义→数据库设计 |
| 代码量 | 前后端合计约80万行 | 构件定义→代码结构 |
| 生命周期 | 瀑布+迭代增量混合模型 | 生命周期选择→组合策略 |
| 架构模式 | B/S架构 + 微服务 + 组件分布 | 基础架构→分层+C-S |
| 非功能需求 | 并发≥5000，响应≤2s，可用性≥99.99% | 系统分析→非功能性需求 |
| 开发团队 | 前端5+后端8+测试3+DBA 2+架构2=20人 | 可行性→技术可行性 |

## 二、七大核心应用模块

华航数据资产智能管理平台的7大功能模块，按优先级分为P0（核心）、P1（深化）、P2（增值）三个等级：

| 优先级 | 模块名称 | 核心功能 | 技术架构 | 一期/二期 |
|:---:|---------|---------|---------|:---:|
| P0 | 数据资产目录 | 元数据采集/资产编目/标签/搜索 | ES+Neo4j+PG | 一期 |
| P0 | 数据质量管理 | 规则配置/质量检测/问题工单/评分 | 规则引擎+消息队列 | 一期 |
| P0 | 运维监控中心 | 集群监控/告警/日志分析/大屏 | K8s+Prometheus+Grafana | 一期 |
| P1 | 数据共享交换 | API网关/数据服务/订阅/审批 | API Gateway+Kafka | 二期 |
| P1 | 数据安全管控 | 分类分级/脱敏/审计/权限 | RBAC+ABAC+加密 | 二期 |
| P1 | 数据血缘图谱 | 自动解析/可视化/影响分析 | Neo4j+D3.js | 二期 |
| P2 | 智能问答 | NL2SQL/知识库/智能推荐 | LLM+RAG+NLP | 二期 |

> **应用系统规划视角**：P0/P1/P2的划分正是APA应用系统组合法的实践——按「业务价值×技术成熟度」两个维度排列，确定建设优先级。

## 三、技术架构（应用系统视角）

### 3.1 分层体系

```
界面交互层    │ React 18 + Ant Design Pro │ 微前端(qiankun) │ 大屏(G2/ECharts)
业务处理层    │ 数据资产目录│质量管理│共享交换│安全│血缘│问答│监控
服务层        │ API Gateway(Kong) │ 规则引擎(Drools) │ 血缘引擎 │ NLP引擎
数据处理层    │ MyBatis Plus │ JPA │ Neo4j OGM │ ES Client
数据存储层    │ PostgreSQL(元数据)│ Neo4j(图谱)│ ES(搜索)│ MongoDB(规则)│ Redis
```

### 3.2 架构选型

| 架构决策 | 选择 | 理由（来自教材知识） |
|---------|------|-------------------|
| 整体架构 | B/S架构 | 29节点跨地域访问，无需安装客户端 |
| 服务架构 | 微服务+组件分布 | 各模块独立部署、独立扩展 |
| 数据架构 | 以数据为中心+分层 | 平台本质是数据处理系统 |
| 通信方式 | RESTful API + Kafka消息 | 同步异步结合，解耦模块间依赖 |
