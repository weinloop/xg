# 主要过程与规划设计方法

> 对应教材 5.3（主要过程）和 5.4（常用方法）/5.5（软件工厂）。
> 五个过程步骤——「初可详析设」，四种方法——APA/TOGAF/SOA/软件工厂。

---

## 第一部分：主要过程（5.3）

> **速记口诀**：「初可详析设」——初步调研→可行性研究→详细调研→系统分析→系统设计

### 一、初步调研（5.3.1）

> **教材**：目标——掌握用户概况，明确初步目标，为可行性研究提供基础。内容——组织概况/组织环境/现行系统概况/各方态度/资源情况。

**项目故事**：2024年4月，我带着2名架构师和1名业务分析师，走进华航集团总部，开始了为期3周的初步调研。

调研围绕教材规定的5个方面展开：

| 调研内容 | 实际获取的关键信息 |
|---------|-----------------|
| 组织概况 | 员工8万+，下辖5区域中心23分公司，航空全产业链（客运/货运/机务/航食/地服/培训） |
| 组织环境 | 受民航局监管，需满足等保三级，与空管/机场/航油等外部机构有大量数据交换 |
| 现行系统概况 | 120+业务系统，FOC（航班运行）/PSS（旅客服务）/RMS（收益管理）/MRO（机务维修）为核心 |
| 各方态度 | 集团CIO高度支持，数据治理委员会已成立，但各业务部门数据开放意愿参差不齐 |
| 资源情况 | 现有IT团队约60人，服务器/网络设备若干，但缺乏数据治理专业人才 |

> **考点提示**：初步调研5项内容可能出简答题——「初步调研的具体内容主要包括哪些？」

---

### 二、可行性研究（5.3.2）

> **教材**：四个方面（经济/技术/社会/管理）+ 八个步骤。结果是三种结论之一（可行/基本可行/不可行）。

#### 2.1 四方面可行性分析 — 华航项目真实数据

**经济可行性**：我与财务团队一起做了详细的成本/效益分析。

| 成本类型 | 项目 | 金额（万元） |
|---------|------|:---:|
| 建设成本 | 硬件设备（服务器/存储/网络） | 180 |
| 建设成本 | 软件许可（数据库/中间件） | 80 |
| 建设成本 | 开发人力（20人×14月） | 260 |
| 建设成本 | 第三方服务（安全测评/性能测试） | 60 |
| 运行成本 | 年度运维+云资源+人员 | 180/年 |
| 直接效益 | 数据共享效率提升→业务决策提速 | 估算年收益≥800万 |
| 间接效益 | 数据安全合规→规避罚款风险 | ≥500万 |
| **ROI** | 三年累计投入1,740万，三年累计收益约3,900万 | **ROI ≈ 280%** |

> 结论：效益大于成本，经济上可行。

**技术可行性**：重点评估了50PB数据入湖的技术方案。我们搭建了一个小规模验证环境，用500TB样本数据验证了Hadoop+Spark的数据采集链路可行性。5月完成PoC，验证通过。

| 技术风险项 | 评估 | 应对 |
|-----------|:---:|------|
| 50PB数据采集性能 | 中风险 | 采用增量采集+并行处理 |
| LLM智能问答效果 | 高风险 | PoC先行，效果不达标可降级为关键词匹配 |
| 120+系统接口兼容性 | 中风险 | 开发统一数据采集适配器框架 |

> 结论：关键技术上可行，采用成熟技术为主（PostgreSQL/K8s/ES），先进技术（LLM）有PoC验证。

**社会可行性**：2024年5月，我向23家分公司发放了调研问卷，了解数据共享意愿。结果显示：12家积极支持，8家观望（担心数据安全），3家有抵触（认为涉及商业机密）。针对观望和抵触的11家，我们设计了三项措施：①数据安全分类分级，明确哪些数据可共享；②数据脱敏机制，共享数据自动脱敏；③数据使用审计，每次访问有记录。

> 结论：通过制度和安全设计可化解阻力，社会可行性具备。

**管理可行性**：集团数据治理委员会已成立（CIO+3位业务VP），高层支持力度大。但中层管理人员担心新系统增加工作量。我们承诺通过自动化减少手工操作，数据管家日常操作从预估的每天2小时降至实际30分钟。

> 结论：高层支持+中层可通过培训和制度解决，管理可行性具备。

#### 2.2 八步骤实施

| 步骤 | 内容 | 华航项目时间节点 |
|:--:|------|---------------|
| 1 | 复查系统目标和规模 | 2024.5.6 与CIO及3位VP确认目标 |
| 2 | 研究目前正在使用的系统 | 2024.5.7-12 分析120+系统文档 |
| 3 | 导出新系统高层逻辑模型 | 2024.5.13-17 绘制顶层数据流图 |
| 4 | 重新定义问题 | 2024.5.20 与用户复查确认 |
| 5 | 导出和评价供选方案 | 2024.5.21-28 提出3种方案对比 |
| 6 | 推荐方案并说明理由 | 2024.5.30 推荐「自研+开源」混合方案 |
| 7 | 草拟开发计划 | 2024.6.1-5 制定资源计划+进度表 |
| 8 | 书写文档提交审查 | 2024.6.10 提交可行性研究报告 |

2024年6月15日，召开了可行性论证会，与会专家一致通过。**结论：项目可行，条件成熟，可以立即建设。**

> **考点提示**：可行性研究的8步骤和4方面，以及可行性研究报告的三种结论，是案例分析题的高频考点。首考真题案例题第2题第1问就是「内容和方法/产出物」。

### 三、详细调研（5.3.3）

> **教材**：6项活动——收集信息→系统需求建模→需求优先级划分→构建系统原型→产生和评估候选方案→和管理部门复查。9个调研范围。

**详细调研的6项活动**（首考真题考点）：

| # | 活动 | 关键问题 | 华航项目实践 |
|:--:|------|---------|------------|
| 1 | 收集信息 | 是否拥有全部信息？ | 调研120+系统，访谈80+用户，收集300+表单 |
| 2 | 系统需求建模 | 系统需要做什么（详细）？ | 绘制200+张业务流程图，50+用例图 |
| 3 | 需求优先级划分 | 最重要的事是什么？ | MoSCoW法划分P0/P1/P2 |
| 4 | 构建系统原型 | 技术能否实现？用户是否理解？ | 开发资产目录原型，两周内获得用户确认 |
| 5 | 产生和评估候选方案 | 最好方案是什么？ | 自研 vs 外购 vs 混合 三方案对比 |
| 6 | 和管理部门复查 | 是否应该继续？ | CIO确认后进入系统分析 |

> **考点提示**：6项活动必须记住，首考案例题直接考察。速记口诀：「收模优型案查」——收集信息→系统需求建模→需求优先级划分→构建系统原型→产生评估候选方案→和管理部门复查。

### 四、系统分析（5.3.4）

> **教材**：三阶段——问题分析→需求分析→需求定义。系统说明书应有6个特征（正确性/完整性/一致性/无二义性/可修改性/可跟踪性）。

**项目故事**：2024年7-8月，我带领分析团队完成了系统分析工作。

**问题分析阶段**：通过观摩法（参观了某航空公司的数据平台）、JAD会议（2天内集中所有利益相关者讨论）、原型法（快速构建资产目录界面原型）引导需求。

**需求分析阶段**：采用结构化方法（数据流图）和UML用例驱动方法相结合——
- 用数据流图描述数据在7大模块间的流动
- 用用例图描述用户与系统的交互（5类用户34个用例）
- 用实体关系图描述50+核心数据实体及其关系

**需求定义阶段**：编写了180页的《需求规格说明书》，包含功能性需求（7大模块功能描述）和非功能性需求（并发5000、响应≤2s、可用性99.99%、数据加密等）。

> **考点提示**：三种需求分析方法——面向过程的结构化方法（数据流图）、面向数据的信息工程方法（ER图）、基于UML的用例驱动方法（用例图+领域类图）。系统说明书的三个部分（引言/概述/实施计划）可能出填空。

---

### 五、系统设计（5.3.5）

> **教材**：5原则（系统性/灵活性/可靠性/经济性/管理可接受）+ 9项设计内容。评价指标：可靠性/可变更性/效率/通用性/工作质量。

| 原则 | 华航项目实践 |
|------|------------|
| 系统性 | 统一数据编码规范，数出一处、全局共享 |
| 灵活性 | 模块化设计，P0/P1/P2分阶段独立建设 |
| 可靠性 | 主备容灾+数据多副本+自动故障转移 |
| 经济性 | 开源方案优先（PG/ES/Neo4j社区版），避免商业许可锁死 |
| 管理可接受 | 界面设计对标业界成熟产品，降低用户学习成本 |

**9项设计内容**中，我重点参与了：
- **系统总体结构设计**：将系统划分为7大模块28个子模块
- **处理流程设计**：数据采集→清洗→入湖→编目→共享的端到端流程
- **数据库设计**：200+表设计+120+索引+10+物化视图
- **安全保密设计**：等保三级方案、TLS 1.3传输加密、AES-256存储加密

> **考点提示**：系统设计的5原则可能出选择题辨析。9项设计内容（总体结构/处理流程/代码/人机界面/输出/输入/数据库/安全保密/物理配置方案+编写说明书）数量多，靠理解记忆。

## 第二部分：常用方法（5.4）

### 六、APA 应用系统组合法（5.4.1）

> **教材**：6步骤——应用系统清单→评估→分析→制定优化策略→实施→监测评估。

**项目故事**：在华航项目中，APA方法帮助我快速梳理了120+套存量系统。

| 步骤 | 华航项目实践 |
|------|------------|
| 清单 | 收集120+系统的名称/功能/技术平台/使用情况信息 |
| 评估 | 按业务价值（高/中/低）+技术健康度（好/中/差）两个维度打分 |
| 分析 | 识别出5套已停用但未下线的系统、12套功能重叠的系统 |
| 策略 | 5套淘汰、12套整合为4套数据采集通道、核心系统保留接口改造 |
| 实施 | 按优先级分批推进，一期改造核心的FOC/PSS/RMS接口 |
| 监测 | 每季度复盘应用系统组合优化效果 |

> **考点提示**：APA的6步骤——「单评析策施监」（清单→评估→分析→策略→实施→监测）。

---

### 七、TOGAF（5.4.2）

> **教材**：6组件（ADM/指南技术/内容框架/企业连续体/参考模型/能力框架）。ADM 10阶段是核心。

**项目故事**：在华航项目中，我们部分应用了TOGAF的ADM方法，涵盖以下阶段：

| ADM阶段 | 华航项目对应 |
|---------|------------|
| 预备阶段 | 定义项目组织架构、架构原则（开源优先/标准化/安全性） |
| 需求管理 | 贯穿全程，用JIRA管理500+条需求 |
| 阶段A：架构愿景 | 制定平台建设愿景——「数据可见、可管、可用、可控、智能」 |
| 阶段B：业务架构 | 定义8大业务域及其数据资产边界 |
| 阶段C：信息系统架构（应用+数据） | 7大模块应用架构+5种存储数据架构 |
| 阶段D：技术架构 | 私有云+K8s+微服务+CI/CD技术栈 |
| 阶段E：机会和解决方案 | 确定P0/P1/P2建设方案，决策制造/购买/重用 |
| 阶段F：迁移规划 | 制定14个月的三阶段迁移计划 |
| 阶段G：实施治理 | 架构委员会每月评审架构合规性 |
| 阶段H：架构变更治理 | 建立变更评审机制（CCB） |

> **考点提示**：TOGAF 6组件和ADM 10阶段名称需要记住。10阶段速记：「预需愿业信技机迁实变」——预备→需求管理→Architecture愿景→业务架构→信息系统架构（Application+Data）→技术架构→机会和解决方案→迁移规划→实施治理→架构变更治理。

### 八、SOA 面向服务的架构（5.4.3）

> **教材**：4设计原则（明确接口/自包含/粗粒度/松耦合/互操作性）+ 6技术（封装/编排/注册发现/治理/安全/可靠性）+ 5应用场景。

| 原则 | 华航平台实现 |
|------|------------|
| 明确接口定义 | 所有服务通过OpenAPI 3.0规范定义接口 |
| 自包含与模块化 | 每个微服务有独立代码仓库+CI/CD |
| 粗粒度 | 7大模块即7大服务族，不是200+微服务 |
| 松耦合 | 通过Kong API Gateway解耦，服务间不直接依赖 |
| 互操作性 | RESTful统一协议，JSON统一格式 |

> **考点提示**：SOA五大应用场景——组织级应用集成（最核心）、业务流程管理、系统扩展和重用、云计算和微服务架构、跨平台集成。

### 九、软件工厂（5.5）

> **教材**：5构成（人员/基础设施/工具技术/流程规范/质量管理）+ 7项敏捷实践。

**项目故事**：华航项目在二期建设中采用了软件工厂模式。

| 构成要素 | 华航实践 |
|---------|---------|
| 专业人员 | 前端5+后端8+测试3+DBA2+架构2=20人 |
| 基础设施 | 20台计算节点+2台GPU节点+CI/CD流水线 |
| 工具技术 | IDEA+GitLab+Jenkins+SonarQube+Docker+K8s |
| 流程规范 | DevSecOps，代码审查+自动化测试+自动化部署 |
| 质量管理 | 单元测试覆盖率≥80%，性能压测每周一次 |

**7项敏捷交付实践**中，我们应用了：Scrum迭代开发（2周Sprint）、产品Backlog管理（JIRA）、自动化测试（JUnit+Selenium）、持续集成/持续交付（Jenkins CI/CD）、用户故事驱动开发、团队每日站会、迭代评审与回顾。

> **考点提示**：软件工厂5构成可能出多选题。敏捷宣言4价值是常考点。
