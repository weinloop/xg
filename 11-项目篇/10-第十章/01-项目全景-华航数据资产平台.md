# 01 · 项目全景 — 华航数据资产平台的云原生实践

> 2024年7月，华航集团启动了数据资产智能管理平台的建设项目。虽然招标书没有直接写「云原生」三个字，但项目的技术选型——Kubernetes容器编排、微服务架构、CI/CD流水线、灰度发布——处处都是云原生的影子。这一章，我用系规师的视角，还原华航项目中的云原生规划实践。

## 二、云原生技术栈全景

### 2.1 容器与编排

华航项目基于 **Kubernetes 1.28** 构建了私有容器云平台，部署架构如下：

```
┌─────────────────────────────────────────────────┐
│                  应用层 (SaaS)                    │
│  数据资产管理 │ 质量治理 │ 安全管控 │ 血缘图谱   │
│  目录服务 │ 智能标签 │ AI辅助决策                 │
├─────────────────────────────────────────────────┤
│                  平台层 (PaaS)                    │
│  K8s 1.28 容器编排 │ Istio 服务网格              │
│  GitLab CI + ArgoCD 流水线 │ Harbor 镜像仓库     │
│  Prometheus + ELK + Jaeger 可观测                │
├─────────────────────────────────────────────────┤
│               基础设施层 (IaaS)                    │
│  20 Worker节点（16vCPU/64GB）                    │
│  2 GPU推理节点（8×A100）                         │
│  50PB存储（Ceph: 30PB对象+15PB块+5PB文件）       │
├─────────────────────────────────────────────────┤
│               部署架构                             │
│  北京总部：主计算集群                             │
│  南京：容灾中心（主备双活，10Gbps专线）           │
│  5大区域：边缘节点                                │
└─────────────────────────────────────────────────┘
```

### 2.2 微服务架构

7大功能模块以微服务形态独立部署，每个模块对应一个独立的 K8s Deployment：

| 微服务 | 实例数 | 技术栈 | 数据库 |
|--------|:---:|------|------|
| 数据资产管理 | 3 | Spring Boot | PostgreSQL |
| 数据质量治理 | 4 | Go | MongoDB |
| 数据安全管控 | 2 | Spring Boot | PostgreSQL |
| 数据血缘图谱 | 3 | Python + Neo4j | Neo4j |
| 数据目录服务 | 5 | Go | Elasticsearch |
| 智能标签 | 2 | Python | Redis |
| AI辅助决策 | 2 | Python + MLflow | PostgreSQL |

### 2.3 DevOps与持续交付

```
代码提交(GitLab) → 自动构建(Docker) → 自动测试(单元+集成)
    → 镜像推送(Harbor) → 自动部署(ArgoCD) → 灰度发布(Istio)
    → 监控告警(Prometheus+ELK)
```

**关键数据**：
- 部署时间：手动部署2小时 → CI/CD流水线 **15分钟**（压缩87.5%）
- 部署成功率：85% → **99%**
- 灰度发布窗口：仅需30分钟即可完成10%→100%流量切换

## 三、云原生七大原则在华航的落地

| 原则 | 华航实践 |
|------|---------|
| **服务化** | 7大模块按业务域拆分，独立迭代，互不影响 |
| **弹性** | HPA基于CPU/内存自动扩缩容，30秒完成 |
| **可观测** | Prometheus+Grafana(指标) + ELK(日志) + Jaeger(链路) |
| **韧性** | Istio熔断/限流/降级/重试，北京→南京主备切换≤12分钟 |
| **自动化** | GitLab CI + ArgoCD全自动化流水线 |
| **零信任** | 基于RBAC+OAuth2.0的服务间认证，Istio mTLS |
| **持续演进** | 增量迭代，试运行期间已完成3次微服务版本升级（均零中断） |
