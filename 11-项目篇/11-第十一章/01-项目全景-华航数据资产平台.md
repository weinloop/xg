## 二、治理架构 — COBIT三层落地

华航项目参照 **COBIT 2019** 框架，建立了「治理-管理-执行」三层架构：

```
┌─────────────────────────────────────────────────┐
│              数据治理委员会（最高管理层）          │
│  华航CIO + 信息中心主任 + 5大区域IT负责人         │
│  职责：IT战略与业务对齐、重大投资决策、风险管理     │
│  会议：季度例会                                  │
├─────────────────────────────────────────────────┤
│           数据管理办公室（执行管理层）              │
│  我方项目经理 + 华航数据架构师 + 质量负责人         │
│  职责：标准制定、流程管理、资源分配、绩效监控       │
│  会议：月度评审                                  │
├─────────────────────────────────────────────────┤
│      数据管家团队 + 运维团队（业务与服务执行层）     │
│  5大区域数据管家 + 开发团队 + 运维团队              │
│  职责：标准落地执行、数据质量巡查、IT服务交付        │
│  会议：周例会                                    │
└─────────────────────────────────────────────────┘
```

### 三层架构的设计故事

2024年7月项目启动时，华航的IT治理结构只有一级——「技术团队」。数据标准制定、变更审批、质量检查全部混在一起，导致标准推行困难：同一个字段名，不同部门有3种命名方式，技术团队没有权限强制统一。

2024年9月，我推动建立了三层治理架构：

| 层级 | 建立时间 | 初期痛点 | 解决效果 |
|------|:---:|------|------|
| 数据治理委员会 | 2024年9月 | 标准推行缺乏高层授权 | 标准审批从平均7天缩短至3天 |
| 数据管理办公室 | 2024年10月 | 变更审批缺少专业评估 | 建立变更评审小组，技术方案通过率从60%→95% |
| 数据管家团队 | 2024年11月 | 标准落地缺乏日常巡查 | 月度质量巡查发现问题从50+降至10以内 |

## 三、核心治理机制

### 6项治理机制在华航的落地

| 机制 | COBIT对应 | 华航实践 |
|------|:---:|------|
| **执行层和高级管理委员会** | EDM | 季度数据治理委员会会议，决策重大投资和方向调整 |
| **架构委员会** | APO | 月度架构评审会，审查新增数据源的接入方案 |
| **有IT人员参与的流程团队** | BAI | 数据管家+业务部门联合工作组，端到端流程管理 |
| **资金投资批准和预算** | APO | 580万年度预算分解到月，季度回顾调整 |
| **服务水平协议（SLA）** | DSS/MEA | 99.99%可用性、RTO≤15分钟、RPO≤5分钟 |
| **IT业务价值的正式衡量追踪** | MEA | 5项绩效指标月度跟踪，季度向治理委员会汇报 |

### 5项治理绩效指标

| 指标 | 目标值 | 2025年1月实际值 | 2025年6月实际值 |
|------|:---:|:---:|:---:|
| 数据标准覆盖率 | ≥90% | 65% | 92% |
| 数据质量合格率 | ≥95% | 78% | 96% |
| 数据资产目录完整率 | ≥95% | 82% | 97% |
| API服务可用性 | ≥99.99% | 99.95% | 99.992% |
| 安全合规达标率 | 100% | 85%（等保测评未完成） | 100% |

> 💡 **论文素材**：2025年1月季度治理评审，数据标准覆盖率仅65%，远低于90%目标。数据治理委员会当即决定将标准覆盖率纳入各分公司信息化考核KPI。三个月后覆盖率提升至92%——这段故事可直接用于论文的「绩效监督」段落。

## 四、治理标准体系

华航项目同时参照三套标准：

| 标准 | 角色 | 在华航的应用 |
|------|------|------------|
| **COBIT 2019** | 治理框架 | EDM/APO/BAI/DSS/MEA五域指导治理与管理活动 |
| **ITSS（GB/T 34960）** | 实施指南 | 通用要求34960.1定框架 + 实施指南34960.2定步骤 |
| **ISO/IEC 38500** | 国际基准 | 6项原则（责战收性一行为）+ 评估/指导/监督三任务 |

## 五、IT审计规划

华航项目在合同中约定每年进行一次IT审计，首次审计安排在2025年6月（试运行期间）。审计范围包括：

| 审计大类 | 审计内容 | 审计方法 |
|------|------|------|
| IT内部控制审计 | 组织层面IT控制 + 一般控制 + 应用控制 | 访谈法 + 检查法 + 测试法 |
| IT专项审计 | 数据安全审计 + 系统运行维护审计 + 项目管理审计 | 观察法 + 程序代码检查法 + CAAT |

首次审计发现3个高风险项（数据备份策略不完善、权限管理存在越权风险、变更管理流程缺少审批记录），均在2周内整改完毕并通过复检。
