# 04 · IT审计实战（教材11.2）

> 治理是「怎么管」，审计是「怎么查」。IT审计是IT治理不可拆分的评估和监督工具。

---

## 11.2.1 IT审计基础

### 一、IT审计定义（5个主流定义）

| 机构 | 定义核心 |
|------|------|
| **ISACA** | 获取并评价证据，判断计算机系统能否保证资产安全、数据完整、有效利用资源并实现目标 |
| **IMF** | 对计算机化系统进行审计，包括现有控制+建立过程+设备网络管理 |
| **INTOSAI** | 获取并评估证据，判断IT系统是否保护资产、利用资源、保障数据安全一致性、达到业务目标 |
| **日本** | 由独立审计人员以第三方客观立场，对信息系统综合检查评价，向最高领导层提出问题与建议 |
| **GB/T 34690.4** | 根据IT审计标准，对信息系统及相关的IT内部控制和流程进行检查、评价，并发表审计意见 |

> 🎯 **考点提示**：GB/T 34690.4的定义是国内标准定义，常被作为「我国IT审计定义」考察。关键词：**检查、评价、发表审计意见**。

---

### 二、IT审计目的

1. 了解组织IT系统与IT活动的总体状况
2. 对组织是否实现IT目标进行审查和评价
3. 充分识别与评估相关IT风险
4. 提出评价意见及改进建议
5. 促进组织实现IT目标

**组织的IT目标（4个）**：
- ①IT战略与业务战略保持一致
- ②保护信息资产安全及数据完整可靠有效
- ③提高信息系统安全性可靠性及有效性
- ④合理保证信息系统符合法律法规及标准

**速记口诀：了解审查识别，建议促进**

---

### 三、IT审计范围（4类）

| 范围类型 | 说明 |
|------|------|
| **总体范围** | 根据审计目的和投入的审计成本确定 |
| **组织范围** | 明确审计涉及的组织机构、流程、活动及人员 |
| **物理范围** | 具体的物理地点与边界 |
| **逻辑范围** | 涉及的信息系统和逻辑边界 |

> 🎯 **考点提示**：实施审计前应先对组织与信息系统相关的总体情况进行**了解和风险评估**，确定主要IT风险（环境控制/系统/数据相关），再确定重点审计范围。

---

### 四、IT审计人员要求（4个方面）

| 方面 | 具体要求 |
|------|------|
| **职业道德** | 独立客观公正、正直诚实守信、正确履行审计职责、对信息保密 |
| **知识技能资格经验** | IT专业知识 + 审计/财务/管理通用知识 + 基本/专业/软技能 |
| **专业胜任能力** | 相适应IT审计职业资格及经验、定期参加持续职业教育和培训 |
| **利用外部专家** | 评价专家资格/独立性/客观性/胜任能力、签订书面协议、评价利用服务结果 |

**速记口诀：德知胜专，四维要求**

---

### 五、IT审计风险（3+1类）

| 风险类别 | 含义 | 关键特征 |
|------|------|------|
| **固有风险** | IT活动本身不存在相关控制时，易于导致重大错误的风险 | 审计人员只能评估，无法控制或影响；不同IT活动固有风险水平不同 |
| **控制风险** | 内控体系不能及时预防或检查出重大错误的风险 | 与内控制度执行有效性有关，审计人员只能评估不能控制 |
| **检查风险** | 预定审计程序未能发现重大错误的风险 | 受审计规范不完善/审计人员/技术原因影响 |
| **总体审计风险** | 针对单个控制目标所产生的各类审计风险总和 | 良好的审计计划应尽可能评估和控制 |

**速记口诀：固控检，总汇合**

| 在华航首次审计（2025年6月）中的体现 |
|------|
| **固有风险**：航空数据涉及国家安全，天然存在较高的合规风险 |
| **控制风险**：变更管理缺少审批记录，内控制度执行不到位 |
| **检查风险**：部分遗留系统日志缺失，审计程序无法覆盖 |
| 首次审计总体风险评级为「中」，整改后降至「低」 |

## 11.2.2 IT审计方法与技术

### 一、IT审计依据与准则

| 国际 | 国内 |
|------|------|
| ISACA信息系统审计准则 | 《中华人民共和国审计法》 |
| COSO内部控制整体框架 | 《中华人民共和国网络安全法》 |
| SOX萨班斯法案 | GB/T 34960.4《审计导则》 |
| COBIT信息及相关技术控制规范 | 行业规范（商业银行/证券期货/保险等） |

---

### 二、IT审计常用方法（6种）

| 方法 | 说明 | 在华航审计中的应用 |
|------|------|------|
| **访谈法** | 面对面交谈了解被审计对象信息 | 对数据管家逐一访谈，了解标准执行情况 |
| **调查法** | 书面或口头回答方式收集资料 | 向5大区域发送数据质量自评问卷 |
| **检查法** | 审查内外部生成的记录和文件 | 检查变更管理审批记录、数据备份日志 |
| **观察法** | 实地察看证实审计事项 | 到北京总部机房实地察看服务器运行环境 |
| **测试法** | 输入跟踪到输出检验程序可靠性 | 对API网关进行压力测试，验证流控机制 |
| **程序代码检查法** | 逐条审查程序指令 | 使用SonarQube扫描核心代码，发现3处SQL注入风险 |

**速记口诀：访调检观测码**

---

### 三、IT审计技术（4种）

| 技术 | 核心内容 |
|------|------|
| **风险评估技术** | 风险识别（德尔菲法/头脑风暴/检查表/SWOT/图解技术）→ 风险分析（定性/定量）→ 风险评价（单因素/总体）→ 风险应对（云计算/冗余/弹性伸缩/灾备/熔断限流） |
| **审计抽样技术** | 统计抽样（属性抽样「有多少」+ 变量抽样金额估计）vs 非统计抽样（判断抽样） |
| **计算机辅助审计技术（CAAT）** | 通用审计软件GAS/测试数据/实用工具/专家系统 |
| **大数据审计技术** | 智能分析（机器学习/数据挖掘） + 可视化分析（R/Python/D3.js） + 多数据源综合分析 |

> 🎯 **考点提示**：属性抽样回答「有多少」的问题（如：申请表中签字比例），变量抽样估计金额或度量单位（如：交易余额）。这两个概念经常混淆出题！

**速记口诀：风险抽样CAAT，大数据四技术**

---

### 四、IT审计证据（5大特性）

| 特性 | 说明 | 在华航审计中 |
|------|------|------|
| **充分性** | 对证据数量的要求，与样本量有关 | 抽取了足够样本量的变更记录 |
| **客观性** | 客观事实材料比需要判断的证据可靠 | 以系统日志为准，不用口头表述 |
| **相关性** | 证据与审计事项必须有实质性联系 | 聚焦数据安全控制，不检查无关系统 |
| **可靠性** | 受证据类型、取证渠道和方式影响 | 直接从数据库导出的审计日志 |
| **合法性** | 必须符合法定种类并依程序取得 | 审计证据采集全程双人操作、全程录像 |

**电子证据**：以电子/数据/磁性形式存在，在收集/提取/保存/出示/审查/判断/认证各环节均需高技术规范。

**速记口诀：充客相可法**

---

### 五、IT审计工作底稿（3类+三级复核）

| 底稿类型 | 内容 |
|------|------|
| **综合类** | 审计计划阶段和报告阶段的底稿（审计业务约定书/审计计划/审计总结/审计报告） |
| **业务类** | 审计实施阶段执行具体程序形成的底稿（内控问题调查表/流程图/项目明细表） |
| **备查类** | 仅具备查作用的底稿（随情况变化更新，注明来源） |

**三级复核制度**：审计机构负责人 → 部门负责人 → 项目负责人

**速记口诀：综业备三类，三级复核**

## 11.2.3 IT审计流程（4阶段）

| 阶段 | 主要工作 | 在华航首次审计中 |
|:---:|------|------|
| **审计准备** | 明确审计目的及任务→组建审计项目组→搜集相关信息→编制审计计划 | 2025年5月编制审计计划，确定审计范围为120+系统/50PB数据，组建5人审计组 |
| **审计实施** | 深入调查并调整计划→了解并初步评估IT内控→符合性测试→实质性测试 | 6月入场，完成全部6种审计方法的实施 |
| **审计终结** | 整理与复核底稿→整理审计证据→评价IT控制目标实现→判断并报告审计发现→沟通审计结果→出具审计报告→归档管理 | 6月底完成审计报告，发现3个高风险项、7个中风险项 |
| **后续审计** | 检查被审计单位对问题和建议是否采取适当纠正措施并取得预期效果 | 7月进行后续审计，确认3个高风险项全部整改完毕 |

**速记口诀：备施结续**

---

## 11.2.4 IT审计内容

### IT内部控制审计（三层）

| 层级 | 审计内容 |
|------|------|
| **组织层面IT控制** | IT战略/组织/架构/业务连续性/风险管理/外包管理/网络信息安全/监督管理 |
| **IT一般控制** | 与应用系统/数据库/操作系统/网络相关的策略和措施 |
| **应用控制** | 业务流程层面运行的人工或自动化程序（输入控制/处理控制/输出控制） |

### IT专项审计（六类）

| 类型 | 审计内容 |
|------|------|
| 信息系统生命周期审计 | 规划/设计/开发/测试/运行和维护 |
| 信息系统开发过程审计 | 规划/设计/建设/实施是否符合IT架构和战略 |
| 信息系统运行维护审计 | IT运维能力/运维流程策划实施监控改进 |
| 网络与信息安全审计 | 以安全为核心，围绕安全相关的组织/人员/系统/设备和环境 |
| 信息系统项目审计 | 对项目管理过程进行评价（组织管理/启动与计划/实施与控制/收尾管理/技术方案） |
| 数据审计 | 分析/验证/讨论/改进数据安全管理相关政策标准和活动 |

**速记口诀：内控三层组般应，专项六类生开运网项数**
