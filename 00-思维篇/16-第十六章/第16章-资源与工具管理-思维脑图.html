16.1 研发与测试管理 研发工具测试工具环境维护 ▼
研发与测试环境概述
  • 研发测试环境 = 软件工具 + 环境集成机制，支持系统软件和应用软件的工程化开发和维护
  • 研发测试环境质量直接影响研发人员工作效率和质量
  • 包括：开发机器获取、网络配置、基本工具、代码获取和配置
16.1.1 研发管理工具 P0高频开代配
  • 研发管理借助信息平台对团队/流程/绩效/风险/成本/项目/知识等进行协调活动
  • 三类管理工具：软件开发工具 + 代码管理工具 + 软件配置管理工具
1) 软件开发工具 V-E-P
  • 两个层次：孤立单个工具（特定活动） vs 集成化CASE环境（一致界面+共享数据库）
工具厂商核心特点关键能力
Visual Studio微软全面IDE，支持C++/C#/VB.NET/F#/Python/JS调试编译强、VSTS敏捷计划/测试管理/CI/CD
EclipseIBM(开源)基于Java的可扩展IDE，插件化架构(PDE)跨平台、开放源码、Ant/Maven集成、CVS/SVN/Git
PyCharmJetBrainsPython IDE，智能代码编辑器代码审查、调试器、单元测试、远程开发、数据库工具
🔑 Eclipse特点：开源/跨平台/插件化/Java支持强/高级编辑(高亮+补全+重构)/Ant+Maven构建/CVS+SVN+Git版本控制/社区丰富
2) 代码管理工具 P0必背已考集SVN分Git
类型代表架构模式关键特性
集中式SVNC/S架构，文件集中存服务器唯一URL、提交必须联网、提交需授权、冲突需先解决 已考
分布式Git本地仓库+远程仓库每人有完整代码库、离线可查日志/提交/建分支、分支易合、本地操作快
🔑 核心区分：SVN提交需联网 vs Git离线可提交｜SVN单中央仓库 vs Git每人都完整仓库｜SVN冲突后提交者需先解决 vs Git分支并行开发
🔑 Git设计目标：分支创建和合并简单而安全（最初为Linux内核开发而生）。Git只关心文件整体是否变化，不保存差异。
3) 软件配置管理工具(SCM) P0项版增程资自期集
  • SCM = Software Configuration Management，贯穿软件开发始终的质量保证活动
  • 常见工具：Harvest、ClearCase、StarTeam、Firefly
功能核心内容
1.项目管理建立配置管理计划、创建配置库；配置项含发行版本/系统文档/环境基线/软件库工具包
2.版本管理和基线控制记录修改轨迹、跟踪修改信息、基线渐进方式、版本差异比较、恢复早期版本
3.增强的版本控制快照(多文件当前版本集合) + 分支；支持批量签入/签出/加标签
4.流程控制和变更管理问题跟踪 + 变更请求管理，支持报告/抓取/跟踪软件变更相关问题
5.资源维护沙箱技术提供独立工作空间，并行开发，修改满意后合并到主线
6.过程自动化事件触发机制，一个事件触发另一事件；缩短开发时间+规范过程
7.管理整个生命周期开发→测试→发布→维护；提供典型开发模式模板 + 支持自定义
8.与主流IDE集成版本控制功能与IDE集成；IDE充当沙箱角色
🔑 易混陷阱：配置管理8大功能(项版增程资自期集) ≠ 配置管理工具功能模块(不同出处分法)。考试问"功能"答8大，问"功能模块"答模块图。
16.1.2 测试管理工具 P0高频
  • 测试工具分两类：自动化软件测试工具(代替人工输入) + 测试管理工具(管理测试流程)
1) 自动化软件测试工具 计设施执
  • 4阶段：自动化测试计划 → 自动化测试设计 → 自动化测试实施 → 自动化测试执行 已考
  • 按测试技术分类：白盒测试工具 / 黑盒测试工具 / 性能测试工具
  • 常见类型：单元测试工具、性能测试工具、功能测试工具
工具类型厂商核心功能
UFT功能测试HP原QTP；GUI测试+API测试+数据驱动+关键字驱动+VBScript脚本+报告分析
LoadRunner性能测试—模拟真实用户行为重现业务压力；三大组件：VuGen(虚拟用户脚本)+Controller(控制器)+Analysis(分析)
🔑 性能测试5步：计划测试 → 创建脚本 → 定义场景 → 运行场景 → 分析结果
2) 测试管理工具 计例执陷报协集
  • 7大功能：测试计划管理 + 测试用例管理 + 测试任务执行 + 缺陷记录跟踪 + 报告和分析 + 团队协作 + 集成其他工具
  • 核心：测试用例库 + 缺陷库
工具类型核心特点关键标签
TestRail用例管理Web化用例管理；3种方式：普通/基线/多套件；不提供需求和缺陷模块，但支持集成JIRA/GitHub用例
Quality Center测试管理Web化，4部分：明确需求→测试计划→执行测试→跟踪缺陷全流程
Bugzilla缺陷跟踪开源；缺陷报告/查询/状态/统计/权限/自定义字段/邮件集成/插件扩展开源
🔑 易混区分：自动化测试4阶段(计设施执) vs 测试管理7功能(计例执陷报协集)。前者是测试过程阶段，后者是管理工具的功能模块。
16.1.3 研发与测试环境搭建和维护
环境8原则 重协生自覆灵隔维
原则含义关键词
可重现性方便复现问题并调试复现问题
可协作性多人协作开发，避免冲突多人协作
与生产环境相似性尽量相似，减少环境问题贴近生产
自动化环境管理自动化工具管理配置，减少人为出错自动化
测试覆盖率确保研发结果符合预期覆盖全面
灵活性可扩展，尝试新方法/框架/工具灵活扩展
环境隔离性避免研发测试人员环境干扰隔离互扰
可维护性能随时更新和维护易维护
环境部署5步 硬系应库测
  • (1) 硬件设备选取和配置 → (2) 操作系统安装和配置 → (3) 应用程序安装和配置 → (4) 数据库安装和配置 → (5) 测试工具和脚本准备
  • 核心要求：与生产环境相同或相近的硬件/OS/应用/数据库
环境维护4要求 备更清监
  • (1) 定期备份数据（建议每天备份）
  • (2) 定期更新软件和补丁（注意先备份）
  • (3) 定期清理数据和日志（释放磁盘+提升性能）
  • (4) 监控环境状态（硬件/软件/网络，实时监控+报警）
16.2.1~16.2.3 运维监控/过程管理/自动化工具 ZabbixPrometheusITSMAnsible ▼
16.2.1 监控工具 P0高频基性能业
  • 3大类：(1) IT基础设施监控(主机/网络/存储/应用/机房动力) (2) 性能监控(业务/应用/网络性能) (3) 业务运营监控(运营管理/流程/容量)
  • 可单一功能监控，也可综合运维监控平台
常见监控工具 Z-N-P
工具类型架构模型核心特点
Zabbix开源分布式—Web界面；分布式系统+网络监控；支持数千台服务器+百万指标；CPU/内存/磁盘/网络/端口/日志；跨平台
Nagios开源Push推模型服务器代理架构；监控可用性；Nagios Core(免费/不支持Web管理) + Nagios XI(付费)；插件丰富
Prometheus开源Pull拉模型HTTP周期抓取；时序数据存储(值+时间戳+标签表)；服务发现+横向扩展；适用微服务/云环境 已考
🔑 核心陷阱：Prometheus = 拉(Pull)模型(Server主动HTTP抓取) vs Nagios = 推(Push)模型(Agent推送数据)。Prometheus支持时序数据，按时间顺序记录状态变化。
统一运维监控平台 采检告故视管
  • 6大模块：数据采集 → 数据检测 → 告警管理 → 故障管理 → 视图管理 → 监控管理
  • 4个统一：统一采集 + 统一检测 + 统一告警 + 统一展示
  • 目标：运维规范化、自动化、智能化
建设方式说明
基于开源自主开发在传统开源工具基础上集成封装和二次开发
定制商业平台选择成熟供应商一体化平台裁剪定制（嘉为蓝鲸/锐捷/华胜天成/联想）
16.2.2 过程管理工具 P0请件题变
  • 根据SLA对运维服务交付全过程管理，实现IT服务可视、可管、可控、可衡量
  • ITSM(IT Service Management)：面向过程、以客户为中心的管理方法和规范
  • 核心4流程：服务请求管理 + 事件管理 + 问题管理 + 变更管理 已考
🔑 陷阱：ITSM核心流程只有4个（请件题变），不包含发布管理、配置管理！不要混淆。
工具核心特点

ServiceHot ITSM可视化引擎+拖拽流程设计；国产化适配（龙芯/飞腾/鲲鹏+中标麒麟/银河麒麟+高斯/达梦/人大金仓）；开箱即用
🔑 过程管理工具逻辑架构：服务目录/自助服务门户 → 服务台+统一请求 → 事件/请求/问题/变更/知识/配置/资产/巡检管理平台 → 基础架构 → 外围接口
16.2.3 自动化专用工具 P0高频
1) 作业调度/批处理工具 P-S-A
工具架构客户端核心特点
PuppetC/S需要较早的Linux自动化工具；跨平台(Linux/Windows/AIX)；客户端周期连接服务器下载配置文件；Web界面集中管理
SaltStackC/S需要加入MQ消息同步；秒级数万台操作；RSA Key确认身份+AES加密；需等待全部返回（可能丢结果）
AnsibleSSH不需要基于SSH协议，无需客户端；普通服务器运行；上千插件模块；批量配置/部署/命令 已考
🔑 核心陷阱：Ansible 不需要安装客户端（基于SSH）！Puppet/SaltStack 需要客户端。SaltStack速度最快（秒级，MQ消息）。
2) 操作自动化工具 J-C
工具定位核心特点
Jenkins持续集成跨平台；自动构建/测试/部署；插件扩展体系；基于Java开源；兼容各种CI/CD工具
Chef自动化部署新一代IT工具；Ruby编写的DSL；定义全面IT任务流程；多平台/云服务；大规模部署；适合云业务DevOps

16.2.5 知识管理 P1ITSM内 Confluence PingCode
  • 知识库确保管理规范化，保证信息准确性、完整性、可用性
  • 促进团队技术管理能力，提升服务质量，减少重复劳动
