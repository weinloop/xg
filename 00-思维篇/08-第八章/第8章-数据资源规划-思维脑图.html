8.1.2 数据资源的定义
  • 定义：将无序、混乱的原始数据开发为有序、有使用价值的数据资源（采集+聚合+加工）
  • 2020年中央文件：数据作为第五要素（与土地/劳动力/资本/技术并列）
  • 五大特征：无可非时依垄 — 无形性与可复制性、非竞争性与弱排他性、时效性、依附性、垄断性
  • 被誉为"21世纪的石油"，具有大宗商品属性
三个阶段 资源化→资产化→资本化
阶段核心产出 1. 数据资源化原始数据→有序有价值高质量数据资源（可用/可信/标准） 2. 数据资产化基于场景加工形成数据产品场景赋能，预期产生经济利益 3. 数据资本化赋予金融属性，流通变现数据要素社会化配置
8.1.3 数据资源规划的定义与四大作用 提缓标市
  • 定义：对数据从产生、获取到处理、存储、传输和使用的全面规划，核心对象是数据本身
  • ① 提质增效 — 解决数据开发不足/利用不够/效益不高
  • ② 缓解"数据孤岛" — 减少重复建设和体系分割
  • ③ 标准化与共享 — 数据标准化，深层共享共用
  • ④ 市场化发展 — 推动市场化，解决低产业化/小规模/缺乏国际竞争力
8.2 数据资源规划的方法 过程·结构·指标 ▼
⭐ 三种方法总对比表 P0必考
方法适用场景优点缺点 稳定信息过程法业务固定，数据少理论成熟、易理解、难度不大步骤繁杂、因素多、数据稳定性差 稳定信息结构法业务多变，数据多理论较成熟、周期短、稳定性好全局设计后置、初期工作量大、并行组织难 指标能力法涉及决策，数据少直撑决策、思路清晰、稳定性好案例少、难度大、对设计人员要求高
8.2.1 基于稳定信息过程的方法（11步）可目准业模数标主分方审 案例
  • 两条主线：功能需求分析 + 数据需求分析
  • 三种模型：功能模型（子系统→功能模块→程序模块）+ 数据模型（基本表→子系统→全域）+ 关联模型
  • 一套标准：数据元素标准、分类编码标准、用户视图标准、概念/逻辑数据库标准
  • 核心11步：可行性分析(资/操/技) → 确定目标范围 → 准备(组团队/定路线/培训) → 业务活动研究 → 建立业务逻辑模型 → 导出数据模型 → 建立管理标准 → 设计主题数据库 → 数据分布分析 → 制定方案 → 审核评价
  • 核心是模型分析，重点是建立主题数据库（共建共用），按职能域划分
8.2.2 基于稳定信息结构的方法（5步）界初核目模 案例
  • 从组织目标→任务→数据→数据关系，从数据角度反推业务
  • 关键：建立"核心数据集"，输出"目标数据集"，实现稳定因素与不稳定因素分离
  • 5步循环：①确定目标与系统边界 → ②获取初始数据集（尽可能全） → ③建立核心数据集 → ④完善目标数据集 → ⑤建立信息模型
  • 核心数据集5审查：项主功任核 — 数据项审查 → 主题审查 → 功能审查 → 任务审查 → 核心数据集审查
  • 任一步骤可返回前面任一步骤，是循环过程
8.2.3 基于指标能力的方法（7步）决指体模融检评
  • 切入点：决策 → 指标 → 数据模型，反推出核心数据集，不需关心具体业务流程
  • 决策评估收集 → 支撑指标分析 → 指标体系构建 → 建立指标数据模型并分析数据集 → 数据子集融合 → 核心数据集一致性检验（去除同义不同名） → 核心数据集评价
  • 评价四维度：准平数利 — 准备级（规章制度/标准规范）→ 平台级（数据供与需载体）→ 数据级（数量/质量/标准/范围）→ 利用级（利用促进/成果产出）
8.3 数据架构 传统→现代 ▼
8.3.1 数据架构定义与目标
  • 构件：当前状态描述+数据需求定义+数据整合指引+数据资产管理规范
  • 必须包含：数据模型（结构+规范）和数据流设计
  • 五大职责：利用新兴技术→业务需求转数据需求→管理复杂数据→确保业务IT一致→支撑变革转型
8.3.2 数据模型（三层）概逻物
  • 概念模型 — 主题域模型组合，业务流程概念/实体
  • 逻辑模型 — 实体+属性+关系
  • 物理模型 — 数据表+字段+主键（机器语言）
  • 构建方法：自上而下（主题→下层）+ 自下而上（现有逻辑→抽象），两种方法结合最佳
  • 主题域识别准则：规范化规则（最有效）/系统组合分离/基于价值链/基于业务能力/基于数据治理结构
8.3.3 数据流设计
  • 数据流：数据在业务流程和系统中流动的过程 = 数据起源→存储→使用→转化（完整记录 = 数据血缘）
  • 表现形式：二维矩阵（多对多场景）+ 数据流图（直观，可扩展至业务属性级别）
8.3.4 演化驱动因素 技业法
  • 技术发展（大数据/云/AI）→ 业务量快速增长 → 业务需求变化 → 法律法规变化（隐私/保护）
8.3.5 传统数据架构
  • 集中式 — 中央数据仓库，数据集中存储/处理，安全性高，适用小型企业
  • 分布式 — 多节点存储，高可靠/可扩展/高效
    · 分布式数据库：DRDS/TiDB/GreenPlum — 计算层+元数据层+存储层
    · 分布式存储：HDFS/Swift/Ceph/GlusterFS
    · 分片(Sharding) = 大库分成多个独立实例 ↔ 分区(Partitioning) = 大表分成小块
    · 水平分区（按行）↔ 垂直分区（按列）
    · 副本一致性 = 整个分布式系统理论核心
⭐ CAP理论 已考 能选二不能全得
模型舍弃说明典型系统 CAP全在一个网络节点内单站点数据库、集群数据库、LDAP CPA保证一致性，牺牲可用性Redis（分布式缓存）、Zookeeper（协调中心） APC保证高可用，最终一致性(BASE)高并发系统（排队+乐观锁）

分布式系统P必选，只能在C和A之间取舍

8.3.6 现代数据架构
① 数据湖架构 高频
  • 特点：储存原始数据/无模式或灵活模式/可扩展/实时处理/海量处理/数据多样性
  • 组件：存储层(HDFS/S3)+管理工具(Spark/Hive/Flink)+治理(Atlas/Ranger)+查询(SQL/Athena)+可视化(Tableau/PowerBI)+流处理(Flink/SparkStreaming)+AI(TensorFlow/PyTorch)
  • 数据湖无治理 = 数据沼泽已考 — 导致数据质量/一致性/可靠性问题，引发错误决策
  • 治理四步：记录业务案例 → 获得高管支持 → 创建治理架构（团队+委员会） → 制定标准和政策
② 云原生数据架构
  • 云环境+容器化+微服务 → 高可扩展/高可用/高安全/高性能
  • 组件：容器编排+微服务框架+无服务器+多云管道+实时分析+大数据存储处理
③ 实时数据架构 接存计平应（五层） 高频
  • 接入层（Kafka收集binlog/日志）→ 存储层（Kafka/HDFS/Clickhouse/HBase/Redis）→ 计算层（Flink实时+Spark准实时+Presto/ClickHouse多维）→ 平台层（统一查询+元数据/指标管理+质量血缘）→ 应用层（大屏/OLAP/特征）
⭐ Lambda vs Kappa 已考
LambdaKappa 通道实时流 + 离线批（两条分支）全程流处理（消息队列替代） 三层批处理层 + 速度处理层 + 服务层单一流处理引擎 代码2套（批+流）1套（全量流）
④ 数据应用架构
  • 微服务 — 小型服务+独立进程+HTTP API通信，可单独开发部署，更快推向市场
  • 数据API — API连接数据与应用，Web API/RESTful/SOAP，无须了解存储实现细节
8.4 数据标准化 系元数码 ▼
四大内容概览 体系+元数据+数据元+分类编码
  • 数据标准体系 — 标准按其内在联系形成有机整体
  • 元数据标准化 — 数据外部特征统一规范描述
  • 数据元标准化 — 数据内部基本元素（名称/定义/表示）规范
  • 数据分类与编码标准化 — 统一分类编码，避免共享/交换困难
8.4.1 数据标准体系三类 指导·通用·专用
  • 1. 指导标准 — 标准体系及参考模型+标准化指南+概念与术语+一致性测试
  • 2. 通用标准（三类）：
    · 数据类 — 元数据标准+分类编码标准+数据内容标准（数据元+模式描述+交换格式+图示表达）
    · 服务类 — 数据发现/访问/表示/操作服务（发布/表达/交换/共享环节）
    · 管理与建设类 — 质量/发布/运行/安全/效益评价/验收/数据中心建设/门户建设规范
  • 3. 专用标准 — 特定领域：领域元数据/分类编码/数据模式/交换格式/数据元目录/图示表达
8.4.2 元数据标准化
  • 定义：关于数据的数据(Data about Data)，是数据与数据用户之间的桥梁
  • 三维结构：内容结构（元素及定义标准）+ 句法结构（XML DTD/Schema/RDF描述）+ 语义结构（ISO/IEC 11179描述方法）
⭐ 元数据五大作用 描定寻评选 重点
作用说明 描述对信息对象的内容描述，为存取利用奠定基础 定位确定数据对象位置，促进发现和检索 寻找/发掘抽出重要特征赋予语义建立关系，检索更精确 评价提供基本属性，不需浏览即可评估价值 选择参照评价标准结合环境做出选择决定
8.4.3 数据元标准化 重点
  • 定义：由一组属性规定其定义、标识、表示和允许值的数据单元（数据的基本单元）
  • 三部分组成：对象类+特性+表示 已考
  • 命名规则：语义规则（对象类+特性+表示各一个）+ 句法规则（对象类第一+特性第二+表示最后）+ 唯一性规则
  • 定义编写6规范：唯一性/准确不含糊/阐述基本含义/描述性短语/简练/能单独成立
  • 表示三要素：数据类型（存储方式）+ 数据表示（展现格式+单位）+ 值域（取值约束）
8.4.4 数据分类与编码标准化
  • 分类五原则：稳系可综兼 — 稳定性+系统性+可扩充性+综合实用性+兼容性
  • 编码四原则：唯匹扩简 — 唯一性+匹配性+可扩充性+简洁性
  • 编码原则之间有冲突（可扩充需要备用码 → 牺牲简洁性），需综合最优设计
8.5 数据管理 治理·质量·安全 ▼
8.5.1 数据治理 规略施嵌
  • 定义：管理数据资产过程中行使权力和管控（计划+监控+实施）
  • 治理 vs 管理：治理=监督（总体视角），管理=执行（执行层面），监督与执行分离
  • 目标：将数据作为资产进行管理，提供原则/制度/流程/框架/指标
  • 四活动：①规划组织的数据治理 → ②制定数据治理战略（章程+运营框架+路线图+运营计划） → ③实施数据治理 → ④（持续运作，接受、监控、测量）
8.5.2 数据质量 高略识评序标操
  • 定义：数据满足数据消费者应用需求目的的程度（取决于使用场景和消费者需求）
  • 五大质量维度：一完合唯效 — 一致性+完整性+合理性+唯一性+有效性
  • 改进三目标：开发受管理方法→定义质量控制标准规范→测量监控报告质量
⭐ 数据质量十大原则 重全预根治标客嵌系关 重点

数据质量八活动 定定识执优定开部
  • ① 定义高质量数据 → ② 定义数据质量战略 → ③ 识别关键数据和业务规则 → ④ 执行初始数据质量评估 → ⑤ 识别改进方向并确定优先排序 → ⑥ 定义数据质量改进目标 → ⑦ 开发和部署数据质量操作
8.5.3 数据安全 需制细评控
  • 定义：安全策略和过程的规划、建立与执行（身份验证+授权+访问+审计）
  • 五要求来源：利政业合合 — 利益相关方+政府法规+特定业务关注点+合法访问需求+合同义务
  • 六指导原则：协企主责元减 — 协同合作+企业统筹+主动管理+明确责任+元数据驱动+减少接触降风险
  • 五活动：①识别数据安全需求 → ②制定数据安全制度 → ③定义数据安全细则 → ④评估当前安全风险 → ⑤实施控制和规程（访问权限+角色+监控+分类+泄露处理）
