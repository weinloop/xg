9.1 概述 安全定义五大属性17种威胁7原则 ▼
信息安全的定义
  • 信息系统（硬件/软件/数据/人/物理环境/基础设施）受保护，不受偶然或恶意破坏/更改/泄露
  • 系统连续可靠运行，信息服务不中断，实现业务连续性
  • 还包括：防范商业机密泄露、防范青少年不良信息浏览、防范个人信息泄露
⚡ 五大基本属性 P0必背保密完可不可
属性含义关键词场景判断
保密性信息只为授权者享用，不泄露给未授权者不被看到数据加密、权限管理、防止信息泄露
完整性真实发信者→真实收信者，传输中不被添加/删除/替换不被篡改校验和、数字签名、防篡改
可用性信息和系统随时为授权者提供服务，不被不合理拒绝随时能用灾备、冗余、防DoS攻击
可控性管理者能对信息实施必要的控制管理，对抗犯罪和侵犯管理者管控内容审计、访问控制策略
不可否认性人要为信息行为负责，提供仲裁信息证据使用者负责数字签名、操作日志、审计追溯
🔑 易混区分：保密性=不被看到（泄露）｜完整性=不被改（篡改）｜可控性=管理者能管控｜不可否认性=使用者要负责
🔴 常见安全威胁 17种泄完拒非窃业假旁授特陷抵重病渎弃侵窃欺
  • 信息泄露 — 信息被泄露给非授权实体
  • 破坏完整性 — 数据被非授权增删/修改/破坏
  • 拒绝服务 — 合法访问被无条件阻止
  • 非法使用（非授权访问） — 非授权方式使用资源 易混
  • 窃听 — 搭线监听、电磁泄漏截取信息
  • 业务流分析 — 统计分析通信频率/流向/总量找规律
  • 假冒 — 冒充合法用户或提权用户
  • 旁路控制 — 利用安全缺陷获得非授权特权 易混
  • 授权侵犯 — 被授权但用于非授权目的（内部攻击）易混
  • 特洛伊木马 — 含察觉不出的恶意程序段
  • 陷阱门 — 特定输入触发违反安全策略
  • 抵赖 — 否认发布过的消息/伪造对方来信
  • 重放 — 截获合法通信数据重发 易混
  • 计算机病毒 — 传染+侵害功能程序
  • 人员渎职 — 为利益/粗心泄露信息
  • 媒体废弃 — 从废弃磁盘/存储介质获取信息
  • 物理侵入 — 绕过物理控制访问系统
🔑 易混区分：非法使用 vs 授权侵犯 → 前=非授权方式，后=被授权但滥用｜旁路控制 vs 陷阱门 → 前=利用已知缺陷绕过，后=特定输入触发｜重放 vs 抵赖 → 前=截获数据重发（技术），后=否认行为（人）
⚡ 七大规划原则 P1场景判断系适时确可易合
原则核心内容场景判断关键词
系统性整体全面体系化，横向到边纵向到底，兼顾当前与长远全局视角、不遗漏
适用性上承信息化保障、下启系统建设运维，与整体环境融合融入环境、衔接
时效性短期（方案性）/中长期（1-3年体系化）/远景（3年+战略）时间阶段、适时
确定性明确无歧义，明确主体和执行对象，不模棱两可表述清晰、不歧义
可行性具体可落地，与文化/管理/职责/流程不冲突能落地执行
易用性决策层抓要点、管理层抓要素、执行层流程清晰好用/可用/易用
合规性满足法律法规/国标/行业监管/内控，整合同类项满足法规、满足标准
🔑 易混区分：适用性 vs 可行性 → 前=能不能融入环境，后=能不能落地执行｜确定性 vs 合规性 → 前=表述明确不歧义，后=满足法规要求
四项注意事项 已考
  • 1.追求高效益的安全 — "有效益的安全"非"为安全而安全"；安全=价值/增值；信息安全减少损失=间接经济效益
  • 2.信息安全战略的校准 — 信息安全 ⊆ 信息系统安全；信息安全早于信息系统存在；信息安全战略与IT战略与组织战略保持一致 核心论断
  • 3.基于业务的风险理解 — 关键风险区域识别 + 风险偏好（不同情境表现不一致）
  • 4.识别出合规性要求 — 外部合规（法律/法规/监管）+ 内部合规（与内部制度一致）
🔑 核心论断：技术随着制度跑。信息系统=制度随技术跑；信息安全=技术随制度跑。IT系统只是实现管理要求的控制措施。
风险管理七过程 识分应监沟急审
  • 风险识别 → 风险分析 → 风险应对 → 风险监控 → 沟通与培训 → 应急准备 → 审计与改进

9.3 信息安全规划的主要内容 五大板块组织/管理/技术/运营 ▼
9.3.1 利益相关方安全诉求
  • 内部：不同部门/层级/业务对象；外部：监管单位/客户/用户/公众
  • 不同视角的诉求可能相互竞争；识别隐性/口是心非的诉求至关重要
  • 成功的关键：一件事的成功是众多人的合力
9.3.2 信息安全组织体系规划 四要素最协内外
组成内容
最高管理层治理者+执行管理者，决策规划层
协调机构最高管理层+各部门负责人，统筹协调
内部组织主管部门+配合部门，可新增信息安全部门或指定IT部门
外部联系消防部门/安全专业组织/政府/地方监管部门，获取资讯
🔑 核心观点：技术只能有限提高战斗力，组织形式才是基础。同样一群人，组织形式不同，绩效差异可能极大。
9.3.3 信息安全管理体系规划 P0
  • 系统化/程序化/文件化；基于风险评估；预防控制为主；全过程动态控制
ISO 27001 vs 等保
  • ISO 27001：着眼于整体业务风险，通过风险评估建立/实施/运行/监视/评审/保持/改进ISMS
  • ISO 27002：配合27001使用，提供安全控制目标和措施
  • 等保：对国家秘密/专有/公开信息分等级保护，产品按等级管理，事件分等级响应
⚡ 等保五级 — 影响递进关系 P0必背
等级名称公民/法人/组织社会秩序/公共利益国家安全

第二级指导保护级严重损害损害—
第三级监督保护级特别严重损害严重损害损害
第四级强制保护级—特别严重损害严重损害
第五级专控保护级——特别严重损害
⚡ 等保基本框架 P0必背 已考
  • "一个中心三重防御"：安全管理中心 + 安全计算环境 / 安全区域边界 / 安全网络通信
  • 等保2.0强化可信计算安全技术要求
  • 管理要求：安全管理制度/机构/人员/建设管理/运维管理
  • 技术要求：安全物理环境/网络通信/区域边界/计算环境/安全管理中心
等保实施方法6步 定分系风改实
  • 安全定级 → 基本安全要求分析 → 系统特定安全要求分析 → 风险评估 → 改进和选择安全措施 → 实施安全保护
9.3.4 信息安全技术体系规划 P1身访入侵防火墙，网防加密七件套
技术类别核心内容与考察重点
1.身份认证10种措施：VIEID/静态密码/智能卡/短信密码/动态口令/USB Key（冲击响应+PKI）/生物识别（身体+行为）/双因素/Infogo/虹膜。what you have / who you are 方法区分
2.访问控制P0必背4种机制：DAC(所有者定义)/RBAC(角色权限)/Rule-BAC(规则条件)/MAC(安全标签) 已考
3.入侵检测实时入侵检测（在线判断）vs 事后入侵检测（定期分析）。已纳入等保和安全测评范畴
4.防火墙内网/外网之间保护屏障，4组成部分：服务访问规则/验证工具/包过滤/应用网关
5.网闸网络隔离技术，两套独立系统间信息摆渡，无直接物理通路；分时使用数据通路，交换时防病毒/恶意代码过滤
6.防病毒6条防护准则：拒绝访问能力/病毒检测(含未知)/控制传播/清除/恢复/替代操作
7.数据加密对称加密(同密钥，快但难分发) vs 非对称加密(公私钥，慢但易管理)；链路加密/节点加密/端到端加密
🔑 易混区分：RBAC vs Rule-BAC → 前=基于角色身份，后=基于规则条件｜DAC vs MAC → 前=所有者自主决定，后=系统强制标签管控｜对称 vs 非对称 → 前=同密钥快但分发难，后=公私钥慢但管理简单
9.3.5 信息安全运营体系规划 P1知权分双转假特
方法核心定义关键区别
因需可知仅授予执行工作所需数据的访问权限我能看什么（数据范围）
最小特权仅授予执行工作所需的特权（读+写+创建+改+删）我能做什么（操作权限）
职责分离确保无人可单独控制关键功能，需两人以上串通才行制衡系统，预防欺诈
双人控制两人批准后才能执行关键任务同行评审，减少串通欺诈
岗位轮换计划性轮岗，交叉培训，减少对个体的依赖检测+威慑，接管可发现欺诈 易混
强制休假突然实施，强制休假1-2周接管岗位可发现欺诈 易混
特权账户管理限制管理员账户，检测提升特权行为长期持续检测监控
🔑 易混区分：岗位轮换 vs 强制休假 → 前=计划性轮岗，后=突然强制｜因需可知 vs 最小特权 → 前=我能看什么（数据范围），后=我能做什么（操作权限）
安全培训四方面 + 应急响应五步
  • 培训四方面：基础知识培训 / 操作规范培训 / 模拟演练培训 / 持续宣传教育
  • 应急响应五步：制定应急策略 → 建立紧急联系渠道 → 制定应急响应流程 → 进行应急演练 → 应急响应报告和记录
  • 事后总结改进五步：收集数据信息 → 分析和评估 → 制定改进措施 → 实施改进措施 → 监控评估改进效果
