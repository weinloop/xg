# 第11章 信息系统治理

> IT治理是组织开展信息技术活动的重要管控手段，IT审计是其不可或缺的评估和监督工具。

---

## 11.1 IT治理

### 11.1.1 IT治理基础

#### 1. IT治理定义

IT治理是描述组织采用有效的机制对信息技术和数据资源开发利用，平衡信息化发展和数字化转型过程中的风险，确保实现组织战略目标的过程。

#### 2. IT治理的驱动因素

高质量IT治理的驱动因素（8条）：
1. 确保组织IT投资的有效性
2. IT属于知识高度密集型领域，价值发挥弹性大
3. IT已融入组织管理、运行、生产和交付等各领域
4. 信息技术的发展演进及新兴技术可为组织提供新发展空间
5. IT治理推动组织充分理解IT价值，促进价值挖掘
6. IT价值取决于好的技术 + 良好的价值管理 + 场景化融合应用
7. 高级管理层管理幅度有限，需明确责权和清晰管理
8. 成熟度较高的组织以不同方式治理IT，获得领先效果

**速记口诀：投密融演进，价值场景高成熟**

#### 3. IT治理的内涵（5个方面）

| 序号 | 内涵 |
|------|------|
| ① | 作为组织上层管理的有机组成部分，由治理层或高级管理层负责 |
| ② | 强调数字目标与组织战略目标一致，为战略规划提供技术或控制支持 |
| ③ | 保护利益相关者权益，有效管理风险，合理利用IT资源，平衡成本收益 |
| ④ | 是一种制度和机制，涉及管理与制衡IT与业务匹配/投资/安全/绩效等 |
| ⑤ | 组成部分包括管理层、组织结构、制度、流程、人员、技术等 |

**速记口诀：上层全局、战略一致、利益风险、制度机制、多面架构**

#### 4. IT治理的主要目标（3个）

| 目标 | 说明 |
|------|------|
| 与业务目标一致 | 从组织目标和数字战略中抽取需求，形成总体IT治理框架 |
| 有效利用信息与数据资源 | 对信息数据资源管理职责进行有效管理，保证投资回收并支持决策 |
| 风险管理 | 制定保护机制，实施有效监控和事件处理 |

**速记口诀：一致利用风险**

#### 5. IT治理的管理层次（3层）

| 层次 | 主要职责 |
|------|----------|
| **最高管理层** | 证实IT战略与业务一致；指导IT战略、平衡投资；指导信息资源分配 |
| **执行管理层** | 制定IT目标；分析新技术机遇和风险；建设关键过程与核心竞争力；分配责任、定义规程、衡量业绩；管理风险和获得可靠保证 |
| **业务与服务执行层** | 信息数据服务的提供和支持；IT基础设施建设维护；IT需求的提出和响应 |

**速记口诀：高证指分，执目新过责险，业服基建需求**

### 11.1.2 IT治理体系

IT治理体系构成：①IT定位（期望行为与业务目标一致）；②IT治理架构（IT权责边界等）；③IT治理内容（决策、投资、风险、绩效、管理）；④IT治理流程（统筹、评估、指导、监督）；⑤IT治理效果（内外评价）。

**速记口诀：定位架构内容，流程效果五维**

#### 1. IT治理关键决策（5项）

| 关键决策 | 关键问题 |
|----------|----------|
| **IT原则** | 组织运行模型？IT角色？IT期望行为？如何投资IT？ |
| **IT架构** | 核心业务流程？关系？哪些信息驱动核心流程？数据如何整合？ |
| **IT基础设施** | 哪些基础设施最关键？哪些应在组织级实现？服务水平需求？定价？外包？ |
| **业务应用需求** | 新业务机会？如何设计实验评估？何时从例外转为标准？ |
| **IT投资和优先顺序** | 哪些变革最重要？投资组合如何分配？与战略一致吗？ |

> 💡 IT原则驱动IT架构，架构决定基础设施，基础设施能力决定业务应用，投资和优先顺序为前四者驱动。

**速记口诀：原架基需投，五决驱动链**

#### 2. IT治理体系框架（6部分）

| 组成部分 | 说明 |
|----------|------|
| **IT战略目标** | 为实现IT价值和目标，使组织从IT投入获得最大收益 |
| **IT治理组织** | 界定治理范围、责权划分及相互关系，核心是治理机构设置和权限划分 |
| **IT治理机制** | 决策机制、执行机制、风险控制机制、协调机制的综合体 |
| **IT治理域** | 在IT治理规则下，对组织IT资源进行整合与配置 |
| **IT治理标准** | 包括基本规范、实施参照、评价体系和审计方法等 |
| **IT绩效目标** | 关注IT价值实现，评价IT规划与构建是否满足业务需求 |

**速记口诀：标组机域准绩，六部闭环**

#### 3. IT治理核心内容（6个方面）

| 核心内容 | 说明 |
|----------|------|
| **组织职责** | 明确信息部门和业务部门的关系和责任，划分所有者/建设者/管理者/监控者 |
| **战略匹配** | 使IT建设与组织战略相匹配，是IT贡献业务价值的重要驱动力 |
| **资源管理** | 确保用户对应用系统和基础设施有良好理解和应用，优化IT投资和资源分配 |
| **价值交付** | 对IT项目全生命周期管理，确保按组织战略实现预期业务价值（创造业务价值） |
| **风险管理** | 确保IT资产安全、灾难恢复、信息资源安全、人员隐私安全（保护业务价值） |
| **绩效管理** | 追踪和监视IT战略、项目实施、信息资源使用、IT服务提供、业务流程绩效 |

**速记口诀：组战资价风绩**

#### 4. IT治理机制经验

建立IT治理机制三原则：**简单**（明确定义责任和目标）、**透明**（依赖于正式程序）、**适合**（鼓励处于最佳位置的人制定决策）。

十种影响力高的IT治理机制：执行层和高级管理委员会、架构委员会、有IT人员参与的流程团队、资金投资批准和预算、服务水平协议、费用分摊机制、IT业务价值的正式衡量追踪。

最佳实践经验：IT指导委员会吸纳业务经理、谨慎管理IT架构和业务架构、设计严格的架构例外处理流程、建立集中化IT团队、连接IT投资和业务需求的流程、集中协作和核准的IT投资流程、费用分摊和服务水平协议机制。

**速记口诀：简单透明适合，导委架构流程投资**

### 11.1.3 IT治理任务

IT治理活动定义为：**统筹、评估、指导、监督**。

**五大主要任务**：

| 任务 | 核心要点 |
|------|----------|
| **全局统筹** | 统筹规划目标范围、技术环境、发展趋势和人员责权；制定可持续IT蓝图；建立持续改进和创新机制 |
| **价值导向** | 建立IT投资价值框架；确保符合组织治理价值导向；权衡实施成本与预期效益并随环境变化调整 |
| **机制保障** | 建立适合组织的机制保障方法；指导规范过程管理和痕迹管理；评审管理体系适宜性/充分性/有效性；审计完整性/有效性/合规性 |
| **创新发展** | 利用IT创新开拓业务、提升管理、改进质量、降低成本；建立围绕知识资产的创新体系；创造技术创新环境 |
| **文化助推** | 营造积极向上、沟通包容的组织文化；建立与IT发展相适应的组织文化发展策略；评估改进文化管理 |

**速记口诀：统价机创文**

### 11.1.4 IT治理方法与标准

#### 1. ITSS-IT治理系列标准（我国）

**GB/T 34960.1《通用要求》**：
- IT治理模型：包含治理的内外部要求、治理主体、治理方法、信息技术管理体系
- IT治理框架三大治理域：**顶层设计**（战略/组织/架构）、**管理体系**（质量/项目/投资/服务/业务连续性/信息安全/风险/供方/资产/其他管理）、**资源**（基础设施/应用系统/数据）

**GB/T 34960.2《实施指南》**：
- 实施环境：组织内外部环境和促成因素
- 实施过程：统筹和规划 → 构建和运行 → 监督和评估 → 改进和优化
- 治理域：顶层设计、管理体系、资源

**速记口诀：通用要求定框架，实施指南四步走，顶层管理资源三域**

#### 2. COBIT框架

COBIT由ISACA组织设计，区分**治理**（评估/指导/监控 EDM）和**管理**（APO/BAI/DSS/MEA）。

| 领域 | 全称 | 说明 |
|------|------|------|
| EDM | 评估、指导和监控 | 治理目标，治理机构评估战略方案、指导执行、监督实施 |
| APO | 调整、规划和组织 | 针对IT的整体组织、战略和支持活动 |
| BAI | 内部构建、外部采购和实施 | 针对IT解决方案的定义、采购、实施及业务流程整合 |
| DSS | 交付、服务和支持 | 针对IT服务的运营交付和支持，包括安全 |
| MEA | 监控、评价和评估 | 针对IT性能监控及其与目标/合规的一致程度 |

COBIT治理系统组件（7个）：流程、组织结构、原则政策和程序、信息、文化道德和行为、人员技能和胜任能力、服务基础设施和应用程序。

COBIT设计因素（11个）：组织战略、组织目标、风险概况、IT相关问题、威胁环境、合规性要求、IT角色、IT采购模式、IT实施方法、技术采用战略、组织规模、未来因素。

COBIT设计流程（4步）：了解组织环境和战略 → 确定治理系统初步范围 → 优化治理系统范围 → 最终确定治理系统设计。

**速记口诀：EDM治理APO组织，BAI构建DSS交付，MEA监控五域全；七组件十一因素四步设计**

#### 3. ISO/IEC 38500国际标准

**六大指导原则**：

| 原则 | 说明 |
|------|------|
| **责任** | 个人和团体理解并接受在IT供应和需求方面的责任 |
| **战略** | 业务战略考虑IT当前和未来能力；IT计划满足业务战略需求 |
| **收购** | IT收购基于正当理由和透明决策，在利益/机会/成本/风险间平衡 |
| **性能** | IT支持组织，提供满足当前和未来业务需求的服务和服务水平 |
| **一致性** | IT使用符合所有强制性法律和法规，政策和实践有明确定义 |
| **人的行为** | IT政策、实践和决策尊重人的行为，包括所有"过程中的人"的需求 |

治理机构通过**评估、指导和监督**三个主要任务治理IT。

**速记口诀：责战收性，一行为**

## 11.2 IT审计

### 11.2.1 IT审计基础

#### 1. IT审计定义

IT审计是根据IT审计标准的要求，对信息系统及相关的IT内部控制和流程进行检查、评价，并发表审计意见（GB/T 34690.4）。

**主流定义**（ISACA）：IT审计是一个获取并评价证据，以判断计算机系统是否能够保证资产安全、数据完整以及有效利用组织资源并有效实现组织目标的过程。

#### 2. IT审计目的

- 了解组织IT系统与IT活动的总体状况
- 对组织是否实现IT目标进行审查和评价
- 充分识别与评估相关IT风险
- 提出评价意见及改进建议
- 促进组织实现IT目标

**组织IT目标（4个）**：①IT战略与业务战略保持一致；②保护信息资产安全及数据完整可靠有效；③提高信息系统安全性可靠性及有效性；④合理保证信息系统符合法律/法规/标准要求。

**速记口诀：了解审查识别，建议促进**

#### 3. IT审计范围

| 范围类型 | 说明 |
|----------|------|
| 总体范围 | 根据审计目的和投入的审计成本确定 |
| 组织范围 | 明确涉及的组织机构、主要流程、活动及人员 |
| 物理范围 | 具体的物理地点与边界 |
| 逻辑范围 | 涉及的信息系统和逻辑边界 |

#### 4. IT审计人员要求

| 分类 | 具体要求 |
|------|----------|
| 职业道德 | 独立客观公正、正直诚实守信、正确履行审计职责、对信息保密 |
| 知识技能资格经验 | 掌握IT专业知识、审计/财务/管理通用知识、基本/专业/软技能 |
| 专业胜任能力 | 拥有与岗位相适应的IT审计职业资格及经验、定期参加持续职业教育和培训 |
| 利用外部专家 | 评价专家资格/独立性/客观性/胜任能力、签订书面协议、评价和利用服务结果 |

**速记口诀：德知胜专，四维要求**

#### 5. IT审计风险

| 风险类别 | 说明 |
|----------|------|
| **固有风险** | IT活动本身所具有，审计人员只能评估无法控制或影响（可从组织层面/一般控制/应用控制三方面分析） |
| **控制风险** | 与IT活动相关的内控体系不能及时预防或检查出重大错误的风险（与内控制度执行有效性有关） |
| **检查风险** | 预定审计程序未能发现重大错误的风险（受IT审计规范不完善/审计人员或技术原因影响） |

总体审计风险 = 针对单个控制目标所产生的各类审计风险总和

**速记口诀：固控检，总汇合**

### 11.2.2 IT审计方法与技术

#### 1. IT审计依据与准则

| 国际 | 国内 |
|------|------|
| ISACA信息系统审计准则 | 《中华人民共和国审计法》 |
| COSO内部控制整体框架 | 《中华人民共和国网络安全法》 |
| SOX萨班斯法案 | GB/T 34960.4《审计导则》 |
| COBIT信息及相关技术控制规范 | 行业规范（商业银行/证券期货/保险等） |

#### 2. IT审计常用方法（6种）

| 方法 | 说明 |
|------|------|
| **访谈法** | 面对面交谈了解被审计对象信息；分结构型和非结构型访谈 |
| **调查法** | 通过书面或口头回答方式收集资料并分析综合得出结论 |
| **检查法** | 对被审计单位内外部生成的记录和文件或资产进行实物审查（审阅/核对/复算/分析） |
| **观察法** | 到经营场所实地察看证实审计事项，可用于补充证实或直接收集证据 |
| **测试法** | 从输入跟踪到输出检验程序可靠性（黑盒法/白盒法） |
| **程序代码检查法** | 对被审程序指令逐条审查，验证合法性/完整性和逻辑正确性 |

**速记口诀：访调检观测码**

#### 3. IT审计技术（4种）

| 技术 | 说明 |
|------|------|
| **风险评估技术** | 风险识别（德尔菲法/头脑风暴/检查表/SWOT/图解技术） → 风险分析（定性/定量） → 风险评价（单因素/总体） → 风险应对（云计算/冗余/弹性伸缩/灾备/熔断限流等） |
| **审计抽样技术** | 统计抽样（属性抽样"有多少"、变量抽样金额估计） vs 非统计抽样（判断抽样） |
| **计算机辅助审计技术** | CAAT，利用计算机执行审计程序和任务（通用审计软件GAS/测试数据/实用工具/专家系统等） |
| **大数据审计技术** | 智能分析（机器学习/数据挖掘）、可视化分析（R/Python/D3.js）、多数据源综合分析 |

**速记口诀：风险抽样CAAT，大数据四技术**

#### 4. IT审计证据

审计证据是形成审计结论的基础。**五大特性**：

| 特性 | 说明 |
|------|------|
| **充分性** | 对证据数量的要求，与样本量有关 |
| **客观性** | 客观事实材料比需要判断或解释的证据可靠 |
| **相关性** | 证据与审计事项之间必须有实质性联系 |
| **可靠性** | 受证据类型、取证渠道和方式等因素影响 |
| **合法性** | 必须符合法定种类并依照法定程序取得 |

**电子证据**：以电子/数据/磁性形式存在并能证明事件事实的材料，在收集/提取/保存/出示/审查/判断/认证各环节均需高技术规范。

**速记口诀：充客相可法**

#### 5. IT审计底稿

审计工作底稿是审计证据的载体，形成于审计过程也反映整个审计过程。

**三类底稿**：
- **综合类**：审计计划阶段和报告阶段的底稿（审计业务约定书/审计计划/审计总结/审计报告等）
- **业务类**：审计实施阶段执行具体程序形成的底稿（内控问题调查表/流程图/项目明细表等）
- **备查类**：仅具备查作用的底稿（随情况变化更新，注明来源）

编制要求：**内容**（资料翔实/重点突出/繁简得当/结论明确）+ **形式**（要素齐全/格式规范/标识一致/记录清晰）

**三级复核制度**：审计机构负责人 → 部门负责人 → 项目负责人

**速记口诀：综业备三类，内容翔重简明，形式全规范清；三级复核**

### 11.2.3 IT审计流程

广义审计流程分为4个阶段：

| 阶段 | 主要工作 |
|------|----------|
| **审计准备阶段** | ①明确审计目的及任务；②组建审计项目组；③搜集相关信息；④编制审计计划 |
| **审计实施阶段** | ①深入调查并调整审计计划；②了解并初步评估IT内部控制；③进行符合性测试；④进行实质性测试 |
| **审计终结阶段** | ①整理与复核审计工作底稿；②整理审计证据；③评价相关IT控制目标实现；④判断并报告审计发现；⑤沟通审计结果；⑥出具审计报告；⑦归档管理 |
| **后续审计阶段** | 检查被审计单位对审计问题和建议是否采取适当纠正措施并取得预期效果（是前一次审计的有机组成部分） |

**速记口诀：准备组建搜集编制，实施调查评估测试，终结整证评报归，后续跟踪**

### 11.2.4 IT审计内容

| 大类 | 子类 | 审计内容 |
|------|------|----------|
| **IT内部控制审计** | 组织层面IT控制审计 | IT战略/组织/架构/业务连续性/风险管理/外包管理/网络信息安全/监督管理 |
| | IT一般控制审计 | 与应用系统/数据库/操作系统/网络相关的策略和措施 |
| | 应用控制审计 | 业务流程层面运行的人工或自动化程序（输入控制/处理控制/输出控制） |
| **IT专项审计** | 信息系统生命周期审计 | 规划/设计/开发/测试/运行和维护 |
| | 信息系统开发过程审计 | 信息系统规划/设计/建设/实施是否符合IT架构和战略 |
| | 信息系统运行维护审计 | IT运维能力/运维流程策划实施监控改进（基础设施/系统运维/质量保证/IT服务管理） |
| | 网络与信息安全审计 | 以安全为核心，围绕安全相关的组织/人员/系统/设备和环境 |
| | 信息系统项目审计 | 对项目管理过程进行评价，向管理层提供合理保证 |
| | 数据审计 | 分析/验证/讨论/改进数据安全管理相关政策标准和活动 |

**信息系统项目管理审计内容**（按项目阶段）：组织管理、项目启动与计划、项目实施与控制、项目收尾管理、技术方案设计开发方法

**速记口诀：内控三层组般应，专项六类生开运网项数**
