# 第15章 技术与研发管理

> 技术与研发管理是信息系统规划与管理的核心能力之一，涵盖技术研发管理、技术研发应用和知识产权管理的全生命周期。

---

## 15.1 技术研发管理

### 技术研发定义与目的

**技术研发定义**：为了有效实施信息系统的运行维护服务，建立、提升组织的核心能力，投入专门的人力、财力、环境等资源，研究和开发与系统运维服务有关的各种方法、工具和手段的活动。

**技术三大特征**：目的性（贯穿技术活动全过程）、社会性（需社会协作和支持）、多元性（有形硬件/无形知识软件/物质载体信息资料）

**技术研发两大目的**：
1. 通过使用研发成果提高系统服务效率和服务质量
2. 通过对组织信息系统相关技术和行业新技术的研究，将其应用到服务产品和服务工具中，丰富和拓展服务范围

**技术研发管理目的**：进行技术创新，提升组织系统服务能力

### 15.1.1 目标和范围

#### 技术研发的五大范围

| 序号 | 范围 | 说明 |
|------|------|------|
| 1 | 与系统运行相关的技术研发 | IT服务对象本身技术（基础环境/服务器网络存储/系统软件/新技术研究应用） |
| 2 | 技术规范的研发 | 服务规范（质量标准）+ 服务提供规范（操作规程/技术操作手册） |
| 3 | 发现问题和解决问题相关技术研发 | 监控诊断分析技术 + 问题处理操作手册/测试环境/工具/脚本 |
| 4 | 运行维护工具研发 | 监控工具、过程管理工具、专用工具 |
| 5 | IT服务产品研发 | 服务有形化、标准化的设计过程，融入核心能力和独特设计 |

#### 技术研发管理对象（6个方面）

| 管理对象 | 核心内容 |
|----------|----------|
| 研发团队 | 不仅是研发部门，还包括质量、营销、生产、采购、人力资源等部门 |
| 研发过程 | 将常规环节程序化、制度化，考虑多项目资源占用的标准化 |
| 研发成本 | 减少不必要开支，用较少投入获取较大成果（非压缩规模或减少投资） |
| 研发项目 | 研发以项目为导向，项目管理不可或缺 |
| 研发绩效 | 评价指标：难度、效率、质量；可用平衡计分卡制定评估系统 |
| 研发风险 | 人员离职风险、信息泄露风险、灾难意外或恶意攻击风险 |

**速记口诀：五范围运规问工具产品，六对象团队过程成本项目绩效风险**

### 15.1.2 组织架构

技术研发管理的核心角色：

| 角色 | 职责 | 常见岗位 |
|------|------|----------|
| 技术研发决策负责人 | 总体决策，负责技术规划、实施、应用和改进 | IT服务主管/副主管/主管技术负责人 |
| 技术研发需求负责人 | 需求调研、成果应用验收，配合立项和详细需求设计 | IT服务部门负责人/技术部负责人 |
| 技术研发负责人 | 技术研发规划、过程组织、应用支持 | 技术总监/研发部负责人/技术主要负责人 |
| 质量管理负责人 | 质量体系建设、实施、检查、改进，参与研发管理体系建设 | 质量管理部经理 |

**其他角色**：财务负责人 — 负责审查投入产出比、筹措研发费用、度量研发成果财务回报

### 15.1.3 管理过程

技术研发管理四大过程：

| 过程 | 核心内容 | 主要工作 |
|------|----------|----------|
| 规划过程 | 确定研发目标，制定方案，分析可行性 | 需求调研→确定目标→制定方案→投入产出分析→立项报告→规划评审发布 |
| 实施过程 | 制订实施计划，组织实施，产出研发成果 | 确定任务、时间进度、责任人、阶段里程碑（做什么/何时做/谁做/如何做） |
| 监控过程 | 组织层面监控质量、成本和进度 | 项目周报、月度报告、里程碑总结、质量审计、内审和管理评审 |
| 应用过程 | 研发成果推广运用到IT服务中 | 从研发部门转移到使用部门，提高人员素质/技能/服务效率 |

**研发成果应用本质**：将潜在生产力通过提高人的素质、改善生产工具和劳动对象来实现

**速记口诀：规划实施监控应用，四环闭合出成果**

### 15.1.4 管理要点

#### 技术研发管理三方面条件

1. **鼓励创新的环境** — 弹性而目标化的管理，不以死板制度限制创意，要求实质成果
2. **市场观念融入研发** — 让市场人员参与研发过程，成果才具有更高价值
3. **研发策略制定与掌握** — 有限资源善加规划运用，最短时间达到最高效益

#### 五类研发管理

**1. 服务产品研发管理**

| 要素 | 内容 |
|------|------|
| 定位 | 提供需方愿意购买的服务产品（需求来源：需方需求+供方业务拓展需求） |
| 队伍 | 虚拟团队（市场/售前/服务交付/质量管理），设产品经理负责 |
| 成果 | 服务目录、服务交付方式、服务质量管理 |

**2. IT服务规范研发管理**

| 要素 | 内容 |
|------|------|
| 定位 | IT服务规范化是服务产品化的前提条件 |
| 队伍 | 质量管理负责人+资深技术专家+资深需方服务经理 |
| 过程 | 编写规范→测试演练定稿→评审组评审→服务交付执行→质量监督 |
| 环境 | 过程规范需个人电脑+办公软件；技术规范需实验环境 |
| 产出物 | IT服务工作指南、过程管理规范、技术手册、故障处理手册 |

**3. 服务工具研发管理**

| 要素 | 内容 |
|------|------|
| 定位 | 两类：面向内部的过程管理工具+面向业务的监控工具和专用工具 |
| 队伍 | 过程管理工具：交付管理人员+软件人员；监控/专用工具：交付技术人员+软件开发人员 |
| 过程 | 参考软件研发过程：需求→设计→编码→测试 |
| 环境 | 开发环境+测试环境 |
| 产出物 | 发布包/使用手册、介绍文档、需求/设计文档和源代码 |

**4. 发现问题和解决问题相关技术研发管理**

| 要素 | 内容 |
|------|------|
| 定位 | 发现问题：信息采集监控手段+诊断分析方法；解决问题：解决方法手段+判断方法 |
| 队伍 | 高级运维工程师+技术专家 |
| 过程 | 工具类按服务工具研发过程；手册类按编写→测试→评审→发布执行→质量监督 |
| 产出物 | 诊断分析软硬件工具、故障分析文档、作业指导书、知识案例库、操作手册 |

**5. 新技术研究管理**

| 要素 | 内容 |
|------|------|
| 定位 | 两类：支撑需方业务的新技术+支撑IT服务的新技术 |
| 队伍 | 资深技术专家 |
| 过程 | 跟踪研究→应用前景分析和知识积累→内部知识传递 |
| 环境 | 实验环境（硬件+软件） |
| 产出物 | 应用前景分析报告、技术文档、培训教材 |

**速记口诀：产品规范工具问题新技术，五类研发各有道**

## 15.2 技术研发应用

IT技术的应用需要经过科学的管理，方可使其发挥最大的作用。应设立专门的部门或岗位负责技术应用与推广管理。

### 15.2.1 管理要点

技术应用推广的六个管理要点：

| 序号 | 管理要点 | 核心内容 |
|------|----------|----------|
| 1 | 技术风险与机遇 | 分析引进与创新风险并控制；分析潜在影响因素（有利与不利）；不利因素纳入风险管理 |
| 2 | 判断与选择 | 科学方法判断应用效果；结构化分析有利不利因素；识别困难并分析资源可行性 |
| 3 | 技术验证 | 性价比较高、风险较大的技术应验证；必要时开发技术原型验证效果 |
| 4 | 技术决策 | 技术方向选择、相关技术选择、工具技术选择、技术可行性分析 |
| 5 | 技术应用 | 传递给人员转变成服务能力；转变成服务工具；作为服务一部分交付客户；创新服务；知识化文档化 |
| 6 | 技术实现跟踪管理 | 定期评估技术实现状态；跟踪评估发现不适用的及时终止；对创新失败妥善处理；分级管理确定负责人 |

**技术应用推广流程**：技术评定报告 → 审批 → 测试 → 验收报告 → 推广

### 15.2.2 主要应用

IT服务过程中技术成果的八个主要应用方面：

#### 1. 知识转移

知识转移是技术部署实施的重要环节，内容包括四大类资料：

| 资料类别 | 具体内容 |
|----------|----------|
| 历史运维资料 | 工作界面和人员职责说明书、内外部支持信息 |
| 基础架构资料 | 系统部署和网络拓扑、架构说明/软硬件配置、备份恢复说明书、应急容灾方案、日常运维操作手册 |
| 应用系统资料 | 测试报告、使用手册、需求设计文档、安装配置手册、应用版本说明 |
| 业务资料 | 业务架构图、业务流程、业务场景说明、业务培训资料、业务运维文档 |

#### 2. 应急响应预案的制定与演练

**应急预案适用情形**（7类）：
1. 自然灾害引起的灾难性破坏
2. 网络通信设备/线路故障导致重大故障
3. 电源电路/机房基础设施故障
4. 数据库/系统存储/中间件故障导致重大系统性故障
5. 网络攻击破坏/病毒传播/违法犯罪活动引发安全突发事件
6. 应用系统发生重大故障
7. 组织认为应采取应急机制的其他重大突发事件

**应急演练四原则**：结合实际合理定位、着眼实战讲求实效、精心组织确保安全、统筹规划厉行节约

#### 3. SOP标准操作规范

**SOP定义**：将某一事件的标准操作步骤和要求以统一格式描述出来，用来指导和规范日常工作。精髓是将细节进行量化，对关键控制点进行细化和量化。

**SOP五大作用**：
1. 将技术经验记录在标准文件中，防止技术人员流动导致技术流失
2. 使操作人员经短期培训快速掌握先进合理的操作技术
3. 树立良好服务形象，取得客户信赖与满意
4. 实现服务管理规范化、流程条理化、标准化、操作形象化简单化
5. 是系统规划与管理师最基本、最有效的技术管理手段

**SOP编写五原则**：资源允许范围内可做到、所有人都能看懂且理解相同、效率最高成本最低并识别关键风险点、发布前经过测试与评价、可根据需求快速迭代

#### 4. 技术手册发布

**发布流程**：审核（验证可行性后存档）→ 存档（分级管理便于快速定位）→ 发放（通知查看、组织培训讲解、确保按手册操作）

#### 5. 搭建测试环境

依据规划设计要求建立测试目标，运用模拟工具模拟真实场景，验证技术可行性和可靠性，规避IT服务潜在缺陷，减少突发事件发生率。

#### 6. 对技术成果进行培训与知识转移

| 培训类别 | 内容 |
|----------|------|
| 知识性研发成果培训 | 方法论框架（鱼骨图法、KT分析法等） |
| 工具类研发成果培训 | 监控或IT服务流程管理工具的功能培训 |
| 应急预案与解决方案知识转移 | 根据不同岗位和工作范围进行知识转移 |

#### 7. 对技术成果进行演练或推演

| 方式 | 说明 |
|------|------|
| 演练 | 定期对应急预案、灾备方案进行仿真演习，必要时所有相关方参加，投入充足资源 |
| 推演 | 通过沙盘或模拟方式研讨可能发生的情况，圆桌会议给予改进建议与评价 |

**演练计划模板要素**：概述（目的/地点/时间/内容/类型）、演练场景、参加人员（内部+外部支持）、过程记录（步骤/操作内容/操作人/计划时间）、结果记录、问题总结、改进行动、演练结论

#### 8. 对技术成果进行优化改进

对技术成果进行评价与评估，根据分析或实践信息进行新一轮开发，并增加相应预算。

**速记口诀：知识转移应急SOP，手册测试培训演练优化**

## 15.3 知识产权管理

**知识产权定义**：在科学技术、文学艺术等领域中，发明者、创造者等对自己的创造性劳动成果依法享有的专有权。

**知识产权范围**：专利、商标、著作权及相关权、集成电路布图设计、地理标志、植物新品种、商业秘密、传统知识、遗传资源、民间文艺等。

### 15.3.1 目标和范围

**知识产权四种主要形式**：

| 形式 | 定义 |
|------|------|
| 专利权 | 对发明的一种技术解决方案所享有的专有权利 |
| 商标权 | 商标所有人对其商标使用和保护的专有权利 |
| 著作权 | 作品的作者对其作品使用和保护的专有权利 |
| 商业秘密 | 组织所拥有的商业信息和技术信息 |

**知识产权管理四大需求**：研发新技术新产品新工艺、提高产品附加值扩大市场份额、防范知识产权风险保障经营安全、提高生产经营效率增加经济效益

### 15.3.2 管理职责

**知识产权管理四项指导原则**：

| 原则 | 内容 |
|------|------|
| 战略导向 | 统一部署经营发展、创新创造和知识产权战略，三者互相支撑促进 |
| 领导重视 | 最高管理者支持和参与是关键，全面负责确保合规义务履行 |
| 全员参与 | 涉及各业务领域和各业务环节，所有人员都应遵守合规义务 |
| 全程管理 | 在产品/服务全生命周期开展知识产权管理，全过程履行合规义务 |

**最高管理者职责**：确保以高质量发展为目标提升竞争力、确保运用知识产权实现短期和长期/显性和隐性/财务和非财务价值、确保维护合规承诺并妥善处理不合规行为、确保合规义务得以履行并识别应对预防风险

**知识产权管理机构七项职责**：
1. 推进识别知识产权合规义务，监督职责在组织内适当分配
2. 就知识产权合规相关事项提出建议
3. 制订和实施知识产权工作计划，监督考核完成情况
4. 负责组织知识产权日常管理工作
5. 负责统筹与其他管理机构相关的知识产权管理工作
6. 宜建立专利导航工作机制，参与重大项目的知识产权布局
7. 组织中的其他部门负责落实相关知识产权工作

### 15.3.3 管理制度和流程

知识产权管理五大过程：

#### 1. 知识产权获取

- 根据目标制订不同类型知识产权获取计划，明确获取方式或途径
- 建立审核机制防止非正常申请专利、不正当获取他人商业秘密、剽窃他人作品
- 确保专利质量管控，申请前进行检索和分析，保障发明创造人员署名权
- 适时办理作品登记，明确职务/委托/合作作品著作权权属，保留创作过程记录
- 通过遴选、密级划分确定商业秘密范围、保密事项、接触范围、流转要求和存证方式

#### 2. 知识产权维护

- 建立知识产权分类管理档案进行日常维护
- 知识产权权属变更与放弃
- 进行知识产权相关会计信息披露
- 建立知识产权会计核算档案，定期核算成本和产出效益
- 保管涉及知识产权的产品/服务资料（宣传、广告、促销、包装、说明书等）
- 对知识产权进行分级管理
- 保留有关维护的成文信息并实施有效管理

#### 3. 知识产权运用（5个方面）

| 方面 | 核心内容 |
|------|----------|
| 实施和使用 | 促进实施和使用，评估贡献，明确管理要求，监控合规实施，对密集型产品备案管理 |
| 许可和转让 | 制定方案，开展评估，履行审查备案登记程序；国有企业遵循国有资产管理规定 |
| 投融资 | 开展尽职调查评估风险和价值；境外投资前进行风险分析 |
| 企业重组 | 合并/并购前开展尽职调查和评估；出售/剥离资产前分析对未来竞争力的影响 |
| 标准化 | 参与标准化组织前了解知识产权政策；提案时披露并做出许可承诺；牵头制定标准时制定工作组知识产权政策 |

#### 4. 知识产权保护

**两大方面**：

**风险管理**：
- 采取措施避免或降低侵犯他人知识产权的风险
- 定期监控产品及工艺可能涉及他人知识产权的状况
- 将知识产权纳入组织风险管理范围，进行识别、分析和监测
- 建立涉密人员、涉密载体、涉密设备、涉密区域、涉密信息管理要求
- 对外信息披露前开展合规、保密审查
- 根据影响严重程度将风险分级，采取适当方式预防和应对

**争议处理**：
- 及时发现和监控知识产权被侵犯情况
- 运用自力救济、行政和司法救济等途径保护知识产权
- 评估协商、诉讼、仲裁、调解等不同处理方式对组织的影响，选取适宜方式

#### 5. 知识产权合规管理

创建管理制度和流程，防止知识产权泄露和侵权行为发生。基于合规义务履行实施必要审查，涉及违法行为时充分评估可能导致的法律后果。

### 15.3.4 评价、审核与改进

组织应策划并实施监控和审查，评价知识产权合规管理体系绩效，确保合规义务被履行。利用分析结果对以下七个方面进行评价：

| 序号 | 评价方面 |
|------|----------|
| 1 | 知识产权价值实现的符合性 |
| 2 | 知识产权合规管理体系的绩效和有效性 |
| 3 | 策划是否得到有效实施 |
| 4 | 知识产权合规的监测结果 |
| 5 | 应对风险和机遇所采取措施的有效性 |
| 6 | 外部供方的绩效 |
| 7 | 知识产权合规管理体系改进的需求 |
