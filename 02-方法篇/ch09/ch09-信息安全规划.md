# 第9章 信息安全规划

> 信息安全规划是组织整体战略在信息安全方面的落实和扩展，目标是建立科学、合理、有效的信息安全管控体系。

---

## 9.1 概述

### 9.1.1 信息安全的定义

**信息安全**：信息系统（包括硬件、软件、数据、人、物理环境及其基础设施）受到保护，不受偶然或恶意原因破坏、更改、泄露，系统连续可靠正常运行，信息服务不中断，最终实现业务连续性。

**信息安全五大基本属性（CIA++）**：

| 属性 | 说明 |
|------|------|
| **保密性** | 保证信息为授权者享用而不泄露给未经授权者 |
| **完整性** | 传送过程中没有被非法添加、删除、替换 |
| **可用性** | 随时为授权者提供服务，不被不合理拒绝 |
| **可控性** | 管理者能对信息实施必要的控制管理 |
| **不可否认性** | 人们要为自己的信息行为负责，提供公证仲裁信息证据 |

**速记口诀：保完用控否**

### 9.1.2 信息安全面临的威胁

**六类系统威胁来源**：物理环境、通信链路、网络系统、操作系统、应用系统、管理系统

**常见安全威胁（16种）**：
信息泄露、破坏完整性、拒绝服务、非法使用、窃听、业务流分析、假冒、旁路控制、授权侵犯、特洛伊木马、陷阱门、抵赖、重放、计算机病毒、人员渎职、媒体废弃、物理侵入、窃取、业务欺骗

**速记口诀：泄完拒非，听流假旁，侵马门赖，放毒渎废，侵窃欺**

### 9.1.3 信息安全规划的七大原则

| 原则 | 核心内容 |
|------|----------|
| **系统性** | 横向到边纵向到底，建立多层纵深防护体系，物理网络主机应用数据多层 |
| **适用性** | 上承信息化保障，下启运维日常，横向与风险管控、审计、法规合规衔接 |
| **时效性** | 短期规划（紧急方案）、中长期规划（1~3年体系化）、远景规划（3年以上） |
| **确定性** | 明确无歧义，不放大缩小，有明确主体和执行对象 |
| **可行性** | 结合实际文化管理模式，指出主体工作大致流程和方法 |
| **易用性** | 决策层抓方向，管理层掌全面，执行层照章办事 |
| **合规性** | 遵守国家法律法规、国标、行业监管、国际合作等合规要求 |

**速记口诀：系适时确，可易合**

### 9.1.4 信息安全规划的注意事项

1. **追求高效益的安全** — 不是"为了安全而安全"，围绕组织业务展开
2. **信息安全战略的校准** — IT战略、信息安全战略均需与组织整体战略保持一致
3. **基于业务的风险理解** — 关键风险区域（识别→分析→应对→监控→沟通→应急→审计）+ 风险偏好
4. **识别出合规性要求** — 外部合规（法律法规监管）+ 内部合规（企业内部制度一致）

> 💡 对于信息系统：制度随着技术跑。对于信息安全：技术随着制度跑。

## 9.2 信息安全架构

### 9.2.1 安全架构的定义和范围

**信息安全架构**：应用全面严格方法描述当前/以后的安全结构、安全过程、信息安全系统、人员和组织子单元，并使之与组织业务目标和战略方向保持一致的实践活动。

**三道安全防线**：
1. **系统安全架构** — 构建信息系统安全质量属性，从源头打造自身安全（不依赖外部防御）
2. **安全技术体系架构** — 构建通用安全技术基础设施（安全基础设施、安全工具和技术、安全组件与支持系统）
3. **审计架构** — 独立审计部门提供风险发现能力（范围：包含安全风险在内的所有风险）

### 9.2.2 商业应用安全架构（SABSA）

**SABSA**（Sherwood Applied Business Security Architecture）：以业务视角作为起点，从6个层面提供信息安全架构完整解决方案，是一套开放架构，可与TOGAF和ITIL无缝结合。

**SABSA六层模型**：

| 视图 | 对应安全架构 |
|------|-------------|
| 业务视图 | 情境安全架构 |
| 架构视图 | 概念安全架构 |
| 设计视图 | 逻辑安全架构 |
| 构建视图 | 物理安全架构 |
| 实施视图 | 组件安全架构 |
| 服务管理视图 | 安全服务管理架构 |

每层回答六个问题：**做什么（资产）、为什么（动机/风险）、如何做（流程）、谁参与（人员）、在哪里做（位置）、什么时候做（时间）**

**SABSA生命周期**（四阶段）：战略与规划 → 设计 → 实施 → 管理与衡量

**速记口诀：情概逻物组营（业架设构实服），资动流人位时**

### 9.2.3 信息系统安全保障模型

**三个维度**（GB/T 20274.1）：
- **保障要素**：技术、工程、管理、人员（四要素综合保障）
- **生命周期**：规划组织→开发采购→实施交付→运行维护→废弃（5阶段）
- **能力成熟度**：5个等级

**安全能力成熟度五级**：

| 等级 | 特征 |
|------|------|
| 基本执行级 | 随机被动，依赖个人经验，无法复制 |
| 计划跟踪级 | 主动计划与执行，未形成体系化 |
| 充分定义级 | 基本实践规范定义与执行 |
| 量化控制级 | 建立量化目标，可度量与预测 |
| 持续优化级 | 根据组织目标不断改进和优化 |

**速记口诀：执跟定量优（基计充量持）**

## 9.3 信息安全规划的主要内容

### 9.3.1 关注利益相关方的安全诉求

利益相关方包括组织内部（不同部门、层级、业务对象）和外部（监管单位、客户、用户、公众）。

规划时必须识别利益相关方的显性诉求和隐性诉求（口是心非的诉求），不同角色的诉求差异显著：
- 信息安全主管：更多安全投资
- 股东：投入是否产生效益
- 员工：安全对自己有什么影响

### 9.3.2 信息安全组织体系规划

**合理的组织框架四要素**：
1. **最高管理层** — 含治理者和执行管理者
2. **协调机构** — 含最高管理层和各部门负责人
3. **内部组织** — 主管部门与配合部门（可新增安全部门主管或指定IT主管）
4. **外部联系** — 与消防、信息安全专业组织、政府监管部门等保持固定联系

**速记口诀：最协内外（最高协调内组外联）**

### 9.3.3 信息安全管理体系规划

**信息安全管理体系（ISMS）**：组织在整体或特定范围内建立的信息安全方针和目标及其实现方法和手段构成的体系。

**ISMS四大特点**：
- 基于风险评估，体现预防控制为主的思想
- 强调遵守法律法规及合同方要求
- 强调全过程动态控制，控制费用与风险平衡
- 强调保护关键性信息资产（不是全部），确保CIA

**两大常见体系**：

| 体系 | 说明 |
|------|------|
| **ISO 27001** | 信息安全管理体系规范性标准，着眼于整体业务风险评估，第三方认证依据 |
| **等级保护（等保）** | 国家强制标准，分等级实施安全保护 |

**等保五个等级**：

| 等级 | 名称 | 破坏后影响 |
|------|------|------------|
| 第一级 | 自主保护级 | 损害公民、法人等合法权益 |
| 第二级 | 指导保护级 | 严重损害公民权益，或损害社会秩序/公共利益 |
| 第三级 | 监督保护级 | 严重损害社会秩序，或损害国家安全 |
| 第四级 | 强制保护级 | 特别严重损害社会秩序，或严重损害国家安全 |
| 第五级 | 专控保护级 | 特别严重损害国家安全 |

**等保基本框架**：**一个中心、三重防御**
- 一个中心：安全管理中心
- 三重防御：安全计算环境 + 安全区域边界 + 安全网络通信

**等保实施方法（6步）**：安全定级→基本安全要求分析→系统特定安全要求分析→风险评估→改进和选择安全措施→实施安全保护

**速记口诀：自指监强专（五级从低到高），一中三防**

### 9.3.4 信息安全技术体系规划

**七大核心安全技术**：

#### 1. 身份认证（10种方式）

| 认证方式 | 特点 |
|----------|------|
| VIEID 虚拟身份电子标识 | 唯一网络身份证 |
| 静态密码 | 最简单，用户自设 |
| 智能卡 | 不可复制硬件，需专用读卡器 |
| 短信密码 | What you have，随机动态码 |
| 动态口令 | What you have，60秒变换，一次有效 |
| USB Key | 软硬结合，冲击/响应或PKI模式 |
| 生物识别 | Who you are，身体特征（人脸）或行为特征 |
| 双因素认证 | 两种方式组合（动态口令+静态密码等） |
| Infogo认证 | 网络安全准入技术 |
| 虹膜认证 | 近红外扫描，高可靠性安全性 |

#### 2. 访问控制（4种机制）

| 机制 | 缩写 | 说明 |
|------|------|------|
| 自主访问控制 | DAC | 由客体所有者定义访问规则 |
| 基于角色的访问控制 | Role-BAC | 按角色定义权限 |
| 基于规则的访问控制 | Rule-BAC | 结合主体、请求、客体综合判定 |
| 强制访问控制 | MAC | 基于安全级别标签 |

**速记口诀：自角规强（DAC、RBAC、Rule-BAC、MAC）**

#### 3. 入侵检测
- **实时入侵检测**：网络连接过程中进行，发现即断连
- **事后入侵检测**：定期或不定期由专业人员进行，不具实时性

#### 4. 防火墙
由服务访问规则、验证工具、包过滤、应用网关四部分组成，在Internet与Intranet之间建立安全网关。

#### 5. 网闸（网络隔离技术）
两套独立系统分别连接安全和非安全网络，通过固态开关读写介质进行信息"摆渡"，保证两套系统之间没有直接物理通路。

#### 6. 防病毒（6条准则）
拒绝访问能力 → 病毒检测能力 → 控制传播能力 → 清除能力 → 恢复能力 → 替代操作

**速记口诀：拒检控清恢替**

#### 7. 数据加密技术

| 类型 | 特点 |
|------|------|
| 对称加密（单密钥） | 加解密用同一密钥，速度快，密钥分发管理困难 |
| 非对称加密（公钥/私钥） | 公钥加密私钥解密，密钥管理简单，速度较慢 |
| 链路加密 | 在通信链路上加密 |
| 节点加密 | 在通信节点上加解密 |
| 端到端加密 | 发送端到接收端全程加解密 |

**速记口诀：对非链节端（对称非对称，链路节点端到端）**

### 9.3.5 信息安全运营体系规划

**5个核心安全控制方法 + 2个运营活动**：

#### 1. 因需可知与最小特权
- **因需可知**：仅授予用户执行工作所需数据或资源的访问权限（目的：让秘密信息保持秘密）
- **最小特权**：主体仅被授予执行指定工作所需的特权（包括数据访问权限和系统任务执行权力）

#### 2. 职责分离与责任
形成制衡系统，确保没有任何个人可危及信息系统或信息安全，增加不法分子的风险成本。

#### 3. 其他常用安全运营方法
- **双人控制**：关键任务需两人批准，实现同行评审
- **岗位轮换**：防欺诈+交叉培训，减少环境对个体依赖
- **强制休假**：突然实施，让他人接管岗位，可发现欺诈
- **特权账户管理**：限制特权账户访问，持续检测特权使用

#### 4. 安全培训与意识提升
基础知识培训 → 操作规范培训 → 模拟演练培训 → 持续宣传教育

#### 5. 应急响应
应急响应计划需规划成周期性活动，定期演练检验。
应急响应五步：制定策略→建立联系渠道→制定响应流程→进行演练→建立报告记录

#### 6. 事件处理与恢复
建立完整的事件处理流程，提高应对能力，降低安全事件损害。

#### 7. 事后总结与改进
收集数据→分析评估→制定改进措施→实施改进→监控评估改进效果

**速记口诀：知权分双转假，训演处事后**

## 9.4 信息安全规划案例

信息安全规划三步骤（通用模型）：

1. **现状调研与需求分析** — 风险评估+合规差距评估+行业最佳实践+外部威胁，明确安全需求
2. **总体架构与蓝图设计** — 根据战略目标和需求分析，构建总体架构和基础架构，提炼建设重点
3. **项目规划与实施设计** — 差距分析→改进措施→关键项目→阶段目标和优先级→实施计划→监督执行

**速记口诀：调研分析，架构蓝图，规划实施**
