## 📖 二、逐节知识精炼

### 4.1 概述

**信息系统规划的定义**：组织决策层任主要负责人，管理层为工作主体，使用自顶向下分解 / 自底向上聚合，确定信息系统的整体发展战略、总体框架、演进路径和资源分配策略。

**信息系统规划的六大原则**（记忆口诀：战整先指柔遵）：

| # | 原则 | 核心要点 |
|---|------|---------|
| 1 | **战略性** | 从战略视角定义目标价值，驱动引领组织建设，与组织战略保持一致 |
| 2 | **整体性** | 四个方面——业务赋能、系统框架、建设实施、集成融合 |
| 3 | **先进性** | ①考虑技术发展趋势选择适当路线；②融合内外部最佳实践 |
| 4 | **指导性** | 从业务需求、技术方案、实施管理、成本控制、范围界定、风险预防等方面给出框架性要求 |
| 5 | **柔性** | 满足对内外部环境变化的适应性，明确监测调整优化的基本原则 |
| 6 | **遵从性** | ①法律法规；②标准规范；③组织战略与数字能力发展需求 |

### 4.2 信息系统规划主要内容（7大体系）

#### 4.2.1 信息系统发展战略

**信息系统战略** = 目标 + 方法 + 策略 + 措施的总称。

**（一）发展战略与目标**

| 要素 | 内容 |
|------|------|
| **基本趋势** | 信息技术革命、互联网创新、数字化转型与智能化发展等外部信息环境 |
| **指导思想** | 覆盖国家战略、行业领域要求、上级主管部门与主要负责人思想 |
| **战略目标** | 以时间为轴线、以阶段为区隔，定性与定量结合表达 |
| **基本方针** | 高度概括、动宾结构排比、方便记忆传播 |

**（二）发展路径与阶段**

**四种路径原则**：业务一致 → 能力主线 → 基础优先 → 稳态先行

**五个发展阶段（成熟度5级）**：

| 等级 | 核心主旨 | 关键词 |
|------|---------|--------|
| 一级 | **打基础** | 业务规范化、数字化意识、局部系统建设 |
| 二级 | **提效率** | 团队/部门职能、工作效率、全面推进系统建设 |
| 三级 | **做协同** | 数据共治共享、数据流优化业务流、多元协同 |
| 四级 | **强决策** | 数据模型开发利用、决策效率效能、治理模式变革 |
| 五级 | **构生态** | 跨组织融合、云和互联网模式、广域协同 |

> ⚡ **首考关联**：2025年11月综合真题考了「敏捷组织 + GBT43439」，这是成熟度相关国标，与本节直接相关。

#### 4.2.2 主要系统框架

**总体框架**：「感、传、智、用、安」五层 + 服务总线 + 安全保障体系

**三种框架演进路径**：

| 框架类型 | 适用阶段 | 核心理念 | 局限 |
|---------|---------|---------|------|
| **以应用功能为主线** | 中小型 / 信息化初期 | "拿来主义"、成套软件、按部门职能建设 | 系统间集成困难 |
| **以平台能力为主线** | 规模扩大 / 个性化需求 | 平层化建设、数据共享、双态IT（稳态+敏态） | 无法包容生态伙伴差异 |
| **以互联网为主线** | 产业链/生态链阶段 | App化微服务、能力封装、成熟度差异适配 | 技术复杂度高 |

**四种分系统划分原则**：技术一致性、工程一致性、职能一致性、数据一致性

#### 4.2.3 组织体系优化

| 模式 | 适用对象 | 特点 |
|------|---------|------|
| **中小型** | 中小企业 | 信息化管理委员会 + 信息化团队 |
| **集中式** | 大型单位 | 专业信息部门、最高管理者第一责任人、专职架构/质量/测试人员 |
| **分权式** | 业务单元差异大 | 各业务单元自行建设、设统筹负责人或虚拟团队 |
| **平衡矩阵式** | 成熟度较高 | 稳态集中建设 + 敏态分权管理，业务侧重数据开发 |

#### 4.2.4 技术体系定义

**六大定义原则**（记忆口诀：可用安全靠灵扩驾）：

| 原则 | 关键内容 |
|------|---------|
| **可用性** | 不是二元（行/不行），是可用程度的问题，需多维度排序 |
| **安全性** | 安全漏洞认知 + 故障影响最小 + 与信息安全管理体系匹配 |
| **可靠性** | 三方面考察：成熟性、技术整体性、技术风险性 |
| **灵活性** | 技术组件化 + 技术组合架构，少量变化满足新需求 |
| **可扩展性** | 韧性拓展，适应更多用户/业务/数据/交互 |
| **可驾驭性** | 直接/间接/混合方式，确保充分掌控关键技术 |

**技术蓝图两种绘制方法**：逻辑结构图 + 技术应用图

#### 4.2.5 任务体系部署

**六步过程**：任务拆解 → 明确目标 → 匹配组织 → 制定策略 → 定义计划 → 监控实施

**三层目标原则**：**S**pecific 具体 + **M**easurable 可测量 + **A**chievable 可实现

#### 4.2.6 资源体系调度

**四步**：资源识别与评估 → 资源关系与控制 → 资源分配与调度 → 资源风险与优化

**资源识别**：可基于能力要素（人员/技术/流程/软硬件），也可基于「人机料法环测」六要素。

#### 4.2.7 保障体系设定

| 保障类型 | 核心重点 |
|---------|---------|
| **组织** | 决策层承诺、组织变革支持、思想认识一致性 |
| **人员** | 全员数字能力培养、变革接受预期、碎片化时间利用 |
| **技术** | 储备预研、微创新鼓励、标准化驱动 |
| **资源** | 软实力建设、云服务获取硬资源、优先级提升 |
| **数据** | 数据治理能力、数据质量、数据标准化、数据开发 |
| **安全** | 安全意识、安全知识技能、安全管理体系 |

### 4.3 信息系统规划工作要点（五步法）

> ⚠️ **重要**：5个工作要点构成一个完整闭环，是案例题的高频考点。

**五步递进**：内外部需求挖掘 → 场景化模型分析 → 深度诊断与评估 → 整体与专项规划 → 持续改进

#### 4.3.1 内外部需求挖掘

**内部需求挖掘 — 五项任务**：理解组织战略 / 熟悉业务流程 / 收集用户需求 / 评估现有系统 / 感知数字环境

**五项注意事项**：以原始信息获取为主 / 避免直接给出解决方案 / 及时开展引导性培训 / 谨慎信息交叉传递 / 关注隐性需求的推演

**外部需求挖掘 — 六项任务**：国家战略导入 / 行业趋势分析 / 技术趋势研究 / 竞争环境分析 / 客户期望调研 / 标准与规范引用

**整合分析关注的9项内容**：主要矛盾、需求优先级、关键干系人需求、外部要求、创新环境、数字化水平、治理与文化模式、重大风险、推进策略

#### 4.3.2 场景化模型分析

**八维度分析模型**：

| 维度 | 内容 |
|------|------|
| 场景定义 | 目标、范围、业务背景、利益相关者 |
| 角色分析 | 职责、需求、行为、作用与影响 |
| 业务分析 | 业务模式、流程、需求、发展 |
| 数据分析 | 数据流、数据来源/类型/结构、开发利用价值 |
| 技术分析 | 管理/工艺/决策/信息技术现状与发展 |
| 组织分析 | 组织文化、人员技能、组织流程 |
| 风险分析 | 技术/安全/管理风险与应对策略 |
| 政策与法律分析 | 合规性分析 |

**三阶段应用**：规划前（识别需求）→ 规划中（评估方案可行性与风险）→ 规划后（监控评估效果）

#### 4.3.3 深度诊断与评估

**核心工具**：成熟度模型（5级）

| 等级 | 核心内涵 |
|------|---------|
| 一级 | 确立主要工作 + 基本策划 + 规范化建设 |
| 二级 | 管理精细化流程化 + 解决运行效率 |
| 三级 | 协同一体化 + 数据流替代业务流程 + 知识沉淀 |
| 四级 | 敏捷能力建设 + 数据模型预测决策 + 治理改革 |
| 五级 | 生态一体化 + 自组织模式 + 应对未知风险 |

**相关国标**：GB/T 43439（数字转型成熟度）、GB/T 39116（智能制造成熟度）

**诊断评估实施三步**：
1. **计划与打分**：0分/0.5分/0.8分/1分四级打分，由低到高逐级
2. **权重与计算**：参考标准或自动设定
3. **记录与确认**：形成底稿，标注不满足项，获得干系人确认

**木桶原理**：组织整体能力水平 = 最短板的能力水平状态

#### 4.3.4 整体与专项规划

**需求整合三维度**：业务领域维 / 能力建设维 / 技术发展维

**整体规划**三要点：与战略一致性、协同一体化、资源优化

**专项规划**四要点：明确主体、领域系统性、技术路线强化、细致时间轴

**一致性检查**四方面：规划-需求对应、内容协调、科学可行性、干系人理解一致

#### 4.3.5 持续改进

**五个关注点**：战略跟踪 → 技术感知 → 数据安全 → 用户体验 → 监测评估

### 4.4 信息系统规划常用方法（⭐高频考点）

> 🔥 **五星重要**：五种方法的名字、提出者、年份、核心思想是综合选择题的绝对高频考点。

#### 对比总表（先记这个）

| 方法 | 提出者 | 年份 | 核心思想 | 一句话 |
|------|--------|------|---------|--------|
| **SST** | William King | 1978 | 组织战略集→信息系统战略集的转换 |「翻译」组织战略为系统战略 |
| **BSP** | IBM公司 | 1970s | 自顶向下分析需求，自底向上设计结构 |「调查分析」企业信息需求定方案 |
| **CSF** | Zani / Rockart | 1970/1980 | 少数关键成功因素决定信息需求 |「抓住」主要矛盾定信息需求 |
| **VCA** | Michael Porter | 1985 | 价值链上识别战略环节优先部署IT |「找到」增值环节优先上IT |
| **Zachman** | John Zachman | 1987 | 6W×6层 = 36格的企业架构分类 |「网格化」描述企业信息 |

#### 4.4.1 SST 战略目标集转移法

- **核心**：把组织战略集（使命/目标/战略/属性）→ 转换成 → 信息系统战略集（系统目标/约束/建设战略）
- **三步法**：①画出利益相关方结构 → ②确定利益相关方要求 → ③定义组织对每个利益相关方的任务和战略

#### 4.4.2 BSP 企业信息系统规划法

- **四个基本步骤**：
  1. **定义管理目标** — 采访各级管理层，绘制目标树
  2. **定义管理功能** — 基于资源的生命周期识别（产生/获得/服务/归宿）
  3. **定义数据类** — 实体法 + 功能法，归纳10~20个数据类
  4. **定义信息结构** — 功能/数据类矩阵→C-U矩阵→聚类分组→子系统划分

- **核心理念**：管理功能应独立于组织机构（组织变动不影响系统设计）

#### 4.4.3 CSF 关键成功因素法

- **四个主要来源**：①个别产业结构 ②竞争策略与产业地位 ③环境因素 ④暂时因素
- **四类CSF**：内部型 / 外部型 / 监控型 / 建立型
- **四步实施**：①确定战略目标 → ②识别所有成功因素 → ③确定关键成功因素 → ④识别绩效指标

#### 4.4.4 VCA 价值链分析法

- **四个基本观点**：价值核心 / 基本+支持活动 / 相互依存 / 竞争优势来自优化
- **四步应用**：识别价值链 → 确定关键价值增加环节 → 确定关键价值减少环节 → 明确IT支持

#### 4.4.5 Zachman框架

- **结构**：6行（纵向）× 6列（横向）= 36格
- **横向6W**：What（数据）/ How（功能）/ Where（网络）/ Who（人员）/ When（时间）/ Why（动机）
- **纵向6层**：范围模型 → 企业模型 → 系统模型 → 技术模型 → 详细模型 → 功能模型

## 📝 四、案例分析答题模板

**STAR-L 答题框架**：
- S - 场景重现 → 定位到4.3五步法哪个环节出了问题
- T - 应达目标 → 引用4.1六大原则或4.2相关体系要求
- A - 应采取行动 → 从4.3工作要点选择对应步骤
- R - 预期结果 → 从4.2各体系输出标准描述
