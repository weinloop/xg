### 6.1 云资源规划概述（口诀：目要流）

云资源规划的定义、目标、要素和流程。口诀「目要流」分别对应：五大目标、七大要素、五步流程。

**云资源规划**定义：在云计算环境中，对可用的云资源（计算、存储、网络）进行合理有效的管理和分配的过程。

**云资源**定义：由云服务提供商所提供的计算、存储、网络等基础设施和服务，通过互联网或专用网络访问使用，用户无须拥有物理设备。

**标准定义**（ISO/IEC 17788 & GB/T 32400-2015）：云计算是一种通过网络将可伸缩、弹性的共享物理和虚拟资源池以按需服务的方式供应和管理的模式。

#### 6.1.1 重要性和目标（5个）

| 目标 | 说明 |
|------|------|
| **提高效率** | 避免资源浪费和过度购买，避免资源瓶颈和性能问题 |
| **降低成本** | 优化资源配置、成本效益高的方案、精确预测和控制成本 |
| **确保可扩展性** | 考虑业务增长和变化需求，防止过度投入或投入不足 |
| **提高可靠性和弹性** | 合理分配冗余资源、高可用性和容灾策略，减少故障和停机 |
| **支持业务需求** | 深入了解资源类型、性能、安全性、可靠性等要求 |

#### 6.1.2 关键要素（7个）

| 要素 | 说明 |
|------|------|
| **业务需求分析** | 确定业务目标、预测资源需求、评估性能要求、数据安全和合规性 |
| **资源评估和规划** | 确定计算、存储、网络资源的数量、类型和规模 |
| **预算管理** | 制订预算计划、预测运营成本、优化资源配置、评估控制云服务商费用 |
| **安全和合规性** | 数据保护措施、访问控制、身份验证、合规性标准满足 |
| **弹性和可扩展性** | 评估弹性需求、设计弹性架构、规划资源扩展能力 |
| **性能优化** | 评估优化计算和存储资源性能、选择适当提供商和配置 |
| **监控和管理** | 制定监控策略、选择监控工具、建立资源管理流程 |

#### 6.1.3 基本流程（5步循环）

| 步骤 | 内容 |
|------|------|
| **① 需求收集** | 理解业务需求和目标（预测增长）、收集业务数据（系统架构/用户量/交易量/存储需求）、调研利益相关者需求 |
| **② 资源评估和规划** | 评估当前资源使用情况（性能/可用性/成本）、预测未来需求、确定云服务模型（IaaS/PaaS/SaaS/FaaS）和提供商 |
| **③ 预算管理** | 制订预算计划（采购/运营/维护成本）、评估定价模型和费用结构、设定费用控制和监控策略 |
| **④ 设计与实施** | 设计云架构和系统配置（计算/存储/网络/安全）、选择提供商并配置部署云资源、迁移应用程序和数据 |
| **⑤ 持续优化** | 监控评估资源性能/可用性/成本效益、根据实际使用调整优化、定期审查更新规划 |

> 整个流程是**循环过程**，随业务需求变化和技术进展不断评估优化。

### 6.2 云计算架构 ⭐（口诀：部内服模）

云计算架构的四大板块：部署模式、内部特征、外部特征、服务模式。口诀「部内服模」。

**云计算架构**定义：在云计算环境下，将各种资源和服务组织起来以满足用户需求的框架，旨在保障弹性、可靠性和高效性。

#### 6.2.1 云计算服务类型（3种部署模式）（口诀：公私混）

| 类型 | 核心属性 | 特点 | 适用场景 |
|------|---------|------|---------|
| **公有云** | 共享资源服务 | 成本低、扩展性好、无须维护、使用便捷；基础设施所有权属云服务商 | 个人用户、互联网企业、大部分客户 |
| **私有云** | 专有资源池 | 数据安全性高、服务质量保障完善、资源使用率高；需大规模投资（3-5年回收） | 对安全要求高的大型企业 |
| **混合云** | 公有+私有协同 | 灵活性+安全性+成本效益平衡；统一服务体验（门户统一/监控统一/账户权限统一） | 稳态业务（私有云）+ 敏态业务（公有云） |

**混合云关键能力**：不是简单叠加，需提供统一的服务体验——服务门户统一、资源监控界面统一、账户权限统一。

#### 6.2.2 云计算内部特征（5个）

| 特征 | 说明 |
|------|------|
| **虚拟化** | 将物理资源（服务器/存储/网络）抽象为虚拟资源，一台物理服务器划分为多个VM |
| **弹性扩展** | 根据流量、负载自动扩展或缩减资源；通过自动负载均衡、弹性自动缩放、自动资源调配实现 |
| **自动化管理** | 自动执行资源配置、监控、部署、备份、恢复等任务；工具包括编排工具、配置管理工具、容器编排工具 |
| **多租户支持** | 多个用户/组织共享同一云环境资源；隔离机制包括虚拟化技术、网络隔离、身份认证和访问控制 |
| **资源编排和管理** | 定义部署应用程序、配置网络和存储；监控资源使用、容量规划、优化资源分配 |

#### 6.2.3 云计算外部特征（4个）

| 特征 | 实现方式 |
|------|---------|
| **可靠性和可用性** | 不同地理位置冗余系统、多数据中心数据备份和镜像 |
| **安全性** | 数据加密、身份认证、访问控制、漏洞管理、监控 |
| **网络连接性** | 高带宽网络、低延迟连接、负载均衡、CDN |
| **成本效益** | 按需分配和释放资源、按实际使用付费、资源利用优化、经济实惠计费模型 |

#### 6.2.4 云计算服务模式（4种）

| 模式 | 全称 | 核心内容 | 主要用户 | 适用场景 |
|------|------|---------|---------|---------|
| **IaaS** | 基础设施即服务 | 虚拟化计算资源（服务器/存储/网络） | 系统管理员 | Web部署、大规模数据处理、备份容灾 |
| **PaaS** | 平台即服务 | 中间件平台（运行时环境） | 开发人员 | Web/移动/物联网/大数据AI开发 |
| **SaaS** | 软件即服务 | 应用程序即服务 | 普通用户 | 办公软件、CRM、HR、SCM |
| **FaaS** | 功能即服务 | 将功能拆分为独立可复用函数 | 开发人员 | 微服务、事件驱动、云原生应用 |

**四种模式的优点速记**：
- **IaaS**：灵活、可扩展、高可用、成本效益
- **PaaS**：灵活、简化部署管理、可扩展、高可用
- **SaaS**：方便、可靠、可扩展、成本效益
- **FaaS**：灵活、可伸缩、可靠（故障隔离）、高效

### 6.3 计算资源规划（口诀：形方步）

计算资源的三种维度：5种形态、7种方法技术、7步关键过程。

**计算资源**：云服务提供商提供给用户的用于执行计算任务和处理数据的资源。

#### 6.3.1 基本概念

**计算资源5种形态**：

| 形态 | 说明 |
|------|------|
| **虚拟机（VM）** | 在物理服务器上创建多个虚拟实例，每个有独立OS和应用 |
| **容器（Container）** | 轻量级虚拟化，将应用及依赖打包成独立可执行单元 |
| **裸金属（Bare Metal）** | 物理机形态提供，面向数据库/大数据/AI等高性能场景 |
| **GPU** | 高性能图形处理器，用于图形渲染/深度学习/科学计算 |
| **弹性计算资源（ECR）** | 根据需求动态分配和释放，自动扩展或收缩 |

**计算资源规划7个范围**：
1. **硬件资源规划** — 服务器、网络设备的规格/数量/配置
2. **虚拟化** — 将物理资源划分为虚拟资源池
3. **容器化** — 应用及依赖打包，便于部署和移植
4. **弹性扩展和负载均衡** — 根据负载自动调整资源，分配请求到不同节点
5. **容量规划和预测** — 基于历史数据和预测模型，确保足够资源
6. **资源管理和调度** — 资源的分配、调度、释放

#### 6.3.2 方法和技术（7种）（口诀：容性负弹虚自云）

| 方法 | 说明 |
|------|------|
| **容量规划** | 基于历史数据和趋势分析预测未来需求 |
| **性能优化** | 调整资源分配、优化算法、改进网络和存储性能 |
| **负载均衡** | 将工作负载分布到多个计算资源，减轻单个资源负荷 |
| **弹性伸缩** | 基于预设规则和阈值动态调整资源 |
| **虚拟化和容器化** | 提高资源利用率和灵活性 |
| **自动化管理** | 自动部署、配置管理、监控报警、自动修复 |
| **云资源管理** | 可视化管理界面、自动化资源调整和成本优化 |

#### 6.3.3 关键过程（7步）

```
需求分析 → 容量规划 → 云服务选择 → 虚拟化策略 → 安全性考虑 → 成本效益分析 → 持续监控维护
```

| 步骤 | 内容 |
|------|------|
| **需求分析** | 评估CPU/内存/存储/带宽需求，通过性能测试和基准测试完成 |
| **容量规划** | 决定能处理多少工作负载、需要多少资源 |
| **云服务选择** | 根据需求选择IaaS/PaaS/SaaS |
| **虚拟化策略** | 采用虚拟化技术提高利用率、灵活性和可扩展性 |
| **安全性考虑** | 数据加密、访问控制、安全审计 |
| **成本效益分析** | 比较不同方案的成本和效益 |
| **持续监控维护** | 监控资源使用、检测性能瓶颈、定期维护更新 |

### 6.4 存储资源规划（口诀：种程）

存储资源的两种维度：7种存储类型、9步关键过程。

**存储资源**：云计算环境中可用于存储数据的各种硬件和服务，提供高可用性、灵活性和可扩展性。常见云存储资源包括**对象存储、文件存储和块存储**。

#### 6.4.1 基本概念（6个方面）

| 方面 | 说明 |
|------|------|
| **存储类型选择** | 根据访问模式、数据处理需求、可用性要求选择块存储/文件存储/对象存储 |
| **存储容量规划** | 分析数据量和增长趋势，结合预测模型和历史数据确定容量 |
| **数据备份和冗余** | 选择备份机制、冗余存储、灾难恢复方案 |
| **存储性能优化** | 选择高IOPS和低延迟设备、使用缓存/负载均衡/数据分区 |
| **数据安全和隔离** | 数据加密、访问控制、身份认证、权限管理 |
| **存储管理和调度** | 存储资源分配、监控、容量管理和调整 |

#### 6.4.2 存储资源和技术（7种）

| 类型 | 全称 | 特点 | 适用场景 |
|------|------|------|---------|
| **DAS** | 直接附加存储 | 直接连接主机/服务器，高性能访问 | 小型环境、高带宽低延迟应用 |
| **NAS** | 网络附加存储 | 通过网络协议(NFS/CIFS/SMB)提供文件级访问 | 文件共享、备份、存档 |
| **SAN** | 存储区域网络 | 专用网络，光纤通道或iSCSI，提供块级存储 | 企业级高性能/高可用/高扩展应用 |
| **对象存储** | Object Storage | 以对象为基本单元，分布式存储，高扩展性 | 大规模数据存储、云存储、数据备份 |
| **云存储** | Cloud Storage | 云服务商存储设施，高度可扩展弹性 | 备份、归档、共享、协作 |
| **分布式文件系统** | Distributed FS | 跨多存储节点分布式管理，高可用容错 | 大规模存储、分布式计算 |
| **虚拟化存储** | Virtualized Storage | 物理存储上创建逻辑存储池，灵活管理 | 虚拟机迁移、存储快照、复制 |

#### 6.4.3 关键过程（9步）

```
收集需求 → 分析评估 → 技术选择 → 架构设计 → 安全规划 → 容量规划 → 性能优化 → 管理监控 → 定期评估调整
```

- **收集需求**：数据量/数据类型/访问模式/保留期限/性能/可用性/安全需求
- **分析评估**：预测数据增长趋势、估算性能和容量要求
- **技术选择**：根据性能/可用性/扩展性/成本选择DAS/NAS/SAN/对象存储等
- **架构设计**：确定存储设备布局、连接方式、存储协议、冗余配置、缓存策略
- **安全规划**：数据加密、访问控制、备份恢复、灾难恢复
- **容量规划**：考虑数据增长率、保留期、备份快照需求
- **性能优化**：性能监控分析、调整参数配置、缓存策略和负载均衡
- **管理监控**：配置管理、容量管理、性能监控、故障管理、变更管理
- **定期评估调整**：跟踪新技术和解决方案，保持有效性和适应性

### 6.5 云数据中心规划 ⭐

**云数据中心（CDC）**定义：支撑云服务的物理载体，处于云计算技术体系核心地位。以调度技术及虚拟化技术为手段，通过建立物理的、可伸缩的、可调度的、模块化的计算资源池，将IT系统和数据中心基础设施合二为一。

#### 6.5.1 基本概念

**四大规划目标**（口诀：可扩效安）：

| 目标 | 实现方式 |
|------|---------|
| **可靠性和可用性** | 冗余设计、备份和灾难恢复策略 |
| **可扩展性** | 弹性伸缩、负载均衡、容量规划 |
| **性能和效率** | 优化网络架构、存储配置、服务器部署、负载管理 |
| **安全和合规性** | 物理安全、网络安全、数据安全、应用安全、隐私合规 |

**七大设计原则**（口诀：可冗弹性优安灵节扩）：
1. **可用性和冗余性** — 冗余电源/网络、备份容灾、故障转移、负载均衡
2. **弹性和可扩展性** — 弹性资源分配释放、自动化伸缩、容量规划
3. **性能优化** — 优化网络/存储/服务器/负载管理
4. **安全和隐私** — 物理安全、网络安全、访问控制、数据加密、合规性
5. **灵活性和可管理性** — 管理监控工具、自动化配置部署、统一管理平台
6. **节能和环保** — 能源管理、热管理、绿色设计
7. **高度可扩展的存储和网络架构** — 分布式存储、SDN、NFV

**五大要素**：

| 要素 | 说明 |
|------|------|
| **面向服务** | 整体结构以服务为导向，资源供给方法对用户完全透明 |
| **资源池化** | 各类IT资源和网络资源构成统一资源池，逻辑资源和物理资源去耦合 |
| **高效智能** | 基于虚拟化和分布式计算，低廉硬件实现高效承载；综合调度策略实现智能化 |
| **按需供给** | 资源池化后将物理资源转化为逻辑资源，根据实际需求动态供给 |
| **低碳环保** | 虚拟化技术实现绿色节能，基于能耗的调度策略降低投入和运营成本 |

> 五大要素速记口诀：**面资高按低**（面向服务、资源池化、高效智能、按需供给、低碳环保）

#### 6.5.2 核心技术（6类）（口诀：网融测虚安节）

**1. 网络架构设计（7要素）**

| 要素 | 说明 |
|------|------|
| 良好的可扩展性 | 拓扑能容纳更多服务设备 |
| 多路径容错能力 | 路径多样性，链路/服务器故障容错，并行路径提供充裕带宽 |
| 低时延 | 满足视频/在线商务/高性能计算等敏感场景 |
| 高带宽网络传输能力 | 支持TB/PB/EB/ZB级数据通信 |
| 模块化设计 | 模块化添加/维护/替换，降低复杂度 |
| 网络扁平化 | 层数尽可能少，利于流量均衡 |
| 绿色节能 | 合理布局利于散热，降低能耗 |

**2. 网络融合技术**：以太网、存储网络及高性能计算网络融合是趋势。主要技术有光纤以太网通道技术、数据中心桥接技术及多链接透明互连技术。

**3. 网络性能测试**

| 层次 | 测试指标 |
|------|---------|
| **网络层** | 连通性、带宽、时延、丢包率 |
| **传输层** | 丢包率、吞吐量、连接数 |
| **应用层** | 页面丢失率、应答延迟、吞吐量 |

两种测试方法：
- **主动测试**：部署测试工具，主动发送探测流 → 适合端到端时延、丢包、时延变化
- **被动测试**：在链路或路由器上被动采集数据 → 适合路径吞吐量等流量参数

**4. 虚拟化技术**

计算机系统5个抽象层：硬件抽象层 → 指令集架构层 → 操作系统层 → 库函数层 → 应用程序层

虚拟机模型：`计算机硬件 + 虚拟机监控器(VMM) + 客户机操作系统(Guest OS)`

四种常用虚拟化技术：

| 技术 | 说明 |
|------|------|
| **硬件仿真技术** | 在宿主机OS上创建硬件VM仿真所需硬件 |
| **全虚拟化技术** | 软件模拟与真实硬件完全相同的环境，OS无须修改，兼容性好 |
| **半虚拟化技术** | 暴露修改过的硬件抽象，以软件形式提供硬件接口 |
| **硬件辅助虚拟化技术** | 借助CPU/芯片组/IO设备虚拟化支持实现高效全虚拟化 |

**5. 安全技术**：安全体系贯穿各环节 → 安全需求 → 安全策略制定 → 防御系统 → 监控与检测 → 响应与恢复

**6. 节能技术**

**PUE（电能使用效率）**：评价数据中心能源效率的核心指标。

```
PUE = 数据中心总用电量 / IT设备总用电量
```

PUE 越接近1，绿色化程度越高。

## ⚡ 七、首考真题印证与易错点

### 首考已验证
- 2025年11月首考**案例出现纯计算题**（vCPU容量/实例数量预测），第6章计算资源规划为重点
- 云计算部署模式（公有/私有/混合）和IaaS/PaaS/SaaS的区别是选择题高频考点
- 新基建七大领域和PUE计算有出题潜力

### 易混淆点

| 易混淆 | 区分 |
|--------|------|
| 公有云 vs 私有云 vs 混合云 | 公有=共享低成本（所有权属服务商）；私有=专有高安全（所有权属企业）；混合=两者协同（统一体验） |
| IaaS vs PaaS vs SaaS vs FaaS | IaaS=提供虚拟机（管理员用）；PaaS=提供开发平台（开发者用）；SaaS=提供软件（用户用）；FaaS=提供函数（函数级） |
| 虚拟机 vs 容器 | VM=完整OS虚拟化（重量级）；容器=共享OS内核（轻量级，快速部署） |
| DAS vs NAS vs SAN | DAS=直连（高性能，小环境）；NAS=网络文件级（易共享）；SAN=专用网络块级（企业高性能） |
| 对象存储 vs 块存储 vs 文件存储 | 对象=以对象为单元(大规模)；块=裸存储卷(高性能)；文件=文件系统层级(共享) |
| 全虚拟化 vs 半虚拟化 | 全虚拟化=OS无须修改(兼容好)；半虚拟化=修改OS内核(性能好) |
| 主动测试 vs 被动测试 | 主动=发送探测流(端到端时延丢包)；被动=采集网络数据(吞吐量) |
| PUE值含义 | PUE=1最优（IT能耗占比100%），数值越大越不绿色 |
| GB 50174 vs TIA-942 | GB 50174=国内标准(A/B/C三级)；TIA-942=国际标准(T1-T4四级) |
| 稳态业务 vs 敏态业务 | 稳态=高可靠低时延(私有云)；敏态=弹性扩展(公有云) |
