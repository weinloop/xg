4.1 概述 ▼
📌 规划定义
  • 基于组织战略，明确信息系统发展愿景、目标、系统框架及各系统关系、建设模式、实施策略
🎯 六大价值与意义 目路识务标源
  • ① 确立数字能力目标 — 聚焦建设重点，带动资源综合开发
  • ② 明确建设路径 — "总分总"思维，策划关键路径+阶段目标
  • ③ 确保认识一致 — 决策层关注愿景/目标/路径；管理层关注变革/分工；执行层关注任务/计划
  • ④ 具象关键任务 — 时间计划/资源投入/责任分工/目标成果/依存关系
  • ⑤ 明确标准与措施 — 做事方法/评估依据/纠偏控制
  • ⑥ 统筹部署资源 — 数据/网络/基础设施/软件 + 人力/管理/技术
⚙️ 六大原则 战整先指柔遵 选择5已考
  • 战略性：从战略视角定义，与组织战略一致，支撑业务目标
  • 整体性：①业务赋能 ②系统框架 ③建设实施 ④集成融合 四整体
  • 先进性：①技术发展趋势 ②内外最佳实践融合
  • 指导性：框架性要求建议，为设计实现提供基本依据
  • 柔性：适应环境变化，明确监测/调整/优化原则
  • 遵从性：①法律法规 ②标准规范 ③组织战略与数字能力需求 已考
4.2 主要内容（七大体系） ▼
📐 4.2.1 信息系统发展战略
  • 战略目标三要素：基本趋势 + 指导思想/战略目标/基本方针 + 目标树（总体→分目标→子目标）
  • 发展路径四原则 业能基稳：业务一致 → 能力主线 → 基础优先 → 稳态先行 已考
  • 发展路径选择考虑：信息基础设施优先、稳敏分离（稳态先行、敏态后发）
  • 五级成熟度 基效协决生：
一级打基础业务规范化+数字化意识+局部系统建设
二级提效率以部门职能为基础，提高工作效率
三级做协同数据共治共享，优化业务流，跨职能协同
四级强决策数据模型+综合应用，变革治理模式
五级构生态跨组织融合，云+互联网模式，广域协同
🏗️ 4.2.2 主要系统框架 案例已考★
  • 总体框架模式："感·传·智·用·安"
  • 三种框架演进：
应用功能型"拿来主义"、成套软件、关注功能、统一规划分步实施中小型/初级阶段
平台能力型"竖井式"→"平层化"、弹性敏捷、自主创新、双态IT成熟度提升期
互联网型App化/微服务、能力封装、动态编排、适配不同成熟度组织产业链/生态链阶段
  • 分系统划分四原则 技工职数：技术一致性 → 工程一致性 → 职能一致性 → 数据一致性
👥 4.2.3 组织体系优化
  • 中小型：委员会+信息团队（主机/网络/开发/桌面组）
  • 大型-集中式：专业信息部门，最高管理者挂帅，分工细（架构/质量/测试）
  • 大型-分权式：各业务单元自行建设，统筹负责人/虚拟团队，快但有集成问题
  • 大型-平衡矩阵：基础集中+应用分权，稳态集中/敏态分散
  • 业务领域：两种模式 — ①设"能手/旗手"重点培育 ②全员数字素养培育
🔧 4.2.4 技术体系定义
  • 六原则 可安可灵扩驾：可用性→安全性→可靠性→灵活性→可扩展性→可驾驭性
  • 范围9领域：应用软件/网络/数据库/中间件/计算机与存储/数据资源/客户端/容灾/信息安全
  • 蓝图绘制：逻辑结构图（按框架表达）+ 技术应用图（按技术族表达）
  • 可靠性三维度：成熟性 · 技术整体性 · 技术风险性
📋 4.2.5 任务体系部署（6步）
  • 拆解→明确目标(SMART)→匹配组织→制定策略→定义计划→监控实施
  • 任务层级：领域 → 工程 → 项目 → 活动
💰 4.2.6 资源体系调度
  • 识别评估 → 关系控制 → 分配调度 → 风险优化
  • 资源识别两维度：①能力要素（人员/技术/流程/软硬件）②任务六要素人机料法环测
  • 资源分权五级：组织权→所有权→保管权→调度权→使用权
🛡️ 4.2.7 保障体系设定
  • 六大保障 组人技资数安：
组织决策层支持变革、全员认识一致、组织架构调整支撑
人员全员数字能力培育、碎片化时间学习、接受变革意识、新技能建设
技术技术储备+预研、微创新鼓励、创新文化、技术标准化
资源重视软实力、新型方法获"硬"资源(云)、提升资源优先级、循环利用
数据治理能力、管理体系、数据质量、标准化、开发利用、保值增值
安全安全意识、知识技能、完善安全管理体系
4.3 工作要点（五步法） ▼
🔍 4.3.1 内外部需求挖掘
  • 内部需求（5项任务）：
  • 理解组织战略 — 与高层沟通，了解期望定位
  • 熟悉业务流程 — 问题/痛点/改进空间
  • 收集用户需求 — 访谈/问卷，操作/数据/功能/价值需求
  • 评估现有系统 — 容量/功能/性能/稳定性/使用情况
  • 感知数字环境 — 数据资产盘点/人才分布/创新/数字素养
  • 外部需求（6项任务）：
  • 国家战略导入 · 行业趋势分析 · 技术趋势研究 · 竞争环境分析 · 客户期望调研 · 标准规范引用
  • ⚠️ 注意事项：原始信息获取为主、避免直接给方案、谨慎信息交叉、关注隐性需求推演
  • 整合分析：主要矛盾/需求优先级/干系人内在需求/外部要求/数字环境状态/重大风险
🎬 4.3.2 场景化模型分析
  • 拆解选择6步：价值链拆解→能力链拆解→交叉找融合点→关键价值点→定义场景需求→评估条件形成清单
  • 场景模型8维构建：场景定义·角色·业务·数据·技术·组织·风险·政策法律
  • 三阶段应用：规划前(识别需求)→规划中(评估方案)→规划后(监控调整)
  • 优点：贴近实际·提供指导·提高适应性 | 缺点：数据难采集·可行性受限
📊 4.3.3 深度诊断与评估 已考
  • 成熟度五级内涵（教材版 vs CMMM版）：
一级规范化确立主要工作+数字化转型基本策划CMMM:规划级
二级精细化/流程化解决运行效率，部署信息系统CMMM:规范级
三级协同一体化数据流替代流程、集成平台化、知识沉淀CMMM:集成级
四级敏捷能力快速响应、数据模型预测决策、治理改革CMMM:优化级
五级生态一体化业务/管理/生产/服务自组织CMMM:引领级
  • 打分法：0分(全不满) · 0.5分(部分满/系统缺陷) · 0.8分(大部分满/局部不足) · 1分(全满足)
  • 木桶原理：整体能力取决于最短板 → 找到最短板 + 延缓/暂停过度发展能力
  • 国标引用：GB/T 43439(数字化转型) · GB/T 39116(智能制造) · 数字城市/IT运维/智慧园区
📝 4.3.4 整体与专项规划
  • 需求整合三维度：业务领域维 · 能力建设维 · 技术发展维 已考
  • 整体规划：解决宏观问题 — 确保战略一致、提高协同一体化、优化资源配置和ROI
  • 专项规划(6类)：应用系统/网络环境/云服务/数据中心/信息安全/云原生
  • 规划模式："自底向上"(效率为主) vs "自顶向下"(协同敏捷为主)
  • 一致性检查：需求对应·内容协调·科学可行性·干系人理解
🔄 4.3.5 持续改进
  • ①跟踪组织战略（与各部门密切合作，更新规划）
  • ②感知技术发展（供应商交流、行业研讨、培训）
  • ③关注数据管理与信息安全（完整性/可靠性/可用性/泄露防护）
  • ④注重用户体验与参与（调研/测试/反馈/易用性设计）
  • ⑤建立监测评估机制（KPI/满意度/定期评估报告→修订完善）

🔄 SST 战略目标集转移法
  • 核心公式：组织战略集（使命/目标/战略/组织属性）→ 信息系统战略集（系统目标/约束/建设战略）
  • 三步过程：①画利益相关方结构 → ②确定各方要求 → ③定义每个利益方的任务和战略
  • 验证：送最高管理者审查，收集反馈，判断战略集元素优���次序
📐 BSP 企业信息系统规划法
  • 四步骤 目功数构：
  1. 定义管理目标 — 采访各级管理部门，绘制目标树
  2. 定义管理功能 — 核心！按资源生命周期识别，独立于组织机构
  3. 定义数据类 — 实体法/功能法，10~20个数据类
  4. 定义信息结构 — 功能/数据类矩阵→聚类→子系统划分
  • 资源生命周期4阶段：产生 → 获得 → 服务 → 归宿
  • 核心理念：管理功能独立于组织机构，减少体制变动影响
🎯 CSF 关键成功因素法
  • 四来源 产竞环暂：产业结构 · 竞争策略/地位 · 环境因素 · 暂时因素
  • 四类型 内监外建：内部型 · 监控型 · 外部型 · 建立型
  • 四步骤：①确定战略目标 → ②逐层分解识别所有成功因素 → ③德尔菲法/模糊评价确定KPI → ④识别绩效指标和衡量数据
  • 特点：抓住主要矛盾，突出重点，适用于高层管理者，简便可行但少涉及IT如何支持目标
🔗 VCA 价值链分析法
  • 4个基本观点：价值是核心 · 基本活动+支持活动 · 相互依存构成系统 · 竞争优势来自价值链优化
  • 基本活动：进料后勤→生产→发货后勤→销售→售后
  • 支持活动：人事·财务·计划·研发·采购
  • 四步骤：①识别价值链 → ②确定关键增值环节 → ③确定关键减值环节 → ④明确IT对关键环节支持
🏛️ Zachman 框架
  • 6行（纵向/角色） 规企系技详功：规划人员(范围)→系统所有者(企业)→架构师(系统)→构造人员(技术)→集成者(详细)→用户(功能)
  • 6列（横向/6W） 数功网人时因：What(数据)·How(功能)·Where(网络)·Who(人员)·When(时间)·Why(动机)
  • 六步骤：①确定愿景原则→②现状描述分析→③目标架构定义→④差距改进分析→⑤制订实施计划→⑥持续改进优化
