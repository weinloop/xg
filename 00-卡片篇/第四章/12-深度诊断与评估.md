# 卡片12：深度诊断与评估

---

## 📖 教材原文

> 通过对内外部需求挖掘和场景化模型分析，并不能完全明确组织信息系统的全面需求。因此，还需要对组织需求进行深度诊断与评估，从而进一步锁定目标、细化需求，以及确认各类需求间的依存关系。

### 一、成熟度与需求控制

**核心观点**：需求永远无止境，差异在于精细度。成熟度高的组织需求颗粒度较细，成熟度不高的组织需求颗粒度较宏观。

**五级成熟度标准：**

| 等级 | 名称 | 核心特征 |
|:---:|------|---------|
| 一级 | 规范化 | 确立业务领域主要工作，推动数字化转型的基本策划 |
| 二级 | 精细化 | 管理精细化和流程化，以运行效率为聚焦点，强调数据使用和系统部署 |
| 三级 | 协同化 | 职能与分工之间的协同一体化，数据流动替代流程管理，集成平台化 |
| 四级 | 敏捷化 | 敏捷能力建设，快速响应客户需求，数据模型+预测+快速决策 |
| 五级 | 生态化 | 生态一体化建设，业务/管理/生产/服务自组织，应对未知风险 |

**木桶原理**：组织整体能力水平取决于最短板。通过能力成熟度不仅找到最短板，还能知道哪些能力发展需要延缓甚至暂停。

**需求控制原则**：不是抑制需求范围或降低目标，而是基于科学方法更全面识别需求、更精细标识需求、对每项需求定义适当的阶段性目标控制。

### 二、诊断与评估模型确立

**两维度模型**：
- **业务能力维度**：能力域 → 能力子域 → 能力项 → 能力分项 → 能力子项 → 能力点（层级由规划范围决定）
- **成熟度等级维度**：5个等级

面向整体规划需定义到能力子域或能力项层面；面向专项业务规划需定义到能力项或能力分项层面。

### 三、诊断与评估实施

**量化打分标准：**
- 0分：全部不能满足
- 0.5分：能够部分满足，形成系统性缺陷
- 0.8分：大部分满足，局部执行或非关键内容存在缺陷
- 1分：全部能够满足

**权重与计算**：引入分项权重获取整体情况，参考国家/行业标准或按业务能力重要程度设定。

**记录与确认**：针对每条成熟度等级设定进行过程记录，不满足情况清晰标注诊断发现。打分结果和评估发现需得到主要干系人确认。

## 🔑 背诵提炼

| 环节 | 核心内容 |
|------|---------|
| 成熟度五级 | 一级规范化→二级精细化→三级协同化→四级敏捷化→五级生态化 |
| 诊断模型 | 业务能力维度（域→子域→项→分项→子项→点）× 成熟度等级维度（5级） |
| 打分标准 | 0（全不满足）/ 0.5（部分-系统性缺陷）/ 0.8（大部分-局部缺陷）/ 1（全满足） |
| 关键原则 | 木桶原理找最短板 + 按规划范围定模型层级 + 干系人确认 |

**本质定位**：诊断与评估不是评估信息系统，而是评估**组织业务与能力发展**

---

## 🧠 背诵口诀

> **五级成熟：规范精细协同敏捷生态** — 规范化、精细化、协同化、敏捷化、生态化

> **两维模型：能力×成熟** — 能力维度（六层分解）× 成熟度维度（五级）

> **四分打：全缺部无** — 0/0.5/0.8/1 对应 全不满足/部分满足/大部分满足/全满足

## 🏢 案例应用

**场景**：华航集团数据资产智能管理平台

**问题1**：请根据五级成熟度标准，为华航集团的数据资产管理能力进行诊断与评估。

**参考答案**：

以"数据质量管理"能力子域为例，进行成熟度诊断：

| 能力项 | 一级 | 二级 | 三级 | 四级 | 五级 | 当前得分 |
|--------|:---:|:---:|:---:|:---:|:---:|:---:|
| 质量规则制定 | 1 | 0.8 | 0 | 0 | 0 | 1.8/5 |
| 质量检测执行 | 1 | 0.5 | 0 | 0 | 0 | 1.5/5 |
| 质量问题处理 | 0.8 | 0 | 0 | 0 | 0 | 0.8/5 |
| 质量报告分析 | 0.5 | 0 | 0 | 0 | 0 | 0.5/5 |

**诊断结论**：集团数据质量管理整体处于**一级末期、二级初期**，核心短板是"质量问题处理"（0.8分）和"质量报告分析"（0.5分），缺乏闭环工单和统一报告看板。根据木桶原理，这是制约整体数据能力的短板。

**需求控制**：基于成熟度诊断，平台一期目标不是直接做到四级敏捷化，而是先补齐二级——配置5,000+质量规则（二级-精细化）、建立问题工单闭环机制（从0提升到二级）、搭建三级质量看板（从0.5提升到二级）。

---

**问题2**：诊断与评估打分后，如何将评分结果转化为信息系统规划需求？

**参考答案**：

以数据质量管理能力域为例：

1. **识别差距**：当前评分——质量规则制定1.8（已达二级）、质量检测执行1.5（一级末期）、质量问题处理0.8（一级初期）、质量报告分析0.5（一级以下）

2. **确定目标**：一期目标各能力项达到二级（均≥2分），规划配置：质量规则≥5,000条；检测任务支持定时+实时两种模式；问题自动生成工单并闭环管理；三级质量看板上线。

3. **需求提取**：
   - 质量规则制定（0.8→1）：新增自定义SQL规则模板
   - 质量检测执行（0.5→1）：新增实时流式检测能力
   - 质量问题处理（0→1）：新建质量工单全流程管理模块
   - 质量报告分析（0→1）：新建集团-区域-分公司三级看板

4. **权重设定**：质量问题处理权重最高（0.35），因它是核心短板且直接影响质量闭环率。
