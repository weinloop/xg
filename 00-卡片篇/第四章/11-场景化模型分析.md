# 卡片11：场景化模型分析

---

## 📖 教材原文

> 场景化模型分析是一种将信息系统应用场景与实际业务活动场景及需求相结合的分析方法。通过对特定场景的分析，可以在信息系统规划过程中更好地理解系统的功能、性能需求，以及其价值定位，并为系统建设与发展提供指导。

### 一、场景拆解与选择（六步法）

1. 从信息系统**目标价值链**角度进行结构化拆解
2. 从业务发展**能力链**角度进行结构化拆解
3. 将价值链与能力链**交叉融合**，找出融合点
4. 在融合点中找出**关键价值点**（特定价值+关键价值）
5. 对关键价值点**聚合**，定义出场景化分析需求
6. 评价是否具备场景化分析条件，形成分析清单

### 二、场景化模型构建与分析（八要素）

| 要素 | 分析内容 |
|------|---------|
| 场景定义 | 目标与范围明确：业务背景/特点/目标/需求 + 业务环境和利益相关者 |
| 角色分析 | 不同角色的职责/需求/行为 + 在业务活动中的作用和影响 |
| 业务分析 | 业务模式/流程/需求/发展/客户需求 + 业务目标与系统价值关系 |
| 数据分析 | 数据流梳理：来源/类型/结构/使用方式 + 关键数据资源需求及管理方法 |
| 技术分析 | 管理/工艺/决策/信息/业务逻辑等技术现状与发展需求 |
| 组织分析 | 组织文化/人员技能/组织流程 + 系统在组织中的角色和影响力 |
| 风险分析 | 技术风险/安全风险/管理风险 + 风险管理策略 |
| 政策与法律分析 | 政策法规要求 + 业务系统融合后的合规性 |

### 三、场景化模型分析应用三阶段

- **规划前**：识别关键需求、明确规划目标、分析环境资源
- **规划中**：评估方案可行性和风险、进行决策支持
- **规划后**：监控评估实施效果、进行调整和优化

### 四、关键价值与优缺点

| 优点 | 缺点 |
|------|------|
| 贴近实际需求、准确理解需求 | 数据采集和分析困难，增加时间和成本 |
| 提供指导和参考，减少错误偏差 | 业务场景持续变化，可行性受限 |
| 提高系统适应性和可用性 | — |

**四大关键价值**：①提高规划决策的科学性和实践性；②确保规划与组织发展的衔接；③降低规划风险和成本；④促进共识和沟通

## 🔑 背诵提炼

| 阶段 | 核心方法 | 产出 |
|:---:|---------|------|
| 拆解选择 | 价值链×能力链→融合点→关键价值→聚合清单 | 场景分析清单 |
| 模型构建 | 八要素分析（场景/角色/业务/数据/技术/组织/风险/法律） | 场景分析模型 |
| 三阶段应用 | 规划前→规划中→规划后 | 全周期价值 |

**核心公式：** 价值链 ∩ 能力链 = 融合点 → 关键价值点 → 场景化分析

---

## 🧠 背诵口诀

> **六选：价能交关聚评** — 价值链拆解、能力链拆解、交叉融合、关键价值、聚合定义、条件评价

> **八要素：景角业数技组险法** — 场景定义、角色分析、业务分析、数据分析、技术分析、组织分析、风险分析、政策法律分析

> **三阶段：前中后** — 规划前识别、规划中评估、规划后监控

## 🏢 案例应用

**场景**：华航集团数据资产智能管理平台

**问题1**：请运用场景化模型分析方法，为华航平台进行"数据质量治理"场景拆解和选择。

**参考答案**：

**第一步-价值链拆解**：华航数据资产管理平台的目标价值链包括：数据可见（资产目录）、数据可管（质量治理）、数据可用（共享交换）、数据可控（安全管控）、数据智能（血缘+问答）。

**第二步-能力链拆解**：从业务发展看，核心能力需求包括：旅客服务质量提升、航班运行安全可靠、财务结算精准高效、机务维修科学经济。

**第三步-交叉融合**：质量治理价值链 × 旅客服务能力链 → 旅客数据质量场景（6个系统12种旅客ID统一）；质量治理价值链 × 航班运行能力链 → 航班数据及时性场景（起降数据延迟≤5分钟）；质量治理价值链 × 财务结算能力链 → 收入一致性场景（客运收入与票证结算一致）。

**第四步-关键价值点**：旅客数据质量问题影响最大（直接关系客户体验和常旅客营销），且PSS系统数据量大、涉及面广，是最关键价值点。

**第五步-聚合定义**：将"旅客数据统一化"和"航班数据及时性"聚合为"核心业务数据质量治理"场景。

**第六步-条件评价**：旅客系统虽然复杂（6个系统），但各系统接口文档相对完整，业务团队配合意愿高，具备场景化分析条件。而货运系统数据较弱，暂不列为重点场景。

**问题2**：针对"核心业务数据质量治理"场景，请按八要素构建场景化模型。

**参考答案**：

- **场景定义**：对旅客服务和航班运行相关的核心数据进行统一质量管理，范围覆盖PSS/常旅客/客服/航食等6个旅客系统和FOC/ACARS航班系统
- **角色分析**：数据管家（制定规则）、业务分析师（发现质量问题）、IT运维（执行检测）、质量管理员（工单分派与验收）
- **业务分析**：旅客系统间数据不一致导致会员权益错配（年损失约200万）；航班数据延迟影响运力调配决策
- **数据分析**：旅客数据涉及姓名/证件号/会员等级/里程/偏好等字段；航班数据涉及起降时间/机型/机组/油量等字段
- **技术分析**：采用规则引擎实现自动化质量检测；利用血缘分析追溯质量根因
- **组织分析**：需打破旅客服务部、IT部、财务部之间的数据壁垒，由数据治理委员会统一协调
- **风险分析**：旅客数据质量问题可能导致数据安全法合规风险（个人信息不准确）
- **政策法律分析**：需符合《个人信息保护法》对个人信息准确性的要求
