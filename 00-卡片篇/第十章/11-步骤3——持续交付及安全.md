# 卡片11：步骤3——持续交付及安全

---

## 📖 教材原文

前两个步骤完成了微服务运行、运营的基础能力。有了部署运维平台和服务管理治理能力，就可以侧重提升研发端的持续交付能力。

以DevOps理论为指导，构建持续集成、持续部署、持续交付、持续监控、持续反馈的闭环流程。之所以要先建设容器云平台和服务管理治理能力，就是要提前准备好支撑弹性伸缩、可视化、可观察、故障隔离、容错、故障自恢复等能力，才能支撑各团队的持续交付要求。

**DevOps核心**：DevOps是一种思想和方法论，核心是协作反馈，只有及时反馈才能反思和改进。

**组织挑战**：组织架构的优化可能是难点。组织领导要能理解DevOps理念并愿意尝试改进；DevOps体系可能涉及众多组件和工具，每种方式都花费大量人力和时间。

**工具链复杂性**：如用开源工具，持续集成和持续交付流程涉及开发、源码管理、源码检查、单元测试、用例管理、构建、安全测试、交付管理等众多工具，仅打通认证权限管理就不容易。

**自研建议**：如果有研发能力，建议尽可能自研或合作研发，为系统融合打好基础，避免众多开源第三方工具带来众多集成问题。

**安全措施**：认证和权限是DevOps体系中的基础安全措施。代码安全检查、镜像安全检查、系统安全、应用安全、接口安全、容器安全等都需要在DevOps工具链和流水线实施及使用过程中逐步完善，以提升云原生的整体安全性。

---

## 🔑 背诵提炼

1. **CD五环**：持续集成→持续部署→持续交付→持续监控→持续反馈（闭环）
2. **DevOps核心公式**：协作+反馈=反思+改进
3. **组织三关**：领导理解+工具选择+权限打通
4. **自研优于开源堆砌**：减少集成问题
5. **安全贯穿全流程**：代码安全→镜像安全→系统安全→应用安全→接口安全→容器安全

## 🏢 案例应用

**场景**：华航平台开发团队分散在3个城市，代码提交频繁但上线周期长达2周，且出现过两次因测试遗漏导致的生产事故。

**问题**：请为华航平台设计DevOps持续交付流水线和安全左移方案。

**参考答案**：

**CI/CD流水线设计（基于CODING DevOps + TKE）**：

```
代码提交(Git) 
  → 代码扫描(SonarQube) + 单元测试(JUnit/Jest) 
  → 构建镜像(Docker多阶段) 
  → 镜像扫描(Trivy漏洞扫描) 
  → 推送TCR镜像仓库 
  → 部署测试环境(K8s Helm) 
  → 自动化测试(Selenium/API Test) 
  → 部署预发环境(灰度10%) 
  → 生产发布(滚动更新/蓝绿部署) 
  → 持续监控(CLS+Prometheus告警)
```

**安全左移措施**：
- 代码提交即触发SAST（SonarQube），阻断高危漏洞合入
- PR/MR必须通过安全团队CR，安全规则写入`.gitlab-ci.yml`
- 镜像构建后Trivy扫描，有CRITICAL漏洞禁止推送
- 部署前K8s Admission Webhook校验Pod Security Policy

**组织协作**：
- 每个微服务团队包含1名SRE（站点可靠性工程师）嵌入开发
- 每日站会同步开发/测试/运维三方进度
- 反馈闭环：生产告警 → 自动创建Jira工单 → 5分钟内响应 → RCA文档沉淀
