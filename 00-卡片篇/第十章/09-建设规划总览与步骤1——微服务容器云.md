# 卡片09：建设规划总览与步骤1——微服务+容器云平台

---

## 📖 教材原文

**总览**：云原生架构体系内容众多，做不到一步到位，需要通过一系列项目持续完成相关能力。需基于"顶层规划＋分步实施"原则，将实施路线图定义为5个步骤：①微服务采用及运行环境容器云平台构建 → ②服务管理和治理 → ③持续交付及安全 → ④自服务敏捷响应基础设施 → ⑤增强生产环境韧性和安全性。

每个步骤可根据实际建设需要分为若干子项目，并可能需要多次迭代。

**步骤1：微服务采用及运行环境容器云平台构建**
云原生架构体系中，应用是交付业务价值的载体，微服务是构建业务应用的技术。经微服务架构分解的应用服务运行在容器中，所以第一步在采用微服务的同时需要构建容器环境支撑。

基于容器调度管理技术（如Kubernetes）构建组织内私有容器云平台，支撑微服务应用系统的部署、运行和管理。基于容器云平台实现：弹性扩展、服务路由、分发限流、健康检查、错误隔离、故障恢复、资源调度等。

**微服务设计方法**：
- 主流：基于DDD（领域驱动设计）分拆微服务。但DDD领域边界难以清晰定义，划分不合理易造成重复
- Martin Fowler建议：先建大一统系统，了解领域后再重构为微服务——有全局视角但大一统系统不易建设
- 「主数据驱动设计」（教材作者提出）：基于主数据设计微服务，天然具备系统间可重用性；基于CDM（Common Data Model）易定义并完善主数据微服务，减少重复迭代

**实践建议**：以云原生12要素为指导设计微服务。容器云平台作为基础设施平台，需要规划采购服务器、存储、网络设备等，并根据微服务改造进度持续采购，建议前期做咨询、规划指导和培训。

## 🔑 背诵提炼

1. **五步路线**：微服容器 → 服务治理 → 持续交付 → 自服务基础设施 → 韧性安全
2. **步骤1核心双轨**：微服务设计（DDD/主数据驱动/12要素）+ 容器云平台（K8s）
3. **三种微服务设计方法**：
   - DDD：领域划分→简化业务关系，但边界不清、重复迭代
   - Fowler法：大一统系统→重构为微服务，全局视角但大一统难建
   - 主数据驱动：基于主数据（系统间共享高价值数据）设计→天然可重用，CDM加速完善

## 🧠 背诵口诀

五步路线：
> **服治交基安**（微服务容器→治理→交付→基础设施→安全韧性）

步骤1：
> **双轨并进：微设计+容平台**（微服务设计方法 + 容器云平台构建）

三设计法：
> **D界不清 → F大难建 → 主数可重**（DDD边界不清、Fowler大一统难建、主数据天然可重用）

K8s自服务能力：
> **弹路限检离复调**（弹性扩展、服务路由、分发限流、健康检查、错误隔离、故障恢复、资源调度）

## 🏢 案例应用

**场景**：华航集团数据资产智能管理平台启动云原生改造，需要选择微服务拆分方法和K8s平台方案。

**问题**：请你为华航平台推荐微服务设计方法并设计容器云平台架构。

**参考答案**：
采用「主数据驱动设计」方法，理由如下：

（1）**天然适配**：华航集团已建立企业级主数据管理（MDM），核心主数据包括：组织机构、人员、飞机、航线、资产分类等。以这些主数据为中心设计微服务天然具备跨系统可重用性——"资产目录微服务"不仅服务本平台，还可被财务/采购/维修等其他系统调用。

（2）**微服务拆分**：基于主数据+业务域，拆分7个微服务模块——数据采集Gateway、数据治理Engine、资产目录Service、质量监控Service、数据服务API、安全管控Service、运营分析Service。每个微服务独立代码库、独立CI/CD、独立部署。

（3）**容器云平台（基于腾讯云TKE）**：
- **集群规划**：1个管理集群+3个业务集群（开发/测试/生产），生产集群3个AZ各部署Master节点
- **节点策略**：计算密集型Worker（数据治理/质量监控）用C6型实例，存储密集型（ES/ClickHouse）用IT5型，常规服务用S5型
- **自服务能力**：HPA弹性扩缩、Ingress服务路由、NetworkPolicy网络隔离、Liveness/Readiness探针健康检查、PodDisruptionBudget故障恢复
- **镜像仓库**：腾讯云TCR企业版，存储微服务镜像+12要素配置注入

（4）**12要素落地**：每个微服务严格按12要素设计——统一代码仓（要素1）、依赖声明（要素2）、ConfigMap/Secret外置配置（要素3）、后端服务化为Service（要素4）、Docker多阶段构建分离（要素5）。
