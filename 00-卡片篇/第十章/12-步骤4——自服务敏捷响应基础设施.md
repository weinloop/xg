# 卡片12：步骤4——自服务敏捷响应基础设施

---

## 📖 教材原文

基础设施大致划分为三个部分：**基础设施资源**、**支撑平台**和**纯技术工具**。

**基础设施资源**：可能有很多种异构资源和云平台，需要通过统一层次（如多云管理平台）来封装，提供统一的基础设施资源服务，隔离底层异构资源细节，简化应用资源调度。

**支撑平台**：主要是微服务开发、运行、运维的平台，例如持续交付平台、容器云平台等。

**纯技术工具**：与业务无关、围绕支撑平台周边的工具，比如消息平台（RabbitMQ/Kafka）、监控平台、权限管理平台、认证平台、人脸识别平台等。这些平台可以提取构建技术中台能力，各业务应用都可以复用这些能力。

**需要重点构建的自服务能力**包括：统一身份认证和权限服务、日志服务、配置服务、监控服务、告警服务、安全服务、AI服务（人脸/文字/图像/语音识别、NLP、知识图谱、算法等）、消息服务、调度服务等基础服务和CI/CD研发流程服务等。

**基础设施资源自服务敏捷响应**是所有服务实现敏捷响应的前提。由于基础设施资源多种多样，需要考虑构建统一的基础设施资源管理平台或多云管理平台。

**组织架构同步调整建议**：
- 基础设施资源团队：运维运营基础设施资源，为平台和工具提供资源服务
- 平台团队：运维运营平台
- 工具团队：持续研发工具和技术中台服务
- 应用研发团队：专注于业务应用微服务研发，使用自服务的资源、平台、工具实现全生命周期管理

---

## 🔑 背诵提炼

1. **基础设施三维**：资源（异构封装） + 平台（Dev/运维平台） + 工具（技术中台）
2. **核心目标**：让开发者自助使用资源/平台/工具，不需运维介入
3. **关键技术中台能力**：认证权限、日志、配置、监控告警、安全、AI、消息、调度、CI/CD
4. **组织四团队**：基础设施团队 + 平台团队 + 工具团队 + 应用研发团队

基础设施三部分：

## 🏢 案例应用

**场景**：华航平台微服务数量已增长至20+，运维团队疲于应付各团队的资源申请（服务器、数据库、消息队列等），每次申请平均等待3天。

**问题**：请设计华航平台的自服务敏捷基础设施方案，实现开发者自助获取资源。

**参考答案**：

**统一资源管理平台设计**：
（1）**多云管理平台**：基于Terraform + 腾讯云API构建统一资源申请门户。开发者通过Web控制台选择：资源类型（TKE命名空间/TDSQL/Redis/COS/CKafka）、规格、环境（dev/test/staging/prod），提交后Terraform自动编排创建。
（2）**TKE命名空间自助申请**：每个微服务团队获得独立K8s Namespace，通过ResourceQuota限制CPU/内存/存储上限，防止资源滥用。

**技术中台服务目录（Service Catalog）**：
| 服务 | 自助方式 | SLA |
|------|---------|-----|
| MySQL | TDSQL自动创建+连接串注入ConfigMap | 99.99% |
| Redis | 申请命名空间级Redis实例 | 99.99% |
| Kafka | CKafka Topic自助创建+ACL权限 | 99.95% |
| ES | 自动创建索引模板 | 99.9% |
| 日志 | Pod自动注入CLS采集Sidecar | — |
| 监控 | Prometheus自动发现+预置Dashboard | — |

**组织调整**：
- 平台工程团队（3人）：运维TKE+TDSQL+基础设施，构建Terraform模块
- 工具团队（2人）：维护CI/CD流水线、监控、日志平台
- 应用研发团队（7个微服务团队）：专注业务，通过自助门户获取资源，从申请到可用<30分钟（原3天）
