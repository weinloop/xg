# 📇 卡片14：TOGAF

---

## 📖 教材原文

> TOGAF是一种开放式企业架构框架标准，它基于一个迭代的过程模型，由一些最佳实践和一套可重用的现有架构资产支持，用于设计、评估并建立适合的企业IT架构。

### TOGAF的4个目标

- 确保从关键利益相关方到团队成员的所有用户都使用**相同语言**，打破沟通障碍
- 避免被"锁定"到企业架构的**专有解决方案**（内部使用免费）
- **节省时间和金钱**，更有效地利用资源
- 实现可观的**投资回报**（ROI）

### TOGAF 9版本的6个组件

| 组件 | 说明 |
|------|------|
| **架构开发方法(ADM)** | TOGAF核心，开发企业架构的分步方法 |
| **ADM指南和技术** | 可用于应用ADM的指南和技术集合 |
| **内容框架** | 架构工件的结构化元模型、可重用架构构件块、典型架构可交付成果概述 |
| **企业连续体和工具** | 对企业内部架构活动输出进行分类和存储的分类法和工具 |
| **TOGAF参考模型** | 技术参考模型和集成信息基础设施参考模型 |
| **架构能力框架** | 建立和运营架构实践所需的组织、流程、技能、角色和职责 |

### ADM全生命周期10个阶段

| 阶段 | 主要活动 |
|------|---------|
| **预备阶段** | 定义组织机构、特定架构框架、架构原则和工具 |
| **需求管理** | 需求的识别、保管和交付，按优先级顺序处理 |
| **阶段A：架构愿景** | 设置范围/约束/期望，创建架构愿景（利益相关者、业务上下文、工作说明书） |
| **阶段B：业务架构** | 开发基线架构描述→目标架构描述→执行差距分析 |
| **阶段C：信息系统架构** | 应用架构和数据架构两个层面，同样：基线→目标→差距 |
| **阶段D：技术架构** | 同上：基线→目标→差距 |
| **阶段E：机会和解决方案** | 初步实施规划，确定构建块交付形式，决定路径（制造/购买/重用/外包/商用/开源） |
| **阶段F：迁移规划** | 绩效分析和风险评估，制订详细实施和迁移计划 |
| **阶段G：实施治理** | 定义架构限制+架构监督+发布架构合同+监测实施符合度 |
| **阶段H：架构变更治理** | 持续监测和变更管理，确保架构响应企业需求并将价值最大化 |

### ADM三级迭代

- **基于架构开发整体的迭代**：环形方式应用ADM，完成一个阶段后进入下一个阶段
- **多个开发阶段间的迭代**：完成技术架构后重新回到业务架构开发
- **一个阶段内部的迭代**：一个阶段内部多个开发活动对复杂内容进行迭代开发

## 🔑 背诵提炼

| 要素 | 核心要点 |
|------|---------|
| **定义** | 开放式企业架构框架，迭代过程+最佳实践+可重用资产 |
| **4目标** | 统一语言/避免锁定/省时省钱/投资回报 |
| **6组件** | ADM(核心)/指南/内容框架/企业连续体/参考模型/能力框架 |
| **ADM 10阶段** | 预备→需求→A(愿景)→B(业务)→C(信息系统)→D(技术)→E(机会)→F(迁移)→G(实施)→H(变更) |
| **3级迭代** | 整体迭代/阶段间迭代/阶段内迭代 |

## 🧠 背诵口诀

```
TOGAF四目标（语锁钱报），
六组件核心是ADM，
十阶段环形迭代走（预需AB CD EF GH），
三级迭代灵活用（整/间/内）。

预——预备阶段定原则，
需——需求管理保交付，
A——架构愿景设范围，
B——业务架构基线标，
C——信息系统分应用数，
D——技术架构定平台，
E——机会方案选路径（制购重用外包开源），
F——迁移规划排风险，
G——实施治理监符合，
H——变更治理续优化。

B/C/D三个阶段三步走：基线描述→目标描述→差距分析
```

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团作为大型航空运输企业，业务覆盖全产业链，IT架构复杂。集团信息中心计划参照TOGAF框架，对企业IT架构进行系统规划。

**考题形式**：

> 华航集团信息中心拟采用TOGAF框架指导企业IT架构规划。请结合ADM全生命周期模型，说明华航集团数据资产智能管理平台如何在各阶段开展架构开发工作。

**参考答案要点**：

| ADM阶段 | 华航项目对应活动 |
|---------|----------------|
| **预备阶段** | 成立集团数据治理委员会，制定架构原则（统一数据标准/共享优先/安全合规），选定工具（Hudi/ClickHouse/K8s） |
| **需求管理** | 收集5大痛点+4大业务域需求，按优先级排序：①资产目录→②质量监控→③数据服务→④安全管控 |
| **A-架构愿景** | 创建愿景：构建覆盖29节点、10万+资产目录的统一数据资产平台，成为航空行业数据治理标杆 |
| **B-业务架构** | 基线：当前各业务系统数据独立管理；目标：统一的资产管理/质量监控/服务编排/安全管控四大业务域 |
| **C-信息系统架构** | 应用架构：27个微服务的Spring Cloud应用集群；数据架构：Hudi数据湖+ClickHouse数仓+MySQL元数据库 |
| **D-技术架构** | K8s容器编排+Spark/Flink实时计算+Kafka消息队列+Redis缓存+OAuth2.0认证 |
| **E-机会和解决方案** | 制造（自研核心资产管理和质量引擎）+购买（采购数据安全分类分级工具）+重用（复用集团现有统一认证平台）+开源（Hudi/Kafka/ClickHouse） |
| **F-迁移规划** | 4迭代逐步迁移，每迭代风险评估（第1迭代：资产目录低风险先行；第3迭代：实时服务高风险需充分验证） |
| **G-实施治理** | 每迭代设置架构评审节点，确保实施符合架构规范；组建设计评审委员会（数据治理委员会+外部架构专家） |
| **H-架构变更治理** | 建立变更管理流程：业务需求变更→影响评估→架构评审→批准实施；季度架构健康度评估 |
