# 📇 卡片17：软件工厂与传统开发对比

---

## 📖 教材原文

> 软件工厂与传统开发在一些方面存在差异，软件工厂更加注重灵活性、自动化和创新，强调持续快速交付、质量保证和高效协作等。

### 1. 敏捷交付

敏捷交付是软件工厂实现快速、灵活、高质量交付的关键方法之一。强调通过迭代、协作和自组织的方式，快速响应变化并持续交付软件产品。

**8个关键实践**：

| 实践 | 内容 |
|------|------|
| **敏捷开发方法** | Scrum、Kanban等，自组织协作+短周期迭代 |
| **用户需求和产品回溯日志** | 用户需求表达需求→产品回溯日志（优先级排序需求列表） |
| **迭代开发** | 迭代周期2周或4周，每迭代完成部分功能+测试验证 |
| **自动化测试** | 自动化测试脚本执行功能/性能/安全测试，持续运行及早发现问题 |
| **持续集成和持续交付(CI/CD)** | 频繁集成代码→自动化构建测试→自动化部署发布 |
| **产品质量和用户反馈** | 持续测试验证+及时修复+倾听用户反馈调整优化 |
| **团队协作和沟通** | 日常站会+迭代评审会+冲刺回顾会 |
| **可视化和透明度** | 看板、迭代仪表盘、信息可视化工具展示项目状态和进展 |

### 2. 流水线作业

将软件开发过程划分为不同的环节和任务，通过流水线方式连接起来，实现高效、规范和持续的软件开发。每个环节有明确的输入和输出，通过任务流转和流转规则实现衔接。

**6个关键内容**：

| 内容 | 说明 |
|------|------|
| **环节划分** | 需求分析→设计→编码→测试→部署等，每环节负责特定任务，有明确输入/输出 |
| **任务定义** | 每环节任务的输入要求、处理规则、输出要求和质量标准 |
| **流转规则** | 任务从一个环节传递到下一个环节的条件和方式（依赖状态/质量标准确定） |
| **并行处理** | 独立任务并行处理以缩短时间，确保任务间流转和依赖关系合理处理 |
| **自动化支持** | 自动化工具支持任务的处理、流转、测试和部署 |
| **监控和优化** | 监控任务状态和流转情况，评估效率和质量的优化 |

### 3. 安全可靠

保障软件系统的安全性和可靠性。

**（1）安全开发实践**：安全需求分析→安全设计原则（最小权限/防御性编程/数据加密/身份验证）→安全编码规范（避免不安全函数/防注入/XSS）→安全测试和审计（漏洞扫描/代码审查/渗透测试）

**（2）数据和隐私保护**：数据加密→访问控制（身份验证/权限管理/访问审计）→隐私保护（匿名化/数据最小化/隐私政策）

**（3）持续集成和持续交付(CI/CD)**：自动构建和测试→持续部署和发布→监控和告警

**（4）团队安全培训和安全意识**：定期安全培训+安全意识培养

### 4. 协同开发

团队成员通过有效的协作和协同工具，共同参与软件开发项目。

**（1）团队协作和沟通**：日常站会（分享进展/问题/需求）、迭代评审会（回顾已完成+收集反馈）、冲刺回顾会（总结经验+改进措施）

**（2）共享知识和经验**：文档和知识库、代码审查、技术分享会

**（3）协同工具和平台**：即时通信（微信/钉钉）、在线文档协作（WPS）、代码托管和协作平台、团队协作工具（金山协作）、数字协同平台（WPS 365）

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台采用软件工厂模式开发，与传统开发模式相比，需要在敏捷交付、流水线作业、安全可靠、协同开发四个维度上体现优势。

**考题形式**：

> 在"华航集团数据资产智能管理平台"项目中，开发团队采用软件工厂模式替代传统开发模式。请从敏捷交付、流水线作业、安全可靠、协同开发四个方面，说明软件工厂模式在本项目中的具体实践。

**参考答案要点**：

**（1）敏捷交付**：

| 实践 | 华航项目做法 |
|------|------------|
| 敏捷开发方法 | 采用Scrum，2周一个Sprint，30人团队分为5个Squad（资产/质量/服务/安全/数据） |
| 产品回溯日志 | 使用JIRA管理用户故事，按业务价值排序（P0:资产目录→P1:质量监控→P2:数据服务→P3:安全管控） |
| 迭代开发 | 每个Sprint交付1-2个可工作的功能增量，如Sprint1交付资产目录列表页+搜索功能 |
| 自动化测试 | 单元测试(JUnit)+API测试(REST Assured)+UI测试(Selenium)，流水线自动执行 |
| CI/CD | GitLab CI Pipeline：代码提交→编译→单元测试→SonarQube扫描→Docker镜像构建→K8s自动部署 |
| 用户反馈 | 每迭代结束邀请10名数据分析师试用并反馈，需求变更走评审流程 |

**（2）流水线作业**：

```
需求分析 → 系统设计 → 编码开发 → 代码审查 → 单元测试
    ↓                                              ↓
  用户确认                                      集成测试
    ↓                                              ↓
  Sprint评审  ←──  验收测试  ←──  预发布环境  ←──  安全扫描
```

- **环节划分**：明确7个环节（需求→设计→编码→审查→测试→扫描→验收）
- **任务定义**：每个User Story从"待开发"→"开发中"→"待审查"→"待测试"→"已完成"状态流转
- **流转规则**：代码必须通过Code Review和自动化测试才能合并至主分支
- **并行处理**：5个Squad并行开发，通过API契约测试确保模块间兼容
- **自动化支持**：GitLab CI全自动化流水线，从提交到部署全程无人值守

**（3）安全可靠**：
- 安全需求分析阶段明确5项安全需求：数据分级管控、旅客信息脱敏、操作审计追溯、API访问认证、传输加密
- 安全编码规范：禁止SQL拼接（统一使用MyBatis参数化查询）、输入校验（OWASP ESAPI）
- CI/CD安全集成：每次Pipeline自动执行SonarQube代码安全扫描+Trivy镜像漏洞扫描，高危漏洞自动阻断发布

**（4）协同开发**：
- **每日站会**：9:30全团队15分钟站会（线上+线下）
- **Sprint评审**：每双周周五下午，邀请集团数据治理委员会代表参与
- **代码审查**：GitLab Merge Request机制，至少1名高级工程师Approve
- **知识共享**：Confluence建设团队Wiki，每周三下午技术分享会
- **协同工具**：企业微信（即时通信）+ GitLab（代码协作）+ JIRA（任务管理）+ Confluence（文档协作）
