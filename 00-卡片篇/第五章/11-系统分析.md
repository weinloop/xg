# 📇 卡片11：系统分析

---

## 📖 教材原文

> 系统分析是应用系统思想和方法，把复杂的对象分解成简单的组成部分，找出这些部分的基本属性和彼此间的关系。这一阶段产生的系统说明书（需求规格说明书）既是后续开发工作的依据，也是衡量一个信息系统优劣的依据。系统分析是系统开发中最重要也是最困难的阶段。

### 系统分析的任务

系统分析阶段的基本任务是：系统分析师与用户在一起，充分了解用户的要求，并把双方的理解用系统说明书表达出来。系统说明书审核通过后，将成为系统设计的依据，也是将来验收系统的依据。

要回答新系统"**做什么**"这个关键性问题。只有明确了问题，才有可能解决问题。拟建的信息系统既要源于原系统，又要高于原系统。

### 系统分析的过程（三个阶段）

**阶段一：问题分析**

问题分析是系统分析的起点，通过详细调查全面深入理解用户的业务，找出用户面临的问题，准确把握用户真正的需要。

问题分析时重点明确：
- 系统建设的背景：为什么会有这个项目？没有这个系统会怎样？
- 系统解决的问题：涉及什么人/什么单位？目标是什么？范围是什么？成功标准是什么？
- 找出关键利益相关人员及待解决的问题。尽可能多地列出可能的利益相关人员，并列出每类利益相关人员需要解决的问题。

需求引导方法：**原型法**（快速构造原型请用户提修改意见，投入额外工作量但直观有效）；**JAD会议**（联合应用开发，将所有利益相关者集中到一起共同讨论，发挥群体智慧但难以控制）；**观摩法**（参观同行业成功信息系统，通过类比思维获得需求）。

**阶段二：需求分析**

分析员与用户充分交流，准确、完整地获取系统需求。系统需求包括：
- **功能性需求**：系统必须完成的所有功能的必要性和相容性，包括软件功能需求和数据需求
- **非功能性需求**：也称为技术性需求，如响应时间、安全性、可靠性、易用性等（例如必须支持100个并发用户，保存订单时间不超过0.5秒）

常用的需求分析方法：
- **面向过程的结构化方法**：自顶向下逐层分解，数据流图(DFD)最重要
- **面向数据的信息工程方法**：以数据为中心，实体关系图(E-R图)最重要
- **基于UML的用例驱动方法**：用例图+领域类图，兼顾功能和数据，目前最为流行
- **基于敏捷过程的用户故事**：非正式自然语言，轻量级描述，用于快速迭代（如Scrum）

**阶段三：需求定义**

整理并建立最终的需求模型，详细定义和描述每项需求，确认约束条件及限制，编写需求规格说明。定义好的需求规格一般用Excel表格或Word文档保存。借助软件工具进行需求采集和管理可实现需求的组织、跟踪、审查、确认、变更和验证。

### 系统说明书

系统说明书是系统分析阶段的技术文档，一旦审议通过则成为有约束力的指导性文件，成为用户与技术人员之间的技术合同。

**特征**：正确性、完整性、一致性、无二义性、可修改性、可跟踪性。

**内容**：
（1）引言：项目名称、目标、功能、背景、引用资料、专门术语
（2）概述：主要工作内容、现行系统调查情况、系统功能需求（数据流模型/用例模型/用户故事）、系统数据需求（领域类图/实体关系图）、系统其他需求（性能/安全/硬件环境）
（3）实施计划：工作任务分解、进度（PERT图/甘特图）、预算

审议通过后系统说明书成为共同意志，系统分析阶段宣告结束。若审议不满意或有重大遗漏误解则返回重新分析。

## 🔑 背诵提炼

| 要素 | 核心要点 |
|------|---------|
| **任务** | 回答"做什么"→充分了解用户要求→用系统说明书表达→设计依据+验收依据 |
| **三阶段** | 问题分析（调研+需求引导）→需求分析（功能性+非功能性）→需求定义（需求规格说明） |
| **四种分析方法** | 结构化(DFD) / 信息工程(E-R) / UML用例驱动 / 敏捷用户故事 |
| **说明书特征** | 正确/完整/一致/无二义/可修改/可跟踪 |
| **说明书内容** | 引言 + 概述（工作内容/现状/功能需求/数据需求/其他需求）+ 实施计划（分解/进度/预算） |

**需求引导三法**：原型法（直观+额外成本）/ JAD会议（群体智慧+难控制）/ 观摩法（类比+缩短周期）

## 🧠 背诵口诀

```
系统分析三阶段（问需定），
四种方法来建模（结信用敏），
说明书具六特征（正完一二可修踪），
三块内容作合同（引概施）。

问——问题分析找根源（背景/目标/利益人），
需——需求分析分两类（功能+非功能），
定——需求定义规约成（模型+约束+规格）。

结——结构化DFD流图，
信——信息工程E-R图，
用——UML用例最流行，
敏——敏捷故事轻量级。

说明书内容：引概施（引言/概述/实施计划）
```

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台完成详细调研后，进入系统分析阶段。

**考题形式**：

> "华航集团数据资产智能管理平台"项目已完成详细调研，现在进入系统分析阶段。请按系统分析的三个阶段，说明你将如何完成该平台的系统分析工作，并编写系统说明书的主要内容。

**参考答案要点**：

**（1）问题分析阶段**：

- **系统建设背景**：数据孤岛/数据质量/数据共享/数据安全/数据价值五大痛点；集团2024年3月数据治理委员会已将平台列为年度一号工程。
- **关键利益相关人员**：
  - 集团数据治理委员会：需要平台实现数据资产的"可见可管可用可控"
  - 数据分析师（2000+人）：需要快速找到高质量数据，减少70%查找时间
  - 数据管理员：需要统一的数据编目和质量监控工具
  - IT运维团队：需要统一的系统对接和运维管理
  - 合规审计部门：需要数据安全流转追踪和审计能力
- **需求引导**：组织3场JAD会议（分别邀请数据分析师、数据管理员、IT运维代表），使用观摩法参观某大型互联网公司的数据治理平台，快速建立需求共识。

**（2）需求分析阶段**：

| 需求类型 | 具体内容 |
|---------|---------|
| **功能性需求** | ①数据资产自动采集与编目（支持120套系统接入）；②数据质量规则配置与自动检核（≥5000条规则）；③数据资产智能搜索与推荐；④统一数据服务API（≥10亿次/年调用）；⑤数据安全分级与访问控制 |
| **非功能性需求** | ①并发用户≥5000；②页面响应≤2秒；③可用性≥99.99%；④支持29个节点全覆盖；⑤数据安全0重大事件 |

**分析方法选择**：
- 以**UML用例驱动方法**为主（目前最为流行，兼顾功能和数据），绘制用例图（资产管理员编目资产、数据分析师搜索资产、质量管理员配置规则等）
- 辅以**结构化方法**绘制顶层数据流图（120套系统→数据采集→数据湖→数据处理→数据服务→用户）

**（3）需求定义阶段**：
编写《华航集团数据资产智能管理平台需求规格说明书》，使用JIRA+Confluence进行需求管理，每条需求建立跟踪矩阵（需求→设计→编码→测试）。

**（4）系统说明书主要内容**：

| 部分 | 内容 |
|------|------|
| 引言 | 项目名称（华航集团数据资产智能管理平台）、目标（可见可管可用可控）、背景（五大痛点+三年规划）、引用文件（招标书HC-2024-DATA-001） |
| 概述-工作内容 | 完成29节点调研、6场座谈会、120套系统接口分析 |
| 概述-现行系统 | 120套系统独立运行、数据标准不统一、跨系统整合困难 |
| 概述-功能需求 | 用例模型（4大业务域/27个用例）+数据流图 |
| 概述-数据需求 | 领域类图（Asset/QualityRule/DataService/SecurityPolicy） |
| 概述-其他需求 | 5000并发、2秒响应、99.99%可用性、0重大安全事件 |
| 实施计划 | 4迭代/14个月、30人团队、580万/年预算 |
