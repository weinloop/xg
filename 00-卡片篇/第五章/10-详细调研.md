# 📇 卡片10：详细调研

---

## 📖 教材原文

> 项目的可行性一旦被认定，系统的建设就进入实质性的阶段。通过初步调研，已对组织、系统功能等有了大致的了解，但对具体的业务处理过程及方法仍不十分清楚，需要做进一步的详细调研。详细调研是系统工作建设中最重要的环节之一，实事求是地全面调查是分析与设计的基础。

### 详细调研的目标

详细调研的对象是现行系统。目的在于**完整掌握现行系统的现状，查明其执行过程，发现问题和薄弱环节，收集资料和数据，为下一步的系统分析和提出新系统的逻辑设计做好准备**。具体调研内容包括管理业务状况与数据流程的调查和分析。

### 详细调研的范围（9个方面）

①组织和功能业务；②组织目标和发展战略；③工艺流程和产品构成；④数据和数据流；⑤业务流程和工作形式；⑥管理方式和具体业务的管理方法；⑦决策方式和决策过程；⑧可用资源和限制条件；⑨现存问题和改进意见。

### 详细调研的6项原则

**（1）自顶向下全面展开**：从组织管理最顶层开始，逐层向下调研，避免被庞大机构搞得不知所措或顾此失彼。

**（2）用户参与**：使用部门的业务人员、领导人员与设计部门的系统分析人员、系统设计人员共同进行，互补不足。

**（3）分析系统有无改进的可能性**：搞清楚管理工作存在的道理、环境条件及详细过程，再通过系统分析讨论优化的可行性。保持头脑冷静和思维开放，避免先入为主。

**（4）工程化的工作方式**：将每一步都事先计划好，对多人工作方法和调研所用的表格及图例统一规范化处理。所有规范化调研结果整理归档。

**（5）全面与重点相结合**：自顶向下全面展开，但每次都只侧重于与局部相关的分支。

**（6）主动沟通和友善的工作方式**：主动与被调研者在业务上沟通，创造积极、主动、友善的工作环境和人际关系。

### 详细调研的6项活动

**①收集信息**：通过各种方式获取所需信息。坚持**准确性、全面性、时效性**三原则。调研人员必须成为系统所支持的商业领域的专家。关键问题："我们是否已经拥有全部的信息来定义系统必须完成的工作"。

**②系统需求建模**：创建多种不同类型的模型帮助记录和关联系统需求。需求模型是逻辑模型（关注"需要什么"而非"采用什么形式"）。关键问题："我们需要系统做什么（详细的）"。

**③需求的优先级划分**：确定哪种系统需求和技术需求最重要。资源有限，需要判断系统的作用域。关键问题："系统要完成的最重要的事是什么"。

**④构建系统原型，检验可行性并发现问题**：构建发现原型的主要目的是更好地理解用户需求，检验业务需求某种实现方法的可行性。关键问题："我们是否可以证明这种技术能够实现我们想让它完成的那些功能"。

**⑤产生和评估候选方案**：定义并评估所有可能性，包括自行开发还是外包、成型的软件包是否满足需求。关键问题："创建系统的最好方案是什么"。

**⑥和管理部门一起复查各种建议**：项目经理提交解决方案并从管理部门获得最终决定。如果项目不值得做或公司目标改变，取消项目可能是最好的选择。关键问题："我们应不应该继续设计和实现我们提出的系统"。

### 详细调研的5种方法

| 方法 | 内容 |
|------|------|
| **收集资料** | 将各部门日常业务所用的计划、原始凭证、单据和报表格式或样本统统收集起来分类研究 |
| **发调研表征求意见** | 两种方式：重点询问（关键因素问卷→自顶向下访问）和全面业务需求问卷调研。常见调研表：上级要求/系统功能/业务流程/组织结构/信息需求/业务文件报表 |
| **开调研会** | 按职能部门召开座谈会或各类人员联合座谈，集中征询意见，适合定性调查 |
| **访问** | 会后进行个别访问，充分听取各方面要求和建议（弥补座谈会时间限制） |
| **深入实际的调研方式** | 直接参加业务实践，深入了解数据产生、传递、加工、存储、输出等环节。好办法：收集一套将来可供程序调试用的试验数据 |

自——自顶向下全展开，
用——用户参与共进行，

收——收集信息三原则（准全时），

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台可行性研究通过后，进入详细调研阶段。集团120套系统、29个节点、6大业务板块，调研工作量巨大。

**考题形式**：

> 在"华航集团数据资产智能管理平台"详细调研阶段，项目组需要对集团总部和28个分支节点进行全面调研。请结合详细调研的原则和方法，说明你将如何组织本次详细调研工作。

**参考答案要点**：

**（1）遵循6项原则组织调研**：

- **自顶向下**：先从集团数据治理委员会（最高层）开始→集团信息中心→5大区域中心IT部门→23家分公司IT部门→各业务部门的数据使用人员。
- **用户参与**：成立联合调研组，集团信息中心派出5名业务骨干+项目组派出8名系统分析师，混合编组，确保业务和技术互补。
- **分析改进可能性**：不预设"现有系统必须推倒重来"的立场，客观评估各系统数据接口的可用性。例如PSS系统虽老旧但数据接口稳定，可通过适配器对接而非重建。
- **工程化**：统一调研模板（系统信息采集表、数据流图模板、业务流程图模板、接口规范表），所有调研结果归档至Confluence。
- **全面与重点结合**：全面覆盖29个节点，但重点调研数据问题最突出的PSS（12种旅客ID编码）、FOC（航班数据）、FMS（财务数据）三大核心系统的数据现状。
- **主动沟通**：在5大区域中心各安排1名驻场分析师，与当地IT人员建立日常沟通机制。

**（2）执行6项调研活动**：

| 活动 | 华航项目实践 |
|------|------------|
| 收集信息 | 收集120套系统的数据字典、接口文档、报表模板；与各系统运维人员访谈 |
| 需求建模 | 绘制数据流图（DFD）：数据从业务系统→采集层→处理层→存储层→服务层；建立用例模型（资产编目/质量检核/服务调用等核心用例） |
| 优先级划分 | 确定最高优先级需求：①数据资产统一编目（解决"找数据难"）；②质量规则自动化（解决报表差异）；③统一API服务（解决共享审批慢） |
| 构建原型 | 开发资产目录浏览器原型（Web界面），邀请10名数据分析师试用并反馈，验证"智能推荐+全文搜索"的可行性 |
| 评估候选方案 | 比较三种方案——方案A（全自研）、方案B（采购商业数据治理平台+定制）、方案C（开源+定制开发）。从成本/周期/适配度评估，推荐方案C |
| 管理部门复查 | 向集团数据治理委员会提交调研报告和推荐方案，获得批准进入系统分析阶段 |

**（3）应用5种调研方法**：

| 方法 | 具体做法 |
|------|---------|
| 收集资料 | 收集120套系统的数据字典、接口规范、运行日志、故障报告 |
| 发调研表 | 向29个节点发放《数据资产管理需求调研表》，覆盖系统功能/信息需求/业务流程/问题意见 |
| 开调研会 | 按业务域召开6场座谈会（客运/货运/机务/航食/地服/综合管理），每场2小时 |
| 访问 | 会后对关键岗位人员（数据管理员/报表分析师/DBA）进行一对一深度访谈 |
| 深入实践 | 项目组分析师跟随数据分析师工作一周，亲身体验"70%时间用于找数据"的真实痛点 |
