# 📇 卡片06：数据定义

---

## 📖 教材原文

> 数据定义就是将需求分析阶段定义的数据对象转换为数据结构和数据库的过程，注意要对程序级的数据结构和应用级的数据库两个方面进行定义。程序级的数据结构定义是采用（伪）代码的方式定义数据结构（数据的组成、类型、默认值等信息）。应用级的数据库定义是根据用户的需求，在某一具体的数据库管理系统上定义数据库的结构和建立数据库的过程。

### 数据库定义过程的5个步骤

**（1）需求分析**
调查和分析用户的业务活动和数据的使用情况，弄清所用数据的种类、范围、数量以及它们在业务活动中交流的情况，确定用户对数据库系统的使用要求和各种约束条件等，形成用户需求规约。

**（2）定义概念模型**
对用户要求描述的现实世界，通过对其中信息的分类、聚集和概括，建立抽象的概念数据模型。概念模型应反映现实世界各部门的信息结构、信息流动情况、信息间的互相制约关系以及各部门对信息存储、查询和加工的要求等。所建立的模型应避开数据库在计算机上的具体实现细节，用一种抽象的形式表示出来。

**（3）定义逻辑模型**
主要工作是将现实世界的概念数据模型转成数据库的一种逻辑模式，即某种特定数据库管理系统所支持的逻辑数据模式。可能需要为各种数据处理应用领域产生相应的逻辑子模式。这一步的结果就是"逻辑数据库"。

**（4）定义物理数据库**
根据特定数据库管理系统所提供的多种存储结构和存取方法等依赖于具体计算机结构的各项物理设计措施，对具体的应用任务选定最合适的物理存储结构（包括文件类型、索引结构和数据的存放次序与位逻辑等）、存取方法和存取路径等。这一步的结果就是"物理数据库"。

**（5）验证**
收集数据并具体建立一个数据库，运行一些典型的应用任务来验证数据库定义的正确性和合理性。大型数据库的定义过程往往需要多次循环反复。当某步发现问题时，可能需要返回前面进行修改。因此，在做数据库定义时就应考虑到今后修改定义的可能性和方便性。

---

## 🔑 背诵提炼

| 步骤 | 核心内容 | 产出物 |
|------|---------|--------|
| **1.需求分析** | 调查数据种类/范围/数量，确定使用要求和约束条件 | 用户需求规约 |
| **2.概念模型** | 信息分类/聚集/概括，建立抽象概念模型；避开实现细节 | 概念数据模型（如E-R图） |
| **3.逻辑模型** | 概念模型→特定DBMS逻辑模式；可能产生逻辑子模式 | 逻辑数据库 |
| **4.物理数据库** | 选定存储结构、存取方法、存取路径 | 物理数据库 |
| **5.验证** | 建库+运行典型任务验证正确性；可能需要循环反复 | 验证报告 |

**两个层面的定义**：
- **程序级**：伪代码定义数据结构（组成/类型/默认值）
- **应用级**：在具体DBMS上定义数据库结构和建立数据库

---

## 🧠 背诵口诀

```
数据定义五分步（需概逻物验），
程序应用两层面（伪代码+DBMS）。

需——需求分析清种类（范围数量约束），
概——概念模型避细节（E-R抽象表示），
逻——逻辑模型选DBMS（转换逻辑模式），
物——物理存储定结构（文件索引路径），
验——建库验证反复调（循环修改方便）。
```

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台需要管理10万+数据资产目录，涉及结构化（数据库表）、半结构化（日志文件）、非结构化（文档/图片）多种数据形态，总数据量超50PB。

**考题形式**：

> 在"华航集团数据资产智能管理平台"项目中，需要管理和存储10万+数据资产目录、50PB数据量。请按照数据库定义的5个步骤，说明该平台的数据定义过程。

**参考答案要点**：

（1）**需求分析**：调研集团总部+5区域中心+23分公司的数据使用情况，摸清数据种类（结构化报表数据、半结构化系统日志、非结构化业务文档）、数据范围（120套业务系统）、数据量（50PB）、业务活动中的数据交流情况（日均数据调用量约2700万次）。形成《华航集团数据资产管理平台数据需求规约》。

（2）**定义概念模型**：建立抽象概念数据模型（E-R图），核心实体包括：数据资产（资产ID、名称、分类、所属系统、数据量、更新频率）、质量规则（规则ID、类型、阈值、适用资产）、数据服务（服务ID、接口类型、调用方式、SLA等级）、安全策略（策略ID、权限级别、加密方式）。反映实体间关系：一个资产对应多条质量规则，一个服务关联多个资产。

（3）**定义逻辑模型**：针对不同数据特点选择不同DBMS：
- 资产目录元数据→MySQL（结构化，支持事务和精确查询）
- 数据质量监控结果→ClickHouse（OLAP分析，支撑5000条规则实时计算）
- 数据湖存储→Apache Hudi（支持大规模数据更新和增量处理）
- 日志和文档→Elasticsearch（全文检索，支撑非结构化数据搜索）
- 高速缓存→Redis（支撑5000并发、≤2秒响应）

（4）**定义物理数据库**：
- MySQL：资产ID建立B+树主键索引，分类字段建立联合索引；
- ClickHouse：按日期分区，按区域中心排序键，位图索引加速过滤；
- Hudi：采用Copy-on-Write模式，按业务域分区，Parquet列式存储；
- 存取路径：OLTP走MySQL主库，OLAP走ClickHouse只读副本。

（5）**验证**：先搭建小规模验证环境（选取华北区域中心3个业务系统数据），运行典型任务（资产编目、质量检核、服务调用），验证正确性后逐步扩展到全部29个节点。

| 步骤 | 华航项目对应 | 产出物 |
|------|------------|--------|
| 需求分析 | 调研120系统+29节点数据现状 | 数据需求规约 |
| 概念模型 | E-R图（资产/规则/服务/安全） | 概念数据模型 |
| 逻辑模型 | MySQL+ClickHouse+Hudi+ES | 逻辑数据库设计 |
| 物理数据库 | B+树索引+分区+列式存储 | 物理数据库方案 |
| 验证 | 华北试点→全集团推广 | 验证报告 |
