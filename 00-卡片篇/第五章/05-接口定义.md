# 📇 卡片05：接口定义

---

## 📖 教材原文

> 接口定义确立了信息如何流入和流出系统，以及被定义为体系结构一部分的构件之间是如何通信的。接口规划设计有三个重要元素：①用户界面；②和其他系统、设备、网络或其他信息生产者或使用者的外部接口；③各种构件之间的内部接口。

### 接口定义的三个方面

**（1）用户接口**：用来说明将向用户提供的命令和它们的语法结构以及应用系统回答信息。

**（2）外部接口**：用来说明本系统同外界的所有接口的安排，包括软件与硬件之间的接口、本系统与各支持系统之间的接口关系。

**（3）内部接口**：用来说明本系统之内的各个系统元素之间的接口的安排。

接口定义的内容应包括：通信方法、协议、接口调用方法、功能内容、输入/输出参数、错误/例外机制等。

### 界面定义的三大原则

**（1）置用户于控制之下**
- 以不强迫用户进入不必要动作的方式定义交互模式
- 提供灵活的交互
- 允许用户交互被中断和撤销
- 当技能级别增长时可使交互流水化并允许定制
- 使用户隔离内部技术细节
- 允许用户和出现在屏幕上的对象直接交互

**（2）减少用户的记忆负担**
- 减少对短期记忆的要求
- 建立有意义的默认设置
- 定义直觉性的捷径
- 界面的视觉布局基于真实世界的隐喻
- 以不断进展的方式揭示信息

**（3）保持界面一致**
- 允许用户将当前任务放入有意义的语境，在应用系统内保持一致性
- 如果过去的交互模式已建立起用户期望，则不要改变它（除非不得已）

### 界面定义的4个核心问题

| 问题 | 要点 |
|------|------|
| **系统响应时间** | 响应时间过长、不同命令差别悬殊，用户难以接受 |
| **用户求助机制** | 集成式/叠加式两类；考虑帮助范围、求助途径、信息显示、返回方式 |
| **出错信息** | 用含义准确的术语，提供错误恢复建议，辅以听觉/视觉刺激 |
| **命令方式** | 键盘命令+菜单并存，供用户自由选用 |

界面定义是一个迭代过程，核心活动：①创建系统功能的外部模型；②确定人和计算机分别完成的任务；③考虑典型问题；④借助CASE工具构造界面原型；⑤评估界面质量。

## 🔑 背诵提炼

| 分类 | 核心要点 | 关键内容 |
|------|---------|---------|
| **用户接口** | 命令+语法+回答信息 | 面向用户的交互定义 |
| **外部接口** | 系统间+软硬件间接口安排 | 本系统与外界的全部接口 |
| **内部接口** | 系统内各元素间接口安排 | 模块间通信协议 |
| **界面三原则** | 控制/记忆/一致 | 置用户于控制之下+减少记忆负担+保持界面一致 |
| **四核心问题** | 响应时间/求助/出错/命令 | 迭代过程5项核心活动 |

外部接口系外联，
内部接口模块间。

控——用户控制不强迫，
记——减少记忆有默认，

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台需要提供统一的数据门户界面，同时需要与120余套现有业务系统和外部监管系统进行接口对接。

**考题形式**：

> 在"华航集团数据资产智能管理平台"中，平台需同时面向集团总部和28个分支节点用户，并集成120套现有业务系统。请从接口定义的角度，说明该平台的接口设计方案。

**参考答案要点**：

（1）**用户接口定义**：设计统一的数据门户（Web端+移动端），遵循界面三原则：
- **置用户于控制之下**：数据分析师可自定义数据看板布局，数据管理员可灵活配置质量规则模板，不强制固定流程；
- **减少记忆负担**：默认展示常用数据资产Top10，智能推荐关联数据集，提供数据资产搜索的直觉性快捷方式（如按业务域、数据类型快速筛选）；
- **保持界面一致**：29个节点采用统一的界面风格和操作逻辑，确保跨区域用户无需重新学习。

（2）**外部接口定义**：
- **与现有业务系统接口**：为120套业务系统（FOC/PSS/RMS/MRO/HR/FMS等）统一制定数据接入规范，采用RESTful API + Kafka消息队列两种方式，定义标准的数据交换格式（JSON Schema）、认证方式（OAuth2.0）、调用频率限制（各系统按数据量分级）；
- **与外部监管系统接口**：民航局数据报送接口采用SFTP文件传输方式，定义报送文件格式（CSV/XML）、加密方式（AES-256）、报送周期（日报/月报/季报）；
- **软件与硬件接口**：定义与Hadoop集群、GPU服务器的资源调度接口（YARN API）。

（3）**内部接口定义**：
- 27个微服务模块之间采用gRPC协议进行内部通信，定义统一的protobuf接口规范；
- 数据采集服务→数据清洗服务→数据存储服务→数据服务发布，各环节定义标准的输入/输出参数和错误处理机制（如重试策略、熔断降级）。

（4）**核心问题应对**：
- 响应时间：页面查询≤2秒，通过CDN+缓存（Redis）+数据库索引优化保障；
- 求助机制：集成式在线帮助系统，覆盖全部功能，支持关键词搜索+场景引导；
- 出错处理：错误信息以中文描述+建议操作（如"数据源连接失败，请检查网络或联系系统管理员xxx"）；
- 命令方式：提供可视化拖拽操作+高级命令行查询（SQL编辑器）并存。

| 接口类型 | 技术方案 | 关键参数 |
|---------|---------|---------|
| 用户接口 | Web门户+移动端 | ≤2秒响应 |
| 外部接口(业务系统) | RESTful API + Kafka | OAuth2.0认证 |
| 外部接口(监管) | SFTP文件传输 | AES-256加密 |
| 内部接口 | gRPC + protobuf | 熔断降级 |
