# 📇 卡片12：系统设计

---

## 📖 教材原文

> 系统设计阶段主要从系统逻辑模型（概念模型）出发，在已获准的系统分析报告的基础上，结合实际的经济、技术条件及时间要求，进行系统物理模型设计，解决系统"如何做"的问题，为后续各项系统实施工作做好具体实施方案。系统设计又称物理设计。

系统设计通常分为两个阶段：**总体设计**（设计系统框架和概貌）和**详细设计**（在总体设计基础上进一步具体化、条理化和规范化），两部分互相联系，需要交叉进行。

### 系统设计的5个目标

| 目标 | 说明 |
|------|------|
| **可靠性** | 抵御外界干扰的能力及受干扰时的恢复能力。从硬件冗余、软件身份验证、防火墙、规章制度等多方面综合考虑 |
| **可变更性** | 系统的可维护性或可修改性。结构化模块设计、数据存储结构规范化、功能设计前瞻性是重要措施 |
| **效率** | 通过响应时间或单位时间处理业务量衡量。与硬件平台、系统软件性能、参数设置、应用软件结构设计合理性有关 |
| **通用性** | 同一软件系统在不同使用单位的可应用程度。业务处理规范化、标准化、完善化是提高通用性的关键 |
| **工作质量** | 处理数据的准确性、输出信息的易懂性和系统操作的方便性。直接影响系统使用效果 |

### 系统设计的5个原则

**（1）系统性原则**：系统是一个有机整体，信息代码要统一，设计规范要统一标准，数据采集做到数出一处、全局共享，一次输入多次利用。

**（2）灵活性原则**：系统需要修改和维护，应有较好的开放性和结构的可变性。采用模块化结构，提高各模块独立性，尽可能减少模块间耦合，使子系统间的数据依赖减至最低。

**（3）可靠性原则**：必须具有较高的可靠性——安全保密性、检错纠错能力、抗病毒能力、系统恢复能力等。系统可靠才能得到用户认可与接受。

**（4）经济性原则**：在满足系统需求的前提下尽可能减小系统开销。硬件投资不盲目追求先进而以满足应用需要为前提；系统设计中避免不必要的复杂化，各模块尽量简洁。

**（5）管理可接受原则**：考虑用户的业务类型、基础管理工作、人员素质、人机界面友好程度、掌握系统操作的难易程度等，设计出用户可接受的系统。

### 系统设计的9项内容

①**系统总体结构设计**：将系统划分成若干子系统和模块，确立模块间的调用关系和数据传递关系。

②**处理流程设计**：系统处理流程设计和模块处理流程设计两方面。

③**代码设计**：为系统处理的实体或属性设计易于处理和识别的代码。

④**人机界面设计**：从系统角度出发，按照统一、友好、漂亮、简洁、清晰的原则设计人机界面。

⑤**输出设计**：根据用户要求设计报表或其他类型输出信息的格式及内容。

⑥**输入设计**：设计系统运行所需输入的各种数据的输入格式，使其操作简单。

⑦**数据库设计**：根据数据字典和数据存取要求，确定数据库的结构。

⑧**安全保密设计**：为确保系统运行安全和数据保密，提出安全保密设计方案。

⑨**系统物理配置方案设计**：进行具体的计算机软硬件及网络的选择和配置。

⑩**编写系统设计说明书**：将系统设计阶段各种资料按规定格式编写，为系统实施提供依据。

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团数据资产智能管理平台完成系统分析后，进入系统设计阶段。

**考题形式**：

> "华航集团数据资产智能管理平台"的系统分析已通过评审，现进入系统设计阶段。请按照系统设计的5个目标、5个原则和10项内容，说明该平台的系统设计方案。

**参考答案要点**：

**（1）5个设计目标如何达成**：

| 目标 | 华航项目设计措施 |
|------|----------------|
| 可靠性 | K8s集群10节点+异地灾备，应用层设置熔断降级+限流保护；身份验证采用OAuth2.0+双因子；数据库主从复制+自动故障切换 |
| 可变更性 | 27个微服务模块独立部署，通过API网关统一路由；数据库采用版本管理（Flyway）；功能设计预留扩展点（插件化质量规则引擎） |
| 效率 | ClickHouse OLAP引擎加速统计分析（P99≤2秒）；Redis缓存热点数据；Kafka异步解耦高频写入 |
| 通用性 | 数据接入层采用标准化的Connector接口，支持JDBC/REST/Kafka/FTP四种协议，可适配不同系统 |
| 工作质量 | 数据校验采用"采集→校验→修正→再校验"闭环流程；界面遵循"减少记忆负担"原则，智能推荐常用操作 |

**（2）5个设计原则如何贯彻**：

| 原则 | 华航项目设计措施 |
|------|----------------|
| 系统性 | 统一数据编码规范（资产ID/规则ID/服务ID全局唯一）；统一接口规范（gRPC+protobuf）；数出一处（数据湖为唯一数据源） |
| 灵活性 | 每个微服务独立Docker容器部署，通过K8s编排；模块间通过API网关松耦合通信，单个服务升级不影响其他服务 |
| 可靠性 | 数据库每日全量备份+增量日志备份；关键服务多副本部署（最少3副本）；防DDoS+WAF+SQL注入防护 |
| 经济性 | 硬件按需采购（高峰期弹性扩容）；开源技术栈为主（Hudi/ClickHouse/Kafka/Redis），降低License成本 |
| 管理可接受 | 界面设计采用集团统一的UI规范；提供操作指引视频+在线帮助；管理后台提供可视化配置（无须编码修改规则） |

**（3）10项设计内容**：

| 序号 | 设计内容 | 华航项目方案 |
|------|---------|------------|
| ① | 总体结构 | 4层架构（界面层/业务层/数据层/存储层）+ 27个微服务模块 |
| ② | 处理流程 | 数据采集→数据清洗→资产编目→质量检核→服务发布（主流程） |
| ③ | 代码设计 | 资产ID编码规则：HC-{域}-{系统}-{类型}-{序号}（如HC-PAX-PSS-TB-00001） |
| ④ | 人机界面 | 数据门户首页+资产管理+质量监控+数据服务+安全管控5大模块 |
| ⑤ | 输出设计 | 资产目录报表（Excel/PDF）、质量监控日报、数据服务调用统计看板 |
| ⑥ | 输入设计 | 数据源配置表单、质量规则配置向导、数据服务申请表单 |
| ⑦ | 数据库设计 | MySQL(元数据)+ClickHouse(分析)+Hudi(数据湖)+ES(搜索)+Redis(缓存) |
| ⑧ | 安全保密 | 数据分级(公开/内部/敏感/机密)+AES-256加密+RBAC权限+审计日志 |
| ⑨ | 物理配置 | 总部K8s集群(10节点)+区域代理服务器(5台)+Hadoop集群(20节点) |
| ⑩ | 设计说明书 | 编写《系统设计说明书》v1.0，提交数据治理委员会审批 |

| 层次 | 技术选型 | 设计要点 |
|------|---------|---------|
| 界面层 | React + Ant Design | 5大功能模块统一入口 |
| 业务层 | Spring Cloud微服务 | 27个服务独立部署 |
| 数据层 | Kafka + Spark/Flink | 异步解耦+实时计算 |
| 存储层 | Hudi + ClickHouse + MySQL | 湖仓一体架构 |
