# 📇 卡片02：基础架构（4种架构）

---

## 📖 教材原文

> 应用系统的框架是指系统的一个或多个结构，包括软件构件、构件的外部可见属性以及它们之间的相互关系。应用系统体系架构是建立在系统支持环境基础上的系统基本框架，是应用系统生命周期中必须具备的骨骼。

### 1. 分层体系

通常，应用系统从上至下可划分为**界面交互层、业务处理层、数据处理层、数据存储层**。分层的优势是系统可分层构建，各个层面有比较确定的功能目标，并有特征明确的构造元素与构造规则：
- **界面交互层**：实现系统与环境的交互，面向用户确定操作规则，构造元素主要是界面控件（按钮、文本框等）。
- **业务处理层**：实现业务流程控制与业务数据计算，构造元素是业务子系统（功能构件）。
- **数据处理层**：实现数据读写处理，构造元素主要是基于SQL语言的函数包（数据视图、存储过程、触发器等）。
- **数据存储层**：实现数据有效存储，构造元素是数据集合体（数据表、数据文件等）。

按分层进行体系架构定义时，可进一步将应用系统架构分为：以数据为中心的架构、客户机/服务器架构和组件分布架构。

### 2. 以数据为中心的架构

对于以数据处理、统计、汇总为业务特征的应用系统，可以数据为中心构建应用系统架构。数据驱动是最常见的设计路线，即先规划设计好数据环境（数据库、数据文件），然后按照系统对数据的业务应用划分来规划设计各个子系统。

### 3. 客户机/服务器架构

基于网络构建，从最初的两层结构到三层结构，再到基于Web的B/S结构：

**（1）两层客户机/服务器架构**
将应用系统分为前端程序与后台数据两个部分。前端程序（界面程序、业务处理程序）安置在客户机上，后台数据安置在数据库服务器上。优点是结构简单、容易实现、操作性能好；缺点是客户端程序需承担信息表示与业务处理双重任务，变更成本大。

**（2）三层客户机/服务器架构**
将业务处理程序从客户机提取出来放到专门的应用服务器上。作用是将容易改变的业务处理部分集中到应用服务器上，系统业务规则改变时只需更新应用服务器上的程序。软件实现技术难度较大，硬件性能要求更高。三层架构是逻辑结构，物理上可以是同一台计算机。

**（3）浏览器/服务器架构（B/S架构）**
互联网环境下特殊的客户机/服务器架构。客户机上的界面程序被Web服务器上的Web页替代，只需通用Web浏览器即可访问。优势是无须对客户机专门维护、支持远程信息服务；不足是数据传输速度、安全性、稳定性低于传统架构。

### 4. 组件分布架构

组件是程序实体，常由对象类集成。组件分布架构可突破传统客户机/服务器架构对分布的限制，使分布对称——某个组件既可以是服务器也可以是客户机，角色取决于它是在提供服务还是请求服务。需要有组件分布中间层构件提供基础服务，如同软件总线支持组件插拔和通信协作。目前主要的组件分布中间层构件有：
- **CORBA**（通用对象请求代理模型）：OMG定义，与机器无关，广泛应用在UNIX、Linux及Windows。
- **DCOM**（分布式组件对象模型）：微软概念，基于COM，通用性不如CORBA。
- **EJB**：Sun公司定义，基于Java的分布式组件对象模型。

## 🔑 背诵提炼

| 架构类型 | 核心特征 | 关键要素 |
|---------|---------|---------|
| **分层体系** | 四层：界面交互层→业务处理层→数据处理层→数据存储层 | 各层独立构建，接口通信 |
| **以数据为中心** | 先设计数据环境，再划分子系统 | 数据驱动，适用于数据处理/统计/汇总 |
| **客户机/服务器** | 两层→三层→B/S逐步演进 | 两层简单但难维护；三层集中业务逻辑；B/S免客户端维护 |
| **组件分布** | 对称分布，中间层构件如软件总线 | CORBA/DCOM/EJB三大中间件 |

**B/S架构 vs 传统C/S架构对比**：
- B/S优势：无须维护客户机、支持远程信息服务
- B/S不足：数据传输速度、安全性、稳定性较低

## 🧠 背诵口诀

```
分层四层架（界业数存），
数据为中心（先库后系），
客户服务器（两三四层演进），
组件分布对（CORBA/DCOM/EJB）。
```

分层体系：**界业数存**（界面交互→业务处理→数据处理→数据存储）
客户机演进：**两简难维 → 三集业逻 → B/S免客**

## 🏢 案例应用

**【华航集团项目场景】**

**问题**：华航集团需要在29个节点（总部+5区域中心+23分公司）部署数据资产智能管理平台，请为该项目选择合适的基础架构方案并说明理由。

**考题形式**：

> 在"华航集团数据资产智能管理平台"项目中，需要覆盖总部和28个分支节点，支撑5000并发用户，年调用量超10亿次。请分析该项目应采用何种基础架构，并说明理由。

**参考答案要点**：

（1）**分层体系**：采用四层分层架构。界面交互层提供统一数据门户（Web端+移动端）；业务处理层承载资产编目、质量监控、数据服务编排等核心业务；数据处理层采用Spark/Flink实现数据清洗与实时计算；数据存储层以数据湖（Hudi）+数据仓库（ClickHouse）为底座，支撑50PB数据资产。

（2）**以数据为中心**：本项目以数据处理、统计、汇总为核心业务特征（10万+资产目录、5000+质量规则、10亿次/年调用），采用数据驱动设计路线——先规划设计数据湖/仓环境，再按业务域划分子系统（资产目录子系统、质量监控子系统、数据服务子系统、安全管控子系统）。

（3）**B/S架构为主**：鉴于29个节点分布全国、5大区域中心各自独立运营的特点，采用B/S架构，各节点通过Web浏览器即可访问平台，无须安装客户端，大幅降低运维成本。核心业务逻辑部署在集团总部的应用服务器集群上，通过负载均衡支撑5000并发。

（4）**组件分布架构**：对于跨区域的数据采集与同步，采用组件分布架构。各区域中心部署数据采集代理组件，通过消息中间件（Kafka）与总部平台通信，实现数据的实时采集与异步同步。代理组件基于EJB（Java技术栈）实现分布式部署。

| 架构层次 | 项目对应方案 | 关键参数 |
|---------|------------|---------|
| 界面交互层 | Web门户 + 移动端 | 响应≤2秒 |
| 业务处理层 | 4大业务子系统 | 5000并发 |
| 数据处理层 | Spark/Flink实时计算 | 10亿次/年 |
| 数据存储层 | Hudi数据湖 + ClickHouse数仓 | 50PB |
| 部署模式 | B/S架构 + 组件分布 | 29节点 |
