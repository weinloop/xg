# 第04章 画一张蓝图

> **教材对照**：第4章 信息系统规划（4.1 概述 · 4.2 规划主要内容 · 4.3 工作要点 · 4.4 常用方法）

---

## 一、大巴上的四个小时

陈工真的没让林小白坐飞机。

去冀南外站机场的大巴摇摇晃晃，手机信号三格变一格。林小白盯着离线缓存的调研表，忽然明白陈工那句「体会信息在物理空间传递的时延」——运控中心看到的航班落地，外站地勤可能要晚二十分钟才录入系统，不是人家偷懒，是**信息在 WAN 上爬得慢**。

外站站长姓何，四十出头，办公室墙上贴着褪色的「安全生产一百天」锦旗，电脑旁堆着手写航班保障单。

「集团要建数据平台？」何站长笑了一下，「去年我们刚用 Excel 把旅客人数报给总部，报上去，总部说人数和订座系统对不上。谁错？都说对方错。」

林小白按陈工教的**内外部需求挖掘**五步法在做：上午**资料收集**（外站近三年报送记录），下午**交流访谈**（何站长、调度、地勤班长），穿插**现有系统查勘**（一台老旧离港终端、一台连集团 VPN 时断时续的 PC），傍晚**业务现场查勘**（机坪、候机楼），夜里回住处做**案头研究**。

外站的痛点很具体：

- 备降航班旅客改签，靠站长打电话找总部运控，**信息方向性**强，但**信道**是人声，没有编码标准；  
- 旅客特殊服务（轮椅、无陪儿童）记在纸质单，进不了 CRM；  
- 民航局运行品质考核要求外站**三十分钟内**上报不正常事件，手写再传真，经常超时。

「这是**外部需求**。」陈工在大巴返程路上说，「监管、旅客、合作伙伴。你们总部会议室吵的是**内部需求**——部门权力和数据归属。规划第一个实质性工作，就是把内外部需求挖透，别急着画架构。」

林小白在笔记本上划了两列。左列写「局方考核、旅客体验、外站报送」；右列写「统一 ID、主数据、质量闭环」。中间用箭头连起来，标注：**平台要解决的是内外部需求交汇处的断裂**。

## 二、场景化：备降日的二十四小时

回到总部，陈工把林小白和周数据关进小会议室，墙上贴着 CA2847 时间线——这是**场景化模型分析**的靶子。

「场景不是讲故事哄领导，」周数据说，「是把信息系统应用场景和业务场景钉在一起。一个完整场景模型有八块：**场景定义、角色、业务、数据、技术、组织、风险、政策法律**。」

他们按八块拆「雷雨备降」：

| 维度 | CA2847 场景内容 |
|------|-----------------|
| **场景定义** | 雷雨单元影响，航班备降外站，旅客改签续程 |
| **角色** | 运控调度、外站站长、客服、旅客、机务跟机 |
| **业务** | 决策备降→落地确认→旅客安置→票务变更→财务结算 |
| **数据** | 航班状态、旅客身份、票款、特殊服务、运行事件 |
| **技术** | AOC、离港、CRM、财务、传真/电话（断点） |
| **组织** | 总部运控垂直指挥，外站横向协调弱 |
| **风险** | 状态不一致、舆情、超时报送 |
| **政策法律** | 民航不正常航班处置规定、旅客权益、数据安全 |

林小白发现：**场景化**用在规划前，能避免「一上来就谈 Hadoop」；用在规划中，能排优先级；用在规划后，能当验收剧本——陈工说这叫场景模型**三阶段应用**。

张架构补充技术场景：「备降时运控要**敏态**，财务结算要**稳态**。场景分析完，你就知道平台不能只有一个同步频率——这就是后面**双态**设计的来由。」

## 三、深度诊断：不是二级半，是哪里二级

第三天，周数据牵头做**深度诊断与评估**。不是重复 GB/T 43439 打分，而是按教材**业务能力维度 × 成熟度等级维度**给数据域做细诊。

评估表每项打四分制：**0 / 0.5 / 0.8 / 1**。

林小白负责「数据共享与集成」一条，硬着头皮填：

- 旅客主数据：0.5（有 CRM，无集团级 ID）  
- 航班运行数据：0.8（运控强，外站弱）  
- 数据质量规则：0（靠人盯）  
- 数据目录与资产登记：0  
- 跨部门实时共享 SLA：0.5（口头约定，无监测）  

周数据汇总后，图形呈「锯齿状」——运控采集强，流通弱；营销应用多，源头乱；机务沉淀深，出口窄。

「诊断结论要写进规划，」陈工说，「**整体与专项规划**前的必做项。别粉饰成『整体二级』，领导看得懂锯齿。」

刘总晚上看诊断图，只问一句：「先补哪几个齿？」

周数据答：「按发展战略路径——**业务一致、能力主线、基础优先、稳态先行**。旅客 ID 和航班状态是主线；外站报送是业务一致；财务稳态接口往后排。」

## 四、方法论周：五张表画出灵魂

刘总批了预算，陈工组织为期一周的「**信息系统规划方法训练营**」——林小白这才知道，软考里那几种方法不是选择题摆设，是拿来吵架用又吵架用的。

### 第一天：CSF，抓关键成功因素

陈工空白板，只写集团战略一句：「安全运行、效益增长、旅客满意、合规可控。」

「**关键成功因素法**，企业信息系统规划**最常用**。四步：定战略目标→识别所有成功因素→筛出**关键**成功因素→定指标和数据来源。」

众人七嘴八舌列因素：准点率、成本控制、品牌、机组实力、油价、监管……陈工用**德尔菲**式投票（三轮贴纸），留下四个 CSF：

1. **运行安全数据实时可信**（内部型 + 监控型）  
2. **旅客服务全渠道一致**（外部型）  
3. **经营决策用数可追溯**（建立型）  
4. **合规报送零超时**（监控型 + 外部型）

CSF 四来源，林小白对号入座：产业结构（航空业监管严）、竞争地位（区域市场）、环境因素（雷雨频发）、暂时因素（备降高发季）。

「平台第一期 KPI，」陈工说，「从这四个 CSF 长出来，别从厂商产品册长。」

### 第二天：SST，战略往下翻译

**战略目标集转移法**——William King，1978。陈工把集团**组织战略集**贴在左墙：使命、目标、战略、约束。

右墙要生成**信息系统战略集**：系统目标、系统约束、系统建设战略。

林小白负责翻译表：

| 组织战略 | 信息系统战略 |
|----------|----------------|
| 使命：安全连接区域 | 系统目标：运行数据单一可信源 |
| 目标：数字化三级 | 系统目标：主题数据资产可目录、可质量、可共享 |
| 战略：智慧民航先行 | 建设战略：旅客主题先行、边云协同 |
| 约束：预算三年分期 | 系统约束（内部）：分期建设、不替换运控核心 |
| 约束：民航数据安全 | 系统约束（外部）：分级分类、等保、出境脱敏 |

「SST 解决的是，」陈工说，「领导说的『数字化转型』怎么变成信息中心主任能招标的句子。」

### 第三天：BSP，数据类从哪儿长出来

**企业信息系统规划法**——IBM，七十年代。四步林小白背了一宿：

**定义管理目标 → 定义管理功能 → 定义数据类 → 定义信息结构。**

周数据带他用**实体法**列数据类：旅客、航班、机组、航材、票款、工卡、保障车辆……控制在十五个。

管理功能按资源**生命周期四阶段**套：产生、获得、服务、归宿。比如「旅客」——产生（订票）、获得（值机）、服务（飞行/延误处置）、归宿（里程入账/档案留存）。

然后画**功能/数据类矩阵**（U/C），林小白第一次画 U/C 手抖，陈工改了八处：「**信息结构**来自矩阵聚类。旅客主题域第一批，因为 U 和 C 最密。」

老周来看了一眼：「运控和航班那一列全是 U，你们真敢动？」

陈工指矩阵：「BSP 不是推翻运控，是看清**哪些数据类被哪些功能反复用**——反复用的，就该平台管。」

### 第四天：VCA，价值链上找刀刃

迈克尔·波特**价值链分析法**。陈工画航空集团价值链：

**基本活动**：进料后勤（航油航材）→ 运营生产（飞行）→ 发货后勤（地服保障）→ 营销销售（订座）→ 售后服务（投诉、里程）

**支持性活动**：采购、研发、财务、人力、计划、IT

四步走完：识别价值链→找**价值增加**环节→找**价值减少**环节→标 IT 支撑点。

结论刺耳却清晰：

- **价值增加**：精准调度减少空飞、金卡旅客留存、航材共享降库存  
- **价值减少**：备降处置混乱、重复录入、报送罚款、舆情  
- **IT 支撑重点**：运行数据流（减损失）、旅客数据流（增留存）

「CA2847 在『运营生产』和『售后服务』的接缝上丢了价值。」林小白写进报告，「平台是缝针，不是新布。」

### 第五天：Zachman，六乘六格填不满别交卷

**Zachman 框架**——6 行 × 6 列。林小白起初头大，陈工只让他填「旅客主题域」一格，其余各组认领。

**横向 6W**：What 数据、How 功能、Where 网络、Who 人员、When 时间、Why 动机  

**纵向 6 层**：范围（规划者）、企业（所有者）、系统（架构师）、技术（构造者）、详细（集成者）、功能（用户）

他填「企业模型」行、「What」列：企业级旅客数据实体、主数据规则、质量阈值——对应周数据的数据委。

「Why」列写动机：备降时不让旅客等四十分钟。

「Where」列：外站 VPN、总部 SAN、营销云——张架构补。

一周结束，墙上六张方法产出物：

- CSF 四要素 KPI 树  
- SST 战略翻译表  
- BSP 的 U/C 矩阵与主题域聚类  
- VCA 价值刀刃图  
- Zachman 旅客域切片  
- 外站场景八维模型  

刘总说：「这才叫**画蓝图**，不是 PPT 贴 logo。」

## 五、蓝图本身：七大体系与一条主线

第二周，陈工带核心组写《星河航空集团数据资产智能管理平台——信息系统规划（初稿）》。林小白负责统稿，终于见到教材 **4.2** 的完整骨架。

### 规划定义与原则

开篇引用定义：在组织内外部条件与**发展战略**基础上，明确信息系统**愿景、目标、框架、逻辑关系、建设模式、实施策略**。

陈工强调规划**六个价值**：确立数字能力目标、明确路径、统一认识、具象任务、标准与控制、统筹资源。特点也写实：**全局性、长远性、不确定性高、概括性强、不宜过细**——主要负责人是**决策层**，工作主体是**管理层**。

六条原则贯穿全文：**战略性、整体性、先进性、指导性、柔性、遵从性**。整体性林小白用四句话落地：业务赋能整体、系统框架整体、建设实施整体、集成融合整体——外站场景写进「业务赋能」，旅客/航班/航材主题写进「框架整体」，分三期写进「实施整体」，运控+营销接口规范写进「融合整体」。

### 发展战略与系统框架

**发展路径四原则**：业务一致、能力主线、基础优先、稳态先行。

**五阶段成熟度**（规划用语）：**打基础 → 提效率 → 做协同 → 强决策 → 构生态**。一期对应「打基础+提效率」，二期「做协同」，三期「强决策」，生态远期。

**系统总体框架**选型，张架构主张第二条：

集团已过「以应用功能为主线」的初级阶段（二十多套部门软件竖井）；应走**以平台能力为主线**——云计算带来的**平层化**：采集、网络、中间件、开发环境统一，**敏态+稳态**并存。第三条「以互联网为主线」、App 化微服务编排，写入三期演进，不一期硬上。

当前落地采用行业常见的 **「感、传、智、用、安」** 模式：感知（机坪传感）、传输（专网 5G）、智能（质量与匹配引擎）、应用（目录与服务）、安全（分级与态势）。

分系统划分遵四原则：**技术一致、工程一致、职能一致、数据一致**——旅客主题、航班主题、治理主题、服务主题四个分系统。

### 组织、技术、任务、资源、保障

**组织体系**：在现有信息化管理委员会下，设**数据治理办公室**（周数据牵头）+ **平台建设专班**（李姐任项目经理）。大型集团模式选**平衡矩阵式**——稳态建设集中（主数据、标准），敏态应用分权（营销标签、运控看板）。业务条线设「数据旗手」：运控一人、机务一人、外站何站长纳入。

**技术体系**六原则：**可用、安全、可靠、灵活、可扩展、可驾驭**。可靠性从成熟性、整体性、风险性三角评估。输出两张图：**逻辑结构图**（五层+主题域）和**技术应用图**（混合云、大数据、边缘、API 网关一族）。

**任务体系**按**领域→工程→项目→活动**拆解。部署六步：**任务拆解 → 明确目标 → 匹配组织 → 制定策略 → 定义计划 → 监控实施**。目标写 SMART：一期旅客 ID 覆盖率 95%、备降场景匹配率 95%、外站事件报送及时率 100%。

**资源体系**用**人机料法环测**识别：人（专班+旗手）、机（云与存储）、料（主题数据）、法（标准与流程）、环（外站网络改造）、测（质量与 SLA 监测）。四环节：识别评估、关系控制、分配调度、风险优化。

**保障体系六类**：组织、人员、技术、资源、数据、安全——各配一条可检查措施，赵安全的数据安全专章占了半页。

### 工作要点闭环

全文按 **4.3** 五要点组织：

1. **内外部需求挖掘** — 外站大巴调研 + 总部访谈  
2. **场景化模型分析** — CA2847 八维  
3. **深度诊断与评估** — 锯齿图 + 0/0.5/0.8/1 打分  
4. **整体与专项规划** — 自顶向下（战略→主题域）与自底向上（外站痛点→接口）结合；需求整合三维：**业务领域、能力建设、技术发展**；做一致性检查  
5. **持续改进** — 跟踪战略、感知技术、关注数据与安全、用户体验、监测评估机制  

陈工补笔：**自顶向下**解决协同与敏捷，**自底向上**解决效率与痛点——本规划两者并用，但以自顶向下定边界，自底向上验场景。

## 六、评审与林小白的一页纸

规划初稿评审会，厂商代表讲半小时「一站式数据中台」，被刘总打断：「你们的方案，CSF 第几条？」

对方愣住。

林小白被点名讲「一页纸摘要」。他没讲技术名词，只讲：

「我们用**五种方法**从战略落到数据类，用**七大体系**安排建设，用**五个工作要点**保证不空转。平台一期只做三件事：旅客主数据、备降场景闭环、外站报送在线化——对应 CSF 的四项关键成功因素，对应 SST 翻译的三条系统目标，对应 BSP 矩阵里最密的旅客列，对应价值链上备降缝口的价值损失，对应 Zachman 里旅客域的企业 What。」

陈工在台下微微点头。

刘总签字：**原则同意，作为招投标与三期投资的纲领性文件。下一阶段进入应用系统规划与数据资源专项设计。**

散会后，林小白站在走廊那张「数据驱动安全运行」海报下，给陈工发消息：「蓝图算画完了？」

陈工回：「规划是活的。监测评估机制写进保障体系了没？写了，就叫画完第一版。下一章，何站长那台离港终端怎么换、旅客服务怎么设计——**应用系统规划**，别又只想写代码。」

林小白笑了。大巴上晃了四个小时的苦，没白吃。

定义；六价值；特点（决策层负责、不宜过细）；六原则；整体性四方面。

### 4.2 主要内容
七大块：发展战略、系统框架、组织、技术、任务、资源、保障。

| 小节 | 要点 | 项目落点 |
|------|------|----------|
| 4.2.1 发展战略 | 路径四原则；五阶段打基础→构生态 | 一期旅客主题；稳态先行 |
| 4.2.2 系统框架 | 三框架演进；感传智用安；分系统四原则 | 平台能力主线；四主题分系统 |
