# 第13章 带队伍

> **教材对照**：第13章 人员管理（13.2 工作分析与岗位设计 · 13.3 人力资源战略与计划 · 13.4 招聘与录用 · 13.5 人员培训 · 13.6 绩效与薪酬管理）

---

## 一、留不住的人

平台和服务都上了正轨，李姐——项目经理——却在例会上叹气：「云原生重构后，我们要数据工程师、数据分析师、平台运维，可招进来三个走了两个。剩下的小赵天天加班，绩效还按开发岗考，他说『干数据治理的活，拿写代码的考核』。」

刘总看林小白：「平台是人建的、人运维的。**人管不好，前面十二章白搭。** 这一章你跟李姐一起，把数据团队的**人员管理**理出来。」

陈工在白板写下**人力资源管理五环节**：

```
规划 → 招聘 → 维护 → 提升 → 评价
```

「李姐现在哪一环都没系统做，」陈工说，「招进来没岗位说明，干着没绩效，自然留不住。先从**工作分析**开始——岗位都没定义清楚，谈什么招人。」

---

## 二、这个岗位到底干什么

林小白第一反应：「数据工程师不就是写 ETL 吗？」

陈工摇头，带他做**工作分析**——四阶段：**明确范围 → 确定方法 → 信息收集和分析 → 评价**。

收集信息找三类人，各有利弊：

| 来源 | 优点 | 缺点 |
|------|------|------|
| **工作分析专家** | 客观 | 成本高 |
| **主管人员**（李姐） | 了解深入 | 负担重 |
| **典型任职者**（小赵） | 熟悉实情 | 标准化差 |

林小白三类都用：访谈小赵、问卷发给团队、自己直接观察一天 ETL 排障。

方法上定性用**面谈法、直接观察法、典型事例法**；定量本想上 **PAQ 职位分析问卷**，李姐嫌重，改用简化版。

产出**工作说明书**，含两部分：

- **工作描述**：工作设定、定义、说明——数据工程师负责主题库 ETL、质量规则维护、订阅链路保障  
- **工作规范**：任职资格——SQL/分布式/数据建模，3 年经验  

小赵看到说明书：「原来我干的是『数据工程师』，不是『打杂的开发』。」——岗位一清晰，认同感就回来一半。

**岗位设计**也补课：工作内容设计讲**广度、深度、完整性、自主性、反馈性**。小赵的活广度太宽（既治理又运维又救火），林小白按**工作特征模型**拆分，把救火剥给服务台（第 12 章），让他专注治理。

## 三、缺多少人，从哪来

岗位定清后，做**人力资源战略与计划**。

陈工介绍两套经典战略，林小白对号入座：

- **戴尔和霍德三战略**：诱因战略、投资战略、参与战略——数据团队偏**投资战略**（培养稀缺人才）  
- **巴伦和克雷普斯三战略**：内部劳动力市场、高承诺、混合——集团选**混合战略**：核心岗内部培养，紧缺岗外部引进  

**需求预测**用**转换比率分析**：平台二期主题域翻倍，按当前人均承载估算，缺 4 名工程师、2 名分析师。

**供给预测**用**技能清单 + 马尔可夫转移矩阵**：盘点现有人员技能，预测流失率——发现分析师岗年流失 40%，是重灾区。

李姐看懂了：「不是盲目招，是算出**缺口在分析师**，且**留人比招人更急**。」

## 四、招聘：渠道与甄选

按**招聘过程**走：计划制订 → 信息发布 → 应聘申请 → 甄选录用 → 评估反馈。

**渠道**针对不同岗位：

| 岗位 | 渠道 |
|------|------|
| 平台运维（量大） | 网络招聘 + 校园招聘 |
| 数据工程师（紧缺） | 员工推荐 + 网络招聘 |
| 数据架构师（高端） | **猎头** |
| 临时标注/清洗 | 临时性雇员 |

紧急要补一个关键的数据治理岗，HR 建议用**职业介绍机构**——林小白记起教材适用场景：急于填充关键空缺、招聘数量少不值得设计详尽方案、缺乏该市场招聘经验，正好对上。

**甄选**用组合：笔试（**能力测试**）、**工作样本法**（现场做一道数据建模题）、结构化为主的**半结构化面试**。多元选择用**补偿性原则**——某项弱可被强项补。

**招聘效果评估**五方面：招聘周期、用人部门满意度、成功率、达成率、成本。李姐第一次拿数据说话：「分析师招聘周期 58 天太长，得提前储备。」

## 五、培训：让人长起来

招进来只是开始。**人员培训**分入职培训和**在职培训**（节约成本、绩效反馈快）。

**培训内容分析三层面**：

- **组织分析** — 集团要做数据资产化，团队需治理能力  
- **绩效分析** — 小赵质量规则做得好，但缺业务理解  
- **任务分析** — 新工程师需补航空业务知识（航班/旅客/航材）  

林小白设计「数据+业务」双向培训：让数据工程师跟班运控，让运控旗手学数据治理——呼应第 1 章「业务与技术融合」。

**培训效果评估四层次**（柯氏模型）：**反应 → 学习效果 → 行为变化 → 培训效果**。不能只看「满意度问卷」（反应层），要看**行为变化**——培训后越权操作是否下降。

**培训迁移**（鲍德温-福特模型）：受训者特征、培训设计、工作环境共同影响学以致用。林小白发现，光培训没用，得改**工作环境**——给治理工具、留实践时间，知识才迁移得动。

## 六、绩效：别拿开发尺子量数据岗

小赵的核心委屈：「数据治理的活，按开发岗代码量考核。」这是**绩效管理**问题。

**绩效管理循环四环节**：**绩效计划 → 实施与监控 → 考核 → 反馈面谈**。

林小白和李姐重设数据岗 KPI，不再数代码行：

- 数据工程师：主题库质量达标率、订阅 SLA、规则覆盖  
- 数据分析师：模型采纳率、业务满意度  

**考核方法**选**行为锚定评价法（BARS）**——把「数据质量处理」分级描述，比单纯打分客观；团队横比用**强制分布**避免大锅饭。

**绩效反馈面谈**是关键，李姐过去从不做。林小白提醒：考核不反馈，等于没考。小赵面谈后说：「终于有人按我真干的活评价我了。」

## 七、薪酬：留住稀缺的人

留人最终落到**薪酬管理**。

**薪酬体系两类三种**：基于职位、基于任职者（**技能薪酬、能力薪酬**）。数据团队选**能力/技能薪酬**——能力越强（多主题域建模、跨域治理），薪酬越高，鼓励成长而非熬资历。

**工作评价**用**点数法**和**海氏系统法**给岗位定相对价值，解决「数据岗 vs 开发岗谁该高」的争议。

**薪酬等级结构五要素**：等级数、目标薪酬、级差、幅度、重叠。林小白发现数据岗与开发岗**薪酬重叠**不足，导致数据人觉得低人一等，调整重叠区间。

**薪酬激励**按人群：

- 平台运维（操作类）— 偏稳定 + 值班补贴  
- 数据分析师（专业技术）— **加薪 + 非金钱**（培训、会议、署名）  
- 数据架构师（高级）— 基本薪酬 + 短期奖金 + 长期激励  

三个月后，分析师流失率从 40% 降到 12%，小赵升为「数据治理主管」。李姐在例会上说：「以前我以为带队伍就是排班。现在懂了——**定岗、算缺口、招对人、育起来、考公平、留得住**，一整套。」

陈工问林小白：「带队伍最难在哪？」

林小白说：「最难是承认——平台是技术，但**跑平台的是人**。人不是资源池里的 CPU，可以随便调度。岗位说明书让他知道自己是谁，绩效让他被公平看见，薪酬让他愿意留下。这一章我学的不是 HR，是怎么让前面十二章的能力**有人持续扛着**。」

刘总合上花名册：「下一章，集团要把咱们这套做法固化成标准和流程，推广到各子公司——**规范与过程管理**，标准化登场。」

## 【林小白的考点笔记本】

### 13.1 概述
人力资源管理五环节：规划、招聘、维护、提升、评价。

### 13.2 工作分析与岗位设计
四阶段；信息来源三类；工作说明书=工作描述+工作规范；方法定性/定量（PAQ等）；岗位设计内容与方法（工作特征模型）。

### 13.3 战略与计划
戴尔霍德三战略；巴伦克雷普斯三战略；需求预测（德尔菲/回归/转换比率）；供给预测（技能清单/马尔可夫等）。

### 13.4 招聘录用
过程五步；渠道八种（职业介绍机构适用场景）；录用测试；多元选择原则；面试结构化程度；评估五方面。

### 13.5 培训
类型；内容分析三层面；效果评估四层次（反应/学习/行为/效果）；培训迁移模型。

### 13.6 绩效薪酬
绩效循环四环节；考核方法（BARS等）；薪酬两类三种；工作评价五法；薪酬结构五要素；分人群激励。

## 【陈工的应试锦囊】

**案例题**

| 题干 | 答法 |
|------|------|
| 岗位职责不清 | 工作分析；工作说明书 |
| 缺多少人 | 需求/供给预测；转换比率、马尔可夫 |
| 关键岗急招 | 职业介绍机构/猎头 |
| 培训没效果 | 四层次评估；培训迁移改环境 |
| 绩效不公 | 绩效循环；BARS；反馈面谈 |
| 留不住人 | 能力/技能薪酬；激励分人群 |

**论文**：数据团队人才战略；岗位—招聘—培训—绩效—薪酬闭环；技术与业务融合培养。

**选择陷阱**：五环节；工作描述 vs 工作规范；培训评估四层次顺序；职业介绍机构适用场景；薪酬两类三种。
