# 第08章 数据是石油

> **教材对照**：第8章 数据资源规划（8.1 概述 · 8.2 规划方法 · 8.3 数据架构 · 8.4 数据标准化 · 8.5 数据管理）

## 一、主数据表听谁的

网络割接周后，数据治理办公室会议室贴满白纸。周数据站在一张 ER 图前，红笔圈住「旅客」实体，声音发硬：

「**证件号码**以 CRM 为准，还是以离港为准？**手机号**营销能改，离港能改，谁覆盖谁？**金卡等级**财务不认，营销认——这张主数据表，今天必须定主人。」

营销信息主管拍桌：「旅客是我们的客户，CRM 说了算。」

离港系统代表不服：「值机现场改号，CRM 滞后两小时，听 CRM 的，安检对不上人。」

运控老周冷声：「你们争姓名手机号，我要的是**统一旅客 ID** 映射各系统键值，别动我 PAX 编码逻辑。」

林小白第一次发现，技术争论（VLAN、云、容器）好歹有指标；**数据争论**全是利益。

刘总把陈工和周数据推上前：「平台项目，**核心战场在第八章**。林小白，你全程记录。这周不出《数据资源规划》，主数据引擎不准投产。」

陈工开场只讲一句教材概述：**数据→信息→知识→智慧**，前者是后者的前提；数据资源有**无形、可复制、弱排他、时效、依附、垄断**等特征——「CRM 把旅客数据当垄断资产，就是**垄断性**；备降信息两小时过期，就是**时效性**。」

周数据补：**数据资源化→资产化→资本化**三阶段——「咱们正在从资源化跨进资产化，别跳去资本化讲故事。」

## 二、选方法：过程、结构与指标

方法选型会，周数据在白板列三种**数据资源规划方法**：

| 方法 | 适用 | 星河判断 |
|------|------|----------|
| **稳定信息过程** | 场景固定、积累少 | 航班运行、值机离港流程相对固定 |
| **稳定信息结构** | 场景常变、积累多 | CRM 日志杂、标签常变 |
| **指标能力** | 决策导向、积累少 | CSF 四项 KPI、备降 SLA |

「不押宝单一方法。」周数据拍板，「旅客主题用**稳定信息过程**建主题库——**两条主线、三种模型、一套标准**；营销标签用**稳定信息结构**迭代核心数据集；集团考核用**指标能力**反推——**决策—指标—数据模型**。」

林小白跟周数据走**稳定信息过程**主线，步骤在墙上排开：

定义职能域 → 职能域业务分析 → 职能域数据分析 → 数据管理基础标准 → 功能模型 → 数据模型 → 关联模型 → **主题数据库**（**共建共用**，否定自建自用）

实施层面，陈工要求补齐可行性（资源/操作/技术）、组建规划小组、业务活动研究、逻辑模型、数据模型、管理标准、**主题库设计**、分布分析、方案与评审——与第 5 章应用规划衔接。

营销副总问：「能不能只上数据湖，别搞主题库？」

周数据摇头：「湖存原始，主题库存**基本表**——第三范式，可共享可治理。湖没有，主题库没有，只有**数据沼泽**。」

## 三、旅客主题库：三种模型落表

林小白被周数据按在 CRM 旁做**职能域业务分析**。三天后产出三张模型：

**功能模型** — 旅客注册、值机、特殊服务登记、备降改签、里程入账五大功能块。

**数据模型** — 实体：旅客、证件、联系方式、会员等级、特殊服务、系统映射。主键：**XH_PAX_ID**（集团统一 ID），非自然人姓名。

**关联模型** — CRM.CUSTOMER_ID、DCS.PAX_NO、FIN.TICKET_NO 均映射至 XH_PAX_ID。

主题库表结构定稿（逻辑模型）：

```
旅客主表（XH_PAX_MASTER）— 姓名、性别、出生日期【权威源：证件 OCR】
证件子表 — 证件类型、号码、有效期【权威源：离港】
联系子表 — 手机、邮箱【权威源：CRM，需冲突仲裁规则】
会员子表 — 等级、里程【权威源：营销，财务只读】
映射表 — 源系统、源键、XH_PAX_ID
```

「**证件号码听离港，手机号听 CRM 但需校验，金卡听营销但财务对账只读**。」周数据逐条念仲裁规则，营销和离港代表勉强签字。

**稳定信息结构**路径并行：从 CRM 导出**初始数据集** → 五维审查（数据项、主题、功能、任务、核心集）→ 形成营销**核心数据集**（标签、行为事件）→ 再完善为**目标数据集**——与主题库通过 XH_PAX_ID 关联，不重复造人。

**指标能力**路径由财务牵头：从 CSF「备降处置及时率」反推指标 → 指标体系（报送时效、匹配率、短信触达率）→ 指标数据模型 → 子集融合 → **一致性检验** → 按准备级/平台级/数据级/利用级评价——一期目标：**平台级达标，数据级部分达标**。

## 四、数据架构：湖、库与 CAP

张架构加入架构评审，讲**数据架构**——管理数据及存用数据的系统，含业务/数据/应用/技术四层组织。

**数据模型**三阶段自上而下与自下而上结合：

- **概念模型** — 周数据的 ER 图  
- **逻辑模型** — 3NF 主题表 + 星型快照（营销）  
- **物理模型** — Oracle RAC 主库 + 对象存储日志 + Redis 映射缓存  

**数据流设计**画**血缘矩阵**：AOC→订阅→匹配→主库→CRM 回写；每条线标注延迟 SLA。林小白负责维护 DFD 与矩阵，备降演练时查血缘定位瓶颈——卡在中间件，不是表设计。

**演化驱动因素**写入规划：法规（民航数据安全办法）、业务量（旅客年增长 12%）、技术（实时架构）、需求（标签扩展）。

传统 vs 现代架构争论聚焦三点：

**集中 vs 分布** — 旅客主库**集中式**（强一致、安全）；日志与标签**分布式**（HDFS/Ceph 对象）。

**分区** — 旅客主表按**垂直分区**拆子表；行为日志按日期**水平分区**。

**CAP** — 订阅服务网络分区时，运控侧选 **CP**（Redis/ZK 保一致，短暂不可用可接受）；营销画像选 **AP**（高并发查询，**最终一致性/BASE**）。林小白曾主张全站 CA，被张架构怼：「单站点思维，分布式必**P**，只能 CP 或 AP 二选一。」

现代架构落地组合：

- **数据湖** — 原始日志、备降回放，灵活 schema，防沼泽靠元数据与生命周期  
- **Lambda** — 批处理层（T+1 报表 Spark）+ 速度层（Kafka 实时）+ 服务层（统一 API）  
- **数据服务** — 四个 SOA 服务封装主题库，**数据 API** 对外

## 五、标准、元数据与数据元

没有标准，主题库仍是方言。周数据组织**数据标准化**攻坚周。

**数据标准三类**：指导标准（集团数据管理办法）、通用标准（数据类/服务类/管理类）、专用标准（旅客数据元规范）。

**元数据**平台上线——关于数据的数据，结构含**内容、句法、语义**；作用：描述、定位、发掘、评价、选择。林小白给每张主题表登记：业务定义、技术类型、权威源、质量规则、血缘上游——客服查「手机号」字段，能点开看到「CRM 写入、日校验、脱敏展示」。

**数据元**规范示例「旅客手机号码」：

- **对象类**：旅客  
- **特性**：联系手机  
- **表示**：11 位数字字符串，国标 E.164 存储  

命名遵守语义、句法、**唯一性**规则；定义遵守唯一、准确、简练、可单独成立等七条编写规范。

**分类与编码** — 特殊旅客类型采用一层数字编码，原则：**稳定、系统、可扩充、综合实用、兼容**；编码**唯一、匹配、可扩充、简洁**。轮椅旅客编码 01，无陪儿童 02——外站何站长终端下拉框与此一致，不再手写「轮椅」二字。

## 六、治理、质量与安全

主题库投产前，赵安全与周数据联合签**数据管理**三章。

### 数据治理

治理是「行使权力和管控」，**不直接管数据**，监督与执行分离。活动：规划治理组织、制定战略、实施、嵌入流程。

交付物落地：

- 《数据治理章程》  
- 运营框架：数据委决策、周数据执行、业务旗手提案  
- 路线图：一期旅客、二期航班、三期航材  
- RACI 矩阵：证件权威源归离港，争议升级数据委  

### 数据质量

质量维度一期强制五项：**一致性、完整性、合理性、唯一性、有效性**。

原则写进质量手册：全生命周期、预防为主、根因修正、标准驱动、客观测量、嵌入流程、系统强制执行、关联 SLA。

**备降质量规则包**（CA2847 遗产）：

| 规则 | 维度 | 动作 |
|------|------|------|
| 三源状态不一致 | 一致性 | 熔断订阅，人工工单 |
| 证件号空 | 完整性 | 阻断金卡权益 |
| 手机号 11 位校验失败 | 有效性 | 退回源系统 |
| 重复 XH_PAX_ID | 唯一性 | 合并任务 |

活动按教材走：定义高质量→战略→识别关键数据与规则→初始评估→改进排序→目标→运营部署。林小白把 89% 匹配原型升级为**质量仪表盘**——老周每天先看红灯。

### 数据安全

安全活动：识别需求（等保、出境、合同）→ 制度 → 细则 → 风险评估 → 控制规程。

身份验证 + **RBAC 授权** + 字段级脱敏 + 全量**审计**。旅客证件仅离港角色明文，客服看脱敏，营销看哈希标签。

## 七、主题库上线与「石油」流动

投产日，何站长在外站录入轮椅旅客「李明」，系统生成 **XH_PAX_ID=XA202506110001**。三分钟後，总部客服、营销、财务映射表同步——CRM 旧 ID 挂接映射，不删历史。

备降演练第二次：CA2916 雷雨备降，AOC 状态 41 秒进入主库，质量规则 0 熔断，CRM 短信 52 秒发出。财务副总看利用级评价表：「数据级达标，利用级勉强。」

刘总视察数据委，周数据汇报三方法组合成果：

- **主题库** — 旅客共建共用，1.2 亿映射关系入库  
- **数据湖** — 备降日志可查可回放，未变沼泽  
- **指标集** — CSF 四项有数据源  

林小白站在 CRM 旁，看客服小刘输入手机号，一次跳出统一档案——不再跳转四个系统。

陈工问：「石油什么意思？」

林小白说：「不流动是泥，流动了才是油。资源化是挖出来，资产化是炼成标准主题库，资本化——刘总说等你考完证再讲。」

周数据递来下一章任务书：「主题库有了，**信息安全规划**专章——赵安全等很久了。等保三级、零信任、出境评估，比争手机号还费劲。」

## 【林小白的考点笔记本】

### 8.1 概述
数据→信息→知识→智慧；资源特征六条；三阶段资源化/资产化/资本化；规划作用四条。

### 8.2 规划方法

| 方法 | 要点 | 落点 |
|------|------|------|
| 稳定信息过程 | 两主线三模型一标准；主题库共建共用 | 旅客主题 |
| 稳定信息结构 | 五步循环；五维审查 | 营销标签 |
| 指标能力 | 决策—指标—模型；四维度评价 | CSF 考核 |

### 8.3 数据架构
概念/逻辑/物理模型；血缘；集中/分布；水平/垂直分区；CAP CA/CP/AP；数据湖、Lambda、数据 API。

### 8.4 数据标准化
标准三类；元数据结构；数据元三部分；分类编码五原则+编码四原则。

### 8.5 数据管理
治理四活动与交付物；质量五维度+原则+活动；安全五来源+原则+活动。

## 【陈工的应试锦囊】

**案例题**

| 题干 | 答法 |
|------|------|
| 多系统主数据冲突 | 稳定信息过程+主题库+权威源仲裁 |
| 场景多变 | 稳定信息结构+核心数据集 |
| 决策 KPI 缺数 | 指标能力反推 |
| 实时+批处理 | Lambda；CAP 分区选 CP/AP |
| 只有湖没有治理 | 数据沼泽；主题库+元数据 |
| 字段口径不一 | 数据元+元数据 |

**论文**：旅客主题库；三方法组合；数据质量备降规则包；CAP 在订阅场景取舍。

**选择陷阱**：三方法适用场景；主题库「共建共用」；CAP 分布式必 P；质量五维度；治理≠直接管理数据。
