# 第11章 治理不是管人

> **教材对照**：第11章 信息系统治理（11.1 IT治理 · 11.2 IT审计）

---

## 一、谁说了算

云原生二期上线后，平台跑得稳，可一件事让刘总皱起眉：营销擅自在测试环境拉了一份全量旅客标签，给一家外部广告商做「联合建模」，被赵安全的审计日志逮个正着。

营销副总委屈：「数据是为了业务增长，我又没卖。」周数据拍桌：「权威源、脱敏、授权流程，全绕过了。」运控老周补刀：「上次还差点把我备降通道停了。这平台到底谁说了算？」

会议室又要变成第 1 章那种菜市场。刘总却没让陈工讲哲学，而是写下三个字：**IT 治理**。

「技术能跑、安全有墙，但**谁决策、谁担责、出了事谁评价**——这套机制没建。今天起，林小白跟数据委一起重组治理架构。记住一句话：**治理不是管人，是定规则和决策权。**」

陈工补充教材定义：**IT 治理**是组织采用有效机制，对信息技术和数据资源开发利用，平衡信息化与数字化转型中的风险，确保实现组织战略目标的过程。

「关键词是**机制**和**战略目标**，」陈工说，「营销那次不是坏人作恶，是**决策权没界定**——谁能批数据对外，没人说得清。」

---

## 二、治理不是又开一个会

林小白起初理解偏了：「那就再成立一个委员会？」

陈工摇头，讲 **IT 治理内涵五方面**：

1. 由**治理层/高级管理层**负责做制度安排——不是基层加会  
2. 数字目标与**组织战略目标一致**——治理服务于安全、效益、合规  
3. 保护利益相关者权益、有效**管理风险**  
4. 是一种**制度和机制**（匹配、投资、安全、绩效评价）  
5. 组成包含管理层、组织结构、制度、流程、人员、技术  

「治理目标就三个，」陈工在白板列 **IT 治理三大目标**：**与业务目标一致、有效利用信息与数据资源、风险管理**。「营销那事，第三条塌了。」

林小白这才明白：治理不是多一个章子，是把「谁能决定什么」写清楚。

---

## 三、三层架构与五项决策

重组方案设计，林小白按 **IT 治理管理三层次** 画组织图：

| 层次 | 星河角色 | 职责 |
|------|----------|------|
| **最高管理层** | 常委会 + 刘总 | IT 战略、重大投资、风险底线 |
| **执行管理层** | 信息中心 + 数据委 | 架构、标准、预算分配 |
| **业务与服务执行层** | 运控/营销/机务/外站旗手 | 需求提出、执行、反馈 |

营销那次越界，正是**业务执行层**擅自行使了**最高管理层**才有的「数据对外」决策权。

接着定 **五项关键 IT 治理决策**，且强调顺序——前者驱动后者：

```
IT 原则 → IT 架构 → IT 基础设施 → 业务应用需求 → IT 投资和优先顺序
```

林小白对照平台填：

- **IT 原则**：数据是集团资产、安全合规优先、共建共用  
- **IT 架构**：混合云 + 微服务 + 主题库  
- **IT 基础设施**：CDC、网络、容器平台  
- **业务应用需求**：旅客、航班、外站等  
- **投资优先顺序**：由前四项驱动，而非营销拍脑袋  

「营销绕过的，是**IT 原则**里『数据对外须授权』那条。」陈工说，「决策有顺序，跳级就是治理失效。」

---

## 四、治理体系六部分与核心六方面

林小白把方案写成《集团 IT 治理体系》，骨架用教材 **治理体系框架六部分**：

1. **IT 战略目标** — 支撑数字化三级  
2. **IT 治理组织**（核心：治理机构设置与权限划分）— 三层架构 + 数据委  
3. **IT 治理机制** — 决策、执行、风险控制、协调  
4. **IT 治理域** — 数据、安全、项目、服务  
5. **IT 治理标准** — 对接 ITSS、COBIT  
6. **IT 绩效目标** — 平衡计分卡指标  

**治理核心内容六方面** 逐条落地，林小白特别记住两组对仗：

| 核心内容 | 含义 | 项目落点 |
|----------|------|----------|
| 组织职责 | 谁干什么 | 三层+旗手 |
| **战略匹配** | IT 贡献业务价值的**驱动力** | 平台对齐 CSF |
| 资源管理 | 人机料法 | 第 4/6 章 |
| **价值交付** | **创造**业务价值 | 备降提效、营销增收 |
| **风险管理** | **保护**业务价值 | 出境、越权管控 |
| 绩效管理 | 平衡计分卡 | 季度评价 |

陈工点睛：「**价值交付是创造价值，风险管理是保护价值**——考试爱考这对。营销想创造价值却破坏了风险管理，治理就是让两者平衡。」

**治理机制三原则**写在文件首页：**简单、透明、适合**。「别搞成谁都看不懂的流程，」刘总说，「旗手能照着做才算数。」

**治理流程四动作**贯穿：**统筹、评估、指导、监督**——也对应 **治理任务五方面**：全局统筹、价值导向、机制保障、创新发展、文化助推。

## 五、对标标准：ITSS、COBIT、38500

外部顾问建议对标国际国内标准，免得闭门造车。林小白整理三套，做成对照卡。

### ITSS（国标）

**信息技术服务标准** 围绕**决策体系、责任归属、管理流程、内外评价**四方面。

- **GB/T 34960.1** 通用要求：三大治理域——**顶层设计、管理体系、资源**  
- **GB/T 34960.2** 实施指南：**统筹和规划 → 构建和运行 → 监督和评估 → 改进和优化**  

「这套是中文语境，局方和集团都认。」赵安全说。

### COBIT（ISACA）

40 项核心治理与管理目标。林小白记结构：

- **治理目标** 归 **EDM**（评估、指导、监控）  
- **管理目标** 四领域：**APO**（调整规划组织）、**BAI**（构建采购实施）、**DSS**（交付服务支持）、**MEA**（监控评价评估）  
- 治理系统**七组件**：流程、组织结构、原则政策程序、信息、文化道德行为、人员技能、服务基础设施与应用  

营销越界事件，林小白用 COBIT 归因：属 **APO**（数据治理与合规策略缺失）+ **MEA**（监控滞后，靠日志事后发现）。

### ISO/IEC 38500

IT 良好治理**六项原则**：**责任、战略、收购、性能、一致性、人的行为**。治理机构通过**评估、指导、监督**三任务治理 IT。

「『人的行为』这条，」陈工说，「正是营销那次的软肋——制度有了，行为没跟上。」

## 六、IT 审计登场

治理体系发布两周，集团内审部门提出：要对数据平台做一次 **IT 审计**——既查营销越界事件，也例行评估。

林小白第一次以「被审计方」身份参与，紧张。陈工反而高兴：「治理靠审计来验证，不然就是纸上规则。」

内审组组长先讲 **IT 审计目的**：了解 IT 总体状况、审查评价 IT 目标实现、识别评估 IT 风险、提出建议。

**审计范围**按**审计目的和投入成本**确定，含组织范围（信息中心+数据委）、物理范围（CDC）、逻辑范围（主题库、API、权限）。

### 三类风险，审计师只能控一类

组长讲 **IT 审计风险**，林小白记下高频考点：

| 风险 | 含义 | 审计师能否控制 |
|------|------|----------------|
| **固有风险** | 无控制时易出重大错误 | 只能评估 |
| **控制风险** | 内控不能及时防错 | 与内控执行有关，与审计无关 |
| **检查风险** | 审计程序未发现错误 | **审计师的决定和行动最可能影响** |

「所以营销越界这种**固有风险**，审计师改变不了，」组长说，「但我们设计的抽样和测试，决定**检查风险**——漏没漏掉，是我们的责任。」

---

## 七、查账：方法、证据与底稿

审计实施阶段（**中心环节、关键阶段**），内审组用多种**审计方法**：

- **访谈法** — 问营销、数据委、运维  
- **检查法** — 审阅授权流程文档、核对日志  
- **观察法** — 现场看导出操作（适用进行中的事项）  
- **测试法** — 黑盒测试越权接口  
- **程序代码检查** — 复查导出接口鉴权逻辑  

**审计技术四类**：风险评估、审计抽样、**CAAT 计算机辅助审计**、大数据审计。查导出行为用 CAAT 跑全量日志，比人工翻强。

**抽样**选**统计抽样—属性抽样**：估计「未授权导出」发生比率；金额相关用**变量抽样**。

最让林小白长记性的是 **审计证据五特性**：

| 特性 | 要点 |
|------|------|
| **充分性** | 数量要求，**与样本量有关** |
| **客观性** | 客观事实比判断证据可靠 |
| **相关性** | 与审计事项实质联系 |
| **可靠性** | 受证据类型、取证方式影响 |
| **合法性** | 依法定种类与程序取得 |

「日志是客观证据，比口头说明可靠，」组长说，「这就是你们安全规划里**不可否认性**的价值。」

**工作底稿**分综合类、业务类、备查类，走**三级复核**。

---

## 八、审计四阶段与整改

整个审计按 **四阶段** 走完：

1. **审计准备**（下达审计通知书）  
2. **审计实施**（中心环节）  
3. **审计终结**（整理底稿、出报告）  
4. **后续审计**（检查整改落实）  

审计内容覆盖 **IT 内部控制审计**（组织层面、IT 一般控制、应用控制——输入/处理/输出）和 **IT 专项审计**（这次重点是**数据审计**与安全审计）。

报告结论刺耳但中肯：

- 数据对外**授权流程缺失**（治理 IT 原则未落地）  
- 监控**滞后**（MEA 弱，靠日志事后发现）  
- 应用控制**输出环节**缺导出审批  

整改清单林小白牵头：补「数据对外授权」决策流程、上线导出**事前审批+水印**、监控从事后改**准实时告警**。三个月后**后续审计**复查通过。

营销副总在整改会上认账：「以前觉得治理是给我添麻烦。现在懂了——没有授权流程，哪天真出事，背锅的是我。」

陈工总结：「治理定规则，审计验规则。**治理不是管人，是让每个人知道自己能决定什么、要担什么责。**」

刘总把整改报告归档：「下一章，马运维那边运维投诉一堆——**IT 服务管理**，ITIL、ITSS、SLA，该理服务了。」

林小白翻开新一页，标题写：服务，不是把系统跑起来就完。

## 【林小白的考点笔记本】

### 11.1 IT 治理
- 定义；内涵五方面；目标三个；管理三层次。  
- 体系构成五项；流程四动作（统筹评估指导监督）。  
- **五项关键决策**（顺序）：IT 原则→架构→基础设施→应用需求→投资优先。  
- 体系框架六部分；核心内容六方面（**价值交付=创造，风险管理=保护**）。  
- 机制三原则：简单、透明、适合。任务五方面。  
- 标准：ITSS（四方面；GB/T 34960.1 三治理域 / 34960.2 四过程）；COBIT（EDM + APO/BAI/DSS/MEA；七组件）；ISO/IEC 38500（六原则；评估指导监督）。

### 11.2 IT 审计
- 目的、范围（目的+成本）、人员要求。  
- 风险三类：固有/控制/检查；**审计师最影响检查风险**。  
- 方法：访谈/调查/检查/观察/测试/代码检查；技术四类。  
- 抽样：统计（属性/变量）、非统计。  
- 证据五特性（充分性=样本量）；底稿三类+三级复核。  
- 流程四阶段（实施=中心环节）；内容（内控审计/专项审计）。

## 【陈工的应试锦囊】

**案例题**

| 题干 | 答法 |
|------|------|
| 谁决策不清、越权 | IT 治理三层；五项关键决策 |
| IT 与业务脱节 | 战略匹配；治理目标一致 |
| 选治理标准 | ITSS / COBIT / 38500 对比 |
| 审计风险归属 | 审计师只控检查风险 |
| 证据是否够 | 充分性=样本量；客观性优先 |
| 审计怎么做 | 四阶段；实施为中心 |

**论文**：集团 IT 治理体系；五项关键决策；引入 IT 审计闭环验证治理。

**选择陷阱**：五项决策顺序；价值交付 vs 风险管理；COBIT 四管理域；38500 六原则；审计师影响检查风险；证据充分性=数量。
