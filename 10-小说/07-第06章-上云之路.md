# 第06章 上云之路

> **教材对照**：第6章 云资源规划（6.1 概述 · 6.2 云计算架构 · 6.3 计算资源规划 · 6.4 存储资源规划 · 6.5 云数据中心规划）

## 一、红灯亮了

主数据引擎上线前两周，集团主机房响起刺耳告警。

林小白冲进机房，看见 UPS 面板上的存储阵列指示灯红了一片。值班工程师摊手：「SAN 剩余容量 7%。日志湖每天涨 800GB，备降场景回放一开，快照把盘吃光了。应用规划写得漂亮，**云和资源**没跟上，照样卡死。」

张架构电话打到刘总：「不是换几块盘的事。运控 AOC、主数据 Oracle、CRM 全挤在**同一套私有环境**，没有**资源池化**，弹性为零。要么停项目扩机房，要么按规划正经做**云资源规划**。」

刘总当天召集专题会，陈工在白板写下云规划**基本流程五步**：

```
需求收集 → 资源评估与规划 → 预算管理 → 设计与实施 → 持续优化（循环）
```

「今天不讨论厂商品牌，」陈工说，「讨论**旅客数据放哪朵云、航班日志放哪种盘、新机房按什么等级建**。林小白，你负责记冲突——运控、安全、财务一定吵。」

林小白翻开笔记本，标题改成：《星河航空数据平台云资源规划备忘录》。

---

## 二、先分云，再分服务

专题会第一轮，市场部和运控就掐起来。

营销副总：「旅客标签、行为分析放**公有云**，弹性好，促销高峰自动扩容。」

运控主任：「航班实时状态出公网？我不同意。AOC 相关组件必须在**私有云**，物理隔离。」

赵安全补刀：「旅客证件号出境航线，**数据不出境**写进合规红线。公有云可以，但必须境内节点、专有云形态，不是随便买个账号。」

陈工画三朵云：

| 部署模式 | 教材要点 | 星河落点 |
|----------|----------|----------|
| **私有云** | 专有资源池；安全高、投资大、3–5 年回收 | 运控只读订阅、主数据 Oracle、核心 API 网关 |
| **公有云** | 共享资源；成本低、易扩展 | 日志分析、营销试验环境、外站弱网缓存副本 |
| **混合云** | 公私结合；稳态私有+敏态公有；门户/监控/账户统一 | **集团选定模式** |

「混合云不是妥协，」张架构说，「是规划里**敏态与稳态**在基础设施层的落地。统一云管平台管调度，用户一套门户，运维一套监控。」

第二轮分 **服务模式**（IaaS / PaaS / SaaS / FaaS）：

| 模式 | 用户 | 平台映射 |
|------|------|----------|
| **IaaS** | 系统管理员 | 虚拟机、裸金属、网络、块存储——张架构团队管 |
| **PaaS** | 开发人员 | 容器平台、Kafka、CI/CD、主数据开发框架——林小白天天打交道 |
| **SaaS** | 业务用户 | 外站报送 Web、数据目录门户——何站长直接点 |
| **FaaS** | 事件驱动 | 备降规则触发、质量熔断函数——二期预研 |

老周听懂了一句：「我只要结果进 AOC，中间你们爱 PaaS 还是 FaaS。」

陈工总结云计算**内部特征**（虚拟化、弹性、自动化、多租户、编排）和**外部特征**（可靠、安全、连接、成本）——「选云时内外都要看。内部做不到弹性，外部再便宜也是摆设。」

## 三、计算资源：裸金属、虚拟机与容器之争

张架构带林小白做**计算资源规划**，按教材 **7 步**推进：

**需求分析 → 容量规划 → 云服务选择 → 虚拟化策略 → 安全 → 成本效益 → 持续监控**

容量数据来自现网：

- 主数据 Oracle：峰值 CPU 68%，内存 72%，要求低延迟 IO  
- 订阅与规则引擎：波峰波谷明显，促销日 QPS 翻三倍  
- 日志与血缘分析：CPU 中等，磁盘暴涨  
- 外站边缘缓存：节点分散，算力小  

技术选型会上，三种**计算形态**对号入座：

**裸金属（Bare Metal）** — 主数据库集群。「Oracle RAC 要稳定 IO，虚拟化损耗受不了。」张架构拍板两台裸金属撑生产库，灾备库一台。

**虚拟机（VM）** — API 网关、ESB 适配层、旧版报表。「稳态、改动少，VM 够用。」

**容器（Container）** — 主数据服务、订阅服务、规则引擎、质量工作台。「**弹性伸缩**、快速发布，两周迭代靠它。」

**GPU** — 暂不采购，延误预测模型训练租用公有云 GPU 集群，按小时计费。

**弹性计算资源（ECR）** — 促销日自动扩容容器副本，夜间缩容。

方法与技术写进方案：**容量规划、负载均衡、弹性伸缩、虚拟化与容器化、自动化管理、云资源管理（CMP）**。

运控问：「容器挂了怎么办？」

张架构答：「Kubernetes 多副本 + **负载均衡**，运控订阅走专用 VIP，故障切换 30 秒内——写进 SLA。」

林小白在成本表里发现：裸金属前期贵，但 Oracle 许可按核计，反而比盲目堆 VM 省 15%——**成本效益分析**不是选最便宜的，是选总拥有成本。

## 四、存储：SAN 满了之后

存储规划由赵安全和存储工程师老孙牵头，走 **9 步**：

收集需求 → 分析评估 → 技术选择 → 架构设计 → 安全规划 → 容量规划 → 性能优化 → 管理监控 → 定期评估调整

现网痛点一目了然：

- 机务 **DAS** 老盘仍在，迁移不动  
- 运控 **SAN** 块存储快满  
- 营销 **NAS** 堆 CSV，文件级共享  
- 日志湖无分级，全写 SAN，最贵最慢  

老孙在白板画新架构：

| 类型 | 访问级别 | 用途 |
|------|----------|------|
| **SAN** | 块级 | 主数据 Oracle、运控关键库——保留，扩容 |
| **NAS** | 文件级 | 备份、共享配置、非结构化归档 |
| **对象存储** | 对象 | 日志湖、血缘快照、备降场景回放——**迁移主战场** |
| **DAS** | 直连 | 仅遗留机务，设退役时间表 |

「对象存储」让林小白想起教材——以对象为单元，海量扩展，适合云环境。甲司中标的大数据组件正好落对象存储，把 800GB/天的增速从 SAN 挪走，SAN 使用率预测回落到 45%。

安全规划：SAN 双活、对象存储多副本、备份 **3-2-1** 规则（三份数据、两种介质、一份异地）。赵安全要求对象存储桶策略默认私有，日志脱敏后方可进分析区。

性能优化：热数据 SSD 层，温数据 SAS，冷数据对象存储自动沉降——周数据说：「跟数据主题生命周期一致，别一刀切。」

## 五、新机房与云数据中心

存储挪走仍不够。集团常委会批准：**冀南航空云数据中心（一期）** 立项，与数据平台同步。

规划组按 **6.5 云数据中心（CDC）** 写可研，林小白第一次听见 **PUE**：

> PUE = 数据中心总用电量 / IT 设备用电量，越接近 1 越绿色。

现有机房 PUE 1.82，新 CDC 目标 1.35，采用间接蒸发冷却、冷热通道封闭。刘总问：「等级呢？」

张架构答：「国标 **GB 50174** 按 A/B/C 三级，我们按 **A 级**关键系统配——运控与主数据。国际 **TIA-942** 对应 **T3**（可并行维护，99.982% 可用性），运控主任才点头。」

CDC **设计原则**七条逐条落地：可用冗余、弹性扩展、性能优化、安全隐私、灵活可管、节能环保、存储网络可扩展。

**五大要素**写成标语挂在工地：

1. **面向服务** — 资源按旅客/航班服务目录供给  
2. **资源池化** — 计算存储网络统一池  
3. **高效智能** — 自动调度、预测扩容  
4. **按需供给** — 业务申请即开通  
5. **低碳环保** — PUE 与清洁能源占比 KPI  

核心技术章节林小白负责整理网络部分：**网络架构设计、融合技术、性能测试**。测试指标分三层——网络层（带宽、时延、丢包）、传输层（吞吐量、连接数）、应用层（页面延迟、吞吐）。外站到 CDC 的专线做**主被动结合**测试，何站长那边丢包率 0.3% 超标，触发专线运营商整改。

**虚拟化技术**选型：生产 VM 用**硬件辅助虚拟化**，容器用 KVM 底座；老孙补充四种类型——硬件仿真、全虚拟化、半虚拟化、硬件辅助——「考试别混，咱们用的是硬件辅助。」

## 六、预算夜与持续优化

李姐拉财务做**预算管理**，陈工强调云规划六要素缺一不可：**业务需求、资源评估、预算、安全合规、弹性扩展、性能与监控**。

一期云资源投资拆分：

| 科目 | 金额（万） | 说明 |
|------|------------|------|
| 私有云扩容 | 680 | 裸金属+SAN |
| CDC 土建机电 | 4200 | T3/A 级 |
| 公有云（三年） | 360 | 分析+GPU _burst |
| 云管平台 CMP | 280 | 混合云统一门户 |
| 安全与等保 | 220 | 赵安全清单 |

财务质疑公有云：「会不会越用越贵？」

林小白展示**持续优化**循环：监控账单 → 识别闲置 VM → 缩容容器副本 → 冷数据沉降 → 下月复盘。「第五步不是写完就结束，是每月开云资源评审会。」

刘总批准：**有条件启动，CDC 与平台一期同步投产，九个月。**

## 七、迁移演练：一朵云上的备降

投产前一个月，项目组做全链路演练——模拟雷雨备降，数据走新架构：

1. AOC 状态变更 → 私有云 **Kafka** 订阅  
2. 主数据服务（**容器**）匹配旅客 ID  
3. 规则引擎触发备降质量包  
4. 客服 **SaaS** 门户推送改签  
5. 外站 **边缘缓存**（公有云节点）降级可查  
6. 日志写入 **对象存储**，SAN 不涨  
7. 事件报送 API 出 **私有云** 专线至局方  

老周在运控大厅盯屏：「延迟 42 秒，比 60 秒 SLA 好。」

何站长在外站终端确认：「轮椅旅客信息有了，不用传真。」

演练结束，张架构拍拍林小白：「应用长出来，云托住。下一章该织网了——专线、5G、外站丢包，网络规划等着你。」

林小白看着监控大屏上统一的混合云资源视图——计算池绿、对象存储绿、SAN 黄但可控——想起两个月前那片红灯。云不是口号，是**把敏态和稳态分开养、把盘和算力按性格安置**。

陈工发来消息：「六要素背一遍。」

林小白站在机房门口回复：「需求、评估、预算、安全、弹性、性能监控。五步流程：收集、评估规划、预算、设计实施、持续优化。混合云，稳态私有敏态公有，IaaS 管机器，PaaS 给开发，SaaS 给何站长，FaaS 二期再说。」

陈工：「及格。去写《云资源规划书》终稿，别写成厂商彩页。」

## 【陈工的应试锦囊】

**案例题**

| 题干 | 答法 |
|------|------|
| 机房容量不足 | 云资源五步；混合云；对象存储分流 |
| 稳态敏态并存 | 私有云稳态+公有云敏态 |
| 数据库性能 | 裸金属；SAN 块存储 |
| 快速迭代 | 容器+PaaS+弹性伸缩 |
| 新机房 | CDC 五要素；PUE；T3/A 级 |
| 成本上升 | 持续优化循环；冷数据沉降 |

**选择陷阱**：混合云定义；IaaS/PaaS/SaaS 用户；PUE 越接近 1 越好；SAN 块级 vs NAS 文件级；云规划五步顺序。

**论文**：混合云架构；计算存储分离；CDC 与平台同步建设。
