# 第01章 困惑的程序员

> **教材对照**：第1章 信息系统与信息技术发展（1.1 信息系统及其发展 · 1.2 信息技术及其发展 · 1.3 新一代信息技术及其发展）

---

## 一、一条对不上的航班

周一早上九点，林小白盯着 Cursor 刚吐出来的一百多行 Spring Boot 代码，心里空落落的。

他在外包公司做了两年 Java，日常就是接需求、调接口、修 Bug。上周突然被「借调」到星河航空集团——一家拥有三十余架飞机的区域性航空集团，正在筹备**数据资产智能管理平台**。甲方信息中心主任刘岩的原话是：「我们需要一个懂技术、能落地的人先进项目组，别一上来就空谈架构。」

林小白以为终于要从「码农」升级成「核心开发」。报到第一天，会议室却坐满了运控、营销、机务、财务、法务的人，每人一份 PPT，标题惊人地一致：「本部门数据是集团核心资产」。

刘总没有寒暄：「集团二十多套系统，航班、旅客、机组、航材、财务各说各话。上周旅客投诉，客服在营销系统里查是『金卡旅客张三』，运控系统里同一人是『PAX-88421』，财务对账又对不上票号。集团常委会决定做**数据资产智能管理平台**，把数据当资产来管、来运营。现在启动的是**规划阶段**——先摸清楚现状，再谈建设。」

门口走进一个穿灰色夹克的男人：「陈志远，系统规划与管理师。后面三个月，我带大家做现状调研和规划方案。可以写代码，但别急着写。」

林小白心里一沉：不是来开发的？

散会前，刘总把一份《项目工作说明书》推到林小白面前。他扫了一眼里程碑：**现状调研 → 需求分析 → 方案设计 → 实施 → 运维**——这不就是教材里说的信息系统生命周期吗？**系统规划、系统分析、系统设计、系统实施、系统运行维护**——只不过他们现在卡在第一步。

当天下午，运控中心就出事了。

CA2847 因雷雨备降邻市，机上 186 名旅客需要改签。营销部在 CRM 里批量发短信，运控大屏却显示航班「正常到达」——备降信息在 AOC 系统里更新了，但没有同步到客票系统。值班经理拍着桌子：「旅客都下飞机了，你们还在卖下一程座位！」

林小白被陈工拽进运控大厅时，大屏上几千条航班动态在滚，告警声此起彼伏。

陈工指着 CA2847 那行记录问：「小白，你觉得问题出在哪？」

林小白下意识说：「接口没做好，我写个同步服务就行。」

「你再想想。」陈工把三张截图摊在桌上——同一次备降，AOC 显示「ALT-备降」、CRM 显示「ARR-到达」、财务结算系统显示「CNL-取消」。「三个系统、三种状态、三个部门各自正确，合在一起全错。这不是某一个 API 的 Bug，是集团**信息化**没做到位——**信息资源**没统一，**信息系统**没集成，**通信网络**上跑的数据各怀心思。」

林小白愣了几秒，忽然想起刘总开会时说的「各说各话」。陈工补了一句：「你将来要建的平台，表面是软件，实质是让航班、旅客、航材这些数据在**信息网络体系**里可识别、可流通、可运营。信息产业、规章制度、组织考核都得跟上，效果也不是上线一天就能看见——旅客投诉少了、备降处置快了，这些**效用**要慢慢攒。主体是运控、营销、机务到地勤的每一个人；手段是平台、云、大数据；途径是改流程、调组织；目标是安全、效益、体验——教材里叫**主时空手途目**，你今晚写进调研笔记里，别背漏了。」

那天夜里十一点，林小白第一次没写代码，而是整理了一份《CA2847 备降事件数据问题清单》，第一条写着：**同一航班在三个系统中标识不一致，根因待查**。

## 二、三天摸底：从机坪到机房

陈工给林小白排了三天「沉浸式调研」，要求只有六个字：**看现场、记问题、别下结论**。

### 第一天：运控与营销——组织比技术硬

周二清晨，林小白跟着运控工程师老周巡检。塔台旁的 AOC 大厅里，调度员盯着六块屏，嘴里蹦出的术语他一半听不懂。老周指着手环：「这是地勤调度终端，蓝牙连手机，手机走 5G 回传——咱们基地内网是 **LAN**，跟外站机场连是 **WAN**，我这手环算 **PAN**。」

林小白边记边问：「昨天 CA2847 的数据怎么出去的？」

「AOC 写入运控库，」老周打开后台，「营销要客票状态，得走中间件，中间件去年升级过一次，映射规则没更完。我们不愿开实时接口——你们做平台的要知道，运控数据一秒变几次，营销拿来发券，万一错了谁负责？这是**管理**问题，不是网线不够粗。」

下午转场到营销客服中心。林小白亲眼看见客服小刘接投诉：旅客报手机号，她在 CRM 查出「张三」；再查运控旅客库，只有「PAX-88421」；财务又要票号 781-2345678901。三张表，三个键，对不上。

营销信息主管叹气：「我们 2018 年上的 CRM，机务 2019 年换的维修系统，运控 2020 年升级 AOC——那几年集团有钱，各部门抢着建，**冗余、不一致、难共享**全来了。刘总后来成立信息中心统预算，就是教材里诺兰模型**控制阶段**的路子。」

林小白翻出昨晚做的笔记，陈工下午过来审阅时在旁边画了一条线：

```
初始 → 传播 → 控制 → 集成 → 数据管理 → 成熟
```

「星河航空八十年代用主机打报表，财务先上机——**初始**；2000 年后离港、订座、机务各建各的——**传播**；刘总 2016 年卡 IT 投资——**控制**；现在常委会拍板数据平台——要进**集成**，将来还要**数据管理**。前三段是**计算机时代**，后三段是**信息时代**。你们项目立项，就是在推动阶段跃迁。」

林小白问：「怎么判断我们真进了集成，而不是换了个新孤岛？」

陈工指着他那份问题清单：「看**统一基础数据库**有没有、**数据标准**有没有、**跨部门共享**有没有实效。CA2847 这种事故再少，才算往前走了一步。」

### 第二天：机务机库——分布式的老底子

周三，林小白穿上反光背心进了机务机库。机务工程师带他看一架 A320 的维修记录：工卡电子化系统能拍照片、填工时，但航材库存还在另一套系统里。

「这套维修系统数据库是早年的 **DAS**，」机务信息员说，「盘直接挂服务器上，别的系统读不了。集团信息中心想把历史维修记录迁到平台里，光拆这一块就得三个月。」

林小白想起昨晚补看的资料：**DAS 直连主机不能共享；NAS 走文件；SAN 是高速专用存储网**。他追问：「旅客画像、航班主题库放哪？」

「航班主题在运控 **SAN** 上，营销日志在 **NAS** 上扔了一堆 CSV，」对方苦笑，「**集中式**年代买的主机还在地下室机房，各机场又有分布式节点——**物理结构**早就**分布式**了，可**逻辑结构**没统一。你们平台要是再叠一层壳，就真成孤岛之王了。」

中午在机库休息室，陈工和白板上的五层塔不期而遇——不是上课，而是对照机务、运控现网填内容：

| 层次 | 现场对应 |
|------|----------|
| 基础设施层 | ADS-B、机坪传感器、机房交换机、磁盘阵列 |
| 资源管理层 | Linux、Oracle、MySQL 混用 |
| 中间件层 | 老旧 ESB，CA2847 就栽在这 |
| 业务逻辑层 | 数据质量规则？几乎空白 |
| 应用表现层 | 各部门各自报表，没有统一数据目录 |

「狭义的信息系统，」陈工说，「是硬件、网络、软件、信息资源、用户、规章制度组成的**人机一体化系统**；广义上还要加上**组织**和**管理**。你昨天想写接口，是因为你只看到技术和软件。机务这套 DAS，财务那台老主机，运控不愿开接口——**三个维度**缺了两个，平台必死。」

林小白把五层塔拍进手机，备注：**平台重点补中间件层规则引擎 + 应用层数据目录，底座梳理 SAN/NAS 现状**。

### 第三天：机房与合规——安全不是事后诸葛亮

周四，赵安全——集团信息安全负责人——带着林小白进主机房。门禁刷卡、视频抓拍、温湿度报警一路响，林小白突然意识到：这些也是数据，只是还没进「资产」账本。

张架构——集团技术总监——指着机柜：「集团骨干网在这，边界 **防火墙** 在这，运控专网隔离在这。上次渗透测试，营销测试库暴露在 **LAN** 里没做 **访问控制**，旅客手机号差点被拖库。」

赵安全把一份《民航数据安全管理办法》拍在桌上：「平台规划阶段就要定分级分类。旅客证件号要**保密性**，航班状态要**可用性**，结算单据要**完整性**和**不可否认性**——**五属性**缺一个，局方检查不过。」

林小白翻前期事件记录：去年集团做过等保测评，运控三级、营销二级，差距在**态势感知**——海量日志没汇聚，威胁看不见。赵安全说：「平台如果做统一日志中心，四件事得规划进去：**汇聚融合、威胁评估、决策支撑、可视化**。现在别谈区块链炫技，先把**身份认证、RBAC 角色访问控制、加密**落地。」

张架构补充了网络侧的现实问题：外站机场回传时延高，**RTT** 经常超 200ms；集团想上 **SDN** 统一调度带宽，厂商方案还在比。**5G** 地勤手持试点用的是 **eMBB** 场景，机腹传感器上传若走 **uRLLC**，还得单独设计——这些写进《基础设施现状报告》，别写进 PPT 空话。

林小白问：「OSI 七层我要背吗？」

张架构笑：「你不用背定义，得知道问题出在哪层。CA2847 中间件映射错了，是**应用层**业务规则；外站链路抖，是**网络层**和**传输层**。**TCP/IP 四层**是工程里真正在用的。」

## 三、周五评审会：技术不是越新越好

周五下午，刘总要听第一周调研汇报。林小白紧张得手心出汗——他准备的不是代码 Demo，而是三十七条问题、四张现状拓扑草图、一份 CA2847 时间线。

陈工替他开场：「先结论：集团信息系统**复杂、动态、可扩展性不足、部门间难用、实时性要求高、安全压力大、可靠性尚可、成本效益倒挂**——八条特征，我们对上了七条半。」

### 争起来的云和边

张架构讲基础设施：「历史航班和旅客行为数据已经 **PB** 级，CRM 日志大量非结构化，符合大数据 **4V**——**规模、多样、价值密度低、产生速度快**。现有 **Hadoop** 批处理 T+1 出报表，运控要秒级——批的不管用。」

运控代表当场反对：「发动机振动数据上传云端再分析？飞机都落地了！必须在机翼边缘节点先滤波，再同步——**边缘计算**做实时，**云计算**做全局模型，**互补不是替代**。」

林小白插话：「那平台架构是不是 **混合云**？核心运控 **私有云**，营销分析可以租 **公有云** **IaaS**，数据开发走 **PaaS**？」

张架构点头：「**快速、按需、弹性**——云的底子。但多租户、访问控制、云安全得一起规划，别先上车后补票。」

### 被否决的「链」和暂缓的「孪生」

机务主任问：「维修换件记录能不能上 **区块链**？听说改不了。」

周数据——数据治理办主任——摇头：「**分布式账本**适合多方互不信任、留痕取证。自家机务内部系统，**SHA256 哈希 + 审计日志**就能满足大部分**完整性**要求。上链要评估**共识机制**的**性能效率和资源消耗**——为修一张工卡搞 **PoW**，不划算。」

法务记录意见：**区块链列入航材跨境溯源预研，本期不建**。

刘总问：「集团宣传片里的 **数字孪生** 机场呢？」

陈工答：「**建模、仿真、数字线程**——远景可以写进三年规划，本期平台先把**物联网**感知数据收全：机坪车辆 **RFID**、行李转盘传感器、机库 **MEMS** 温湿度，三层 **感知—网络—应用**，现在感知层数据大量浪费，没进主题库。」

### 数据仓库为什么建了用不上

周数据把最难听的话说出来：「2021 年我们做过航班主题 **数据仓库**，定义是**面向主题、集成、非易失、随时间变化**——四条全满足，可源系统数据质量太差，**OLAP** 跑出来的延误分析，运控不认、营销不用，项目半死不活。」

林小白举手：「所以平台首要不是再买一套 **Spark**，而是**采集、整合、清洗**——大数据获取三步；关系库走 **ACID**，旅客主数据必须事务一致；机型、航材知识图谱可以考虑 **NoSQL** 图库，但别指望它替你保证事务。」

周数据看了他一眼：「这句话写进规划建议书，加粗。」

### 人工智能：有米才能下锅

营销部问：「能不能上 **AI** 做旅客标签？」

陈工反问：「**算法、算力、算料**——你们连旅客统一 ID 都没有，标签打给谁？先把主数据弄对，再谈 **专家系统** 式的规则引擎还是机器学习。延误预测模型需要五年以上清洗过的航班数据——那是平台第二阶段的事。」

刘总敲桌子：「同意。第一期：**目录、标准、质量、共享、安全**；第二期：**分析、智能、孪生**。别颠顺序。」

## 四、第一份交付物

周末，林小白在工位上敲《星河航空集团数据平台现状调研报告（初稿）》。陈工只改了三处，却让他记了十年：

第一处，在「信息化总体判断」里加了一段：集团信息化具有**广泛性**（全业务条线）、**深度性**（改变运行与服务方式）、**快速性**（技术迭代快于制度迭代）、**数据量巨大**、**交流快**、**处理能力强**、**跨界整合**（运控+营销+机务）、**生产方式改变**（从经验调度到数据驱动）、**安全问题突出**——「别罗列名词，每一条后面括一个本集团实例，考官爱看这个。」

第二处，在「与国家战略符合性」里写上《国家信息化发展战略纲要》**三步走**，以及集团属于民航 **2012 年至今创新跨越** 阶段——「规划要有高度，(height) 但落脚点仍是 CA2847。」

第三处，删掉林小白写的「建议立即开发数据中台」，改成「建议按**信息系统生命周期**推进：本期完成规划与需求分析；设计阶段明确逻辑五层与物理分布式部署；实施阶段分主题域迭代；运维阶段建立数据质量与安全运营闭环。」

林小白问：「那我还写代码吗？」

陈工说：「写。但你要写的是**规划里的原型验证**——比如用一个小脚本证明旅客三表能匹配，叫**可行性**；不是上来就搭中台。程序员转规划师，最难的是从『我能实现』变成『该不该实现、先实现哪一段』。」

## 五、困惑还在，路清楚了

下周一晨会前，林小白独自站在运控玻璃幕墙前。CA2847 已恢复正班，大屏上绿灯一片。他手机里是陈工转的集团档案室照片：八十年代那台**集中式**主机，标签褪色；旁边是 2024 年新建分布式机房的新闻剪报——**同一组织四十年信息化演进史**，比任何课件都直观。

刘总走过来：「第一周感觉怎么样？」

林小白说：「我以前觉得，借调就是来写平台的。现在才知道，平台还没出生，咱们在做的是给它找**出生理由**和**成长路径**——航班数据、旅客数据、维修数据是**输入**，质量规则和分析是**处理**，改签少出错、延误少扯皮是**输出**；缺组织协同和管理制度，输入输出全白搭。」

刘总笑了：「这话你可以亲自跟常委会说——下周规划论证会，你来讲 CA2847。」

林小白深吸一口气。困惑还在：混合云边界怎么划、边缘节点放几个、数据委员会怎么设——都要在后面章节一点点解开。但他已经明白，**系统规划与管理师**的第一课不是背下诺兰六阶段，而是在机坪、机房、客服中心里看见：**技术、组织、管理**三条线如何绞在一起，然后动手写第一份有人愿意拍板的交付物。

陈工发来微信：「笔记别丢。下周开始读 **数字中国** 和集团「十四五」信息化规划——你会明白，这个项目为什么叫**数据资产**，而不叫**数据接口**。」

林小白回了一个字：「好。」

窗外，又一架飞机拖着晨光滑向跑道。他忽然想起老周那句话：「数据一秒变几次。」——好的信息系统，得跟得上这一秒。

## 【林小白的考点笔记本】

## 【陈工的应试锦囊】

**案例题：把故事翻译成得分点**

| 题干信号 | 答题方向 |
|----------|----------|
| 多系统数据不一致、备降/客诉 | 诺兰**控制→集成**；信息孤岛；统一标准+基础数据库 |
| 实时运控 + 海量分析 | **边缘计算**（局部/实时）+ **云计算/大数据**（全局/离线）；边云协同 |
| 老系统 DAS、数据难共享 | **物理分布式**；存储 **SAN/NAS** 整合；中间件层治理 |
| 旅客信息泄露风险 | 五属性；**RBAC**；等保；态势感知四技术 |
| 盲目上新技术 | 生命周期分阶段；第一期目录/标准/质量，二期智能 |

**论文可用素材（本章已埋梗）**

- **项目背景**：星河航空数据资产智能管理平台；CA2847 暴露跨系统不一致。  
- **可写挑战**：组织壁垒、DAS 遗留、2021 数据仓库闲置。  
- **可写做法**：现状调研、诺兰阶段判断、混合云+边云协同、分阶段建设。  

**选择题陷阱**：诺兰阶段顺序；边缘 vs 云「互补非替代」；数据仓库四特点缺一不可；NoSQL 不保证 ACID。
