```
定义（规划什么）→ 理念与原则（怎么设计）→ 流程（怎么推进）→ 评估与优化（怎么管好）→ 架构与形态（落到什么形式）
```


### 一、应用系统规划的主要内容
**口诀：生体接数件**

- 生命周期选择
- 体系结构定义
- 接口定义
- 数据定义
- 构件定义

**接口三要素**：用户界面 / 外部接口 / 内部接口


### 二、设计理念与原则

**敏捷宣言四种核心价值：**
- 个体和互动 高于 流程和工具
- 工作的软件 高于 详尽的文档
- 客户合作 高于 合同谈判
- 响应变化 高于 遵循计划

**用户界面定义三原则：**
- 置用户于控制之下
- 减少用户的记忆负担
- 保持界面一致

**构件定义典型任务（7项）：**
- 标识问题域对应的类
- 确定基础设施域对应的类
- 细化非可复用构件类
- 说明持久数据源与管理类
- 开发类/构件行为表示
- 细化部署图
- 考虑可选方案


### 三、应用系统规划主要过程
**总口诀：初可详分设**
```
初步调研 → 可行性研究 → 详细调研 → 系统分析 → 系统设计
```

**3.1 初步调研内容：**
- 组织概况 / 组织环境 / 现行系统概况 / 各方态度 / 资源情况

**3.2 可行性研究 → 口诀：经技社管**
- 经济可行性
- 技术可行性
- 社会可行性
- 管理可行性

**可行性研究8步骤：**
复查目标规模 → 研究现行系统 → 导出高层逻辑模型 → 重新定义问题 → 导出评价方案 → 推荐方案 → 草拟计划 → 文档审查

**可行性报告内容：**
- 建设任务提出 / 系统目标 / 初步调研概况 / 实施方案与比较 / 可行性研究 / 结论

**3.3 详细调研活动：**
- 收集信息 / 系统需求建模 / 需求优先级划分 / 构建原型验证 / 产生评估方案 / 复查建议

**3.4 系统分析三阶段：**
- 问题分析阶段 → 需求分析阶段 → 需求定义阶段

**系统说明书特征：** 正确性 / 完整性 / 一致性 / 无二义性 / 可修改性 / 可跟踪性

**3.5 系统设计评价指标 → 口诀：可变效通工**
- 可靠性
- 可变更性
- 效率
- 通用性
- 工作质量


### 四、评估与管理（应用系统组合法APA）
**口诀：应评分制实监**

- 应用系统清单
- 评估应用系统
- 分析应用系统组合
- 制定优化策略
- 实施优化计划
- 监测和评估


### 五、应用架构与形态

**SOA主要适用场景：**
- 组织级应用集成 / 业务流程管理 / 系统扩展和重用 / 云计算和微服务架构 / 跨平台集成

**软件工厂构成：**
- 专业人员 / 基础设施和硬件 / 工具和技术 / 流程规范和方法论 / 质量管理

**软件工厂建设方法：**
- 组织建设 / 资源部署 / 业务管理 / 体系保障

**软件项目交付内容：**
- 发布管理 / 安全性检查 / 事件响应计划

**软件发布后运营阶段：**
- 安全监控 / 安全运营 / 风险评估 / 应急响应 / 升级与变更管理 / 服务与技术支持 / 运营反馈
