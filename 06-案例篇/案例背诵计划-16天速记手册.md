## 第1天 · 第十二章 试题一（服务战略规划）

**服务目录管理6步骤**：成立管理小组→列举服务清单→确定服务类别与代码→编制服务详述→评审并发布→完善服务目录
> 口诀：**成列确编评完**

**服务需求6类**：可用性需求、连续性需求、服务能力需求、信息安全需求、价格需求、服务报告需求
> 口诀：**可连能信价报**

**可用性3指标**：

| 指标 | 含义 | 公式 |
|------|------|------|
| MTBF | 平均无故障时间 | 运行时间/故障次数 |
| MTTR | 平均故障修复时间 | 故障耗时/故障次数 |
| MTBSD | 平均故障间隔 | MTBF + MTTR |

> 口诀：**BF间故障→TR修修复→BSD间间隔**

**信息安全需求3方面**：机密性（保密性）、完整性、可用性
> 口诀：**机完可**

**服务成本6类**：设备、软件、人力、第三方支持、管理、其他
> 口诀：**设软人三管他**

**SLA/OLA/UC**：SLA（供方↔客户）、OLA（供方内部）、UC（供方↔外部供应商，SLA+法律条文）
> 口诀：**SLA外客OLA内UC法**

## 第5天 · 第四章 试题一（规划价值·原则·框架·路径）

**信息系统规划的价值与意义（6点）**

1. 确立组织关键**数字能力目标**
2. 明确数字能力建设**路径**（总分总思维）
3. 确保数字能力建设**认识一致性**（决策层/管理层/执行层）
4. 具象数字能力建设的**关键任务**（时间/资源/责任/成果/关联）
5. 明确数字能力**标准与控制措施**
6. **统筹部署与管理**相关建设资源（数据/网络/基础设施/软件/人力）

> 口诀：**目标 → 路径 → 一致 → 任务 → 标准 → 统筹**

**信息系统规划的6项原则**

1. **战略性** — 与组织战略保持一致
2. **整体性** — 业务/系统/建设/集成四个整体
3. **先进性** — 选择适当技术路线，融合最佳实践
4. **指导性** — 给出框架性要求和建议，不宜过细
5. **柔性** — 适应内外部环境变化
6. **遵从性** — 符合法律法规、标准规范

> 口诀：**战整先指柔遵**

**三种系统总体框架**

| 框架 | 关键词 | 适用对象 |
|------|--------|---------|
| 以**应用功能**为主线 | 成套软件、接口集成 | 信息化初级阶段 / 中小型工业企业 |
| 以**平台能力**为主线 | 平层化、双态IT、快速定制 | 数字化转型中期，向自主创新演进 |
| 以**互联网**为主线 | App化（微服务）、编排组合、云原生 | 集团化企业 / 产业链生态阶段 |

**发展路径选择的4项原则**

1. **业务一致** — 与业务发展路径匹配
2. **能力主线** — 找到符合组织需求的核心能力主线
3. **基础优先** — 优先规划信息基础设施
4. **稳态先行** — 稳态内容先行规划和建设

> 口诀：**业能基稳**

## 第6天 · 第四章 试题二（组织体系·技术体系·资源体系·保障体系）

**大型单位信息组织体系的3种模式**

| 模式 | 特点 | 优点 | 缺点 |
|------|------|------|------|
| **集中式** | 专业信息部门统筹 | 统一规划，避免重复建设 | 响应慢，脱离业务 |
| **分权式** | 各业务单元自建 | 快速响应业务需求 | 重复投资，集成难 |
| **平衡矩阵式** | 基础集中+应用分权；稳态集中+敏态分权 | 集两者优点 | 建设难度大，需治理成熟 |

**技术体系定义的6项原则**

1. **可用性** — 满足建设/运行/发展需要
2. **安全性** — 满足安全要求，保密性和完整性
3. **可靠性** — 从成熟性、整体性、风险性三方面考察
4. **灵活性** — 适应内外部需求变化
5. **可扩展性** — 韧性拓展，适应更多用户/业务/数据
6. **可驾驭性** — 组织能够充分掌控技术体系（尤其关键技术）

> 口诀：**用安可灵展驾**（用安可靠，灵活可扩展，可驾驭）

**资源体系调度的4个方面**

1. **资源识别与评估** — 容量、可用性（特征/时间/财务属性）
2. **资源关系与控制** — 依赖关系、优先级、冲突矛盾、控制指标
3. **资源分配与调度** — 分配策略、分权体系、异常/应急调度方法
4. **资源风险与优化** — 风险分析、应对措施、替代方案

**保障体系的6个方面**

组织保障 / 人员保障 / 技术保障 / 资源保障 / 数据保障 / 安全保障

> 口诀：**组人技资数安**

## 第7天 · 第四章 试题三（需求挖掘·成熟度·规划方法·场景化模型）

**内部需求挖掘的5条注意事项**

1. 以**原始信息获取**为主（文件/数据/总结/问卷类资料）
2. **避免直接给出解决方案**，以听取倾诉为主
3. 及时开展**引导性培训**（需获高层批准）
4. **谨慎信息交叉传递**（未确认内容不交叉传递）
5. 关注**隐性需求的推演**（对基本需求进行科学推演）

**成熟度5个等级**

| 等级 | 名称 | 侧重点 |
|------|------|--------|
| 一级 | **打基础** | 业务规范化、数字化意识、局部信息系统 |
| 二级 | **提效率** | 团队/部门职能为基础，全面推进信息系统 |
| 三级 | **做协同** | 数据共治共享，优化业务流，多元协同 |
| 四级 | **强决策** | 数据模型开发利用，提升决策效率，变革治理模式 |
| 五级 | **构生态** | 跨组织融合，云和互联网模式，广域协同 |

**三种规划方法核心要点**

**SST（战略目标集转移法）**
- 核心：组织战略集 → 信息系统战略集（转换映射）
- 信息系统战略集 = **系统目标 + 系统约束 + 系统建设战略**

**CSF（关键成功因素法）**
- 4步：确定战略目标 → 识别所有成功因素 → 确定关键成功因素 → 识别绩效指标
- 4来源：**产业结构 / 竞争策略与产业地位 / 环境因素 / 暂时因素**

**VCA（价值链分析法）**
- 两类活动：**基本活动**（生产/销售/进料后勤/发货后勤/售后服务）+ **支持性活动**（人事/财务/计划/研发/采购）
- 4步：识别价值链 → 确定关键价值增加环节 → 确定关键价值减少环节 → 明确IT对关键环节的支持

**场景化模型的8个组成部分**

场景定义 / 角色分析 / 业务分析 / 数据分析 / 技术分析 / 组织分析 / 风险分析 / 政策与法律分析

> 口诀：**场角业数技组风政**

**信息系统规划的5个工作要点**

内外部需求挖掘 → 场景化模型分析 → 深度诊断与评估 → 整体与专项规划 → 持续改进

> 口诀：**挖场诊规改**

## 第8天 · 第四章 试题四（分系统划分·发展战略·任务体系·保障体系·Zachman）

**分系统划分的4项原则**

1. **技术一致性** — 按信息技术分类划分（云/物联网/互联网等）
2. **工程一致性** — 持续建设、相对独立的场景单独划分
3. **职能一致性** — 结合职能分工划分（高变更场景按业务边界划分）
4. **数据一致性** — 数据活动作为独立且完善的系统存在

> 口诀：**技工职数**

**信息系统发展战略的主要内容**

1. **发展战略与目标**：基本趋势 + 指导思想/战略目标/基本方针
2. **发展路径与阶段**：路径选择 + 阶段性定义（5级成熟度模式）

**任务体系部署的6个过程**

1. **任务拆解** — 层次化/精细化（领域→工程→项目→活动）
2. **明确目标** — 各层级目标与系统发展目标一致（具体/可测量/可实现）
3. **匹配组织** — 每项任务有对应团队承担，必要时优化组织架构
4. **制定策略** — 针对重点任务制定实现策略，感知风险
5. **定义计划** — 任务内容/干系团队/责任人/时间表/评估指标
6. **监控实施** — 监测措施/会议与报告机制/沟通协调机制

> 口诀：**拆目匹策计监**

**保障体系与任务/资源体系的区别**

- 任务体系 + 资源体系：关注**可量化定义**的内容
- 保障体系：关注**无法量化定义**的内容（组织承诺/人员意识/安全意识/数据治理等"软性"保障）

**Zachman框架**

- 横向6W：**What（数据）/ How（功能）/ Where（网络）/ Who（人员）/ When（进度）/ Why（战略）**
- 纵向6层：**范围模型→企业模型→系统模型→技术模型→详细模型→功能模型**
- 6步实施：确定愿景原则 → 现状分析 → 目标架构定义 → 差距分析 → 制订实施计划 → 持续改进优化

## 第9天 · 第五章 试题一（抽象·基本概念·分层体系·C/S架构）

**抽象的4种类型**

1. **业务抽象** — 聚焦价值本质，面向"场景"建模，可管控/可显性/可重用
2. **过程抽象** — 明确有限功能的指令序列，暗示功能但隐藏细节
3. **数据抽象** — 描述数据对象的具体数据集合（属性集合）
4. **技术抽象** — 可持续开发利用的技术体系，确保技术一致性

> 口诀：**业过数技**

**9个基本概念的逻辑关系**

抽象 → 体系架构 → 模式 → 关注点分离 → 模块化 → 信息隐蔽 → 功能独立 → 求精 → 重构

关注点分离 → 模块化（最常见表现）→ 信息隐蔽（模块化标准）→ 功能独立（前三者的产物）

独立性评估：**内聚性**（模块内功能强度）+ **耦合性**（模块间依赖性）→ 高内聚低耦合

> 口诀：**抽体模关模信功求重**

**分层体系4层**

| 层次 | 功能 | 构造元素 |
|------|------|----------|
| 界面交互层 | 系统与环境交互 | 界面控件 |
| 业务处理层 | 业务流程控制与数据计算 | 业务子系统/功能构件 |
| 数据处理层 | 数据读写处理 | SQL函数包（视图/存储过程/触发器） |
| 数据存储层 | 数据有效存储 | 数据集合体（数据表/数据文件） |

**3种C/S架构对比**

| 架构 | 优点 | 缺点 |
|------|------|------|
| 两层C/S | 简单易实现，操作性能好 | 客户端负担重，变更成本大 |
| 三层C/S | 业务集中，维护方便 | 技术难度大，硬件要求高 |
| B/S | 无需客户端维护，支持远程 | 速度/安全/稳定性低于C/S |

## 第10天 · 第五章 试题二（生命周期·敏捷宣言·数据流方法·Jackson方法）

1. 个体和互动 > 流程和工具
2. 工作的软件 > 详尽的文档
3. 客户合作 > 合同谈判

> 口诀：**人软客变**（人=个体互动，软=工作软件，客=客户合作，变=响应变化）

- 步骤：区分输入/变换中心/输出 → 初始结构图 → 优化

**Jackson方法3种数据结构**

> Jackson方法 vs Warnier方法：Jackson同时考虑输入和输出数据结构，Warnier仅考虑输入

> 口诀：**序选循**

> 口诀：**冗弹优安灵节高**

**4种虚拟化技术**：

| 技术 | 原理要点 | 特点 |
|------|---------|------|
| 硬件仿真 | 在宿主机OS上创建硬件虚拟机仿真硬件 | 兼容性最强 |

> 口诀：**硬指操库应**

**网络架构7要素**：可扩展性、多路径容错、低时延、高带宽、模块化、扁平化、绿色节能

> 网络层口诀：**连带延丢**

**网络测试2方法**：主动测试（发送探测流，适合端到端时延丢包）、被动测试（被动采集数据，适合路径吞吐量）

**PUE公式**：PUE = 数据中心总用电量 / IT设备总用电量（越接近1越绿色）

**数据中心分级**：GB 50174 → A/B/C三级；TIA-942 → T4/T3/T2/T1四级

**建设项目4分类**：建筑工程、机房空调与配电工程、供电系统工程、机房工艺工程

**发展趋势与挑战8项**：多云和混合云环境、自动化和智能化、弹性和可扩展性提升、绿色和可持续发展、安全和合规性、数据治理和隐私保护、边缘计算崛起、AI和机器学习应用
